# AA explainer diagrams (SVG)

Hand-built SVGs, generated by a small Python script, rendered to PNG with Playwright and checked by
eye, then saved as **catalogue artifacts**: the SVG beside a sidecar that names it and marks its
regions, so requirements can link to the diagram or to a spot in it (the Requirements Board's
Artifacts tab shows them, the spot in a red box). The two reference diagrams are artifacts in
`docs/discovery-reference/Updated Requirements/catalogue/artifacts/`:

- `AR-02.svg` (Finding a procedure and choosing its contract): **user view**, three columns (blue
  tree, charcoal table of stacked cards, lavender steps). Generator: `examples/procedure-and-contract-selection.py`.
- `AR-01.svg` (How the system works out a price): **system view**, four stage cards joined by
  chevrons plus a worked-examples table. Generator: `examples/how-a-procedure-is-priced.py`.

Their sidecars (`AR-01.md`, `AR-02.md`) show what regions look like. The artifact format is under
Artifact file in `catalogue/SCHEMA.md`.

Files in this skill:

- `svgkit.py`: palette, primitives and components (`Diagram`, `panel`, `heading`, `tree_section`,
  `tree_collapsed`, `tree_trunk`, `stacked_group`, `table_header`, `table_row`, `step`, `card`,
  `chevron`, `down_arrow`, `pill`, `note`, `bottom_bar`). Start new diagrams from this. `rect`,
  `panel`, `card`, `stacked_group`, `step` and `note` take an optional `id=`: give every part a
  requirement might point at one (`id="stage-3"`), so its region's anchor is `#stage-3`.
- `render.mjs`: SVG to PNG at the SVG's own size. `node .claude/skills/aa-svg-diagram/render.mjs <in.svg> [out.png]`
- `examples/`: the two generators above. They predate the kit and carry their own copies of the
  helpers; read them for layout patterns, coordinates and copy, and keep them runnable
  (`python3 examples/<name>.py <out.svg>`).

## Workflow

1. **Decide the audience and the one question the diagram answers.** A user-facing view (what
   people see and choose) and a system view (how it works behind the screens) are different
   diagrams with different layouts; never mix them in one image, and never give two diagrams the
   same layout if they explain different things.
2. **Gather real content first.** Use real names, codes and figures from the repo (catalogue,
   `docs/discovery-reference/Data files/`, the NZSA RVG PDF) where they exist. Invented figures are
   fine for illustration; keep them plausible and consistent across rows.
3. **Write a generator script** in the scratchpad (not the repo) that imports the kit:
   ```python
   import sys; sys.path.insert(0, "<repo>/.claude/skills/aa-svg-diagram")
   from svgkit import *
   d = Diagram(W, H, title="Short name")
   ...
   d.save(sys.argv[1])
   ```
   Lay out with explicit coordinates and keep layout numbers as named constants (column x
   positions, row pitch) so later edits are one-line changes.
4. **Render and look**: `node .claude/skills/aa-svg-diagram/render.mjs out.svg`, then Read the PNG.
   SVG cannot measure text, so the PNG is the only proof that nothing overlaps or overflows. Fix,
   re-render, repeat until the checklist below passes.
5. **Save it as an artifact** (unless the user wants it somewhere else):
   `npm --prefix requirements-board run artifact:new -- <scratch>/out.svg --title "<what it explains>" --kind diagram --date <today> --author "..." --source "..."`.
   It takes the next `AR-nn`, copies the SVG to `catalogue/artifacts/AR-nn.svg` and writes the
   sidecar. The PNG stays in the scratchpad: it is only the check render (the board draws the SVG,
   sharp at any zoom). Revising an existing diagram: overwrite its `AR-nn.svg` in place, keep its ID.
6. **Mark its regions** in the sidecar, one per part a requirement might point at (each stage,
   panel, group, note): `around: ["#stage-3"]` where you gave the part an `id`, else
   `text=<its exact heading text>` or a `rect[x="..."][y="..."]` selector; the box goes round
   every anchor's match together. Add a one-line description of the diagram.
7. **Link requirements** to it: `artifacts: [AR-nn#stage-3]` on each item it illustrates (just
   before `images:` in the item's frontmatter), the most specific item, a spot where one fits.
   Read each item first. Then `npm run check` (it fails when an anchor matches nothing) and report
   what changed, briefly.

## Visual language

**Canvas.** Page background `#F3F6FA`. No title text on the image: content starts 20px from the
top, with the same 20px outer margin on every side (use `top_crop` or simply start at y=20). Make
the canvas as wide and tall as the content needs (the references are 1760 to 1890 wide); widen
rather than squeeze.

**Type.** Font stack `'Schibsted Grotesk', 'Helvetica Neue', Helvetica, Arial, sans-serif`.
Panel headings 27 to 29 / 800. Card and group titles 18 to 21 / 700 to 800. Body 15 (row names),
12.5 to 14 (captions, muted `#55555E`). Pills 11 to 12.5 / 600. Bottom bar 19, labels 800.

**Shape.** Rounded rectangles everywhere: panels r12 to 14, cards and groups r9 to 10, rows r7,
pills fully rounded. Strokes 1.2 to 1.6px. Tree connectors are the one heavy line: `#2E2E31`,
2.2 to 2.5px, rounded caps.

**Colour roles** (constants in `svgkit.py`):

| Role | Fill / stroke | Use |
|---|---|---|
| List panel | `BLUE` / `BLUE_S` | a master list or tree |
| Hero panel | `CHAR` (charcoal), text white / `LIGHT` | the main subject of a user view |
| Side column | `#F1EDFD` / `LAV_S` | steps, "how to" |
| Section box | `GRN` / `GRN_S` | a top-level group inside a list |
| Sub-box | `SUB` / `SUB_S` | a nested group |
| Leaf item | `PEACH` / `PEACH_S` | the specific thing (a procedure) |
| Notes, summary bar | `YEL` / `YEL_S` | "Good to know", warnings, the bottom bar |
| Kinds | `KIND["green" / "lavender" / "rose"]` | one colour per category of thing; never two similar hues for different kinds |
| State pills | `GOOD_F/GOOD_T` yes, `LOCK_F/LOCK_T` no or locked | a yes/no attribute |
| Pricing pills | `UNITS_*` green for units × rate, `CHIP`/`CHIP_T` grey for a fixed price | how a row is priced |
| Payer pills | `PERSON_*` orange (patient), `INSURER_*` indigo, `HOSPITAL_*` teal: one colour per payer type | who gets the invoice |
| Highlight | `WIN` green outline | the winning value, the rule that applied |
| Accent | `ACCENT` blue | numbered circles, flow chevrons |

Keep each colour to one meaning within a diagram. When things come in kinds, add a small key
(three swatch cards) near where the kinds first appear.

**Recurring patterns.**

- *Tree*: section boxes ticked off a trunk; the trunk starts above the first tick so the list
  implies a parent off-picture. Expand two or three sections, then collapsed grey rows with a `…`
  row, then the last few. A dashed peach connector can link a leaf to where it is used.
- *Stacked group*: kind-coloured card with an offset shadow (reads as "one of many"), a solid
  stripe on the left, title left, a plain right-aligned note (when it is shown, who it is for) rather
  than another pill, white rows inside, caption below. Keep pills for row values; too many pills
  turn into noise.
- *Table inside cards*: one dark header band with dividers; every row repeats faint dividers at
  the same x positions so columns run straight through all the cards. Badges that classify a row
  ("System generated", "Submitted by insurer") sit right-aligned in the name column.
- *Steps*: numbered white cards; a short value chip on the right for pick-one steps, two or three
  lines of muted text for explain steps.
- *Flow*: equal stage cards left to right with `chevron`s in the gaps, a running example carried
  through every stage, then a full-width worked-examples table.
- *Bottom bar*: one sentence that sums the diagram up, `Label:` bold, parts joined by `·`.

**Copy.** Short, plain sentences. Use `·` as a separator and "to" for ranges; avoid en and em
dashes. `→` is fine for sequences. Names over codes, but show the code where users see it
(`Face Lift - H3`).

## Spacing checklist (check on the PNG, every time)

- At least `PAD` (14px) between any box edge and its contents, including pills and value cells
  at the right-hand end of a row.
- No text touching or crossing another box, line or arrow; arrows visible in their own gap.
- Captions clear of the card below; footnotes clear of the panel bottom.
- Columns line up from header to last row.
- Pills fit their label (widen the pill, not shrink the text).
- Panels in a row share top and bottom edges; leftover space is spread, not dumped at one end.
- Nothing runs past the canvas; the 20px outer margin holds on all four sides.
