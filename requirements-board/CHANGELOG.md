# Changelog

Bump `version` in `package.json` and add an entry here before each kit export.

## 1.21.0 · 2026-11-20

- **Long documents diff by what changed.** A one-word change in a long transcript (two joined, 1,500 paragraphs and more) is now one edited row with the rest folded, where every paragraph showed as edited; a one-word change in a long paragraph marks that word instead of tinting the whole paragraph as rewritten; a one-line change in a long field's History line diff is that one line. The shared comparison (`shared/textCompare.ts`) matches the common start and end at any length and, past its table's budget, cuts the rest at lines or words found once on each side; any input its table could hold gets exactly the answer it got before. Two wholly different 1,000-paragraph documents now pair in about 100 to 200 ms (1.2 s before).
- **List markers are not content.** An item inserted in or removed from a numbered list (at the top included) is one added or removed row; the items renumbered after it read unchanged and fold. Another bullet character (`-`, `*`, `+`) is no change. A bullet turned into a number, or a list that now starts at another number, is an edit with the marker itself marked. No edited row ever shows without a mark: one with no changed word (a heading's level) is tinted whole.
- **"Minor" means nothing a reader would notice.** Joining or splitting paragraphs, merging or splitting list items or acceptance criteria, a new list depth, a line turned into a heading, and adding, removing, joining or splitting a mermaid diagram's lines are now changes, shown and counted. **The Diff tab's count can rise** after this update for exactly those cards, which used to be hidden as minor: that is the fix, not a regression. Re-wrapping, spacing and marker-only list changes stay minor.
- **Marks end where the change ends.** A change that starts or ends inside a code span (one crossing a line included), an image or raw HTML no longer marks the rest of the paragraph.
- **Artifacts.** An edited mermaid diagram shows its Before and After drawings beside the source's line diff, tagged "Drawing changed" (Whole card no longer calls two different drawings unchanged), and a source change keeps the card shown and not minor. A file that changed format (Markdown to SVG, or back) shows the Markdown side typeset and the other as its picture, never a broken image. **Open** shows only for a record on the board now.
- **The page tells the truth while it reads.** After a new pick, only "Reading git" shows until the new comparison arrives: never the old "No card differs", "Nothing matches the filters" or a git error under the new versions; an error belongs to the pick that raised it.
- **Keys never pull the page back.** One landing at a time: j, k, Shift J, Shift K, v and the jump list each replace the last, and your own wheel, touch, click or scroll key ends it at once. A target near the bottom that the page cannot bring up stops where the page stops, with nothing left waiting; under reduced motion nothing keeps writing the scroll position. Leaving the tab ends a landing.
- **Viewed ticks from every tab survive.** A tick changes only its own card in the stored comparison, so another tab's ticks are never erased or restored, and other open tabs show it at once.
- **History.** An entry keeps its open disclosure when a refresh adds one above it (entries keyed by what they are, not their place); a line diff shows only lines next to a change as context (no stray first and last line); an open History re-reads when one of the card's own screenshots is re-captured (D-10's versions), never for another card's. A change committed while the board was off now shows once: the journal writes a `seen` line when it first sees a card, and the timeline's detail starts there; a card first seen uncommitted has a "Created" entry. Journals written before keep reading as they did, and an older board ignores `seen` lines.
- **Diff review, artifact files from the repository.** A file named from the repository's top (`/docs/...`) is found when `REPO_ROOT` names the repository through a link.

## 1.20.0 · 2026-11-19

- **A save never reverts what you did not touch.** The item, question and artifact details sheets now send only the fields you changed, with the values you started from. Keep mine lays your fields over the file as it is now, so an agent's `artifacts:`, a re-captured screenshot or your own drag of the card survives it. A change on disk that touches only fields you have not changed is taken into your draft quietly; Keep mine / Load theirs appears only for a field changed on both sides, and the banner names it. The status menu, Retire and the answer flow send the status alone.
- **Nothing typed is lost to a save, and nothing unchanged is saved.** Typing on while a save is in flight stays an unsaved change on the saved copy. Cmd/Ctrl S with nothing changed writes nothing (still no browser save dialog), so a blank new card is still dropped when you leave it.
- **Orphaned drafts.** A record that goes from disk while you have unsaved edits shows every changed field in readable form (cards by title, statuses by name, a cleared field as Cleared), and every way out asks first: Esc, the scrim, the close button, a click on the board. A confirmed discard is final, and a card the board creates or deletes clears any draft left under its ID, so a reused ID never opens with a dead card's text. The artifact page does the same for its details and leaves full screen when the artifact goes. A sheet opened before its record exists shows it when it appears (a question then steps from where it lands), and names the check's error for a file that does not read.
- **Focus.** A modal sheet opened in Edit keeps your typing in its title; closing gives focus back to what had it (the first opener, after stepping through siblings), or to the page, never to nothing. The discard question takes focus once, when it appears, never again when a file changes; answering it puts focus back where you were. Leaving Edit keeps focus in the sheet. Save errors are announced. A way out raised inside a question over the docked panel goes ahead (the panel keeps its draft) instead of waiting on a question nobody can see; a New card waiting on the panel's answer uses the form as it is then.
- **Settings saves only real, current changes.** Each section sends the revision it was edited from; a section changed in the file meanwhile shows Load theirs / Keep mine (merged row by row; a new status whose number the file has meanwhile used takes the next free one). A section is dirty only when saving would change the file (a project name with spaces, a lower-case component code). A damaged status list, or a project or components section that does not read cleanly, is locked until the file is fixed, and comes back live; a list with lesser problems can be saved to repair it. Components count artifacts in "Used by"; once the list names one component, any in use but unlisted are named with an "Add them" button and Save waits; a new row is never locked because of its name.
- **Server.** A whole-record save (`{ record }`) and a Settings section sent without its base are now refused (400): the board no longer sends either. A components save that would leave a component in use newly unlisted is refused (422), judged against the file, and a project or components save over a section that does not read cleanly is refused. The config carries `sectionState` for `project` and `components`.
## 1.19.0 · 2026-11-19

- **Card moves are no longer lost.** Leaving or reloading the tab while a card move is not saved yet (waiting, failed, or being sent, a Mapped drop included) now asks first, as unsaved sheet edits do. Unsaved Freeform moves are kept for the tab (session storage) across a reload, including Vite's automatic one after the dev server restarts: they show on the board after it and are sent, then forgotten. A Mapped move still saving at a reload is never sent again; afterwards the board checks whether it landed and says so only if it did not.
- **The board notices its server coming back.** While Offline the board asks its own server every 2 s, even after "Stay" on a leave prompt (when Vite stops trying). When it answers, kept card moves are saved and the problem pill reads "Server is back", with a Reload in its list. The Offline line now says what is kept (card moves) and what stays a draft (sheet edits); the card-move problem no longer repeats its own prefix. The reconnect handler that never ran is gone.
- **Live updates arrive in order, in one piece.** Each re-sync or write request now reaches every open tab as one `catalogue:changed` delivery carrying all its records, layout, config, issues and screenshot versions, numbered within the server's run. A snapshot (start-up, a second load, a reload) never takes the board back: deliveries that arrived while it was on its way are applied over it, and of two overlapping loads the later one wins. One delivery is one store update and one board rebuild; cards it did not change keep their node and do not re-render. In a scratch copy of this catalogue, 300 records changed at once settled in about 1 s with 504 card renders and one rebuild, where it took 8.4 s with 4,690 renders and 300 rebuilds. An artifact entry is applied only when its rev or its file's facts changed.
- **A burst of file changes costs what changed.** The watcher hands the re-sync the paths that changed, and it re-reads only those files: a note, a change log or the board's own write echoing back costs nothing beyond reading that file, and a screenshot change scans one card's folder. A folder added or removed, a watcher error or more than 500 paths at once reads the whole folder, as before. The result equals a full re-read (tests/resync.test.ts proves it over random bursts). On a copy of this catalogue a one-file re-sync takes about 35 to 90 ms against 540 to 1,490 ms before.
- **Screenshot versions (D-10).** Every screenshot has a version, its git blob hash: `assets` in the catalogue snapshot and the store, and in a delivery when a screenshot is rewritten, added (its version) or removed (null). A touch without a content change keeps it. `assetUrl(src, version)` puts it in the URL as `?v=`; any version is served the current file. The History and gallery use it from B09 and B10.
- **Card moves are saved in order, and never for a removed card.** Freeform saves now go one at a time, so a failed earlier save can no longer put an older position over a newer one, and two saves can no longer reach the file out of order. While a move is saving, a layout change from the file moves every other card but leaves the moving one where you put it. A card deleted here or on disk leaves every waiting, failed and kept save and every undo and redo step, and the server no longer writes a position for a card with no file.

## 1.18.0 · 2026-11-19

- **A save changes only what it changes.** Saving a card, a question or an artifact's details now edits the file in place: only the lines of the fields you changed are rewritten. Every other key keeps its order, quoting and flow or block style, and comments, keys the board does not know, values it cannot read and the body sections you did not touch stay byte for byte. On a file already in the board's own form the result is exactly what it wrote before. A change that cannot be saved without losing something is refused, never written. New records are still written whole in the board's form.
- **Artifact details keep everything else.** Renaming an artifact or editing its details no longer drops a `cited_as` mapping, keys the board ignores in regions, steps, moves and citations, a row that is not a mapping, a value such as `pad: wide` (once written as `.nan`), comments, or the prose and extra fences in `## Source`. The `cited_as` lint now says a save keeps what it cannot read.
- **Saves send their changes, not the whole record.** A record write may send only the fields it changed (`patch`), with the rev it edited and, optionally, each field's starting value (`base`). The server lays the patch over the file as it is now, so a field you did not touch keeps whatever an agent or a drag wrote there meanwhile. With `base`, a save still goes through when the file changed on disk but none of its own fields did; a clash is a 409 that names the fields (`collisions`) and carries the current copy. A batch names every record that blocked it (`blocked`). A save that changes nothing writes nothing, journals nothing and sends no event. Today's whole-record saves keep working, refused on any change on disk as before, and are written as the fields that differ from the file. The protocol is documented at the top of `server/catalogueApi.ts`.
- **Settings sections carry their own revision.** `config.revs` holds one per section (project, components, item statuses, question statuses), in the catalogue and in config events. A config write may send the ones it edited from (`bases`); a section an agent changed since is a 409 with the section as it is now, never overwritten.
- **Renaming or removing a lane is one change.** `POST /api/lanes` rewrites the lane list and the `swimlane` of every story in the lane together, or nothing: it is refused, changing no file, when a story or the lane list changed on disk since (`layout.lanesRev`), the new name breaks a lane rule, or `board-layout.json` cannot be read. The board's lane rename and remove use it, so a refused rename no longer leaves stories in a lane that does not exist. A lane write may send `lanesRev` to be refused if the list changed meanwhile.
- **Card moves are never refused for a lane problem they did not cause.** A layout write that only moves cards is accepted whatever the lane list on disk holds, and a lane change is refused only if it adds a problem. The check now reports every lane rule the board enforces: a name over 40 characters, spaces around a name, a repeated name (case aside, the first lane's included), and an entry that is not a name.
- **All or nothing, and cheaper.** A write that changes several files (a Mapped board move, a delete, a lane change) puts back the files it already wrote if one fails. One write request runs the integrity check once after writing and sends one issues event, whatever its size: a 40-story lane rename sent 80 events before. A check that fails on unexpected data no longer turns a save into a server error.
- **Creates work without hard links.** Creating a card, a question or an artifact sidecar now works on exFAT drives and network mounts that refuse hard links (checked by hand on an exFAT disk image): the ID is still claimed exclusively, so two creators never collide.
- **`artifact:new` claims its ID first.** It claims the next `AR-nn` before touching any file and moves on if another session took it, never copies or moves a file over another (a stray `AR-nn` drawing already in `files/` makes it take the next ID), and gives the claim back if bringing the file in fails, leaving it where it was and no copy behind. A tracked file is moved without staging (no more `git mv`): add both paths when you commit. Its arguments and output are unchanged otherwise.
- **A reused ID's history starts with the new card.** When the board reissues a deleted card's ID, or an agent re-creates it as another card, its History no longer shows the deleted card's commits and journal entries as its past, whether or not the deletion was committed in between. A card restored as it was (a revert, an undo) keeps its history across the gap. An artifact ID reissued after a committed deletion starts afresh the same way. Plain-text mentions of a deleted ID in other records stay as written and name whichever card later takes the ID.

## 1.17.0 · 2026-11-19

- **History follows HEAD's first parents.** A card's, sidecar's, artifact file's and screenshot's history now lists only commits on HEAD's first-parent chain, each compared with its first parent, as the Diff review already did. A lane merged with `--no-ff` now shows as **one entry at the merge**, with the merge's own message, where it used to show its lane commits interleaved with master's. That interleaving made the timeline show false reverts. A fast-forward merge still lists the lane's commits one by one.
- **Moves are followed exactly.** Each earlier path counts only up to the commit that moved the file, so an archived file (`pricing.svg` renamed `pricing-v1.svg`) and a new file later added at its old name keep their own histories, and a chain of renames is followed step by step. A screenshot is followed through its own renames: a file moved from another card's folder no longer brings that card's screenshot history with it. A folder moved with plain `mv`, not yet staged, keeps its history at once when its files are unchanged. A move that also edited a file shows once staged. History is never kept stale after staging, unstaging or committing a move, in a linked worktree as in the main checkout.
- **Deletions are marked.** A committed deletion stays in the list as a version with `deleted: true` (and on an artifact file's commit, and in a card's `screenshotsEnded`), so a reused ID's history can be cut there. A branch switch or a stash creates no mark.
- **Any file name, either hash width.** Accented and other non-ASCII names, quotes, backslashes, tabs and newlines in paths read correctly whatever `core.quotePath` is set to, including a non-ASCII folder that has moved. SHA-256 repositories get artifact-file and screenshot history and working names in their own width. The journal now records screenshot hashes in the repository's width. A hash kept in the other width (a SHA-256 repository's journal from an earlier version) is taken afresh on the next scan without logging a change, and those old journal entries cannot be fetched.
- **Unchanged files read as unchanged.** A file on disk is named as `git add` would store it (`core.autocrlf`, `.gitattributes` `text`/`eol`, clean filters such as LFS), so the Diff review and an artifact's history no longer report a change in a file nobody touched. `/history-blob/` serves a version as a checkout would write it (smudge filters and line endings applied; an LFS version as its pointer, so a request never fetches from the network), and serves a screenshot by `src` only when the blob was ever that file.
- **Reading history never locks git.** Every git call the board makes runs with optional locks off, so `git status` no longer rewrites the index under `index.lock`, which could make an agent's `git commit` or `git add` fail with "index.lock exists". Inherited variables such as `GIT_DIR`, which would point git at another repository, are ignored, and settings that change git's output (`status.showUntrackedFiles`, `core.quotePath`, `log.follow`) are pinned.
- **Cheaper and bounded.** Identical reads in flight share one git run (a Diff count runs the whole-history rename log once, not three times), uncommitted renames are cached until the index changes (also in linked worktrees), and every history cache has a size bound. A cached comparison of two commits reads today's artifacts afresh on each response. A card's history on this repository: 5.5 s cold before, 2.6 s now.

## 1.16.0 · 2026-11-19

- **One rule, one implementation.** Each catalogue text rule now has one home in `shared/`, used by the check, the server, the document viewer and the scripts alike, so the check no longer accepts what the board cannot show, or refuses what it shows correctly.
- **What counts as code** (`shared/markdownCode.ts`) follows CommonMark: a code span closes only on a run of backticks of the same length and never crosses a blank line, a lone backtick is plain text, and a fence closes only on the same character, at least as long. Delete planning and the check now agree, so a delete the dialog allows is never refused for a link it said it would unlink. Each field of a card, question or artifact is read on its own, so a backtick in one field can't hide a link in the next (the check and an artifact's Linked tab). An image whose target is a record ID (`![x](US-01.1.2)`) is an image, not a link, for every reader.
- **Headings keep their slugs in the page.** The document viewer gives each heading the slug of the source heading on its line, as the server, the check and the Sections list do, so a heading that holds a record ID (drawn as its title) opens from the Sections list and from any link the check accepts. `heading=` anchors match on the source heading's text in the check and the viewer alike.
- **Heading and quote text read as the page shows them.** An underscore inside a word stays (`fee_schedule`), an entity is its character (`Q&amp;A` is "Q&A", slug `qa`), `# C#` keeps its `#`, strikethrough marks go, a defined reference link and an autolink read as their words, an escape as its character. A stray `<` no longer swallows the text after it in a document's quote text. A `quote=` anchor is compared in Unicode NFC on both sides, so a decomposed passage ("Māori" typed as a plus a macron) is found and boxed over exactly its words, and a passage across a bare record ID matches as written in the source.
- **Mermaid node IDs are read as mermaid reads them**: `A --> B[Label]` declares B, the flag shape, `@{ ... }` shapes, every link form (`--o`, `--x`, `o--o`, `<-->`, long, dotted, thick, labelled) and `&` chains are read, and no `o` or `x` edge head becomes a node. Tested against mermaid's own parser over a corpus of every form.
- **A selector the browser rejects** (`rect.panel,`, an empty part of a comma list) is a warning that the board draws nothing for it, never "the box spans them all".
- **One spot rule.** A spot exists or not by one rule for the check, sources, the hand-on to a replacement and `cited_as`: a page only on a PDF, lines only on a Markdown document (from 1, first line first), points only where a file has them. A `cited_as` `spot` may be a page or line range as well as a region, step or heading. An item's `artifacts:` entry and a pasted `AR-nn#spot` take any spot the slug rule makes (`#te-reo-māori`). A source naming a page on a Markdown file or a drawing, lines on a PDF, a reversed or zero line range, or points on a file with none, warns naming the artifact and spot. A source on a retired artifact is worked out on its replacement, with no warning about the old one.
- **Sources read as written.** `OQ-01 · answered by Sam` is OQ-01. A points list `#2 #3`, `#2#3` or `#2, #3` checks every point. A note cite whose words name a note but whose tail is no spot says so, naming the right file. Two sidecars on one file, and a prefix one artifact lists twice, warn (they never block a save).
- **Frontmatter lint tells the truth.** A `#` inside a block scalar (`caption: |-`) or a quoted list value is no longer flagged, and a real unquoted ` #` is confirmed against what YAML kept. `cited_as` is linted: not a list, an entry neither a prefix nor a mapping, or a key the board ignores (`pageOffset`: did you mean `page_offset`?), each dropped on the next board save.
- **Agent tools use the same rules.** An agent tool imports `shared/*.ts` directly, found from the catalogue path it takes (accepted decision 18; Node 22.18 or later). `resolveNoteCite(loadSourceIndex(req), cite)` (`shared/sources.ts`, `server/sourceIndex.ts`) gives an agent the note a `Notes <date> · ...` cite opens, exactly as the board resolves it (`agent/shared-rules.test.mjs`).
- `BOARD_E2E_REAL_PORT` moves the opt-in real-catalogue browser checks off port 5181, for a worktree with its own ports.

## 1.15.0 · 2026-11-19

- **Bad data never white-screens the board.** A card that is its own parent, or in a parent cycle, opens, draws its lineage, drags and deletes like any other (each card is walked once); the check names the cycle on every card in it. A card whose `type` is not an item type is drawn in the column of cards without a valid parent, its sheet and delete question open, and its type shows as stored (never `undefined`), sorted after the known types.
- **A crash stays in its part of the page.** Each view and each sheet (modal and docked) has an error boundary: a part that fails to draw shows a recovery panel in its place (what failed, Close card, Try again, Go to board, Details to copy) while the masthead and the rest keep working, and the problem pill lists it under "This page" until it recovers. It tries once more by itself when the catalogue changes, and never loops. Close card clears the card from the address, so a reload does not reopen it. Unsaved drafts survive and the leave prompt still protects them. Uncaught errors from clicks and promises are listed under "This page" too (dismissable), and a saved browser preference that could not be read, and was reset, under "Saved preferences".
- **Nothing counted is hidden.** The Outline lists every card: a last group, "Not under an epic", holds cards whose parent is missing, non-epics with no parent and parent cycles, each with its reason, searchable and reachable by keyboard. Outstanding items lists a question whose status is not configured in a group of its own after the others, steppable from its sheet, so the list matches the masthead count.
- **One file never stops the catalogue loading.** An artifact file that can't be read, or whose contents can't be made sense of (a character reference past U+10FFFF), is an issue on that artifact, retried on the next load; the rest loads. A screenshot folder with a dangling link, an unreadable image or a torn record no longer stops the dev server starting, a sync or a delete. If the check itself fails, one error says so. Files whose names start with `.` in the record folders (`._EP-01.md`, `.#US-01.1.1.md`) are ignored and claim no ID.
- **Files are read the way editors write them.** A byte-order mark at the start of a record, `board-layout.json`, `board.config.json` or `status-recodes.json` is read past, and kept when the board or `statuses:recode` rewrites the file. Layout positions that are not `{ x, y }` numbers are ignored and named in an error on `layout`; the next card move writes the file without them, and a delete over such a file succeeds. A layout that is valid JSON but not an object says so.
- **Deleting a card in a parent cycle works:** each card goes once, the layout is tidied, and the request succeeds (it used to fail part way).
- **Saved browser preferences can't break a view.** Every preference kept as JSON (board view, Artifacts view, board position, Outline folds, the Diff review's Viewed ticks) is read through one rule: a value of the wrong shape reads as the defaults for the wrong parts. The next tick repairs the Viewed store.
- **Find keeps its matches on the right letters** after a character whose lower case is longer ("İ"), and counts the same before and after a PDF page is drawn; a word-final sigma finds a capital one.
- **PDFs are read once.** Their facts are kept in `.pdf-facts/` beside the board (gitignored; `PDF_FACTS_DIR` overrides), keyed by the file's content and the extractor's version, so starting the board or running the check again does not re-read an unchanged PDF; every PDF that does need reading is read in one child process. A damaged entry is rebuilt, two processes can write at once, and a failed run is never kept. `npm run check` on this catalogue: 2.3 s before, 0.55 s once the facts are kept.

## 1.14.0 · 2026-11-19

- **A status number means what the project's list says, or nothing.** A status list with a problem is never swapped for the built-in lists, whose numbers mean different things (built-in 5 is Retired; a project's 5 may be Confirmed). A bad `tone` falls back for that status alone and the list stays usable (*degraded*). A structural problem (a missing or doubled code, a role or settle rule broken, a config file that does not parse) makes the list *damaged*: the board reads only what it can of the project's own list (a role two statuses claim counts for neither, so nothing is hidden as retired on a guess), the check reports the list once instead of flagging every card, and the server refuses status saves for that list, leaving the file untouched. New cards are refused while the default status can't be told; a card's status can change only to one the project's list defines. Each list's state reaches the client as `config.statusState` (`healthy`, `degraded`, `damaged`, its problems and high-water mark), ready for Settings to lock a damaged list.
- **A status number is never handed out twice.** Removing a status in Settings records it under `removedStatuses` in `board.config.json` (code and last label); old versions storing it read as that label, marked removed, and the check says when a card still holds one. A new status takes a number past every code the list has used: live, removed, in a recode, or on a card. The server refuses a list that reuses one. Whether a status is in use is judged against the file on disk, not the server's copy.
- **`statuses:recode` is safe to renumber with.** It refuses a map that would merge statuses silently (a live status left out while others are renumbered), a target that it or an earlier recode moves away, or one used before, so following the recorded recodes always reads a version saved before or after a recode right; to merge on purpose, name the status kept too (`3=4,4=4`), and the dry run lists merges. It now also moves the codes in `board.config.json`. It records the run first and writes each file whole (temp file, then rename); a journal line it can't read is kept byte for byte, and if a step fails it names the file and step, and the same command run again finishes the recode without recording it twice. It refuses to run while a board watches the same catalogue (the board keeps a lock in its journal folder; a stale one is ignored), which used to leave journal entries for status changes that never happened. The journal pass also runs on a scratch catalogue (`HISTORY_DIR`). It refuses, writing nothing, when `status-recodes.json` can't be read (it used to replace it), and appends to it with every earlier entry kept as written. An old name (from before statuses were codes) may map to a live code or a fresh one, never a spent one. The check reports an overlapping recode history, and a live status whose code a recode moved away.
- A status's `label`, `help` or `heading` that is not text is reported (the list stays usable). A Settings save over a `board.config.json` that is not an object is refused with 422 instead of failing with 500.
- **The CSV export shows status labels**, from the project's list, in place of bare numbers; a code the list does not define is written as stored. Columns are unchanged.
- **A saved status filter survives a config that is broken for a moment.** It is pruned only when a status is really gone, never while a list is damaged or the file can't be read.

## 1.13.0 · 2026-11-19

- **Drawings cannot run script or reach out.** The SVG sanitiser judges links by what a browser resolves, not how they are written: any URL-bearing attribute (`href` under any prefix, `src`, `action`, `data` and the like, in any namespace) keeps only `#id` (not a board route, `#/...`) or a picture as data; `url()`, `image-set()`, `@import` and the like that load from elsewhere go from presentation attributes, `style` attributes and `<style>` elements, read as a browser reads them (newlines normalised, escapes undone, a `/*` inside a string no comment). A `<style>` loses only the declarations that reach out, the rest kept exactly as written, in linear time whatever it holds (a large embedded font included). Elements from other vocabularies (HTML, MathML) go, and so does a drawing whose root is not an SVG element. References to the drawing's own elements (`url(#id)`, `<use href="#id">`, gradients, markers) stay, now including `url( "#id" )` written with spaces and quotes, which was blanked before.
- **A link in a drawing never moves the board.** Only the board's own record links open anything (a click opens the record, a modified click a new tab). A drawing's own link to one of its spots (`#id`) brings that spot into view; any other link does nothing, plain, modified, middle-clicked or by keyboard.
- **Raw catalogue files are served only by the board's routes.** The plugin adds a Vite `server.fs.deny` rule for the catalogue folder being served and the one beside the board (as written and as real paths), and answers 404 itself for any path into them, decided by what the file system opens (folders compared by identity), so no spelling gets through: `%72equirements`, upper case, `requirementſ` (Unicode case folding), decomposed accents, `//`, dot segments, `/@fs/`, `/@id/`. Its own `/requirements/` route reads every spelling the same way and serves only image files under `assets/`.
- **Misses are 404s.** `/artifact-file/` and `/history-blob/` answer 404 (GET and HEAD) when they cannot serve, never the app's page; a failing history lookup no longer leaves an unhandled rejection, which could stop the dev server. The viewer's "the file is missing" now shows.
- **Other origins cannot read the board.** CORS is off, and a read another site's page asks for (fetch metadata `cross-site` or `same-site`, other than a top-level visit) is refused 403 on every route, Vite's own included (so another page can no longer trigger `/__open-in-editor`); the API and file routes also send `Cross-Origin-Resource-Policy: same-origin`. Every file sent carries `X-Content-Type-Options: nosniff`; every SVG the no-script CSP.
- **Malformed URLs are client errors.** One decode rule (`idFromPath`) for every ID taken from a URL: a bad `%` escape is 400, and so is an ID with a path separator, `.` or `..`, or a control character, refused before any file is read. A bad escape on any other path is 400. A name every object inherits (`__proto__`, `constructor`) is a 404 on the history routes, not a 500.
- **Symbolic links that lead out of their folder** (a screenshot, an artifact file) are still served, with a warning in the server log and a check warning naming where they lead. Paths are compared as real folders, so a requirements folder or repository reached through a link (a macOS temp folder under `/var`) gets the right repository-relative path for its artifacts.
