Set up the Requirements Board

A requirements catalogue kept as Markdown files in git, a local board to read and arrange it, and Claude Code skills that keep it up to date from your meetings and decisions.

Kit {{version}}

Files in git

Every epic, feature, story and question is a Markdown file. A commit is a version of the requirements.

A local board

Runs on your machine and edits the same files: arrange cards, set statuses, answer questions, open diagrams.

Claude's skills

Turn transcripts, notes and decisions into changes to those files, and keep a build plan in step.

1Check what you need

  • Node 22.18 or newer. Check with node -v; get it from nodejs.org or nvm.
  • Claude Code, for the skills.
  • git (recommended): the build plan skill works from commits, and git keeps the requirements' history.

2Put this folder in a repo

The requirements-board folder goes at the root of a repo: beside your app or prototype, or on its own in a new repo. It never touches your app.

your-repo/ ├── requirements-board/ ← this folder ├── your-app/ (if you have one) ├── .claude/skills/ (the board's skills are copied in here, next to any you have) └── CLAUDE.md

Starting fresh? Make a new folder, put requirements-board in it, and run git init there.

3Set it up

With Claude Code easiest

Open Claude Code at the repo root and paste the prompt below. It installs everything, copies the skills in, adds a section to your CLAUDE.md, asks you a few questions about your project, and starts the board.

By hand

Run the commands yourself: open "Set it up by hand" below the prompt.

Set up the Requirements Board in this repo. Its folder, requirements-board/, is at the repo root.

1. Check that Node is 22.18 or newer (node -v). If it isn't, tell me how to upgrade and stop.
2. Run `npm --prefix requirements-board install`, then `npm --prefix requirements-board run install-skills`.
3. Add the "Requirements" section from requirements-board/START-HERE.html to the CLAUDE.md at the repo root. Create the file if there is none, and don't add the section twice.
4. Fill in every <TODO: ...> placeholder in the "This repo" section of each skill in requirements-board/agent/skills/ (requirements-board/ADOPTING.md, step 4, says what each one needs). Look in this repo first, then ask me for whatever you can't find, all in one go. Afterwards run `npm --prefix requirements-board run install-skills` again.
5. Run `npm --prefix requirements-board run check`, then start the board with `npm --prefix requirements-board run dev` in the background and give me its URL.

Claude Code will ask you for:

  • who signs the requirements off (your client, product owner, sponsor);
  • where your app lives, and where the build plan should go;
  • the people involved and which documents count for most when sources disagree;
  • a folder outside the repo for consistency review runs.
Set it up by hand
  1. From the repo root, install the board and copy its skills into .claude/: 
    npm --prefix requirements-board install
npm --prefix requirements-board run install-skills
  2. Add this section to CLAUDE.md at the repo root (make the file if there is none): 
    ## Requirements

The requirements live in `requirements-board/requirements/` (format: its `SCHEMA.md`). Edit them as files or on
the Requirements Board (`npm --prefix requirements-board run dev`, http://localhost:5180), then run
`npm --prefix requirements-board run check`, which must pass. Record meetings and decisions with
`/update-requirements`; after a commit, `/update-build-plan` keeps the build plan in step. The skills'
source is `requirements-board/agent/`: edit them there, then run `npm --prefix requirements-board run install-skills`.
  3. In each requirements-board/agent/skills/*/SKILL.md, fill in the <TODO: ...> placeholders in its "This repo" section (ADOPTING.md, step 4, says what each needs). Then run install-skills again.
  4. Start the board: 
    npm --prefix requirements-board run dev

4Open the board

Go to http://localhost:5180. It starts with a few cards, a question and a diagram that explain how it works.

  • Start here (top right) opens the About page: the requirements loop, every skill, and what is on the board.
  • Settings (the cog): name the board and the project, set your components and statuses, and edit the writing voice: how Claude Code writes your requirements (kept in requirements/VOICE.md), to match how your team writes.
  • Start a new Claude Code session so it picks up the skills: type / to see them.
  • When you're ready, delete the starter cards (the "Delete these examples" card says how).

5Go round the loop

After each meeting or decision, hand Claude Code the evidence with /update-requirements, review the result on the board, commit, then keep the build plan in step with /update-build-plan.

If something goes wrong

The skills don't show when I type /

Start a new Claude Code session at the repo root. Still missing? Run npm --prefix requirements-board run install-skills from the repo root: it copies them into .claude/skills/, and says if it skipped any because your repo already has a skill of the same name.

I edited a skill and nothing changed

The skills' source is requirements-board/agent/skills/; .claude/skills/ holds copies. Edit the source, then run install-skills again. Edits made in .claude/ are overwritten.

"Port 5180 is in use"

The board is probably already running in another terminal: open http://localhost:5180. Otherwise stop whatever holds the port.

Errors about Node or TypeScript files

The board's scripts need Node 22.18 or newer (node -v). Upgrade, then run the install again.

Checks show an error

Click Checks in the board's masthead to see which file and why, or run npm --prefix requirements-board run check. Ask Claude Code to fix it if it isn't obvious.
