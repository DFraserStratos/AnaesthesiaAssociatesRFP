The Contracts to set tab of [the Lists section](US-13.1.3) shows, across every date, the Lists whose Procedures still need a Contract: one row per List, with how many of its Procedures are set ("3 of 5 set"). An admin opens a List from its row to set the rest.

The Day view's rail shows the same for the day in view, on a Contracts tab beside the [to-do list](US-13.7.2) and the [notifications](US-13.8.1).

This is so the office can work through the Contracts it still has to set as one steady queue, without them burying the warnings that need action.

- Each Procedure still to set shows how far it has got: nothing chosen yet, or where the invoice goes chosen but no Contract yet.
- Lists whose date has passed come first, marked strongly, as they hold up submission. The rest follow, soonest first.
- A List leaves both tabs once every Procedure on it has a Contract, whoever set it.
- Only a missing Contract puts a List there. The RVG code, times and modifiers the anaesthetist fills in under a Contract priced from RVG units never do.

## Acceptance criteria

- **One row per List.** Given a List with five Procedures, two of them with no Contract, then the Contracts to set tab shows one row for the List, reading "3 of 5 set".
- **Every date.** Given Lists needing Contracts on today and on a day next week, then the Contracts to set tab shows both, and the Day rail's Contracts tab on today shows only today's.
- **How far it got.** Given a Procedure whose invoice destination is chosen but whose Contract is not, then its List's row shows it part way, apart from one with nothing chosen.
- **Past first.** Given a List dated yesterday and one dated tomorrow, both still needing Contracts, then yesterday's comes first and is marked strongly.
- **Leaves when set.** Given a List with one Procedure left to set, when the anaesthetist or the office sets its Contract, then the List leaves both tabs.
- **RVG detail is not a gap.** Given a Procedure on a Contract priced from RVG units with no RVG code yet, then its List is not on either tab for it.
- **Not a to-do.** Given a Procedure with no Contract, then it does not appear on the to-do list.
