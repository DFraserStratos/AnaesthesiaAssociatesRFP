Billing failure is per Booking. A List never fails as a whole: when one Booking in a List fails during processing, the Billing/Invoice Engine still invoices the List's other Bookings, and the failure stays visible for the office to resolve.

If the billable party fails on any Procedure in a Booking, the whole Booking is held back, none of its invoices is issued, so an admin can inspect it and fix it by hand ([manual intervention](US-13.3.2)).

## Acceptance criteria

- Given a Booking with one failed Procedure, when the List is processed, then none of that Booking's invoices is issued and the List's other Bookings are invoiced.

## Technical discussion

Proposed in our RFP response: one authorised List can produce several invoice pairs across counterparties, and a pair already in Xero cannot be unwound. AA's answer (OQ-05) sets the policy: billing state is tracked per Booking, not per List, so a failed Booking is held back as a whole and falls back to a manual fix by AA admin staff while the rest of the List bills. A Booking with some pairs already posted to Xero when another fails is part of that manual fix.
