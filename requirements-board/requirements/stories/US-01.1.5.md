An admin can split an anaesthetist's AM or PM session into two Lists, an A and a B List (AM A and AM B, or PM A and PM B), when two surgeons share the session. Each List has its own surgeon and follows the [pairing rule](US-01.3.1): one surgeon and one hospital per List.

This is so each surgeon's Bookings sit on that surgeon's own List when a surgeon who cannot fill a whole session shares it with another.

A session splits into two at most. Most sessions are never split, and a split Slot is the one exception to one List per Slot ([two Slots per anaesthetist per day](US-01.1.1)).

## Acceptance criteria

- **Two Lists in one session.** Given an anaesthetist's AM session, when an admin splits it between two surgeons, then the anaesthetist's day shows an AM A and an AM B List, each with its own surgeon and its own Bookings.
- **No more than two.** Given a session already split into an A and a B List, when an admin tries to split either List again, then the split is not offered.
- **Normal by default.** Given a List created by an admin or from a [recurring booking](US-01.3.2), then its session is not split unless an admin splits it.

## Technical discussion

If agreed, a Slot holds up to two Lists rather than at most one, and the domain model's Slot changes with it (ERD line "SLOT ||--o| LIST : holds at most one"). One surgeon per List keeps the data simple to filter: [a surgeon's specialties](US-13.6.6) narrow the Contracts offered on their Lists.

Not yet worked out:

- whether each half has its own times within the session ([Slot default times](US-01.1.4))
- whether the second half can go to a different anaesthetist (Ben: "Typically it would be the same anaesthetist"); our reading is that a different anaesthetist's half is a List in that anaesthetist's own Slot
- how a split shows on the anaesthetist's schedule and in the [availability finder](US-01.4.2), and whether a [Draft List](FT-01.6) can be one half
- how a List that already holds Bookings is split, and whether the halves can be joined again.
