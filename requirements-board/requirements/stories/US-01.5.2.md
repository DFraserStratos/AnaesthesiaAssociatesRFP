When a List conflicts with a [hospital closure](US-01.5.1), the Scheduling Engine flags it, rather than silently merging the data.

The flag is a soft warning, not a block: the Booking stays where it is, an availability conflict appears, and the List changes colour so the office can see it and resolve it (see the [availability conflict dashboard](US-01.5.4)). Blocking creates more problems than it solves.

An anaesthetist's unavailability, short-notice sickness included, is never a conflict flag: a List never stays with an anaesthetist who is unavailable. When they mark a Slot unavailable, they [return the List to the office or assign it to a colleague](US-01.5.5). A surgeon's [recurring booking](US-01.3.2) that lands on a Slot the anaesthetist has already marked unavailable is likewise created as a [Draft List](FT-01.6), with no anaesthetist, for admin staff to resolve.

## Acceptance criteria

- Given a List whose hospital is closed, when a Booking is made on it, then the Booking is accepted and the List is flagged as a conflict.
- Given a booked List, when a hospital closure is added, then the Bookings stay and the List is flagged.
- Given a surgeon's recurring booking that lands on a Slot the anaesthetist has already marked unavailable, when Lists are generated, then its List is created as a Draft List with no anaesthetist.
- Nothing in the flow blocks the admin from continuing.

## Technical discussion

Proposed in our RFP response: this is treated as a business policy question for AA (OQ-09). Because bookings must be accepted up to the start of a session and theatres open for emergency work, a rule that cannot be overridden would be worked around outside the system. AA's answer (OQ-09) is a plain soft warning, so the response's confirm-with-a-captured-reason step is not required.

## Notes

Settled: soft warning (OQ-09). Private hospitals close on statutory holidays and over Christmas shutdowns; emergency work then goes to public hospitals, which are out of scope.

An anaesthetist who marks a Slot unavailable while it holds a List is not left with a flagged List: they choose to return it to the office or assign it to a colleague ([mark unavailable while holding a List](US-01.5.5), OQ-64). The conflict flag covers hospital closures only. The 2026-10-02 requirements review settled the order in which the calendars are painted (the anaesthetist's calendar first) and the outcome for a recurring booking that lands on an unavailable Slot (Donald: "automatically create that list as a draft rather than assigning it to an anaesthetist"; Greg: "So do I... And it should blank it"), reversing the earlier accept-and-flag view (OQ-81).

The 2026-09-29 meeting said the same mechanism covers a short-notice sickness (the Booking stays and is flagged). OQ-81 replaced that: short-notice sickness takes the same path as any other unavailability, and the List never stays with the anaesthetist.
