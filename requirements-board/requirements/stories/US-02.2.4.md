Each List records where it came from: a surgeon's rooms' PDF, the hospital's list, or entry by hand. For a List from a surgeon's rooms' PDF, it also records the email address the PDF arrived from.

This is so the office can reply to whoever sent the List. The office's [booking update emails](US-02.3.3) and [requests for a missing NHI](US-11.1.5) go back to that address, and fall back to the surgeon's [office contacts](US-13.6.5) only where the List has none.

## Acceptance criteria

- **From a PDF.** Given a List created from a surgeon's rooms' PDF, then the List records that it came from a PDF and the email address the PDF arrived from.
- **From the hospital or by hand.** Given a List created from the hospital's list or entered by hand, then the List records where it came from and holds no sender address.

## Technical discussion

Today an admin uploads each emailed PDF ([read and ingest a surgeon PDF list](US-02.2.1)), so the sender address is either entered with the upload or read from the mailbox if the system reads it directly. Which address a List keeps when a later PDF for it arrives from a different address is a build choice. A List made from a [recurring booking](US-01.3.2) has no sender address; whether it records that as its origin is a build choice too.
