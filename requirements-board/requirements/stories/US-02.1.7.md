The matching screen has a second view, beside the [feed](US-02.1.4), that shows the office the state of each source of incoming Lists: each connected hospital and the rooms' mailbox.

This is so the office can tell at a glance that every source is coming in, and spot a source gone quiet or a message that failed before a List goes missing.

For each source the view shows:

- whether it is receiving
- when it last sent something
- how many messages came today, and what each became
- anything that could not be read or was held, with the reason

Sources not yet connected are listed as such. The view states that AA only reads from these sources and never writes back to them.

## Acceptance criteria

- **Each source.** Given St George's, Southern Cross and the rooms' mailbox are connected, then the sources view lists each with whether it is receiving and when it last sent something.
- **Today's messages.** Given a source sent five messages today, then the view shows five, and what each became.
- **Held, with the reason.** Given a message from a source could not be read, then it is listed under that source with the reason.
- **Not connected.** Given a hospital that is not connected, then the view lists it as not connected.
- **Inbound only.** Given the sources view, then it states that AA only reads from these sources and never writes back.

## Technical discussion

Retrying a failed message and alerting the office to it belong with integration failure visibility, which is Future Work.
