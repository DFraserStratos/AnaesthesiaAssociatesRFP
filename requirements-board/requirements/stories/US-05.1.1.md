Admins hold each RVG group as published in the NZSA guide. For each group, this includes:

- A unique system (human readable) code: still open, Greg's proposal to come back to.
- its code and description, as published
- its anatomy heading (for example Head), as the guide prints it ([body sections](US-05.1.3))
- its recommended base units, always set and above 0
- its modifier units, 0 by default

AA can also add its own groups, where the guide does not cover what it needs, and set their base units.

This is so every RVG code has base units to start from. A Procedure takes them [when its RVG code is chosen](US-03.3.1), unless the [Contract line](US-04.2.4) states its own, and the anaesthetist may change them. Users find a code with a type-ahead that shows each row's code, short description and base units, since the same code can appear on more than one row with different values.

## Acceptance criteria

- **Base units always set.** Given an RVG group, when it is saved, then it has base units above 0, and modifier units of 0 unless set.
- **AA-added groups.** Admins can add groups that the NZSA guide does not cover, and set their base units.
- **Type-ahead.** Given the RVG code search, when a user types "H1", then it lists every row with that code, each showing its description and base units.

## Technical discussion

The technical design v6 holds this as the RVG group ([fields](AR-29#rvg-group-fields), [ERD](AR-30#rvg-group)):

- a hidden key, because RVG codes are not unique enough to be keys
- the code, anatomy and procedure wording as published
- base units, required and above 0
- modifier units, required, 0 by default, "how the system populates the default modifier value"

Greg keeps modifier units there quietly for the future: "The user never interacts with it."

## Notes

Base units live here; [a Contract line may state its own](US-04.2.4) (OQ-62). There is no procedure level any more (OQ-88). This replaces the earlier reading that base units come from each procedure's default RVG Contract. Greg (7 October) called it "a default RVG relationship" rather than a default RVG Contract. [No contract (RVG)](US-04.3.3) is the one default Contract, offered first on every Procedure, and it holds no base units of its own.

A group's modifier units stay 0 under the directors' modifier rule (only age and [included modifiers](US-05.1.4) are pre-applied, and none is locked); the v6 design keeps the field at 0 by default.

Where the guide prints a range of base units (for example H4, 10 to 12), the v6 design holds one number. How a range is held is OQ-101.

Merges the former US-05.1.2 (Add AA codes), now Retired. AA-added groups are not marked as AA-sourced (2026-10-02): the guide is only a guide, and a group AA adds is not wrong. Donald: the RVG list is "more just a rough reference, a very slim starting point." Greg (7 October) wanted every procedure to have an RVG code; on 16 October he said selecting an RVG is not necessarily needed when the price or rate is fixed.

The unique system code is Greg's (from Ben: "Every line needs a unique identifier"): a human readable, quasi-structured code that users see and can start typing to find, distinct from the underlying RVG code, and called a code, not an ID. "System" rather than "AA" because the owner may change. Greg: "We'll come back to it." OQ-88 is answered: the RVG groups are the one list; Contract lines carry their own system line key. The v6 design gives each group a hidden key, because RVG codes are not unique.

The RVG guide is only a guide. Donald found it sparse (about 30 entries), and the same code can appear with different base units (a T2 with four or five), so a code alone is not a key. AA can set any base units, whatever the guide says, on its own groups, on a Contract line or on the Procedure itself.
