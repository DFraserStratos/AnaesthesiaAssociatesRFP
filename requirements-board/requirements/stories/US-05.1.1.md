Admins hold each RVG group as published in the NZSA guide. For each group, this includes:

- A unique system (human readable) code.
- its code and name, as published
- the [body section](US-05.1.3) it sits under (for example Head), which is the top level of the procedure picker
- its recommended base units, always set and above 0
- its modifier units, 0 by default

AA can also add its own groups, where the guide does not cover what it needs, and set their base units.

This is so every procedure has base units to start from. A [procedure](US-05.1.6) uses its group's base units unless AA sets its own figure for it, and a Contract line may override both.

## Acceptance criteria

- **Base units always set.** Given an RVG group, when it is saved, then it has base units above 0, and modifier units of 0 unless set.
- **AA-added groups.** Admins can add groups that the NZSA guide does not cover, and set their base units.

## Technical discussion

The draft technical design holds this as RVG_GROUP ([AR-29 p3](AR-29#p3), and [the ERD](AR-30)):

- a hidden key, because RVG codes are not unique enough to be keys
- the code and name as published
- the body section, the top level of the picker
- base units, required and above 0: the bottom layer the [price resolver](FT-05.2) looks through to, so base units always resolve
- modifier units, required, 0 by default, under review

A procedure's own base units, and a Contract line's, sit above it and win where set. The design is a draft and may change before the catch-up build.

## Notes

Base units live here. This settles where they live (OQ-62) in favour of the guide, which is taken as true for now: each procedure "uses that group's base units unless AA sets a different figure for that procedure". It replaces the earlier reading that base units come from each procedure's default RVG Contract. Greg (7 October) called it "a default RVG relationship" rather than a default RVG Contract. In the guide, No contract (RVG) is the one default Contract, offered first for every procedure, and it holds no base units of its own.

A group's modifier units stay 0 under the directors' modifier rule (only age and [included modifiers](US-05.1.4) are applied); the draft design marks the field under review.

Where the guide prints a range of base units (for example H4, 10 to 12), the draft design holds one number. How a range is held is OQ-101.

Merges the former US-05.1.2 (Add AA codes), now Retired. AA-added groups are not marked as AA-sourced (2026-10-02): the guide is only a guide, and a group AA adds is not wrong. Donald: the RVG list is "more just a rough reference, a very slim starting point." Every procedure always has an RVG code (Greg, 7 October).

The unique system code is Greg's (from Ben: "Every line needs a unique identifier"): a human readable, quasi-structured code that users see and can start typing to find, distinct from the underlying RVG code, and called a code, not an ID. "System" rather than "AA" because the owner may change. Greg: "We'll come back to it." Whether it belongs on this list or on each [procedure](US-05.1.6) is still OQ-88. The draft design gives each group a hidden key, because RVG codes are not unique.

The RVG guide is only a guide. Donald found it sparse (about 30 entries), and the same code can appear with different base units (a T2 with four or five), so a code alone is not a key. AA can set any base units, whatever the guide says, on its own groups or on a procedure.
