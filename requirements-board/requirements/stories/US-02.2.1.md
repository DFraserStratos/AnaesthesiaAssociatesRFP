Admins upload an emailed PDF list of a surgeon's bookings. The system reads the PDF and extracts the bookings from it, so staff can review them before they're ingested. Rooms re-send the List as a PDF whenever it changes, so the office gets a review and merge step: it sees what has changed, actions anything needed and accepts it (see [differences on match](US-02.1.3) and [inbound changes until submit](US-02.5.4)).

Before an extracted row is ingested into the schedule, the admin can correct its fields.

This is so mistakes the extraction introduces, such as an [invalid NHI](US-11.1.2), are fixed before the Booking reaches the schedule.

## Acceptance criteria

- **Correction before ingest.** Before an extracted row is ingested into the schedule, the admin can correct its fields, such as fixing an invalid NHI, so mistakes the extraction introduces don't reach the Booking.
