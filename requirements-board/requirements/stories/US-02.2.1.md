The system reads the surgeons' rooms' PDF Lists from the office's mailbox as they arrive, and the List each PDF holds lands on the [matching screen](US-02.1.4) for the office to review before it is ingested. A PDF's sender is the email address it came from. A PDF that reached someone's own inbox can be added by hand, with its sender.

This is so every rooms' List reaches the office without anyone uploading it, and mistakes in reading it, such as an [invalid NHI](US-11.1.2), are fixed before a Booking reaches the schedule.

- **The PDF beside what was read.** The office sees the PDF beside the values read from it. Each value shows how sure the reader was; a value it was unsure of is marked for the office to check, and shows where it sits on the page.
- **Correction before ingest.** Before a row is ingested, the office can correct its fields.
- **A re-sent List is merged.** Rooms re-send the whole List as a PDF whenever it changes. A PDF for a surgeon, hospital, day and session AA already holds a List for is the next version of that List: the office sees what changed ([differences on match](US-02.1.3)), such as times or patients added, and accepts it. Bookings missing from it are offered as [removals](US-02.2.3).
- **Never dropped.** A PDF that cannot be made into a List still lands in the feed, with the reason.

## Acceptance criteria

- **Read from the mailbox.** Given a rooms' PDF emailed to the office's mailbox, then its List appears on the matching screen with the address it came from, without anyone uploading it.
- **Added by hand.** Given a PDF that reached someone's own inbox, when an admin adds it with its sender, then it is read and lands on the matching screen like a PDF from the mailbox.
- **Shown beside the PDF.** Given a PDF's List on the matching screen, then the office sees the PDF beside the values read from it, each showing how sure the reader was.
- **Unsure values marked.** Given a value the reader was unsure of, then it is marked for the office to check, and the office can see where it sits on the PDF.
- **Correction before ingest.** Before a row read from a PDF is ingested into the schedule, the admin can correct its fields, such as fixing an invalid NHI, so mistakes in reading it don't reach the Booking.
- **Re-sent List merged.** Given AA holds a List for a surgeon, hospital, day and session, when a rooms' PDF for the same surgeon, hospital, day and session arrives, then it is proposed as the next version of that List with its differences shown, not as a new List.
- **Unreadable PDF.** Given a PDF that cannot be made into a List, then it shows in the feed with the reason.

## Technical discussion

How a PDF is read is the development team's choice.
