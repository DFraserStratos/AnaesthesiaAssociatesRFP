For each row imported from a hospital download, the admin decides what happens to it. They can:

- match it to an existing List and Booking
- create a new Booking on an existing List
- create a new List in an anaesthetist's Slot
- create a [Draft List](US-01.6.1) when nobody is assigned yet
- reject it

A row with [no NHI](US-11.1.4) cannot become a Booking: it waits in the [unmatched queue](US-02.1.4) until the office adds the NHI.

Each row shows its procedure text exactly as received, so the admin can read it while matching ([kept as received](US-02.5.7)).

This is so the schedule always reflects the hospital's data, whichever of these a row needs.

## Acceptance criteria

- Given an imported row, then its procedure text shows exactly as the hospital sent it.
