The system's starting reference data is loaded at cutover by a one-off data load. Exactly what is loaded, and from what source, is not yet clear; it is expected to cover:

- hospitals
- surgeons and surgeons' rooms
- [RVG groups](US-05.1.1), with base units
- [modifiers](US-05.1.5) with their units
- contract holders
- Contracts and their lines (RVG, fixed or other)
- anaesthetists

The starting data is seeded once, run by a developer (directly against the database or similar), and then changed by hand on screen. This one-off seeding is separate from the [Contract schedule upload](US-04.2.13). Loading is repeatable, so a test system can be wiped and reloaded.

This is because there are few enough hospitals and surgeons to rebuild clean reference data rather than migrate it.

## Acceptance criteria

- Recommendation: given the data load, when it runs, then rows failing validation are reported and not loaded.
- Given a test system, when it is wiped and the same data is loaded again, then it holds the same reference data.

## Technical discussion

The technical design v6 ([data loading](AR-29#data-loading)) has all master data prepared by AA in AA-defined templates and loaded repeatably, with a developer-run import as the suggested baseline, then office screens to create, edit and retire records.
