A developer loads the system's starting reference data once, at cutover; after that it is changed by hand on screen. The load is repeatable, so a test system can be wiped and reloaded. Exactly what is loaded, and from what source, is not yet clear; it is expected to cover:

- hospitals
- surgeons, with their practice names; a surgeon loads without an HPI CPN, which admin staff then fill in on screen
- [RVG groups](US-05.1.1), with base units
- [modifiers](US-05.1.5) with their units
- Parties
- Contracts, one per priced item, with their price ranges
- [specialties](US-13.4.4) and [funding tags](US-13.4.5)
- each surgeon's specialties
- anaesthetists

This is so AA starts with clean reference data: there are few enough hospitals and surgeons to rebuild it rather than migrate it.

[Export and re-import of Contracts](US-04.2.13) by the office is Future Work.

## Acceptance criteria

- **Validation** (recommendation). Given the data load, when it runs, then rows failing validation are reported and not loaded.
- **Repeatable.** Given a test system, when it is wiped and the same data is loaded again, then it holds the same reference data.
- **Surgeons without an HPI CPN.** Given a surgeon row with no HPI CPN, when the load runs, then the surgeon is loaded, with the HPI CPN blank for admin staff to fill in.

## Technical discussion

Greg's technical design v6 has all master data prepared by AA in AA-defined templates and loaded repeatably, with a developer-run import as the suggested baseline, then office screens to create, edit and retire records. The load runs directly against the database or similar.
