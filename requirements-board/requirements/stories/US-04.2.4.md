Admins enter a Contract's lines, one per procedure. A [combination Contract](US-04.2.11) has a line against each of its parent procedures.

Each line:

- names the procedure, which always has an RVG code, so there is no separate RVG mapping
- may carry the holder's own code and description, kept for reference and searchable when [picking a Contract](US-04.3.2)
- carries only the [terms it sets](US-04.2.2): a fixed price held excluding [GST](US-05.2.7), a fixed rate, a fixed discount, or base or modifier units

A blank means "use the value beneath", and 0 means zero.

Lines are not only for fixed fee schedules: an agreed-rate Contract, such as an ACC one, has lines too. No Contract sets one price for a whole RVG group, so lines for a group are not needed.

A line can also carry an optional time band; whether it stays is open (OQ-89).

This is so every Contract states its terms per procedure in one consistent shape, whatever kind of arrangement it records.

## Technical discussion

The draft technical design calls these contract lines ([data model](AR-29#p3)): each sets terms for exactly one procedure, every pricing field can be left blank so the line carries only what it sets, and a Contract has at most one line per procedure. It is a draft and may change before the catch-up build.

## Notes

Real examples: SXAP AP codes, CES HNZ codes, ACC OPT codes, Merivale set fees, vitrectomy time bands, liposuction per area.

The add-on flag and quantity rule were dropped on 7 October, so GA add-on fees, once an example here, are no longer a line (Notes 2026-10-07 · AA meeting with Greg #5).
