Admins enter a Contract's lines. Each line sets the terms for a group of procedures, for example "Cataracts" or "Facelift plus 1 add on", and carries only what it sets:

- a description, which becomes the Procedure's starting invoice description in place of the Booking's description when the line is chosen, and can be edited ([invoice description](US-08.4.6))
- the holder's own reference code, optional and unique within the Contract, kept for reference and searchable when [picking a Contract](US-04.3.2)
- a default RVG code, optional: it fills in the Procedure's RVG code when the line is picked, and lets a search by RVG code find the line
- the [terms it sets](US-04.2.2): a fixed price held excluding [GST](US-05.2.7), a rate, a discount, or base or modifier units

Each line also has a system line key, never reused, which keeps its identity when a new version copies it. A blank means the line does not set that value; 0 is a value.

Lines stand alone: they do not nest, and several lines may share an RVG code. A Contract may have no lines at all, such as a hospital's plain RVG Contract. Lines are not only for fixed fee schedules: an agreed-rate or discount Contract has lines too.

The v6 design has no time band on a line; whether it is dropped is OQ-89.

This is so every Contract states its terms in one consistent shape, whatever arrangement it records.

## Technical discussion

The technical design v6 calls these contract lines ([fields](AR-29#contract-line-fields)): line key, reference code, description (if blank, the Booking's description is used on the invoice), an optional RVG group, base and modifier units, price, rate and discount, every pricing field optional.

## Notes

Real examples: SXAP AP codes, CES HNZ codes, ACC OPT codes, Merivale set fees, vitrectomy time bands, liposuction per area.

The add-on flag and quantity rule were dropped on 7 October, so GA add-on fees, once an example here, are no longer a line (Notes 2026-10-07 · AA meeting with Greg #5).
