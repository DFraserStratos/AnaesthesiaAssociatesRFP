The office can load a Contract's lines from a schedule in the AA template, one row per line, as well as [editing them on screen](US-04.2.4). The upload is for Contracts only, not for other master data. Price lists arrive in each holder's own form, so the office transposes them into the template.

Two modes, chosen on the upload screen:

- **Alter**, for a correction or mid-term additions and updates to some lines (some hospitals send these regularly): the new version starts as a copy of every current line, each row says what to do with its line (add, alter or remove), and lines not in the file carry forward unchanged
- **Replace**, for a periodic renewal or any complete new schedule: the file is the whole new schedule, and lines not in it stay on the previous version only

Rows are matched to existing lines by the line's system key where present, otherwise by the holder's reference code. Exporting the current Contract to the template, with its line keys, is the easiest way to prepare an Alter upload. A blank cell means the line does not set that value; 0 is a value.

An upload is staged and reviewed like any other change before it becomes a [new version](US-04.2.10) ([stage and submit Contract changes](US-04.1.6)).

This is so a holder's schedule can be loaded in one go, with every change checked before it applies.

Greg (16 October) calls this "a proposal for how an upload might work... The developers might go, oh, this is ridiculously difficult or expensive. And that's fine", and the template "to be confirmed". The v6 baseline for the first release is a developer-run import then office screens, with the upload for ongoing maintenance.

Donald and Nick hold that schedules change rarely and can be keyed by hand. Whether the upload is needed for the first release is not settled (OQ-100).
