Admins can export Contracts to a spreadsheet, either all of them or one holder's, edit the spreadsheet, and import it back to update the system.

This is so AA keeps a safe copy of its Contracts outside the system, and can change a large price list in one go rather than item by item.

What an import does:

- each row is matched to its Contract by [AA code](US-04.1.4)
- a matched row updates that Contract's settings and [price ranges](US-04.2.15)
- a row with a new AA code creates a Contract
- a row marked Disabled disables its Contract

An import never deletes a Contract, and never changes a Contract's prepaid setting or [pricing kind](US-04.2.2), which are fixed once it is created. Every change it makes is [audited](US-04.1.3) like an [edit on screen](US-04.1.2).

## Acceptance criteria

- **Export.** Given the Contract list filtered to one holder, when an admin exports it, then a spreadsheet holds one row per Contract with its AA code, settings and price ranges.
- **Safe copy.** Given an export, then it opens in a spreadsheet program without the system.
- **Update.** Given an exported spreadsheet with one rate changed, when an admin imports it, then that Contract's rate changes and the change is audited, and no other Contract changes.
- **New Contract.** Given a row with an AA code the system does not hold, when an admin imports it, then a new Contract is created from the row.
- **Disable.** Given a row marked Disabled, when an admin imports it, then its Contract is disabled, not deleted.
- **Check first.** Given an import, before it is applied, then the admin sees the Contracts it will create and change, and can cancel it.

## Technical discussion
