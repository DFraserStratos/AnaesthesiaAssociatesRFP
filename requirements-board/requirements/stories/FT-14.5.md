Health systems integration guarantees message delivery and gives visibility when something goes wrong, through:

- a durable queue between hospital messages and the core system, so an accepted message is never lost even if a downstream component is down or under load
- automatic retries with exponential backoff, absorbing most transient failures without any human involvement
- alerting when a hospital feed goes unexpectedly quiet, catching a message, such as a cancellation, that never arrived at all
- a manual intervention path for when a message still can't get through

This matters because the HL7 v2 integrations AA already has are unreliable and frequently fail.

## Technical discussion

Proposed in our RFP response:

- A durable Azure Service Bus queue sits between the outside world and the core, decoupling receipt from processing; once accepted, a message cannot be lost even if a downstream component is unavailable, restarting or under load.
- Exponential-backoff retries in queue processing absorb transient failures, very often with no human involvement.
- Silence is a failure too: an expected-traffic profile per hospital feed raises an alert when a site goes unexpectedly quiet, catching messages that never arrived (e.g. a missed cancellation).
- End-to-end testing explicitly covers failure and recovery scenarios for hospital integration pathways: message delivery, error handling, retry and alerting.
