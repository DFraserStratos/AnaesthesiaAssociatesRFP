The system validates both NHI formats: the current format (AAANNNC, checked with a modulus 24 check digit) and the new format Health NZ is introducing (AAANNAX, checked with a modulus 23 check digit).

Because new NHIs are issued randomly rather than in sequence, the system never assumes an NHI is numeric or sequential.

This must be working before 1 July 2027, the date Health NZ requires all systems to support both formats.

## Technical discussion

Proposed in our RFP response:

- The NHI is encapsulated in a single domain value object. It parses both the current and new structures, selects the correct check-digit algorithm from the identifier's shape and cannot be constructed in an invalid state, so an invalid NHI cannot enter the system at all.
- Because new NHIs are issued randomly rather than sequentially, the value object stops surrounding code assuming ordering or numeric ranging. It is the one place to change if the specification is refined.
- Dual-format support and completed compliance testing are to be met from go-live, ahead of the 1 July 2027 obligation. Stratos already has systems supporting both formats.
- Testing: a strong unit-test suite behind the value object; dual-format regression testing across every NHI-handling path (patient registration and record matching, [NHI lookups via the Health NZ Digital Services Hub](US-14.4.1), inbound HL7 v2 and FHIR messages, reporting); and Health NZ's published compliance test completed in test environments before go-live, within the Testing milestone.
