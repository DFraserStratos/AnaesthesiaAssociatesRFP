Admins keep a curated list of procedures. Each procedure is the specific operation, worded as it should appear on the invoice. The list sits between the wording the rooms and hospitals send and the RVG.

- Every procedure belongs to exactly one [RVG group](US-05.1.1), so it always has an RVG code. Procedures are not nested.
- A procedure uses its group's base units unless AA sets a different figure for it. A variant can be held this way, for example "Face-lift complex" at 10 base units.
- AA decides how fine the list is, for example one tooth extraction or several.
- Every RVG group has a general procedure, the one a Procedure takes when it is priced on No contract (RVG) from the RVG codes route without a more specific procedure.

Staff find a procedure on the picker's Procedures tab by [body area, then subgroup, then procedure](US-05.1.3) (for example "01 - Head" > "00 - General" > "Face Lift", RVG code H3), or on its RVG codes tab by body area (and the guide's sub-heading), then RVG code, reaching the procedure through the Contract line they pick.

The list holds no prices. Positioning loadings such as sitting (beach-chair) or prone are [modifiers](US-05.1.5), not base units. If a procedure's base units are consistently overridden, AA should change its own data rather than keep overriding.

This is so the many ways the same operation is named map to one reliable starting point for base units, and the [Contract list can be narrowed](US-04.3.2) to the Contracts relevant to the procedure.

## Acceptance criteria

- Given a procedure in the list, when it is saved, then it belongs to exactly one RVG group.
- Given a procedure with no base units of its own, when it is priced, then its group's base units are used.
- Given a procedure with base units AA has set, when it is priced, then that figure is used instead of the group's.
- Given a Contract that sets base units for the procedure, when the Procedure is priced, then the Contract's figure is used.
- Given the procedure picker, when staff search, then they can reach a procedure by body area, subgroup and procedure, or by body area and RVG code.
- Given any RVG group, then it has a general procedure.
- Given a Procedure reached by an RVG code and priced on No contract (RVG), then its procedure is that group's general procedure.

## Technical discussion

The draft technical design holds this as PROCEDURE ([AR-29 p3](AR-29#p3)): exactly one parent RVG group and no nesting; the name is the invoice wording; base and modifier units are left blank unless AA sets them, and blank means the group's value is used ("Typically null"). A procedure "need only be defined when AA needs it". The design is a draft and may change before the catch-up build.
