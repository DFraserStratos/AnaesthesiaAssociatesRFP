From a current or [past Procedure](US-03.1.6), the anaesthetist adds an event with its own date and time, recording either a time or a fixed fee. Events take no other modifiers. An admin can also add an event, for example when someone rings and asks the office to record it.

The event is its own element attached to the original Procedure, so it stays traceable.

- It has a tick box for whether it will be invoiced.
- Its [billable party](FT-11.2) is set in the event pop-up with a "same as" tick (the Procedure's billable party); with the tick cleared, the party is filled in.

## Acceptance criteria

- Given a past Procedure, when the anaesthetist adds a post-op event with a time, then it is saved against that Procedure with its own date.
- Given an event, then no modifiers can be added to it.
- Given the invoice tick box is cleared, then the event is recorded but not invoiced.
- Given the same-as tick is cleared, when the event is saved, then it carries the billable party entered.
- An admin can add an event to a Procedure.

## Notes

If the work is significant, the anaesthetist creates another Booking instead (Greg). The default for the same-as tick was not stated, and "same as the Procedure's billable party" is our reading of Greg's courier comparison.
