Each Procedure keeps the procedure text exactly as each originating system sent it: the surgeon's rooms' description (from their PDF, email or booking) and, separately, the hospital's description from its theatre list or feed, which often expands the rooms' abbreviations. Neither is ever edited or overwritten; a later update with different wording is added beside it with its source system and time.

The procedure on a Booking is now just this text: there is no procedure master to match it to. The anaesthetist reads it as the input for choosing the Contract and the RVG code. The Booking also holds an [invoice description](US-08.4.6), separate from these texts, for the invoice; which description the invoice prints is OQ-103.

When an admin or anaesthetist enters a Booking by hand, the procedure text is what they typed or were told, kept as the source text in the same way.

This is because the wording that arrives is short codes and snippets in endless variety ("WLE MM", "RTK", "blephs"), which someone who knows the work can read, and the person choosing the Contract and RVG code, or checking that choice later, needs the original. It is shown [with the Contract and RVG choice](US-03.1.9).

## Acceptance criteria

- **Verbatim.** Given a Booking from any channel, then its Procedure's source text is stored exactly as received, character for character.
- **Never overwritten.** Given a later update with different wording for the same Procedure, then the earlier text is kept and the new text is added with its source system and time.
- **Entered by hand.** Given a Booking entered by hand, then the procedure text typed or told is kept as its source text, and is shown with the Contract and RVG choice.
