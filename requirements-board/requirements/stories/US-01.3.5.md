When an admin puts a List with an anaesthetist and the surgeon and anaesthetist have a [not-preferred pairing](US-13.6.3) (in either direction), the system shows a warning. This applies whenever the office makes the pairing:

- assigning a List in a Slot
- assigning a [Draft List](US-01.6.3)
- moving or [reassigning a List](US-01.4.1) to another anaesthetist

It is a soft warning: the admin can still go ahead.

The pickers also separate the not-preferred options from the others:

- choosing a surgeon for an anaesthetist's Slot, the surgeons with a not-preferred pairing for that anaesthetist sit in their own clearly labelled group
- choosing an anaesthetist for a Draft List, or to move or reassign a List to, the available anaesthetists without a conflict are shown separately from the available anaesthetists who have one

The available anaesthetists are also ordered by their [priority tier](US-01.3.6), and the admin sees [preferred pairings](US-13.6.4) (who someone does want to work with) alongside the not-preferred ones when making the match.

This is so the office sees a bad pairing before committing to it, without a hard block that would be worked around, the same way [hospital-closure conflicts](US-01.5.2) only warn (OQ-09). Admin staff already have permission to know these preferences; anaesthetists never see them, and an anaesthetist moving their own List gets [no warning](US-01.4.5).

## Acceptance criteria

- **Separated.** Not-preferred options appear apart from the others and are labelled.
- **Still selectable.** An admin can select a not-preferred option.
- **Warned.** Given a not-preferred pairing is selected, then a warning names the pairing before the assignment is saved.
- **Every office path.** The warning shows when assigning a List in a Slot, when assigning a Draft List, and when an admin moves or reassigns a List.

## Notes

Donald's recap on 7 October, not objected to: "when admin staff are assigning or moving someone, the system can surface that information because admin already has permission to know it. For example, when assigning a draft list, admin could see available anaesthetists without a conflict separately from available anaesthetists who do have a conflict. It is a warning to inform the decision, not a hard block" (OQ-43).

The name "blacklist" will change: Donald wants a better term, and "not-preferred pairing" is a working description until AA picks one. Positive preferences (a "whitelist" for now) are wanted too. The names are OQ-102.

How the tier order and the conflict grouping combine (tiers ordering the anaesthetists within each group) was not discussed; it is an assumed reading.
