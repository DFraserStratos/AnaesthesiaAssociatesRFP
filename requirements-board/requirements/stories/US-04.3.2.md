Admins and anaesthetists picking a Contract see only those relevant to the Booking:

- "[No contract (RVG)](US-04.3.3)" first, always
- then the hospital's Contracts
- then any surgeons' and anaesthetists' arrangements

Each is [valid on the procedure date](US-04.2.10) and has a [holder](US-04.1.5) that fits the Booking: the List's hospital, or the Booking's anaesthetist or surgeon for a Contract that belongs to one, found by their practitioner IDs. A surgeon's arrangement is one Contract linked to one or more surgeons, not one Contract per surgeon, and is held against those individual surgeons, not their rooms. It is found by the practitioner ID of any surgeon it is linked to, so it is offered on a Booking with any of them, whichever anaesthetist does the work. The list shows Contracts, not lines; picking one leads down to its lines.

An anaesthetist sees only their own price list Contracts, never everyone's, and a St George's Contract never shows on a List at another hospital. Staff may also start from the contract holder. Where an RVG code has been picked, the lines carrying it as their default RVG code are found directly (a reverse lookup), and on a fixed-price Contract no RVG code is needed. The insurer and approval number are stored on the Booking ([insurer and approval number](US-11.4.3)); whether insurance narrows the Contract list is open (OQ-93).

This keeps the picker short and relevant, rather than showing every Contract AA holds.

## Acceptance criteria

- **Filters.** The list shows No contract (RVG) first, then only the Contracts valid on the procedure date whose holder fits the Booking's hospital, or that belong to the Booking's anaesthetist or are linked to its surgeon.
- **Surgeon's arrangement.** Given a Contract linked to surgeon S, when a Booking with surgeon S is set up, then it is offered whichever anaesthetist holds the Booking; on another surgeon's Booking it is not offered.
- **One Contract, several surgeons.** Given one Contract linked to surgeons S and T, when a Booking with surgeon S or with surgeon T is set up, then that same Contract is offered, found by that surgeon's practitioner ID.
- **Own price lists.** Given anaesthetist A's Booking, then anaesthetist B's own price list Contracts are not offered.
- **RVG lookup** (agreed in principle; Ben has not yet been asked). Given RVG code H3 is picked, then the lines whose default RVG code is H3 are offered under their Contracts.
- **AA code search.** Typing a Contract's [AA code](US-04.1.4) filters the list to that Contract.
- **Holder code search.** Typing a holder's own code (for example 8942) filters the list to that Contract.
- **Composite search.** One search finds Contracts across the holder, the Contract's name and the codes.

## Technical discussion

The technical design v6 lists the default contract first, then every contract valid on the procedure date that fits the booking's context (the hospital, the surgeon or rooms, anaesthetist-specific lists), with no test that it has a line for the procedure ([contract selection](AR-29#contract-selection)).
