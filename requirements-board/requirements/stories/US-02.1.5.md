Booking data from St George's and Southern Cross syncs into the [matching screen](US-02.1.2) by itself, without an admin importing it.

This is so the office stops pulling from these two hospitals by hand, and keeps the checking step it relies on (who is on the List, double bookings, changed times, patients appearing and disappearing).

Matching is a manual admin review. The integration only brings rows in; nothing is applied to a Booking until an admin decides.

## Acceptance criteria

- **No silent apply.** Given rows have arrived, then every row still goes through the admin's match, create or reject decision, and rows that cannot be matched stay in the [unmatched queue](US-02.1.4).

## Technical discussion

The particulars of the technical implementation are yet to come. Today an admin imports these two hospitals' files into AA's current matching screen through an integration, and matching is a manual admin review. How each hospital delivers its data today is to be confirmed (OQ-13). The cadence is one theatre list a day for the next day's bookings, with no repeated updates (Vanessa, via Greg, 16 October). Vanessa holds a few old emails about the current integrations. This story covers St George's and Southern Cross; the other providers are Future Work ([feeds from the other Christchurch providers](US-14.6.1)).
