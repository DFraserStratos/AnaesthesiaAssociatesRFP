A combination is just [a line](US-04.2.4) on its holder's [fixed-price Contract](US-05.2.5), not a procedure or a separate Contract. For example, the Merivale Plastic Surgery set fee schedule (a surgeon's rooms' arrangement, billed to the patient) has the lines:

- "Face lift" at $3,565
- "Facelift plus 1 add on (eg bleph)" at $3,910
- "Facelift plus 2 add ons (eg bleph & fat grafting)" at $4,255

Each line stands alone. It can carry a default RVG code (for example H3) so a search by RVG code finds it.

When a billable party wants the combined price broken into parts, the admin raises [additional invoices](US-08.6.4).

This prices combined work the way it is agreed, with no extra structure.

## Acceptance criteria

- Given the Merivale Contract, then "Facelift plus 1 add on" is a line priced at $3,910.
- Given that line carries the default RVG code H3, when the user searches by H3, then the line is found.

## Notes

With the procedure master gone (OQ-88), a combination no longer sits against parent procedures: "No nesting of individual contract lines is provided. Each stands alone." (v6). The single and the combination lines are both offered, since the combined price can be lower than the parts.

Contract lines are expected to number in the thousands, with Contracts far fewer; they are kept navigable by the holder filters and code search (OQ-66). A default RVG code on a line was agreed in principle by Donald and Greg on 16 October (Notes 2026-10-16 · AA meeting with Greg #40); Ben has not yet been asked, and 14 October left it open. A line may carry one, as an option; Ben is still to confirm it.

A split after invoicing is a credit note against the original combined invoice, then new additional invoices ([split a combined Procedure](US-08.6.4), OQ-72).
