When an arriving List matches a List AA already holds, the office sees why it was matched and what it would change, before anything is applied.

This is so the office can trust what has come in, and check exactly what an update changes before it reaches the schedule.

- **Match keys.** Each key and whether it agreed: the surgeon, the hospital, the day and session, and how many of the List's patients were found by NHI. There is no confidence score.
- **Earlier versions.** Where the List first came from, and each later arrival for it.
- **Its Slot.** The anaesthetist's Slot the List sits in.
- **Differences.** Each Booking's field-level differences, such as time, patient or procedure.
- **One List, several versions.** The hospital's List for the same surgeon, hospital, day and session as a List the rooms sent is proposed as an update to that List, not as a new List.

## Acceptance criteria

- **Keys shown.** Given an arriving List matched to a List AA holds, then the office sees the surgeon, hospital, and day and session each marked as agreeing or not, and how many of its patients were found by NHI, with no confidence score.
- **Hospital updates the rooms' List.** Given a List placed from a rooms' PDF, when the hospital's List for the same surgeon, hospital, day and session arrives, then it is proposed as an update to that List rather than as a new List.
- **Earlier versions.** Given that update, then the office sees the rooms' PDF as the List's first version and the hospital's List as the proposed update, with the Slot the List sits in.
- **Differences before applying.** Given a matched List with a changed time on one Booking, then the office sees the current and the new time before applying the change.

## Notes

An update to an already matched Booking still goes through this manual approval, showing the differences; for a row with no match, the office effectively accepts it as a new record (Greg). Donald: automating updates after the first match "wouldn't take too much", but this manual step stays in for now. Confirmed again on 2026-10-07: a later update is matched by "the date, the surgeon, the location, the slot", and staff "just say approve update"; automated approvals come once the matching is trusted.

Donald, 26 November (for the build; not yet seen by AA): the screen shows each match key, the List's earlier versions and the Slot it sits in, with no confidence score: "I want this to seem like a bit more of a robust tool that is giving confidence about the things that are coming in and how they have been ingested in our systems." The rooms' List and the hospital's are versions of the same List: "in the matching screen we should be able to see that it's a proposed update."
