The Lists entry in the Admin app's side nav carries one badge, counting each List once however many tabs it shows on ([the Lists section](US-13.1.3)). Added up across Draft Lists, Conflicts, Contracts to set and To authorise, that comes to 74 Lists on the prototype's demo day, and a number that size may stop meaning "act now".

Should the badge count every List that needs something, or only the Lists in the next 7 days plus anything overdue?

What hangs on it: whether the badge reads as a to-do count or an alarm, and which Lists the office is nudged to work first. Donald leans towards counting everything. The prototype shows both, with a toggle in its demo bar that opens on counting everything, so AA can see each before choosing.
