**Already settled:** there are no per-Contract multi-procedure rules (Donald, 2026-10-05), so Contracts cannot override the RVG default. One part of the RVG default is confirmed: modifier units split equally across procedures once the total exceeds four (OQ-15).

**Still to answer, for AA:**

1. **Do the other two parts of the RVG default still apply to every Booking with more than one Procedure?** They are: base units charged on the primary procedure only, and time units charged on every procedure. The alternative is pricing each Procedure on its own for base and time units. The v6 design states the rule as applied, but AA have not confirmed it. If it applies, which Procedure is primary matters: Vanessa's practice, relayed on 16 October, takes the most expensive.

Recommendation: keep the default (FT-05.3 and US-05.3.1) as the one system-wide rule until AA says otherwise. It is how the RVG itself prices multiple procedures, and Contracts cannot override it now. Ask AA to confirm it and, if each Procedure is priced alone, retire the rule.

Donald dropped per-Contract multi-procedure rules on 2026-10-05 and said the concept is "not part of the modelling in my head". The RVG default is still in the catalogue:

- base units on the primary procedure only
- time units on every procedure
- modifier units split equally across procedures once the total exceeds four

Original question: does this default still apply at all, to every Booking with more than one Procedure? Or is each Procedure priced on its own, with no cross-procedure rule?

Update 2026-10-07: not answered. One leg of the default was confirmed in the room: the modifier split once the total exceeds four (OQ-15), "basically what Vanessa does in the office normally". The RVG itself says "When multiple procedures are performed during one anaesthetic only ONE Base Unit should be charged". The draft technical design lists the rule as still being confirmed with AA: if it applies, "it adjusts the units of CALCULATED procedures" before pricing. (See "Notes 2026-10-07 · AA client meeting #1", "Notes 2026-10-07 · Pricing model documents #32 #45")

Update 2026-10-16: not answered. The v6 technical design now states the rule without its earlier caveat: "The multi-procedure rules (for example base units on the primary procedure only, allocation of Modifiers) are applied to adjust the units of CALCULATED procedures". AA have not confirmed it in these documents. On 16 October Vanessa's practice was relayed that the most expensive procedure is the primary ("the big thing being the big thing"), which bears on which Procedure carries the base units. (See "Notes 2026-10-16 · Pricing model documents v6 #38", "Notes 2026-10-16 · AA meeting with Greg #43")

## Answer

keep the default as defined in [Multi-procedure rule (supersedes RFP split-billing rule)](FT-05.3)

The meeting adds: the default is base units on the primary procedure only, time units on every procedure from its own recorded times, and modifiers on the primary procedure when the units total four or fewer, split equally above four. Greg corrected Donald's first reading that time units are charged only on the primary procedure: "procedure 2 has its own time recording... there should be no base units on the secondary procedure." Pricing each Procedure alone for base and time units is "not correct". Which Procedure is primary was not discussed. See "Notes 2026-10-19 · AA meeting with Greg #10".
