**Still to answer, for Donald and Greg:**

1. **Should an RVG group hold its published base unit range as well as a starting figure, or only the starting figure?** Some [RVG groups](US-05.1.1) print a range of base units (for example H4 complex procedures, 10 to 12) and the anaesthetist [chooses the exact value](US-03.3.1). With only a starting figure the anaesthetist is free to change it; holding the range as well would allow an out-of-range warning. The draft and v6 designs hold one required base units figure on each RVG group.

Recommendation: Hold a starting figure and the published range on the group; the anaesthetist starts from the figure and may pick any value, with an out-of-range warning for the office.

Update 2026-10-16: the v6 design still holds one required base units figure on each RVG group, so the question stands. On 14 October Donald and Greg agreed the RVG picker shows each row's code, short description and value, "because there'd be two T2s represented": the same code can appear on more than one row with different base units. (See "Notes 2026-10-14 · AA meeting with Greg #20", "Notes 2026-10-16 · Pricing model documents v6 #23")

## Answer

If the RVG guide gives a range, then the app should present that. As I think it already does.

Update 2026-10-29: so an RVG group holds its published base unit range where the guide prints one, as well as its starting figure, and the anaesthetist is shown the range when choosing the exact value ([RVG groups](US-05.1.1), [choose the RVG code](US-03.3.1)). The anaesthetist may still pick any value, and an out-of-range value warns the office.
