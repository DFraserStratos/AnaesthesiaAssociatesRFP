Fixed fee schedules use the holder's own codes (SXAP AP codes, HNZ codes, ACC OPT codes). Should the anaesthetist select the holder code directly when such a Contract applies, with an optional RVG mapping for BTM recording, or always pick an RVG code and have the system map it?

## Answer

We will have a master procedure list and a master contract list. 
If we need to use a contract from one of these parties, we will store their codes for reference.

But the pair of Procedure & contract means that there could be both an RVG code, and a paritie's code

Transcript adds: Contracts may keep the holder's own codes as reference codes, and they are searchable (typing "8942" filters to that Contract). AA will also need its own unique identifier for every Contract, a coding scheme still to be worked out. Donald has doubts about the model; it is marked answered for now and built into the prototype, to be validated later. See Notes 2026-10-01 · AA meeting with Greg #10.

The meeting adds: the RVG link is not optional. Greg: "it's mandatory, isn't it?"; Donald: "There will always be an RVG attached", and the optional RVG mapping was removed from the schedule line story. The holder's own code stays as a reference and is searchable when picking a Contract (Greg: "Absolutely"), and Greg asked for "some sort of composite... like a modern search where you can type it in and figure out where it is". (See "Notes 2026-10-07 · AA meeting with Greg #4 #31")

Follow-up: OQ-66.

The meeting adds, and supersedes the master procedure list and the mandatory RVG link above: there is no procedure master (OQ-88). The RVG code is optional on the Booking ("if you can find it, fine; if you don't know, don't worry"), and a fixed-price line may carry an optional default RVG code. The holder's own code stays as the line's reference code, searchable. (See "Notes 2026-10-14 · AA meeting with Greg #19 #20", "Notes 2026-10-16 · AA meeting with Greg #35 #39 #40", "Notes 2026-10-16 · Pricing model documents v6 #44")

Update 2026-11-05 (Donald, for the build; not yet confirmed by AA or Greg): with no Contract lines, what the paragraph above says of a line now holds of the Contract itself. A holder's schedule becomes one Contract per item; the item's code is the Contract's holder reference code (for example SXAP `AP0126`), printed on the holder's invoices and searchable, and the Contract may carry an optional default RVG code, which fills the Procedure's RVG code when it is empty and lets typing an RVG code find the Contract (AR-58 section 5.7). What is picked is still the Contract. Whether an RVG code is needed now turns on the Contract's pricing kind. Donald: "On an RVG price, the RVG code, time and modifiers are required; on a fixed or open price the form collapses to an optional RVG code for reference." This follows the meeting: Ben, "if I'm just doing a price, I don't want to fill out any of this rubbish", and Donald's "gut" that a fixed price takes an optional RVG code with no time or modifiers.
