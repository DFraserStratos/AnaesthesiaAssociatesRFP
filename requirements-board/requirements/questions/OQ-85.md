**Already settled:** an anaesthetist can move a single Booking as well as a whole List (Greg, 2026-10-02).

**Still to answer, for Donald:**

1. **How does the anaesthetist find the receiving anaesthetist?** The app could not show every List; Donald: "you'd kind of want it to just have a search box to search by an anaesthetist".
2. **Where does the Booking land when the receiver has no List in that Slot?** One option is a List created on the fly with that one Booking; if so, may others then add Bookings to it (Greg's favour case)?
3. **Does the move notify as a List move does?** That is, post to the shared notification pool and offer the update email.
4. **Does the blacklist warning apply?**

Recommendation: search by anaesthetist; only receivers whose Slot is available are offered; a List is created in the receiver's Slot when none exists; the move notifies and warns as a List move does.

## Answer

1. **Finding the receiver:** the anaesthetist either scrolls the colleagues who are free in that Slot (the prototype's List reassignment orders them by tier and preferred pairing) or types in a search box that filters the names as each letter is typed, like the RVG code picker.
2. **Where it lands:** only on a colleague who is free in that Slot. Moving the Booking creates a List in the receiver's Slot holding it. A Booking is never moved into another anaesthetist's existing List. This is the requirement for now and can change if it does not work in practice; two Lists in one Slot are not supported (today an anaesthetist who does two hospitals in one half day handles it outside the system). Whether others may then add Bookings to the new List was not discussed.
3. **Notifying:** the mover has an option to notify the admin team (a notice in the shared pool, needing no action) or raise the update email; it is not required. Greg: "they could offer to raise an email or they could just flag it. Don't bother." Donald: "there's an option to notify the admin team if needed."
4. **The blacklist:** no warning (Donald's recollection of Ben, which Greg backed). An anaesthetist is never shown another anaesthetist's not-preferred pairing with a surgeon; it is sensitive, and the anaesthetists "are professionals and they can deal with it".

Greg recalled the use case: "somebody rang Ben and said, I don't want to do this child... Ben was free, created a list and put the one booking on it." Greg: "let's make the requirement at the moment that the anaesthetist has to be free... we can change it later if it's not working." Donald asked for the question to be updated. See "Notes 2026-10-19 · AA meeting with Greg #7 #16 #17".
