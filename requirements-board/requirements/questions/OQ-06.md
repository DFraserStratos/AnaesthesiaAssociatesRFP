Recommendation: base units live on the RVG code master; a Contract may override them. The alternative (every RVG code has its own default Contract carrying base units) multiplies Contracts by codes. Confirm the recommendation.

Meeting 2026-09-29: the RVG code alone cannot derive the base units, because the same code appears with different values (minor versus simple), so authoritative base units are needed per procedure; Contracts can still override them. Revised recommendation: base units live on a Procedure master (operation name mapped to an RVG code or category, [Procedure master](US-05.1.6)), a Contract may override them, and the RVG code master keeps the guide's own values. Confirm. Also confirm whether the anaesthetist picks a Procedure by operation name (which seeds the RVG code and base units) or by RVG code as [selecting an RVG code](US-03.3.1) describes.

## Answer

base units live on the RVG code master; a Contract may override them.

Transcript adds, and differs from the answer above: the meeting agreed the revised recommendation. Base units live on a master procedure list, each procedure with its own base units (ideally derived from an RVG code), and the default and hospital Contracts take them from that list; a Contract may override them. The RVG guide is only a guide (the same code appears with different base units), so Donald proposes calling it the master procedure list rather than RVG. If a base unit is consistently overridden, AA should change its own data on the default Contract. Vanessa is filling in a standard procedure list with RVG codes and base units. Not answered: whether the anaesthetist picks a Procedure by operation name or by RVG code. See Notes 2026-10-01 · AA meeting with Greg #4 #55 #59.
