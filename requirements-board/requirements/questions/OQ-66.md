Every Contract needs AA's own unique identifier, with holder codes kept for reference, and combinations are Contracts too, so there will be "thousands". What coding scheme does AA use for Contracts, and how is the bucket kept navigable when picking one (procedure, then hospital, then search by code)? Donald: "Give me a shot to make it navigable."

Recommendation: a short structured AA code per Contract and a picker filtered by procedure and hospital with code search.

## Answer

Lets go with your Recommendation for now

The meeting adds: Greg agreed, "It's to be designed... We need to design a contract", and noted it to think about over the weekend. The code format is not set. (See Notes 2026-10-02 · AA meeting with Greg #7)

The meeting adds: Greg read the AA identifier story without change ("OK. So far so good") and asked for a composite search, "like a modern search where you can type it in and figure out where it is", with the holder's own codes searchable. Finding a Contract: the Contract list filters by active or all and by contract holder; Greg: navigation starts two ways, the raw RVG tree or the contract holder, which "provides you with the natural filters of what contracts are available"; the client meeting has the procedure picked first (by body section and subgroup, or by RVG code), then the Contract list filtered. An anaesthetist sees only their own first-party Contracts, not everyone's. The draft technical design gives a Contract no AA code beyond its name, and leaves the candidate list context rules open.
