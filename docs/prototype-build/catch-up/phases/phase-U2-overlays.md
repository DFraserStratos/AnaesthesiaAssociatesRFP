## Goal

One modal behaviour, one sheet header, one footer, one confirm, and the Escape bug fixed. No redesign.

1. **One modal layer** (U02). Today four implementations handle Escape and focus on their own: Dialog keeps a topmost check, MasterPanel moves focus in and back but closes on any Escape, BottomSheet has no Escape, the three drawer shells have none of it. Nothing traps focus and nothing makes the background inert. That is why, with the RVG code picker open in the Contract panel, one Escape closes both and loses the form (README section 4 bug 1; reproduced 12 November, `docs/ui-unification/shots/escape-bug-before.png` and `escape-bug-after.png`). After this phase one stack decides: one Escape closes only the top layer, focus goes in and comes back, Tab stays inside, the background is inert, and every close of a layer runs through its one `onClose`.
2. **One side panel** (U19). The Admin List drawer, the empty-session drawer, the Draft List drawer and the Contract and Party panel share one `SidePanel`; the main Admin drawer gains a dialog role, an accessible name, Escape and focus handling. SlotDrawer stops re-declaring `drawerParts`.
3. **One popover** (U30). The open, outside-click and Escape code written five times becomes `usePopover` and `PopoverPanel`; the Contract combo returns focus on Escape.
4. **One sheet header** (U03). About 64 hand-typed titles become `OverlayHeader`: an h2 at 18/700 that names its dialog (today 1 of about 66 overlays has a name). Web dialogs get the drawer's corner X (question 11).
5. **One footer, one confirm, one done step** (U18). About 45 footers on `SheetActions` (stacked on the phone, one row on desktop with the primary last and filling, question 13), about 15 confirms on `ConfirmSheet` or `InlineConfirm`, five done steps on `DoneStep`.
