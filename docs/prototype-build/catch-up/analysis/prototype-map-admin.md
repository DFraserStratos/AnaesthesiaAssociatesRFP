# Prototype map: Admin Web App (`aa-prototype/src/apps/admin`)

All paths below are relative to `aa-prototype/src/` unless they start with `apps/admin/` (written `A/`). `S` = `store/`, `D` = `domain/`. Code is truth; comments cite old phase numbers only as leads.

**Orientation.** The Admin app is the office persona's desktop app (Kirsty W., one hard-coded actor `OFFICE_ACTOR = {who:'Kirsty W.', role:'office', source:'office'}`, `S/demoActors.ts:14`; there is no login, no role switch and no per-user state inside Admin). `A/AdminApp.tsx` is the layout (dark `SideNav` + routed `<Outlet context>` + two overlay drawers). Screens are React Router sub-routes defined in `router.tsx:101-131` and wrapped by `A/routes.tsx`. Overlays (session drawer, Draft List drawer, every flow/sheet) are state, not routes. Domain state is read via store hooks/selectors and written only through `S/*Actions` (audited `mutate()`, `Outcome` refusals shown inline). Core concepts: Slot (a stored AM/PM session per anaesthetist per day, carries an availability status), List (ACTIVE/SUBMITTED/AUTHORISED when assigned; DRAFT = no anaesthetist, no Slot), Conflict (derived: hospital closed, or session status closed), Warning (one rule only: unpaid prepayment), review flags, billing monitor, AA fee invoices, master data.

### 3.2 `DayGrid` (`components/DayGrid.tsx`, 447 lines)

- Block text: kind label/hospital + surgeon or template note; a conflicted List shows the reason ("Hospital closed" / "Anaesthetist unavailable", `+n`); tooltip carries surgeon, reasons, warning count, note, booking count. Left bar = kind colour; conflict = warning tint + amber border; open strong warning = red outline, mild = amber outline; amber `!` for list-level attention; booking-count badge on each List block (`data-shot=daygrid-block-count`).
- **Draft Lists band** above the rows (`DraftListBand.tsx`): day's waiting Draft Lists at default session times, lane-stacked, "UNASSIGNED" micro-caps, ignores all filters, click opens drawer.
- Filters: interactive legend chips (`StatusLegend`, hides a display key; legend keys come from the live status master) plus focus toggles Needs attention / Conflict / Has note / Has warnings; non-matching rows sink below a divider; footer counts "x of y anaesthetists ... Showing a of b blocks". Reset button.
- Click a block -> `onSelectSlot(slotId)` (session drawer). A free session is clickable too.

### 3.5 Session drawer (`components/SlotDrawer.tsx`; test id `admin-list-drawer`)
Follows the List across a reassign (`followListId`). Two bodies:
- **ListBody** (session holds an assigned List): header surname-first, date, session, `LIST_STATE_LABELS` state, booking count, kind chip (+ session status chip when closed); `ConflictPanel`; "Moved here by Dr X" line from the notification pool (`MovedHereLine`, an anaesthetist's own move); Session rows (Times with Own/Default, Hospital, Surgeon link to profile, Note, "From a recurring booking"); Bookings list with patient, status (Completed/In progress/Cancelled), `WarningTriangle`, **Open** (-> Booking detail) and **Move** (hidden when List AUTHORISED); read-only Attachments (`AttachmentStrip canRemove=false`: no admin attach UI). Footer: **Edit list**, **Reassign list** (hidden when AUTHORISED), **History** (`HistorySheet` over list+slot ids).
- **EmptySessionDrawer**: status, times, note; if status closed shows soft warning "A List or Booking added here is accepted and flagged as a conflict"; footer **Assign List** (primary), **Book (phone advice)**, **Edit times**, **History**.
- Flows: `AssignListSheet` -> `assignListToSlot` (`S/slotActions.ts:399`): office only; session must be empty; `pairingIssues` requires hospital + surgeon (`D/listPairing.ts:40`); kind private/public/preop; never refuses closed session/closed hospital/not-preferred pairing (flag + `list.pairingAcknowledged` audit). `AssignListFields.tsx` (Pre-op kind forces AA rooms hospital, `withKind`). `PhoneAdviceBooking` = assign step then the shared `AddBookingFlow` on the new List (abandon after assign leaves the List). `EditSlotTimesSheet`/`EditListSheet` -> `setSlotTimes` (`slotActions.ts:687`: office only, not on AUTHORISED List, `HH:mm`, start < end, empty clears override) and `editList` (`S/lifecycle.ts:507`: hospital/surgeon cannot be cleared, edit-rights matrix, an edit of hospital/surgeon/notes drops `recurringBookingId` provenance, surgeon change onto not-preferred pairing is acknowledged not refused). `ReassignListFlow` -> `reassignList` (`slotActions.ts:620`): candidates are colleagues with an open session same day+session; vacated session returns to Free or a status the office picks; closed-session source allowed; not-preferred target warns ("Confirm reassignment anyway"); billing never recalculated. `MoveBookingFlow` -> `reassignBooking` (`lifecycle.ts:574`): pick target day then any List; blocked if source or target AUTHORISED; pairing mismatch is advisory.

## 5. Conflicts
- **Rule** (`D/conflicts.ts:114 expectedConflicts`): a List conflicts when (a) its hospital has a holiday row on its date (`kind:'holiday'`) or (b) its Slot's status is closed (`kind:'availability'`, `isClosed` = status not bookable, keyed on status ID). AUTHORISED Lists and backdrop `L-HIST*`/`L-RB-*` Lists never conflict; Draft Lists can only have holiday conflicts. Soft warning only (OQ-09): nothing is blocked. Reconciled automatically inside `mutate()` (`S/conflictReconcile.ts`), never stamped by actions. Wording derived by `describeConflict` (`:243`); `CONFLICT_REASONS` = "Hospital closed" | "Anaesthetist unavailable".
- **`screens/ConflictsScreen.tsx`**: all conflicts grouped by day via `conflictRows`; filters (URL): reason chips, When (From today / Next 2 weeks / Whole canvas / Include past), hospital, anaesthetist, "Show cleared". Row actions: open session (`onOpenSession`) or Draft List drawer, **Reassign** (`ReassignListFlow`), **Clear conflict** (`ClearConflictSheet` -> `clearListConflict` `S/conflictActions.ts:27`, optional note; a clear holds only while the cause stands) and **Flag again** (`restoreListConflict` `:64`). Confirmation line after reassign says whether still flagged.
- `ConflictPanel` (in both drawers): live conflicts with reason/detail + Clear; cleared ones as muted line + Flag again. `ConflictCallout` shows the pending clash before confirm in assign/phone/edit/move flows (`conflictPreview` `D/conflicts.ts:272`); hospital options labelled "closed" on that date.
- Badges: side nav + To-do line use `openConflictCount` (today..horizon, `S/selectors.ts:1649`).
- **Hospital holidays** (Master data "Hospitals & holidays", `masters/HospitalsView.tsx`, `flows/HolidaySheet.tsx`): per-hospital closure rows, List view (buttons per holiday) or Calendar view (one hospital month, Monday first, bounded by horizon, cell shows closure name, List count, "n flagged"); add (hospital, date, name), edit date/name, delete with confirmation stating how many flags clear. Actions `addHospitalHoliday/editHospitalHoliday/deleteHospitalHoliday` (`S/mastersActions.ts:467-572`); `hospitalMonth` selector (`selectors.ts` ~1665).
