# Prototype map: Admin Web App (`aa-prototype/src/apps/admin`)

Orientation. The Admin Web App is the office's desktop app, mounted at `/admin` (route table in `aa-prototype/src/router.tsx:102-133`; thin route wrappers in `apps/admin/routes.tsx`; layout and shared derivations in `apps/admin/AdminApp.tsx`). It is a React front end over the in-browser zustand store: components read selectors/hooks from `src/store` and write through audited actions (`mutate()`), always with the one hard-coded actor `OFFICE_ACTOR = { who: 'Kirsty W.', role: 'office', source: 'office' }` (`store/demoActors.ts:14`, used at `AdminApp.tsx:239,262,315,338,354`). There is NO login, role switch or route guard inside the Admin app: "roles" are (a) that fixed actor, (b) `actor.role !== 'office'` refusals inside store actions, (c) an info overlay (`RolesInfo.tsx`). The layout is a dark 216px side nav + routed content + transient overlays (Session drawer, Draft List drawer, Out-of-hours sheet) held in `AdminShell` state, not in the URL. Almost all screens are real (store-backed); stubs are called out in section 12. All paths below are under `aa-prototype/src/` unless stated; `apps/admin/` is abbreviated `A/`.

## 1. Shell, nav, badges, overlays (`A/AdminApp.tsx`, `A/components/SideNav.tsx`)

- `AdminApp` wraps `AdminShell` in `SurfaceProvider variant="web"`. `AdminShell` renders `SideNav`, `<Outlet context={AdminOutletContext}>` (type in `A/outlet.ts`), and three overlays.
- Min width 1320px (`AdminApp.tsx:295`); no mobile layout. Content padding `A/layout.ts` (28px); list drawer width 440.
- Side nav sections (`SideNav.tsx:36-47`, path map `AdminApp.tsx:281-292`): Day view `/admin/day/<lastDate>[?sort=az]`, Draft lists, Conflicts, Notifications, Review queue, Invoices, Billing monitor, Integrations, Master data, Audit. Active section from `sectionForPath` (`AdminApp.tsx:42`); `billing/aa-fees*` highlights Billing monitor.
- Badges (all derived, never hardcoded): Review = count of SUBMITTED lists (crimson); amber ("warn") for Draft Lists `waitingDraftListCount`, Conflicts `openConflictCount` (today..horizon), Notifications `activeNotificationCount`, Billing `billingAttentionCount` (failed cases + Xero handoff faults, `store/selectors.ts:539`), Integrations `integrationAttentionCount` (deadLetter + manualIntervention messages, `selectors.ts:1437`).
- Footer: "Roles in this prototype" button (`RolesInfo.tsx`) and `PersonaChip` for `PERSONAS.kirsty` (`shell/appConfig.ts`).
- Day and sort persistence: the `/admin/day/:dateISO` param and `?sort=az` are the state; off a day route the last pair is remembered in refs (`AdminApp.tsx:117-131`) so "Day view" returns there.
- Overlay state: `drawerSlotId` (Session drawer), `drawerDraftListId` (Draft List drawer), `openOutOfHoursFor`, `drawerAssign`. Any pathname/navigation-state change closes them (`AdminApp.tsx:136-153`). A List can be opened on its day via navigation state `{ openListId }` (`openList`, `AdminApp.tsx:275`), a Draft List via `?open=<listId>` on `/admin/draft-lists`. After "assign draft list" (`onAssigned`, `AdminApp.tsx:318-328`) the UI goes to the drawer / `?assigned=<id>`.
- Layout-level derivations (read once, passed by outlet context): `rosterForDate` (anaesthetists with a session that day; seeded cast order, A-Z sort option by surname), `slotViewsForDate`, `scheduleHorizon` (end date), `draftListsForDate`, `bookingCountsByList`, summary line (`N anaesthetists · N sessions · N free · N submitted · N Draft Lists`), review rows (SUBMITTED lists sorted date then anaesthetist id), `warningSummaryByList` (selected day) and `openWarnings` (all dates) from `store/warnings.ts:140,177`.

## 4. Day-view flows (`A/flows/`)

All write via store actions, show the store's `Outcome` refusal text verbatim, are office-only.
- `AssignListSheet` + `AssignListFields` + `pairing/SurgeonPicker`: free session -> List (`assignListToSlot`, `store/slotActions.ts:387`). Refuses: not office, session occupied, session not open (closed status), pairing issues (`pairingIssues`, `domain/listPairing.ts`: hospital and surgeon both required and known), invalid kind (private/public/preop). Records a pairing acknowledgement (`list.pairingAcknowledged` audit) when the chosen surgeon is Not preferred for that anaesthetist; the UI warning reads "Assign anyway" and never blocks. New List starts ACTIVE.
- `PhoneAdviceBooking`: assign (same fields) + set times + first booking on a free session ("Book (phone advice)") via `assignListToSlot` and `setSlotTimes`.
- `AvailabilityFinderSheet`: for day + AM/PM/(session) lists anaesthetists whose session is open (`openSlotViews`, `isOpenSlot`) through `pairing/AnaesthetistCandidates` (tier order, preferred pairing first, shuffled within from `useSuggestionKey`, tier filter, name type-ahead, Not-preferred group still selectable once a surgeon is chosen); pick opens the drawer on Assign List with surgeon pre-chosen (`onAssignFromFinder`). Test `AvailabilityFinderSheet.test.tsx`.
- `EditListSheet`: hospital, surgeon, notes via `editList` (`store/lifecycle.ts:644`), session times via `setSlotTimes` (`slotActions.ts:751`) only if changed; `SessionTimesFields` ("Use default" clears the override); warns (never blocks) if hospital closed that day (OQ-09).
- `EditSlotTimesSheet`: times on an empty session (`setSlotTimes`).
- `ReassignListFlow` (illness cover; test `ReassignListFlow.test.tsx`): move a List to a colleague's open session same day and session via `reassignList` (`slotActions.ts:631`), keeping id/Bookings/history; office chooses what the vacated session becomes (Free or Unavailable; no "keep as is", D60); candidates via `AnaesthetistCandidates`; colleagues marked not available in a collapsed read-only group (`closedEmptyColleagueSlots`); Not-preferred target warns, "Confirm reassignment anyway"; no billing recalculation (US-06.3.5).
- `SessionStatusSheet` (test `SessionStatusSheet.test.tsx`): change a session's status. Empty or still-open status saves at once (`setAvailability`, `slotActions.ts:728`). A closing status on a session holding a List asks "Where does this List go?": Return to the office (-> Draft List) or Hand on to a colleague (open sessions only; tiered; Not preferred apart), then what the session becomes; committed via `markUnavailableAndMoveList` (`store/listMoveActions.ts:286`). SUBMITTED List can only be handed on; AUTHORISED refused. Unavailability is never a conflict (D59).
- `OpenOutOfHoursSheet`: `openOutOfHoursSession` (`store/outOfHoursActions.ts:20`); rules in `domain/outOfHours.ts:77-125`: office only, today or later, anaesthetist on the schedule that day, not already open, times HH:mm, start before end and not before the PM session end. Then opens the new session's drawer.
- `MoveBookingFlow`: move a single Booking to another day's List (any anaesthetist/session), advisory pairing mismatch and conflicted-target warning (never block) via `reassignBooking` (`lifecycle.ts:712`; refuses AUTHORISED source/target). Pure logic `domain/bookingMoves.ts`. Test `store/bookingMoveActions.test.ts`.
- `RecurringBookingSheet` (+ `recurringBookingCopy.ts`): add/edit/retire a recurring booking (weekday, kind private/public/preop, hospital, surgeon, anaesthetist, start/end dates, note) with live preview (`previewRecurringBookingChange`, `previewRetireRecurringBooking`), primary "Apply to canvas now" projects over the horizon from tomorrow (`addRecurringBooking`/`editRecurringBooking`/`retireRecurringBooking`, `store/mastersActions.ts:724,859`); clashes (closed/unavailable session) become Draft Lists (`domain/recurringBookingProjection.ts`, `domain/draftLists.ts recurringClashDraft`). Reached from Master data > Recurring bookings.
- `pairing/*` (admin-only, enforced by `apps/officePrivacy.test.ts`): `AnaesthetistCandidates`, `SurgeonPicker`, `NotPreferredWarning`, `TierPill/PreferredPill/NotPreferredPill`, `PairingSection` + `PairingAddSheet`/`PairingEndSheet` (office-private pairing preferences on both profile pages), `DraftListCandidates`, hooks in `useOfficePairings.ts`. Rules in `domain/pairingPreferences.ts` (labels `PAIRING_LABELS`, `TIER_LABELS`: "Not preferred", "Preferred", Tier 1 to Tier 4, Tier 4 default; names open as OQ-102, D36); `store/officePrivate.ts` holds `officePrivate.pairingPreferences` and priority tiers.
