# Prototype map: Admin Web App (`aa-prototype/src/apps/admin`)

Orientation. The Admin Web App is the office's desktop app, mounted at `/admin` (route table in `aa-prototype/src/router.tsx:102-132`; thin route wrappers in `apps/admin/routes.tsx`; layout and shared derivations in `apps/admin/AdminApp.tsx`). It is a React front end over the in-browser zustand store: components read selectors/hooks from `src/store` and write through audited actions (`mutate()`), always with the one hard-coded actor `OFFICE_ACTOR = { who: 'Kirsty W.', role: 'office', source: 'office' }` (`store/demoActors.ts:14`, used at `AdminApp.tsx:239,262,315,338,354`). There is NO login, role switch or route guard inside the Admin app: "roles" are (a) that fixed actor, (b) `actor.role !== 'office'` refusals inside store actions, (c) an info overlay (`RolesInfo.tsx`). The layout is a dark 216px side nav + routed content + transient overlays (Session drawer, Draft List drawer, Out-of-hours sheet) held in `AdminShell` state, not in the URL. Almost all screens are real (store-backed); stubs are called out in section 12. Refreshed at HEAD 63a44902 (catch-up phases through 25 incl. 17a, 22a, 23, 24, and UI unification U1 to U6). Screens now sit on shared parts (`shared/ui`: `PageHeader`, `Card`, `TextAction`, `StatTile`, `DefList`, `LineTabs`, `SelectField`; `shared/table`: `TableShell`, `Th`, `Td`, `ClickableRow`), so markup lives there. All paths below are under `aa-prototype/src/` unless stated; `apps/admin/` is abbreviated `A/`.

## 1. Shell, nav, badges, overlays (`A/AdminApp.tsx`, `A/components/SideNav.tsx`)

- Day and sort persistence: the `/admin/day/:dateISO` param and `?sort=az` are the state; off a day route the last pair is remembered in refs (`AdminApp.tsx:117-131`) so "Day view" returns there.
- Overlay state: `drawerSlotId` (Session drawer), `drawerDraftListId` (Draft List drawer), `openOutOfHoursFor`, `drawerAssign`. Any pathname/navigation-state change closes them (`AdminApp.tsx:136-153`). A List can be opened on its day via navigation state `{ openListId }` (`openList`, `AdminApp.tsx:275`), a Draft List via `?open=<listId>` on `/admin/draft-lists`. After "assign draft list" (`onAssigned`, `AdminApp.tsx:318-328`) the UI goes to the drawer / `?assigned=<id>`.
- Layout-level derivations (read once, passed by outlet context): `rosterForDate` (anaesthetists with a session that day; seeded cast order, A-Z sort option by surname), `slotViewsForDate`, `scheduleHorizon` (end date), `draftListsForDate`, `bookingCountsByList`, summary line (`N anaesthetists · N sessions · N free · N submitted · N Draft Lists`), review rows (SUBMITTED lists sorted date then anaesthetist id), `warningSummaryByList` (selected day) and `openWarnings` (all dates) from `store/warnings.ts:140,177`.

## 4. Day-view flows (`A/flows/`)

All write via store actions, show the store's `Outcome` refusal text verbatim, office-only.
- `AssignListSheet` + `AssignListFields` + `pairing/SurgeonPicker`: free session -> List (`assignListToSlot`, `store/slotActions.ts:387`). Refuses: not office, occupied, closed status, `pairingIssues` (`domain/listPairing.ts`: hospital and surgeon required and known), bad kind (private/public/preop). A Not-preferred surgeon records a `list.pairingAcknowledged` audit and warns "Assign anyway" (never blocks). New List ACTIVE.
- `PhoneAdviceBooking`: assign + times + first booking on a free session (`assignListToSlot`, `setSlotTimes`).
- `AvailabilityFinderSheet` (test): anaesthetists with an open session for day + AM/PM via `pairing/AnaesthetistCandidates` (tier order, preferred first, shuffled within tier by `useSuggestionKey`, tier filter, type-ahead); pick opens the drawer on Assign List (`onAssignFromFinder`).
- `EditListSheet`: hospital, surgeon, notes (`editList`, `lifecycle.ts:731`), times via `setSlotTimes` (`slotActions.ts:751`); warns, never blocks, if hospital closed that day (OQ-09). `EditSlotTimesSheet`: empty session times. `SessionTimesFields`: "Use default" clears override.
- `ReassignListFlow` (illness cover): move a List to a colleague's open session same day/session via `reassignList` (`slotActions.ts:631`), keeping id/Bookings/history; vacated session becomes Free or Unavailable (D60); Not-preferred target warns; no billing recalculation (US-06.3.5).
- `SessionStatusSheet`: change a session status (`setAvailability` :728). Closing a session holding a List asks Return to the office (-> Draft List) or Hand on to a colleague, via `markUnavailableAndMoveList` (`store/listMoveActions.ts:286`); SUBMITTED can only be handed on; AUTHORISED refused. Unavailability is never a conflict (D59).
- `OpenOutOfHoursSheet`: `openOutOfHoursSession` (`store/outOfHoursActions.ts:20`; rules `domain/outOfHours.ts:77-125`: office, today or later, anaesthetist on schedule, not already open, HH:mm, start before end and not before PM end).
- `MoveBookingFlow`: move one Booking to another day's List via `reassignBooking` (`lifecycle.ts:799`; refuses AUTHORISED source/target; pairing mismatch and conflicted target warn); logic `domain/bookingMoves.ts`.
- `RecurringBookingSheet` (+ `recurringBookingCopy.ts`): add/edit/retire with live preview (`previewRecurringBookingChange`), "Apply to canvas now" projects over the horizon from tomorrow (`store/mastersActions.ts addRecurringBooking/editRecurringBooking/retireRecurringBooking`); clashes become Draft Lists (`domain/recurringBookingProjection.ts`). **BillingMonitorScreen** (`screens/BillingMonitorScreen.tsx`; `billingMonitor` selector `store/selectors.ts:764`, stages ~845-890): one pipeline per AUTHORISED non-backdrop List: List authorised -> Billing run -> Invoices generated -> Sent or to post -> Xero handoff, each a `StageChip` with state done/partial/pending, a per-Booking row beneath with status pill (Invoiced, Handed off, Part paid, Paid, Disbursed, Failed, Cancelled, Pending, "Handoff failed").
