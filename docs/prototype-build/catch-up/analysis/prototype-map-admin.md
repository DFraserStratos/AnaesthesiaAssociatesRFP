# Prototype map: Admin Web App (`aa-prototype/src/apps/admin`)

> Phase 15 renamed Card to Booking and Phase 15a removed the pre-payment override gate; this map uses the current names (refreshed after 15a).

**Orientation.** The Admin Web App is the office (persona Kirsty W., role `office`, source `office`) desktop app, mounted at `/admin` (min width 1320px). One layout component (`AdminApp.tsx`) renders a dark side nav plus an `<Outlet>`; screens are router sub-routes declared in `aa-prototype/src/router.tsx:89-106` with thin route wrappers in `routes.tsx`. There is NO real auth or role switching: `AdminApp.tsx:25` hardcodes `OFFICE: Actor = { who:'Kirsty W.', role:'office', source:'office' }` and passes it to every screen. All data comes from the Zustand store (`useAppStore`), all writes go through store actions returning `Outcome` (`ok` / `refuse(code,message)`) that are audited via `mutate()`. Screens hold only UI state. Paths below are relative to `aa-prototype/src/apps/admin/` unless they start with `store/`, `shared/`, `domain/` (relative to `aa-prototype/src/`). Nothing here talks to a network.

## 3. Day view

- Signals per block: amber "!" when `attentionReasons(list)` non-empty (`util.ts:111`: any `list.conflicts[].message`, plus "Surgeon not yet assigned" for a `private` list with no surgeon; public/preop never flag); note dot (`hasNoteSignal`: note text on a booked block with a surgeon, so not already the subtitle); "$" corner for pre-payment flag (tooltip "Pre-payment outstanding" only since 15a). Tooltip lists reasons and note.
- Client-only filters (state in component): hide/show by status via `StatusLegend` chips (`STATUS_ORDER`: `theme/statusColours`), focus filters Needs attention / Has note / Pre-payment flagged (OR-combined), Reset. Non-matching rows sink below a divider. Footer counts "N of M anaesthetists ... Showing X of Y blocks" and the sentence "At production scale (~85) this view pages and virtualises ... narrated here, not simulated" (:241). **Only the seeded cast is shown; no paging/virtualisation.**
- Six statuses in the app: `private, public, preop, holiday, unavailable, free` (master `listStatuses`; `ListStatusKey`). Unavailable is hatched, Free dashed (`theme/statusColours`).
**`components/RightRail.tsx`**: (a) `MiniCalendar` (Monday-first month grid, ISO week number, full keyboard nav, month arrows navigate the day to +/-1 month); (b) `InternalNotes` for the selected day (list of notes `HH:mm · initials`, amber left border if flagged, add form with "Flag (amber)" checkbox; note = `DayNote {id, atISO, initials, text, flagged}`); (c) "Awaiting review" rows -> `/admin/review/:listId`. ## 7. Billing monitor (`screens/BillingMonitorScreen.tsx`, selector `billingMonitor`, `store/selectors.ts:429`)

- Top banner counts failed + handoff-failed cards. Per-card isolation: a failed card blocks only its own invoice. Monitor is unbadged "proposed product UI"; the reading that it lives in Admin (vs a separate Billing Engine screen) is stated in copy.

## 10. Audit viewer (`screens/AuditViewer.tsx`, `shared/audit`)
Global append-only `state.audit` feed, newest first (`sortAuditNewestFirst`), capped at 500 rows. Filters: entity type (derived from data), source (all/anaesthetist/office/integration/system/demo), From/To date. Columns: At, Action (human label from `actionLabel` + raw code), Who, Role · source, Entity (type, id), Change (one-line summary, `summariseAuditChanges(auditFieldChanges)`). Read-only ("Nothing here is ever edited or deleted"). No export, no free-text search, no per-user filter. Per-record trails elsewhere: shared `HistorySheet` (list drawer, card detail, review screen).

## 11. Roles / RBAC representation
Single hardcoded office actor. `RolesInfo.tsx` is a static overlay (from side-nav footer) describing four roles: Anaesthetist (own Lists/Cards only, edit on DRAFT), OfficeAdmin (Kirsty W.: everything, edits DRAFT+SUBMITTED, cannot edit AUTHORISED), Integration (HL7/FHIR feed, writes only DRAFT, otherwise refused into manual-intervention), System/Demo (billing run, canvas roll). Enforcement lives in store guards, e.g. `editRefusal(actor, list)` (`store/lifecycle.ts:48`) and per-action `actor.role !== 'office'` refusals (`officeOnly`). Role/persona switching happens in the app switcher (`shell/appConfig.ts` `PERSONAS.kirsty`), not in admin. There is no user/role management screen, no permission editing, no login.

## 12. Key store rules touched by admin (line refs `aa-prototype/src/store/`)
- List lifecycle DRAFT -> SUBMITTED -> AUTHORISED strictly ordered; `authoriseList` `lifecycle.ts:277`; AUTHORISED locks all cards (`listAuthorised` refusal).
- Billing run on `listAuthorised` (`billingRun.ts:457` `wireBillingRun`, `runBillingForList` :68): one atomic `mutate`, actor system, invoices grouped per counterparty per Card, per-card exceptions do not block the list, sets `list.billedAtISO` (removes list from anaesthetist views).
- Edit-rights: office may edit DRAFT and SUBMITTED; integration only DRAFT.
- Contract protection, in-use delete guard: `contractActions.ts:106-170`.
- Prepayment status `none|required|outstanding|paid` (`overridden` removed in 15a): `selectors.ts:372`.
- Money model: paid-in (ACCREC) and disbursed (ACCPAY) as independent dated states on `BillingCase` (`paidInAtISO`, `disbursedAtISO`, received/authorised/disbursed amounts).
