# Prototype map: src/domain (excluding seed)

Orientation. `aa-prototype/src/domain/` is the prototype's pure rules layer: typed entities (`types.ts`), the demo clock, and about 60 rule modules with no React, store, theme or real clock (enforced by `domainPurity.test.ts`; the only sanctioned bridge out is `statusTokenParity.test.ts`). It has NO routes, screens or store actions: each module is called by store actions in `src/store/` and by screens in `src/apps/*`. Where a module names a Phase ("catch-up Phase 21") that is the build phase that wrote it; the code is the truth. Money is held GST exclusive; GST 15% is added at invoice foot. Most modules carry a `*.test.ts` beside them (not listed individually). All paths below are relative to `aa-prototype/src/domain/` unless stated; `billing/` is `domain/billing/`.

Contents
1. Entity types and enums (types.ts)
2. Time, clock and dates
3. Schedule: Slots, statuses, series, conflicts, recurring, out-of-hours
4. Lists: lifecycle, Draft Lists, pairing, moves, progress
5. Pairing preferences and tiers (office-private)
6. Masters helpers: surgeons, specialties, names, Party, funding tags
7. Contracts, fallbacks, step rail, price ranges
8. RVG groups, time units, modifiers, fee calculator
9. Completion, billing pre-flight, review flags, warnings
10. Who is billed, payer, split, invoice build and presentation
11. BCTI, AA fee, payable release, Xero contact
12. Patient: NHI, ethnicity, lookup, search
13. Integrations (HL7, FHIR, PDF, canned messages)
14. Hardcoded, provisional, stubbed or missing
15. Test and demo affordances

## 2. Time, clock and dates
- `clock.ts`: pure demo clock. `DEMO_TODAY = '2026-07-21'` (32), `INITIAL_CLOCK` 08:00 (40), `today/now/advanceMinutes/advanceDays` (46-78). Horizon: `HORIZON_PAST_DAYS = 14`, `DEFAULT_HORIZON_MONTHS = 4`, `horizonFor` (104), `horizonDatesBetween`, `addDaysISO`, `enumerateDatesISO`.

## 3. Schedule
- `slots.ts`: Slot id `S-<anaes>-<date>-<session>` (35), projected List id `L-...` (46), `defaultScheduleSettings` (AM 07:30-12:30, PM 13:00-17:30, OOH 18:00-21:00) (22), `effectiveSlotTimes` (74, slot override vs default), `displayStatusKey` (58: a List's kind shows in place of the Slot status). UI says "session", never "slot" (OQ-64).
- `slotStatus.ts`: availability statuses are master data (`masters.slotStatuses`). Seed keys `free|holiday|unavailable` (`SEED_STATUS`, 37). Lookups `activeStatuses`, `anaesthetistChoices` (71, those the anaesthetist may set), `defaultSlotStatus`, `isOpenForBooking`/`isClosed` (bookable flag), `isOpenSlot` (131). Validators: `validateSlotStatusDraft` (199: length limits 16/32/160, no long dashes, no word "slot", not a List state word or List kind name, unique label, colour/treatment from fixed sets, default must be bookable, exactly one default) and `validateRetireSlotStatus` (234: not default, no active series using it). `validateAvailabilityRange` (277), `sessionsOf`, `slotsInRange`.
- `availabilitySeries.ts`: repeating days off (rule + per-instance exceptions). `validateSeriesDraft` (59), `seriesOccurrences/Instances`, `planSeriesWrite` (157: writes status only onto Slots still at default status and not owned by another series; reports leftAsIs), `describeSeries`, `isSeriesActive`, `activeSeriesUsing`.
- `conflicts.ts`: the one conflict rule. A List conflicts only when its hospital has a holiday on its date (kind `holiday`, soft warning, never blocks). Never for AUTHORISED Lists (unless ignoreLock), removed Drafts, or backdrop Lists (id prefix `L-HIST` or `L-RB-`, `isBackdropList` 42). `expectedConflicts` (102), `reconcileListConflicts` (136), `reconcileAllConflicts`, `liveClears` (clears persist only while the cause lives), `describeConflict`, `conflictPreview`. Anaesthetist unavailability is never a conflict: the store moves the List first.
- `recurringBookingProjection.ts`: `projectRecurringBookingChange`/`projectAllRecurringBookings` (209/315) return a pure plan {create, update, remove, kept, skipped, draftUpdate, draftRemove}. Skipped sessions (calendar closed) become recurring-clash Draft Lists in the store. Kept reasons: hasBookings, hasRecords, submitted, authorised, officeEdited, movedByOffice, otherRecurringBooking, draft (labels 99). Only own empty ACTIVE Lists are removed. `answeredKey` stops re-raising a clash already answered.
- `outOfHours.ts`: OOH session (US-01.1.6). Never generated; office opens one per anaesthetist per day (`maxPerDay: 1`, default 18:00-21:00). `openOutOfHoursRefusal` (88: office only, not past, anaesthetist on schedule, not already open); `outOfHoursTimesRefusal` (109: start<end, start not before PM end); `sessionText` ("Out-of-hours"), `sessionRank/compareSessions`, `listsOnDay`.

## 8. RVG, time units, modifiers, fee

## 9. Completion, pre-flight, review flags, warnings
- `completion.ts` `completionFailuresFor` (77): per Procedure on a non-cancelled Booking: (1) Contract present and existing (messages "This procedure needs an invoice destination."), (2) on RVG kinds: RVG code, start, finish, finish after start, modifiers step answered (`modifiersStepAnswered`, "Add any modifiers that apply, or choose None apply."; first Procedure only) and claim explanations, (3) not "Needs a price". Each failure has field anchor and `fixableBy` anaesthetist|office. Nothing else blocks (no approval number, payer contact, base-units range, insurer).
- `validateBookingForBilling.ts` (151): billing-run pre-flight only: rateTime lines need `permitsRateTime` (`INDIVIDUAL_ARRANGEMENT_MESSAGE`), holder must exist, price resolvable, override needs a reason and must not go negative, split must still fit and its parties still be on the Booking. Also `feeContextFor`, `billingReferenceMissing`.
- `reviewFlags.ts`: non-blocking flags in order (`REVIEW_FLAG_RULES` 188): contractChanged ("Changed by X: was Y"), contractNoLongerFits, needsInvoiceDestination, needsPrice, typedPrice ("Price typed: $x (computed $y)"), notCompleted, payerContactMissing, btmOverride ("... set manually" / "adjusted +n manually"). No billing-reference flag; Disabled-contract flag deliberately absent (OQ-135).
- `warnings/`: five rules (`rules/index.ts`): prepaymentUnpaid (beforeProcedure, strong; required vs outstanding text), baseUnitsOutsideGuide (afterProcedure, mild; skips additional Procedures), childPayer (beforeProcedure, mild; patient under 18 on List date, payer = patient, a Procedure bills the payer), approvalNumberMissing (beforeProcedure, mild; funder is an insurer-kind Party with no number), splitDoesNotFit (afterProcedure, mild). `evaluateWarnings` (routine.ts): cancelled Bookings none; per-rule on/off and numeric params from `AppSettings.warningRules`; clearance key `booking:rule[:procedure]` covers a finding only if stored strength >= finding strength; sorted strong first. Warnings never block. `defaultAppSettings` (settings.ts).

## 11. BCTI, AA fee, payable release
- `bcti.ts`: one BCTI per receivable invoice (its ACCPAY); counted once, against the anaesthetist who did the procedure; counted only once paid, in the paid month (`BCTI_COUNT_RULE = {paidOnly: true}`); never missed: a BCTI paid into an already-invoiced month counts in the next uninvoiced month, and charged ones never recount; fee never netted against payables. `bctisFor` (93), `bctiRecordsFrom`, `bctiFeeHistory`.
- `aaFee.ts`: fee = fixedItems + perBctiCharge * count, GST at foot (`aaFeeFor` 25); `validateAaFeeSettings`; `buildAaFeeInvoice` (93) returns AaFeeInvoice + ACCREC; labels "BCTIs paid in <Month Year>".
- `payableRelease.ts` `payableReleasedFor`: released = amount received clamped to payable, to the cent.
