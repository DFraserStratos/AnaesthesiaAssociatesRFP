# Prototype map: src/domain (excluding src/domain/seed)

All paths are under `aa-prototype/src/domain/` unless stated. Line numbers are from the code at HEAD d4369476.

## Orientation

`src/domain` is the pure layer: typed entities (`types.ts`, ~1450 lines, no logic except a few constant tables), the demo clock and seeded RNG, and pure rules. It has NO routes or screens (those are in `src/apps/*`, `src/shell`), and NO state or lifecycle guards: the store (`src/store`, not mapped here) owns state, `mutate()` and the List/Booking lifecycle transitions (assign, submit, authorise, detach to draft). The domain only supplies the state unions, predicates, refusal functions and planners the store and UI call. Purity is enforced by `domainPurity.test.ts` (no React/store/theme/apps imports). `statusTokenParity.test.ts` is the one allowed bridge to `../theme/statusColours`. Four files in this area import from `./seed/*` (cast ids, slotHash): `integrations/feeds.ts`, `integrations/messages.ts`, `integrations/pdfSamples.ts`, `pairingPreferences.ts`. `index.ts` re-exports types, clock, slots, listPairing, draftLists, rng, nhi, nzhis, billing, seed, warnings only; other modules are imported by path.

## 5. Recurring booking projection (recurringBookingProjection.ts, FT-01.2/01.3)

`projectRecurringBookingChange(input, claimed?)` L209 plans, over a date range, how a recurring booking (before/after) maps to Lists: `create`, `update`, `remove`, `kept` (with reason), `skipped` (closed session), `draftUpdate`, `draftRemove`. `KeptReason`: hasBookings, hasRecords (notes/attachments/clears), submitted, authorised, officeEdited (List not from a recurring booking), movedByOffice, otherRecurringBooking, draft; labels in `KEPT_REASON_LABELS`. Closed session at create time -> `skipped` (the store raises a recurring-clash Draft). `projectAllRecurringBookings` (ids sorted, `claimed` set stops two recurring bookings claiming one slot). Helpers `coversDate`, `activeOn`, `recurringBookingFor` (lowest id wins), `answeredKey`, `projectedFields`, `timesToReset`, `firstAffectedDate`. Note `projectAllRecurringBookings` does not merge `remove`/`draftRemove`.

## 7. Billing maths (billing/, barrel `billing/index.ts`; pure, Vitest-tested)

- `money.ts`: `roundToCents`, `toCents` (comparisons via cents).
- `timeUnits.ts`: `timeUnitsFromMinutes` L: 1 unit per 15 min for first 120 min (8 units), then 1 per 10 min; partial intervals round UP (`PARTIAL_INTERVAL_ROUNDING='up'`, flagged assumption); <=0 gives 0.
- `modifierCodes.ts`: `MODIFIER_CODES` (20 codes: PA1-5, A1-2, AS1-4, ASE, OB1-4, P1, AI1, PO1-2) with DEMO-PLAUSIBLE unit values (not an NZSA schedule). One code per band for groups PA, A, AS, OB (`EXCLUSIVE_MODIFIER_GROUPS`); PA5 exempt (`STACKS_WITHIN_GROUP`, lets PA reach 5). `toggleModifierCode` (tap swaps within band), `ASA_SEED_UNITS`.
- `modifierUnits.ts`: `modifierUnits(codes, baseCode)` sums units; refuses unknown codes, a second code in a band, and codes the base RVG code absorbs; returns `refused[]` with reason text.
- `fee.ts`: `resolveBtm(procedure, baseCode)` L58: base (single / range via baseUnitsSelected / overridden), time (from anaesthetist start to handover, or overridden), modifiers (selected plus the ASA class code if not selected, or overridden); provenance `seeded|overridden`. `splitBillingUnits`: additional procedure bills time units only. `feeFor(procedure, ctx)` L180: unit rate = anaesthetist.unitValue; Type 2 `agreedUnitRate` or `percentDiscount` (unitValue x (1-p/100)); Type 3 matches a `ContractPrice` (a price row without procedureOrdinal is ignored for an additional procedure) and emits a fixed "Contract price" line with unitRate null, otherwise RVG line = units x rate; non-RVG stored lines added (`fixed` amount, `rateTime` hours x rate); `priceOverride` applied last (fixedFee replaces, dollarAdjustment adds, percentAdjustment multiplies); returns lines, subtotal, override {before, after}, total, chargeBasis `rvg|fixed|rateTime|mixed`.
- `contracts.ts`: `isEffectiveOn`, `selectContract` (individual-anaesthetist scoped rank 2 > specific org rank 1 > default Type 1 rank 0; filtered by holder and date), `matchContractPrice` (most specific match wins on rvgBaseCode / surgeonId / procedureOrdinal; no match -> BTM fallback).
- `validateBookingForBilling.ts`: `validateBookingForBilling` L104 returns field-level failures per procedure (none for a cancelled Booking): billingRoute required; RVG code or non-RVG line required; RVG code in master; anaesthetist start and handover recorded, handover after start; range base code needs baseUnitsSelected in [min,max]; insurer route needs insurer that `acceptsDirectClaims`; billableParty route needs `patientPaymentCategory`; `selfFundedPrepayment` needs prepaymentDetail and, for split, deposit > 0; rateTime line needs contract with `permitsIndividualArrangement` (`INDIVIDUAL_ARRANGEMENT_MESSAGE`); price override needs reason and must not make fee negative; funder-split lines must sum to the fee (cents). `billingReferenceMissing` (hospital route without reference). `feeContextFor`.
- `invoiceBuild.ts`: `GST_RATE = 0.15` (L39). `resolveContractForProcedure` L114 (stored governing contract if effective; ineffective hospital/insurer contract falls back to protected default; other holder types raise `contractIneffective`; missing stored contract `contractMissing`; no stored contract resolves by route: hospital default via List hospital, insurer default, billableParty none; else `noBillingRoute`). `counterpartyForProcedure` (insurer / billable party or patient / contract holder). `layoutFor` (patient and billableParty -> `patient` layout, else `contractHolder`). `buildInvoicesForBooking` L264: per-procedure fee lines tagged to counterparty (funderOverride splits), "Price override" delta line, "Less pre-payment deposit already invoiced" credit line; exceptions `prepaidFunderOverride`, `prepaidCounterpartyChanged`, `allocationStale`, `negativeTotal`; groups by counterparty into one draft invoice each; zero-total groups dropped; GST 15% added on top. `buildPrePaymentInvoiceForBooking` L456 (only billableParty + selfFundedPrepayment; split = deposit line, full = estimated full fee via feeFor with no contract; patient layout).
- `bcti.ts` (FT-10.3): BCTI = the procedure ACCPAY. `bctisFor(records, anaesthetistId, month, rule, history)` counts per paid month (`BCTI_COUNT_RULE.paidOnly = true`, the one switch; being confirmed with AA's accountant), one per ACCPAY, by the ACCPAY's anaesthetist, not voided, never charged twice, carried to the next un-invoiced month. `bctiFeeHistory`, `bctiRecordsFrom(xero)` (aaFee ACCRECs have no ACCPAY, so never counted). ## 10. NHI, NZHIS, Xero contact

- `nhi.ts`: `validateNhi` returns `{normalised, format 'current'|'new'|null, valid, reason}`. Alphabet A-Z minus I,O; weights 7..2 over chars 1-6. Current `AAANNNC`: mod 11, remainder 0 is never assigned, check = 11-r (10 -> 0). New `AAANNAX`: mod 23, check letter = alphabet[23-r-1]. Corrected to official Health NZ maths; the RFP's "Modulus 24" label is flagged as a discovery item. `generateNhi(format, rng)`.
