# Reverse check: what the prototype does that is now wrong or unwanted

Scope: the opposite of the gap analysis. Four checks: Retired items still implemented, Future items still showcased, Decisions-log rulings the catalogue has since overturned, and prototype behaviour with no catalogue backing that would mislead. Code is the truth; old build docs were used only as leads. Catalogue links are relative to this file. Paths are under `aa-prototype/src/`. Each finding was adversarially verified against the code and the cited catalogue files (verdict shown as "Verified").

Key facts that shape the result:

- **All 23 Retired stories are merges, not withdrawals.** Each one's text was folded into a live parent (for example [US-05.3.3](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-05.3.3.md) into [US-05.3.1](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-05.3.1.md)). So "retired but still implemented" only applies where the prototype does the opposite of the merged text. Four qualify (RV-01 to RV-04). The other 19 are either honoured by the prototype or simply missing (gap analysis territory, not listed here). Spot-checked as honoured: [US-07.1.2](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-07.1.2.md) (`submitList` refuses while any live Card is incomplete), [US-09.1.2](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-09.1.2.md) (invoice number and case reference are carried), [US-09.3.2](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-09.3.2.md) (NHI never crosses to Xero), [US-11.1.3](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-11.1.3.md) (`upsertPatient` dedupes on NHI), [US-02.4.2](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-02.4.2.md) (simulated photo capture), [US-03.5.3](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-03.5.3.md) (adjustment reason is mandatory).
- **The single biggest source of drift** is the catalogue's "one Contract per Procedure, no billing route" model ([EP-04](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-04.md), domain-model section 1). The prototype is built on billing route plus Type 1/2/3 governing contract, and that leaks into billing, validation, UI and seed.
- **Future integration work is the most visible mis-showcase**: S1 is built around a pushed HL7 message, and the Admin nav carries a dead-letter/feed-mapping monitor.
- **Several catalogue items are still Open or Verify** (OQ-02, [OQ-17](../../../discovery-reference/Updated%20Requirements/catalogue/questions/OQ-17.md), [OQ-27](../../../discovery-reference/Updated%20Requirements/catalogue/questions/OQ-27.md), [OQ-31](../../../discovery-reference/Updated%20Requirements/catalogue/questions/OQ-31.md), [OQ-39](../../../discovery-reference/Updated%20Requirements/catalogue/questions/OQ-39.md), [US-03.3.1](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-03.3.1.md), [FT-08.6](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/FT-08.6.md), [EP-06](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-06.md)). Where a finding leans on one, it says so; the plan should treat those as "labelled simplification until AA answers" rather than "wrong".
- The catalogue's own screenshots were captured from an earlier build of this prototype, so some captions (for example "aged" on [US-08.3.5](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-08.3.5.md), "productivity" on [US-12.2.3](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-12.2.3.md)) echo prototype behaviour the item text does not require. The text wins.

Size key: S under a day, M 1 to 3 days, L up to a week, XL more.

Verification result: 21 findings kept (13 upheld, 8 corrected), 1 dropped (RV-16), 0 added. IDs are stable, so RV-16 is intentionally absent below.

## 1. RetiredStillImplemented

### RV-01 Billing engine re-resolves the contract and payer at billing time; no contract lock at AUTHORISED
- Verified: corrected (narrowed). Catalogue: [US-08.1.2](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-08.1.2.md) (Retired, merged into [US-08.1.1](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-08.1.1.md)), [US-04.3.5](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-04.3.5.md), [EP-04](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-04.md), [US-07.3.1](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-07.3.1.md). The engine "does not resolve a billing route or determine a payer"; it reads the Contract locked to each Procedure at AUTHORISED.
- Prototype: `domain/billing/invoiceBuild.ts:114-190` `resolveContractForProcedure` uses the stored `governingContractId` only while it is effective on the List date; otherwise it falls back to the holder's protected default Type 1, or, when nothing is stored, resolves by `billingRoute`. `counterpartyForProcedure` (:192) derives the payer from route and contract holder. `apps/admin/screens/BillingMonitorScreen.tsx:65-78` "Resolve & retry" edits the master contract's end date (`editContract ... effectiveToISO: undefined`) so a failed case passes. There is no contract-version snapshot on the Procedure at AUTHORISED (no `snapshot` anywhere in the domain; only the invoice line text snapshots the rate).
- Correction to the draft: the stored contract IS authoritative when in effect, and the billing run fires on the `listAuthorised` event, so the practical gap is (a) no lock or version snapshot, so a later master edit or the Retry hack changes what a re-run prices, (b) the fallback and route-based re-resolution, and (c) payer derived from route. (c) disappears with RV-08.
- Action: Rework. Snapshot the Contract version onto each Procedure at authorise, price and route from the snapshot, drop the fallback and the clear-the-end-date fix. Size L. Touches S4 billing-failure beat and S5 contract-snapshot claim.
