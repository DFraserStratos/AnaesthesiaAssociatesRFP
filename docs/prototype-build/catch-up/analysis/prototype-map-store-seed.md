# Prototype map: store and seed

Scope: `aa-prototype/src/store/` (Zustand store, audited `mutate()`, lifecycle guards, every action) and `aa-prototype/src/domain/seed/` (the deterministic pristine dataset). All paths below are relative to `aa-prototype/src/` unless absolute. Line numbers verified against the code at the time of mapping (HEAD 63a44902 plus working tree).

Orientation. There is no backend: one persisted Zustand store (`useAppStore`, key `aa-demo`, `PERSIST_VERSION = 50`) holds `masters`, `schedule` (slots, lists, bookings, procedures, billingLines, warningClearances, availabilitySeries), `audit`, `settings` (demo), `appSettings` (warning rules, schedule horizon/default times, AA fee), `dashboards`, `dayNotes`, `officePrivate`, `notifications`, `counters`, `clock`, `billing` (invoices, lines, cases, receipts, locks, aaFeeInvoices), `xero` (contacts, ACCREC, ACCPAY, payments, disbursements), `integrations` (feeds, messages) and `shell`. Every write goes through `mutate()` (`store/mutate.ts:198`), which commits patch + audit entries + Booking lastModified stamp + conflict reconcile in one `setState`. Actions are plain functions `(api, actor, ...args) => Outcome`; guards return `refuse(code, message)` as data, never throw. Roles are decided by the `Actor` ({who, role: anaesthetist|office|system, source: anaesthetist|office|integration|system|demo, anaesthetistId?}), not by a login. The seed (`buildSeed()`, built once at module load) is a 4-month schedule canvas from the pinned demo date Tue 21 Jul 2026 08:00, 14 anaesthetists, 6 locations, ~140 surgeons, a long scripted tableau of Bookings for demo scenarios S1 to S5, seeded billing/Xero history, and a seeded audit trail.

- Discipline tests: `store/mutate.test.ts` `storeDiscipline` (:116) scans all `src` so only `mutate.ts` and `clockActions.ts` call `.setState`; `domainPurity.test.ts` keeps `domain/` free of store/clock leaks. ## 2. mutate(), audit, actors, ids, clock

- `mutate(api, actor, metas, recipe)` `store/mutate.ts:198`: runs recipe -> `reconcileConflictsInPatch` (store/conflictReconcile.ts, raises/clears `List.conflicts`, appends `list.conflict` / `list.conflictResolved` metas) -> one `AuditEntry` per meta (`{id A####, entityType, entityId, who, role, source, action, atISO, before?, after?}`, timestamp = demo clock) -> stamps `lastModifiedBy/AtISO` on the touched Booking (derived from booking / procedure / billingLine entity; `stampBookingId: null` suppresses) -> single `setState`. Throws if given zero metas (programmer error). Patchable slices (`DomainPatch`): masters, schedule, settings, appSettings, counters, billing, xero, integrations, dayNotes, officePrivate, notifications. `audit` is wrapper-only.

- `allocateId` :129 + `ID_FORMATS` :65: deterministic counters (A####, BK####, P####, BL####, PT####, BP####, DN####, NT####, LG####, ST####, AS####, HN###, PYN###, CTN###, SPN###, TGN###, SN###, RMN###, SGN###, PPN###, RCN###, RCBN###, HHN###, RGN###, MOD-AA-###, INV####, IL####, BC####, `AA-2026-####` invoice numbers (year pinned), XC/XR/XP, PMT, DSB, PR, RCT, AF####, `AA-FEE-2026-####`, IM####). Runtime prefixes are disjoint from seed ids.
- `clockISO(clock)` :60 local-naive `YYYY-MM-DDTHH:MM:00`.
- `resetDomainState` :270 = demo Reset (reseed all slices, clock to INITIAL_CLOCK, keep `shell` but zero `suggestionSeq`, re-lock seeded AUTHORISED Lists). Not audited (wholesale replace).
- Actors (`store/demoActors.ts`): `OFFICE_ACTOR` (Kirsty W., office), `SOUTER_ACTOR` (Dr Melanie Souter, anaesthetist 34821), `OFFICE_SIMULATION_ACTOR` ("AA office (simulated)", office-shaped so it passes `officeOnly`), `DEMO_TRIGGER_ACTOR` (system/demo), `DEMO_OFFICE_ACTOR` (office rights, source demo), `anaesthetistActor(state,id)`. ## 3. Lifecycle and edit-rights guards (`store/lifecycle.ts`)

List states: `DRAFT | ACTIVE | SUBMITTED | AUTHORISED` (`domain/types.ts:74`). Slot has status key (free / holiday / unavailable + user-maintained).

- `editRefusal(actor, list)` :64, the one edit-rights matrix for Booking/Procedure writes: removed Draft -> `listRemoved`; AUTHORISED -> `listAuthorised` (nobody, office included); integration source only on ACTIVE else `integrationImmutable`; anaesthetist: refused on DRAFT, on someone else's List (`notOwnList`), allowed on ACTIVE and SUBMITTED own; office/system/demo: DRAFT, ACTIVE, SUBMITTED.
- `completeBooking` :134: refuses `notFound`, `bookingCancelled`, `integrationForbidden` (integrations never complete), `listNotActive` (Draft List), `alreadyCompleted`, then `completionBlockersFor` :114 (domain `completionFailuresFor`, catch-up 21a: Contract, RVG detail on RVG kinds, a price; `noContract` surfaces as `needsInvoiceDestination`, else `validationFailed` with details). Warnings never block. Audits `booking.complete`, stamps `completedAtISO`. `uncompleteBooking` :186 ("Amend").
- `submitList` :244 ACTIVE->SUBMITTED: `listNotActive` (Draft/other), `submitForbidden` (integration/system), `notOwnList`, `bookingsNotCompleted` (`incompleteBookingsOn` :235, non-cancelled Bookings not complete). Audit `list.submit`. No role check beyond ownership (office may submit too).
- `authoriseList` :304 SUBMITTED->AUTHORISED, office only (`officeOnly`), `listNotSubmitted`, price blockers first (`authoriseBlockersFor` :409: one kind, `needsPrice` via domain `priceStatusFor`), then `bookingsNotCompleted`. In ONE commit: list state, approves every pending anaesthetist Contract change (`approvalsAtAuthorise`, contractApprovalActions.ts:102), writes the pricing snapshot `billing.locks[bookingId]` (`takeLockFor`, store/locks.ts:52; shape `domain/billing/lock.ts`), audits `list.authorise` + `booking.lock` per Booking. Then emits `listAuthorised` (after commit, errors swallowed).
- `editBooking` :535 (whitelisted keys `BOOKING_PATCH_KEYS`), `editProcedure` :639 (cannot touch Contract/rail answers, `enteredPrice`, texts, `isPrimary`: those have their own actions; modifiers via modifier actions, `MODIFIERS_THROUGH_ACTIONS_MESSAGE`), `withRvgRowChange` :616, `editList` :731 (hospital/surgeon/notes), `cancelBooking` :481 (audited soft cancel, `cancellation` record), `reassignBooking` :799 / `reassignBookingCore` :857 (move one Booking to another List), `logListNote` :440 (office phone-call note).
- Warnings are derived, never gates (`store/warnings.ts`; rules in `domain/warnings/rules/`: approvalNumberMissing, baseUnitsOutsideGuide, childPayer, prepaymentUnpaid, splitDoesNotFit). Only state: `schedule.warningClearances` via `clearWarning` :224.
