# Prototype map: store + seed

Orientation. All domain state lives in ONE zustand store (`aa-prototype/src/store/appStore.ts`) seeded deterministically by `aa-prototype/src/domain/seed/index.ts` `buildSeed()`. Paths below are relative to `aa-prototype/src/`. Components never own domain state; every write is an exported guard/action function `fn(api, actor, ...) => Outcome` (refusals are DATA: `{ok:false, code, message}`) that commits via `mutate()` in `store/mutate.ts` (patch + audit entry + Card stamp in one `setState`). There is NO real auth/user model: the "actor" is a plain object `{who, role: anaesthetist|office|system, source: anaesthetist|office|integration|system|demo, anaesthetistId?}` passed by the caller (built in apps/admin/AdminApp.tsx, apps/demo/*, pwa/officeSimulation.ts, mobile/web apps). Roles are enforced only inside the store guards. Prototype covers 14 seeded anaesthetists (not 85), 5 hospitals, 10 surgeons, 2 insurers, 1 contract-holder org. Time is the pinned demo clock (DEMO_TODAY 2026-07-21 08:00). Routes/screens are NOT in this area (see the app maps); this map lists which store fns/selectors each concern needs.

## 1. Store core

- `store/appStore.ts`: `AppState` = SeedState {masters, schedule, audit[], settings, dashboards, dayNotes, counters} + `clock` + `billing` {invoices, invoiceLines, cases, receipts, contactIdCache} + `xero` {contacts, accRecs, accPays, payments, disbursements} + `integrations` {feeds, messages} + `shell` {currentApp}. Only own action: `setCurrentApp`. `freshAppState()` L~120 composes seed + `buildSeedBillingSlice` (paid pre-payment + history). `useAppStore` singleton = `createAppStore({persisted:true})`.
- Persistence: zustand `persist`, key `aa-demo`, `PERSIST_VERSION = 13` (appStore.ts, comment block lists v2..v13 reasons). `migrate` returns fresh seed (version mismatch discards persisted state). `merge = backfillMerge` (one-level-deep backfill of missing sub-keys, record maps taken wholesale). Storage = `store/persistStorage.ts` `resilientLocalStorage`: 250ms coalesced trailing write, try/catch latching `persistDisabled` (quota/private mode), flush on `pagehide` + `visibilitychange`; `persistStatus()`, `bytes()`, `flushPersist()`, `STORAGE_BUDGET_BYTES` 5MB. Pristine seed ~1.17MB; ~5.8KB per advanced day. localStorage only, per-browser, no server/multi-user sync.
- `store/mutate.ts`: `mutate(api, actor, metas, recipe)` (L~112): recipe returns `DomainPatch` (masters|schedule|settings|counters|billing|xero|integrations|dayNotes; NOT audit/clock). Throws if zero metas. Appends one `AuditEntry {id A####, entityType, entityId, who, role, source, action, atISO(demo clock), before?, after?}` per meta (append-only, no delete/edit path). Stamps `lastModifiedBy/AtISO` on the touched Card (derived: card->self, procedure/billingLine->parent; `stampCardId:null` = none). `allocateId(counters, kind)` deterministic ids (ID_FORMATS: A/C/P/BL/PT/BP/AV/DN/LG/HN/CTN/CPN/PLN/HHN/INV/IL/BC/`AA-2026-`nnnn invoice numbers/XC/XR/XP/PMT/DSB/PR/RCT/IM). `Outcome`, `ok`, `refuse`. `resetDomainState(api)` = demo Reset (reseeds all domain slices + clock, keeps shell). Write discipline enforced by `storeDiscipline` test in `store/mutate.test.ts`.
- `store/events.ts`: tiny emitter, events `listAuthorised{listId}` and `dayAdvanced{todayISO}`. Wired once in `main.tsx` L11-20: `wireBillingRun`, `wireReconciliationPoll`, `wireArchiveJob`, `wireIntegrationRetry` (PWA entry wires the same; `pwa/officeSimulation.ts` simulates the office for the PWA).
- `store/clockActions.ts` (clock writes bypass mutate, roll canvas via mutate): `advanceClockMinutes/Days/ToNextMorning/ToDate(dateISO)` (forward only, lands 08:00), `resetDemo`. On day change: `rollCanvasForward` generates far-edge Lists (`canvas.rollForward` audit per day, actor "Demo control", source demo) with the same slot-hashed generator as the seed, then emits `dayAdvanced` (=> reconciliation poll, then archive job). Domain clock maths in `domain/clock.ts` (HORIZON 14 days back, 4 months forward, `INITIAL_CLOCK`, `DEMO_TODAY_LABEL`).
- `store/demoSettingsActions.ts`: `setArchiveWindowDays(days)` (office only, audit `settings.archiveWindow`), `armHandoffFault()` (audit `settings.armHandoffFault`, sets `settings.failNextHandoff`).
- `DemoSettings` (domain/types.ts L886): `contactArchiveInactivityDays` (seed 90), `failNextHandoff?`, `volumeStory {invoicesPerYear 28000, oneTimePct 99, activeContacts 9820, softLimit 10000}` (narrated counters, not real records).

## 2. Lifecycle guards: `store/lifecycle.ts`

State machine: List `DRAFT -> SUBMITTED -> AUTHORISED` strictly forward; NO Returned state anywhere; AUTHORISED locks Cards.
- `editRefusal(actor, list)` L48: shared edit-rights matrix. AUTHORISED => `listAuthorised`; integration source => only DRAFT else `integrationImmutable`; anaesthetist => own List only (`notOwnList`) and DRAFT only (`listSubmitted`); office/system => DRAFT + SUBMITTED. Used by every Card/Procedure/patient/List write.
- `completionBlockersFor(state, card)` L93 / `completeCard` L130: blockers = `validateCardForBilling` failures (`domain/billing/validateCardForBilling.ts`; code `validationFailed`) + pre-payment gate (`prepaymentUnpaid` when status required/outstanding). Refuses cancelled, integration source (`integrationForbidden`), already completed. Audit `card.complete`. `uncompleteCard` L179 ("Amend"; `card.uncomplete`, same rights matrix).
- `submitList` L225 (DRAFT only; anaesthetist own or office; integration/system refused; every non-cancelled Card must be `completed`, else `cardsNotCompleted` with ids; audit `list.submit`).
- `authoriseList` L277 (SUBMITTED only, office only; audit `list.authorise`; emits `listAuthorised` AFTER commit -> billing run).
- `logListNote` L322 (office only, any list state; audit `list.phoneNote`; stored in `List.phoneNotes`).
- `cancelCard` L363 (soft cancel: `Card.cancellation {reason,by,role,source,atISO}`; reason required; retained, excluded from validation/billing; rights matrix; audit `card.cancel`). No hard delete of Cards.
- `editCard` L415 (scheduledTime, notes, attachments; `card.update`), `editProcedure` L445 (any Procedure field except id/cardId; `procedure.update`; NO field validation here, validation deferred to completion), `editList` L498 (hospitalId, surgeonId, startTime, endTime, notes; empty string clears; `list.update`; status and anaesthetist not editable here).
- `reassignList` L550 (office only; move a whole List to another anaesthetist: target slot must be Free (`targetNotFree`), its empty List absorbed, vacated slot regenerated as free/unavailable/holiday; blocks AUTHORISED; audits `list.reassign`+`list.absorb`+`list.regenerate`). Prototype's PROPOSED answer to an open RFP question.
- `reassignCard` L640 (move one Card + procedures to another List; blocked if either List AUTHORISED; anaesthetist only between own DRAFT Lists; office may target SUBMITTED; audit `card.reassign`).
- `setAvailability` L703 (anaesthetist own or office; integration refused; writes `masters.availability` row `available|unavailable|holiday` + note, then reconciles that slot's List: truly-Free empty DRAFT List => `list.restatus`; List with booking context => advisory `ListConflict {kind:'availability'}` (`list.conflict`, replaces not stacks); un-block symmetric). Immediate: NO leave request/approval workflow.
- `requestCover` L844 (anaesthetist; `offer` on own free session, `request` on someone else's free session; sets `List.coverRequest`; audit `list.coverRequest`; simulated, no notification).

## 9. Time-relative / clock-coupled behaviour

Everything keys off `state.clock` (DEMO_TODAY 2026-07-21 08:00), never the real date. Day advance: canvas rolls forward; reconciliation poll; archive job; receivables aging buckets and overdue computed against `todayISO` (`bucketForAgingDays`); `addPostOpAddendum` targets TODAY's sessions; `setInsurerDirectClaims` default contract dated `clock.todayISO`; invoice number year fixed `2026`; audit `atISO` from clock. Seed dates are absolute (2026-07-xx, Aug), so rewinding is impossible (forward-only) and real-world date (Sept 2026) is irrelevant.

## 10. Stubs, hardcoded, visual-only, absent (relevant to catch-up)

- No authentication, users, role/permission master, sessions or per-anaesthetist login: actor is a caller-supplied object; `AdminApp`/apps hardcode office actor (e.g. "Kirsty W.") and mobile/web hardcode Souter.
- No real notification/email/SMS/push: cover request, invoice email, "sent" states are markers plus audit only.
- No leave request/approval or roster workflow: `setAvailability` is immediate; dashboard "pending leave" is seed data only. Dashboard productivity, six-month comparison and leave are hardcoded seed figures for Souter only; other anaesthetists honest-empty.
- No create/edit/delete for surgeons, insurers (only direct-claims toggle), organisations, RVG codes, modifier codes, list statuses, patients merge, hospital rename/edit/delete, anaesthetist delete (only `active` flag). Billable parties only created, never edited.
- No document/attachment storage beyond `CardAttachment {name, kind, dataUrl?}` in localStorage; no PDF generation of invoices.
- `createCard` does not validate billing route completeness; validation only at `completeCard`/submit.
- Xero, HL7/FHIR, NHI Hub are in-browser simulations; `lookupNhi` canned (5 patients); contact volume ("9,820 of 10,000") is narrated; ACCPAY 5% service fee is an invented assumption; GST rate 15% fixed; billing year fixed 2026.
- Persistence is single-browser localStorage; multi-user, concurrency, backup/restore and server audit retention are not represented; audit log is an unbounded in-state array.
- Prototype scale is 14 anaesthetists, ~150 patients (RFP: ~85 anaesthetists, ~28k invoices/yr).
- Settled-ruling reminders (PROGRESS Decisions log): no Returned state; billedAtISO removes Lists from anaesthetist views; pre-payment blocks completion (override audited); Card Copy is the additional-procedure mechanism; soft-cancel only.
