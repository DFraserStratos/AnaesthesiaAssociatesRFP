# Prototype map: store + seed

Paths are under `aa-prototype/src/` unless stated. Refreshed 2026-11-17 at c9b65ad8 (PERSIST_VERSION 44, was 26 in the 2026-11-04 map; this file replaces it). This area has NO routes or screens: it is the Zustand store (`store/`) and the deterministic seed (`domain/seed/`). Screens are mapped in the other map files; section 9 lists which screen files call each action. Facts come from reading the code; where I only confirmed an action by its exports and doc comment (not its body) it is marked "(not traced)".

Orientation. One Zustand store (`store/appStore.ts`) holds seeded domain state (masters, schedule, audit, settings, appSettings, dashboards, dayNotes, officePrivate, notifications, counters) plus clock, billing, xero, integrations and shell slices. Every domain write goes through `mutate()` (`store/mutate.ts:195`): in one `setState` it applies the recipe patch, re-runs the conflict rule, appends AuditEntries and stamps the touched Booking. Actions are plain functions `(api, actor, ...) => Outcome`; refusals are data (`{ok:false, code, message, details?}`), never throws, and messages render verbatim in the UI. Time is the demo clock (pinned 2026-07-21 08:00), randomness is hashed/seeded. The seed is built once at module load (`domain/seed/index.ts:811 SEED_BUILD`) and shared. Since the July build the domain moved: the Contract is flat and held by a Party (no types, no dates, no default); one Contract per Procedure chosen on a "step rail"; the payer lives on the Booking; modifiers are claimed one by one with explanations; invoices carry supplier/agent/delivery and a split; the anaesthetist can edit a SUBMITTED List until AUTHORISED; Lists/Slots are two records; Draft Lists; notifications pool; look-back selectors.

## 4. Lifecycle guards (`store/lifecycle.ts`)
