# Prototype map: aa-prototype/src/shared (+ src/theme)

Paths are relative to `aa-prototype/src/` unless stated. Facts are from the code, not from build docs.

## Orientation

`src/shared` has NO routes and NO screens of its own. It holds components the three apps (mobile, web, admin) and the PWA reuse: the Booking detail body with BTM capture, add-booking / edit / cancel / move-list / submit sheets, availability editor, warnings UI, audit-trail reading layer, status resolution, formatting, the "surface" seam (bottom sheet vs dialog), UI primitives, and the demo-trigger registry. Rule: shared components never own domain state; they read store hooks and call audited store actions (`useAppStore`, then `editProcedure(useAppStore, actor, ...)` etc.), and show the store's refusal message verbatim. The caller passes an `Actor` (`role` anaesthetist/office; `source` integration). Routes that mount these live in `apps/*` and `router.tsx` (see "Consumers"). Fee maths is NOT here: `capture/feeContext.ts` only gathers inputs for `domain/billing/fee.ts`. `src/theme` is tokens only.

## 1. Surface seam: `shared/surface/`
- `context.ts`: `useSurface()` returns `{variant:'mobile'|'web', Overlay, BookingLayout, BookingTotal, Pair}`. Throws outside `SurfaceProvider`.
- `SurfaceProvider.tsx:296`: `variant` mobile gives `BottomSheet` overlay + `MobileBookingLayout` (one scroll column, folding masthead, pinned dock; BookingTotal renders nothing); web gives `Dialog` + `WebBookingLayout` (12-col grid: banners span 12, capture span 8, sticky commit rail span 4 with ink BookingTotal panel and a separate Complete bar) + `WebPair` (two equal cols). The admin app uses the web variant.
- `BottomSheet.tsx`, `Dialog.tsx`: plain modal containers (motion from `theme/motion.ts`).
- Only the desktop surface shows the money panel, and only for non-anaesthetist actors (see 2).

## 2. Booking detail body: `shared/booking/BookingDetailBody.tsx` (774 lines)
One body behind mobile `BookingDetailScreen`, web `BookingDetailView`, admin `AdminBookingDetail`. Props `{bookingId, actor, onBack, header?}`.
- Reads: booking, list, procedures (sorted by id), billingLines, masters, audit, `prepaymentStatusFor`, `useBookingWarnings`.
- Edit rights (BookingDetailBody.tsx:313, mirrors `store/lifecycle.ts:50 editRefusal`): `canEdit = !cancelled && list.state !== 'AUTHORISED' && (list.state==='ACTIVE' || actor.role==='office')`. Anaesthetist: own ACTIVE list only; office: ACTIVE and SUBMITTED, never AUTHORISED. `canCapture = canEdit && !booking.completed`.
- Live validation: `validateBookingForBilling` (domain/billing) run against built `BookingBillingContext` (:~200); skipped when list DRAFT/no anaesthetist/cancelled. Failures show only after a refused "Mark complete" (the "showValidation latch"), then live-clear; first failure is focused/scrolled via `data-validation-fields` attributes.
- Fee: `showBookingTotal = actor.role !== 'anaesthetist'` (:133). Anaesthetist Booking shows NO calculation (no units, no $). Office sees `bookingFee` totals plus breakdown lines (per procedure if >1, per fee line if 1 procedure with >1 lines), rate label ("FEE @ $x/UNIT" or "FIXED CONTRACT PRICE", only when all procedures agree), override note ("Override applied · was $x"). Draft-list Bookings show no total (no anaesthetist to price).
- Sections (data-shot names): banners (warnings first, cancelled, post-op addendum note, prepayment paid, errors); Patient (NHI badge, DOB + age, contact; Edit opens EditPatientSheet); Scheduled time (stepper +/-5 min via `editBooking`, `shiftTime` :~70); Source line (`BOOKING_SOURCE_LABELS`, shown when `booking.source` set); Attachments (add/remove); "Notes for the office" (commit on blur via `editBooking`); Procedures (one `BtmCaptureBlock` each, "Add another procedure" via `addProcedure`); Office billing setup (office actor only); Cancel booking; Post-op addendum; History.
- Actions: `completeBooking` (success overlay, 1050 ms timer, then `onBack`), `uncompleteBooking` ("Amend", only while `canEdit`), `cancelBooking` (via CancelBookingSheet), `raisePreProcedureInvoice` (office button on the prepayment warning row, when `prepaymentStatus==='required' && canEdit`), `addPostOpAddendum` (button shown when `list.state==='AUTHORISED'` and booking not already an addendum; creates a linked Booking on "today's free session"; message string at :~640), `removeAttachment`.
- History: `HistorySheet` entity ids = booking + procedures + billing lines + ids of removed procedures/lines recovered from `procedure.remove` audit snapshots; labels "Procedure n · description" when >1 procedure.

`booking/OfficeBillingSetup.tsx` (office only): summary rows Route, Insurer, Category, Payer, Contract, Reference (shows "Missing" via `billingReferenceMissing`), Override, Funders ("n of m lines reallocated"); buttons open EditBillingSetupSheet, PriceOverrideSheet, FunderAllocationSheet (only if `canEdit`).
`booking/HistorySheet.tsx` + `HistoryTimeline.tsx`: overlay; merged append-only audit of given entity ids, newest first (`sortAuditNewestFirst`), day headings, per-field ledger "old to new", coalesced groups. Read-only, no semantic colours.

## 3. Capture cards: `shared/capture/` (one procedure's BTM capture)
Composition in `BtmCaptureBlock.tsx`: header (PROCEDURE n only if >1; description or "Operation to capture"; Edit; Remove on ordinal>1 only when `canCapture`) -> read-only context line (route chip + contract/insurer/billable party/billing reference; label map `ROUTE_LABEL` "Hospital / contract holder", "Billable party", "Insurer (direct claim)") -> "Additional procedure" note when `isAdditional` ("bills for time units only; base and modifier units stay on the first procedure") -> ASA + ProcedureCode (Pair) -> Times -> Units -> Override + BillingLines (Pair) -> Notes -> leftover failures. Every edit is write-through `editProcedure(useAppStore, actor, procedure.id, patch)`; free text commits on blur/Save.
- `AsaCard.tsx`: ASA I to IV segmented (`AsaClass` AS1..AS4); caption "ASA III seeds +3 modifier units" from `ASA_SEED_UNITS` (domain/billing). Disabled for additional procedures.
- `ProcedureCodeCard.tsx` + `CodePickerSheet.tsx`: RVG code picker (search code/description, grouped by `anatomicalSite`, shows `B n` or `B min to max`). Picking a code clears `baseUnitsSelected` and `baseUnitsCaptured`. Range-base codes show a stepper clamped to min..max (`baseUnitsSelected`). Caption "Includes positioning; P1 is not added separately" when the code absorbs P1.
- `TimesCard.tsx`: "Start now"/"Finish now" stamp the demo clock (`clockISO`), -5/+5 nudges; enforces >=5 min between start and finish (nudges clamp; Finish now falls back to start+5 min if clock earlier). Fields `anaestheticStartISO`, `handoverISO`. `timeIso.ts` = string maths (no UTC conversion; NZ DST on 27 Sep 2026 noted).
- `UnitsCard.tsx`: B / T / M stepper rows read RESOLVED values from calculator `BtmBreakdown`; a step writes `{units: resolved±1, source:'overridden'}` (floor 0) to `baseUnitsCaptured|timeUnitsCaptured|modifierUnitsCaptured`; "Adjusted manually · Use seeded value" resets (no auto-clear on equality). T caption states "part intervals round up (assumption)". B and M steppers hidden on additional procedures. M caption lists contributing codes (ASA seed + modifiers, skipping codes the calculator refused).
- `ModifierChips.tsx`: bands PA (PA1..PA4), A (A1,A2), OB (OB1..OB4) are exclusive segmented controls (derived from domain `modifierBandOf`); free-stacking chips PA5, ASE, P1, AI1, PO1, PO2; toggles via `toggleModifierCode` into `selectedModifierCodes`. Codes absorbed by the base code are struck through with the domain's refusal reason. Caption: "Modifier values are demo-plausible ... not an authoritative NZSA schedule" (labels in `modifierLabels.ts`).
- `OverrideCard.tsx`: mobile/anaesthetist override: None / Adjustment $ / Charge $ (writes typed `priceOverride` `dollarAdjustment` | `fixedFee`) with MANDATORY reason; amount rules: charge >0, adjustment !=0. A `percentAdjustment` (office-set) shows read-only. Read-only when `!canCapture`.
- `BillingLinesCard.tsx` + `AddBillingLineSheet.tsx`: non-RVG lines (`removeBillingLine`, `addBillingLine`). Fixed ancillary amount, or rate x time (hours x $/h, `roundToCents`) enabled only if governing contract `permitsIndividualArrangement` (else disabled with `INDIVIDUAL_ARRANGEMENT_MESSAGE`; the Method 3 gate). Funder-override lines show "Billed to <counterparty>" and hide Remove from anaesthetists. ACC flat-fee codes CS250/CS260/CS70 mentioned only in a caption (no ACC code master here).
- `NotesCard.tsx`: Int notes / Op notes (`intNotes`, `opNotes`).
- `CompleteBar.tsx`: "Mark complete" teal bar, or "Booking complete" with Amend link. `CompletionOverlay.tsx`: tick overlay with "N units · $X" only when `showCalculation` (office). `BookingTotalPanel.tsx`: desktop ink panel, ticking values (`useTickingValue.ts`, 320 ms rAF tween).
- `feeContext.ts`: `procedureFee` (governing contract = procedure's STORED `governingContractId`, never auto-suggest; ordinal feeds Type 3 second-procedure pricing; surgeon id from list) and `bookingFee` (sum units and total, Booking order). Throws if list has no anaesthetist.
- `ui.tsx`: `CaptureSection` (with `validationTarget`), `StepperButton`, `NudgeButton`, `FailureNotes` (validation failures verbatim), `Caption`.

## 5. Availability: `shared/availability/` (same form on mobile sheet and web rail)
- `AvailabilityEditor.tsx`: tapped day opens `AvailabilitySlotPanel` (AM/PM sessions); range or "Add days off" preset opens `AvailabilityForm`.
- `AvailabilitySlotPanel.tsx`: per session shows status chip (`displayKey`), List hospital, "marked <status>" if closed over a List, note, series line ("repeating"), conflict flag text "This List has a conflict for the office to resolve". Actions: past = "Past sessions cannot be changed"; `anaesthetistCanSet===false` status = "Set by the office. Ask the office to change it."; series instance = Change this one / Delete this one / Delete the series (confirm); one-off = Change / Remove (shown only if not plain default or has note); ACTIVE own List + anaesthetist = "Move this List". `clearAvailability`, `deleteAvailabilitySeries`.
- `AvailabilityForm.tsx`: status chips (anaesthetist: `anaesthetistChoices`; office: `activeStatuses`), Sessions AM/PM/Both, Repeat (none / every week / every 2 weeks / More = every 3 or 4 weeks) with weekday chips and Until (or "No end date"), From/To dates bounded `todayISO`..`horizonEndISO` (`scheduleHorizon`, FT-01.1), optional note. Save: no repeat -> `setAvailabilityRange`; repeat -> `createAvailabilitySeries` (with `adoptSlotIds` after a move-first). Refusal `holdsList` triggers the move prompt per List then re-saves. Result line from `describeAvailabilityOutcome` (pure; "N sessions set to X, ...", "N Lists' conflicts were resolved", never claims office notified).
- `SeriesList.tsx` ("Your series": rule in words, Delete with confirm), `useAvailability.ts` (`useAvailabilityMonth/Day/Bounds`, `useActiveSeries` over `availabilityMonthFor`, `activeSeriesFor`), `monthCells.ts` (Monday-first grid), `dayLabel.ts` (screen-reader day text).

## 6. Warnings: `shared/warnings/` (US-13.7.x)
- Domain: `domain/warnings/` (types.ts; ONE rule registered: `rules/prepaymentUnpaid.ts`, `WarningRuleId = 'prepaymentUnpaid'`). Kind beforeProcedure, strength strong for both statuses `required` ("Prepayment required. No prepayment invoice has been raised yet.") and `outstanding` ("Prepayment invoice unpaid. Check with the patient before surgery starts."); header notes strength escalation by date is a later phase. Warnings never block (no guard reads them); derived, only office clearances stored (`schedule.warningClearances`).
- `useBookingWarnings(bookingId)` / `useListWarnings(listId)` -> `warningsForBooking/List` (store/warnings.ts). `WarningTriangle` (amber mild, red strong, mist when all cleared, count when >1, not interactive). `WarningsPanel`: heading "Warnings n open / All cleared", row text + kind + strength pill, cleared rows show who/when (`clearanceWhen`); office-only `ClearWarningButton` ("Clear" or "Clear (optional)" for mild) -> `clearWarning(useAppStore, actor, bookingId, key)`.
- `tone.ts`: `KIND_LABELS` Before/After procedure, `STRENGTH_LABELS`, colours from semantic tokens.

## 7. Audit reading layer: `shared/audit/`
