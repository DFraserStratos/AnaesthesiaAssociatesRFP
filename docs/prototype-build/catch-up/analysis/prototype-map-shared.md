# Prototype map: aa-prototype/src/shared and src/theme

Orientation. `src/shared` is the code that the three apps (mobile, web, admin) and the installable PWA all import. It owns NO routes: there is no `<Route>`, `navigate()` or path in it. Screens live in `src/apps/*`; this folder supplies the Booking detail body (patient, payer, funder, per-procedure capture with its Billing card and step rail, price card, completion), every Booking and List sheet or dialog ("flows"), availability editing, the List row and progress words, warnings, audit-trail reading, the demo-trigger registry, the table kit, and the UI primitives and overlay seam. It reads and writes only through `useAppStore` and audited store actions (each returns `{ok, message}` or `{ok, value}`); nothing calls `fetch`. `src/theme` is tokens, motion, status palette, haptics and the mobile gradient only. Phone vs desktop differences come through `useSurface()` (`variant: 'mobile' | 'web'`), not branching in bodies. This map reflects the code at HEAD 63a44902 (after catch-up Phases 23, 24, 25 and U6); it replaces an earlier map that pre-dated them. All paths are under `aa-prototype/src/`. Rules live in `src/domain` (not mapped here); this folder renders them.

## 2. Booking detail body: `shared/booking/BookingDetailBody.tsx`

Mounted by thin chrome wrappers (mobile `BookingDetailScreen`, web `BookingDetailView`, admin Booking page; all in `apps/*`). Props `bookingId`, `actor`, `onBack`, `header`. It builds slots (`header/history/banners/context/capture/actions/summary/completeBar/overlay`) for `useSurface().BookingLayout`. Same body, same guards on every app.

Reads: booking, lists, procedures, billingLines, `billing.invoices/invoiceLines/locks`, masters, audit, `prepaymentStatusFor`, `useBookingWarnings`, `useToday`. Store writes: `editBooking` (notes on blur; scheduled time +/-5 min steppers, `shiftTime` line 79: clamps 00:00 to 23:55, starts at 08:00 if unset, lines 410-411), `addProcedure` then `setRailAnswers` to seed the new procedure (line 423), `completeBooking` (429), `uncompleteBooking` (Amend, 503), `raisePreProcedureInvoice` (512), `addPostOpAddendum` (516), plus sheets (cancel, patient, Paid by, funder, remove procedure, `MakePrimarySheet` line 914).

Pricing: one `bookingFee({procedures, list, masters, billingLines, patientId, held, lock})` per Booking (`bookingTotals`), where `held = heldPricesForBooking(...)` (invoiced or prepaid or typed amounts hold a price) and `lock = billing.locks[bookingId]` (an AUTHORISED Booking prices from its snapshot, never masters). Result gives per-procedure `views` (fee, allocation, Contract, RVG group), `units`, `total`, `needsPrice`, `primaryId`, `structural` (`NO_PRIMARY_MESSAGE` notice when no or several primaries). Draft List Bookings are not priced ("The fee shows once an anaesthetist is assigned", ~line 735).

Sections:
- Banners (~line 520-612): `WarningsPanel` first (US-13.7.3; office "Raise pre-procedure invoice" extra on `prepaymentUnpaid` when status `required` and `canEdit`); "moved to you by" notice; cancelled notice (reason; "excluded from the list's completion count and billing"); post-op addendum notice; green "Prepayment received" when `prepaymentStatus === 'paid'`; action error; completion-refusal notice with booking-level failures after the latch; for the anaesthetist, "The office puts the Contract or the price right. If you cannot finish this Booking, use Alert the office" when any failure has `fixableBy === 'office'`.
- Patient: NHI badge ("NHI ABC1234" or "NHI pending"), DOB/age, phone, scheduled time with steppers; Edit opens `EditPatientSheet`. Payer details (`PayerDetailsView`) and funder (`FunderDetailsView`, "No approval number" pill; "None, the patient pays"); source line (`BOOKING_SOURCE_LABELS`); "Notes for the office".
- Capture column: Draft List shows procedure labels only; otherwise one `data-shot="procedure-block"` per procedure in `inDisplayOrder` (primary first) with `BtmCaptureBlock`, plus `OfficeBillingSetup` for the office actor; "Add another procedure" when `canCapture`. Make primary slide-in animation (`motion.selectionSlide`, reduced-motion fade) when the primary changes (lines ~240-262).
- Actions: `AlertOfficeEntry` (anaesthetist) / `OfficeAlertLine` (office); "Move to a colleague" (`canMove`); "Cancel booking" when `canEdit`; "Add post-op event" only when `list.state === 'AUTHORISED'`, not `isBackdropList`, not an addendum.
- History link opens `HistorySheet` with the Booking id, its procedure and billing-line ids, plus ids of removed procedures/lines recovered from `procedure.remove` audit snapshots (so removals stay reachable).
- Summary (money): shown for EVERY actor since Phase 24 (US-03.3.10, RV-29): desktop `BookingTotalPanel`, phone `BookingTotalStrip` dock. Hidden when cancelled, no procedures, or DRAFT. Breakdown: rows per procedure (multi) with `allocationNote`, or per fee line (single procedure, several lines). Rate label from the price ladder: "PRICE TYPED", "INVOICED PRICE", "PREPAID PRICE", "FIXED CONTRACT PRICE" or "FEE @ $x/UNIT", shown only if all procedures agree. Notes: "No base units billed (provisional, OQ-132)" when the primary is fixed/open priced; "Modifiers n, split a · b" when shared. Override note: "Price typed · computed $x", or "Price typed on n of m procedures".
- Complete bar (`CompleteBar`) and completion overlay (1050 ms real `setTimeout`, line 482, tap to dismiss; dismisses before `onBack()`).

Rules here: `canEdit = !cancelled && editRefusal(actor, list) === null` (line 390; store gate: office edits ACTIVE and SUBMITTED not AUTHORISED; anaesthetist edits own Lists until authorised, 38a). `canMove` (394): anaesthetist, `source !== 'integration'`, `bookingMoveRefusal(...) === null`. `canCapture = canEdit && !completed`. Completion failures: `completionFailuresFor(booking, procedures, completionContextFor(...))`, shown only after the first refused Mark complete (latch `showValidation`) then live-clearing; on refusal the first field found via `[data-validation-fields]`/`data-validation-procedure-id` is focused and scrolled.

## 4. Capture cards: `shared/capture/`

`BtmCaptureBlock.tsx` composes one procedure, in this order: `ProcedureStack` (heading, "Primary" pill, Make primary `canMakePrimary`: multi, not primary, editable, anaesthetist only while not completed; Remove `canRemove`: multi, not primary, editable, `canCapture`), `BillingCard`, `ContractApprovalLine` (anaesthetist), contract failure notes, an "Additional procedure" notice (RVG priced: "Base units are charged on the primary procedure only. It earns its own time units, and an equal share of the Booking's modifiers once they total more than 4."; fixed price: "Its Contract's price is the whole price; its units are recorded for reference."), the price-status notice (`needsPriceMessage`), then, only when `rvgDetailFor(contract).times !== 'hidden'`, `TimesCard` + `UnitsCard` (modifiers `required` on RVG kinds). A fixed/open-priced PRIMARY of a multi-procedure Booking still shows a `UnitsCard` (B 0, Modifiers only, `capture-booking-modifiers`). Then `Pair` of `PriceCard` and `BillingLinesCard`, `NotesCard`, and "Also outstanding on this procedure" for unanchored failures. Recorded times/units are kept when hidden. Write strategy: write-through per tap, commit-on-blur for text.

- `feeContext.ts`: `bookingFee` (line ~70) is the ONE UI assembler (kept in step with the store's `feeContextFor`): per-procedure `ProcedureFeeContext` (anaesthetist rates, list date, `masters.rvgTimeRule`, patient DOB for age modifier, modifiers master, non-RVG lines, Contract, RVG group, `held`), through `bookingFeeFor` (domain). Throws if the List's anaesthetist is missing. `lockedFeeTotals`: when `lock.state === 'locked'` and every snapshot has a fee, totals come from the snapshot (`priceBookingFromLock`), otherwise live. A Disabled Contract still prices a Procedure already on it.
- `PriceCard.tsx` (Phase 24, replaces the old OverrideCard; US-03.3.10, 03.5.1, 05.4.1, 05.4.3, RV-29): always shown. Figures in mono: "12 units x $30.00 = $360.00", "Discount n% · minus $x", "Fixed price $x", "Needs a price" pill (`NEEDS_PRICE_LABEL`), "Price $x" with a held label ("Price typed", "Invoiced", "Prepaid") and "Computed $x". States (`data-state`): override | amount | read-only | needs-price | no-charge | locked. Editable only for the anaesthetist when `anaesthetistPriceRightFor(masters, procedure).may` and `priceChangeRefusal(...)` is null: one "Price $" field, "Save price" and "Use the computed price" (clears) via `setProcedurePrice`; a typed 0 is allowed and gives a "no-charge invoice". No reason is asked. Otherwise a read-only caption (the store's refusal sentence or `anaesthetistPriceCaption`).
- `TimesCard.tsx`: Start/Finish stamps, one travelling teal action ("Start now" then "Finish now") on the demo clock (`clockISO(store.clock)`); Finish falls back to start + 5 min; nudges keep >= 5 min apart (`timeIso.ts`). Writes `anaestheticStartISO`, `handoverISO` via `editProcedure`. Missing time shows a red outline, no "Required" caption unless `required`.
- `UnitsCard.tsx`: B/T/M stepper rows from `BtmBreakdown`; a step writes the whole `CapturedUnits` `{units: resolved ± 1, source: 'overridden'}`, floor 0, no auto-clear; "Use seeded value" resets. Additional procedure: B "Base units are on the primary procedure" and M no stepper, caption with its share or "Modifiers are recorded once for the Booking, on the primary procedure."; primary on fixed/open price: B 0 "No base units billed on a fixed price (provisional, OQ-132)". T caption "From start and finish stamps · RVG time tiers", title `describeTimeRule(masters.rvgTimeRule)`. Contains `ModifiersSection`.
- `ModifiersSection.tsx` (US-03.3.4/3.3.8/5.1.4): ledger of pre-applied rows (age modifier, modifiers included in the RVG base, removable, "Put back" `restoreModifier`), claimed rows with explanation, "Add a modifier" (`ModifierPickerSheet`), "None apply" (`confirmNoModifiers`) with "Required" caption on RVG kinds (`modifiersStepAnswered`, `MODIFIERS_STEP_MESSAGE`), `removeModifier`, `claimCompletionProblems`. `ModifierPickerSheet`: RVG + AA modifier table, searchable, explanation required and units stepper when `needsEnteredUnits`; `claimModifier`/`editModifierExplanation`.
- `ProcedureCodeCard.tsx` (`RvgCodeField`, `OUTSIDE_GUIDE_CAPTION`; props `codeRole` required|reference, `emptyHint`): RVG code type-ahead (inline on web, `CodePickerSheet` on phone; `RvgCodeList` groups by anatomy, `searchRvgGroups`); `pickRvgGroup` clears chosen/typed base value; a ranged group's base units via `RangeUnitsRow`, outside the guide accepted with "Outside the guide range. The office will see a warning after the procedure." (warn, never block). Never suggests a code from procedure text.
- `BillingLinesCard.tsx` + `AddBillingLineSheet.tsx`: ONLY "ancillary fixed amount" lines now (description + amount > 0, `addBillingLine` chargeBasis 'fixed'); the Rate x time basis and its Contract gate are gone (Phase 24, RV-03); `removeBillingLine`. Hardcoded caption on the ACC pre-op flat-fee code set CS250, CS260, CS70. Code comment: "until 39b replaces billing lines with billing events".
- `NotesCard.tsx` (Int/Op notes via `editProcedure` on blur). `BookingTotalPanel.tsx` (desktop ink panel, ticking values `useTickingValue` 320 ms, green flash). `BookingTotalStrip.tsx` (phone dock, Phase 24; fee and units, chips P1..P3 for multi-procedure, `MAX_CHIPS = 3`, then count). `CompleteBar.tsx` ("Mark complete" teal CTA; once complete a green "Booking complete" bar with Amend while editable). `CompletionOverlay.tsx`. `capture/ui.tsx`: `CaptureSection`, `NumberStepper`, `NudgeButton`, `FailureNotes` (failures verbatim), `Caption`, `RequiredCaption`.
