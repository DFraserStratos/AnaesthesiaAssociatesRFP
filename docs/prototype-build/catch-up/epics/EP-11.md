# EP-11 · Patients and billable parties · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-11) · catalogue `501b0b8` · [EP-11](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-11.md)

> Keystone gaps. (1) No admin patient record/search screen (master data has no patients; EditPatientSheet only via a Card and cannot touch NHI or ethnicity). One new Patient screen with add-NHI, edit and per-patient invoices serves US-11.1.1, 11.1.4, 11.1.5 and 11.3.1. (2) No admin dashboard or to-do list (US-13.7.2), needed by US-11.1.5 (problem list) and US-11.2.4 (child-payer warning). The Integration monitor data-quality tab (ethnicity quarantine) is a ready pattern. (3) Billable party is welded to the old billing route in code (counterpartyForProcedure, EditBillingSetupSheet, ManualCardForm default route 'hospital', validator requires a route), while the catalogue says the Contract replaces the route step, payer is independent of pricing, defaults to the patient, and a Booking carries an invoice email. Re-grading FT-11.2 and US-11.2.2 to Contradicts; do both with US-11.2.3 (invoice email) and EP-04 Contract work, not piecemeal. The guardian as separate BillableParty record also clashes with US-11.2.4 ('no separate guardian record') pending OQ-67. (4) NHI-pending work needs an add-NHI action, an authoriseList guard (store/lifecycle.ts:277), a review/problem flag, and a seeded NHI-arrival path via the existing HL7/PDF simulator (Noah Prescott is the seed hook); NHI optional today and re-entry without NHI always duplicates (OQ-49). (5) Balance alert: only a boolean tag, post-authorisation, any payer; needs booking-time alert, age-based mild/strong from invoice raisedAtISO, admin threshold setting, and payer filter; demo clock advance already exists. Seed Grace Park has a guardian payer so a child-as-payer example must be added. (6) Insurer master is toggle-only; add/edit/retire is an S item. Demo guide beats to revisit: Prior balance tag in Billing monitor, guardian/two-funder asides (~line 242), intake dedupe (~114) and HL7 reprocess (~334) stay valid.

## US-11.2.2 · Guardian or other override · Contradicts

[US-11.2.2](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-11.2.2.md) · [board](http://localhost:5180/#/board?item=US-11.2.2) · status Open · surfaces: domain, store, admin, mobile, web, seed, demo-guide · confidence medium

- **Requirement:** Admins and anaesthetists can set a different billable party and invoice email on a Booking (e.g. guardian), independent of how the Procedure is priced; AC: on the default RVG Contract, setting a hospital as billable party leaves price unchanged and the invoice goes to the hospital. Open (OQ-67: per-Booking override vs Contract-defined).
- **Prototype today:** Office EditBillingSetupSheet: Payer select (patient default, existing BillableParty rows, 'New guardian' name/relationship/phone) shown only when route=billableParty. Anaesthetist ManualCardForm payer select (existing parties only), same route condition. Hospital 'payer' = route 'hospital' which prices by the hospital contract (default Type 1) and bills the holder. FunderAllocationSheet can split lines by amount between funders incl. billable parties.
- **Missing or wrong:**
  - WRONG: billable party is not independent of pricing: payer can only be chosen on the billableParty route; guardian under a hospital/insurer Contract, or hospital payer on any pricing basis, is not a separate choice
  - WRONG vs catalogue: guardian is a separate BillableParty record (name/relationship/phone) whereas US-11.2.4 says there is no separate guardian record and OQ-67 asks whether guardian details sit on the Contract
  - Missing: no invoice email field or override; new-guardian form has no email field though BillableParty.email exists
  - Anaesthetist cannot create a new guardian or edit payer after creation (EditBillingSetupSheet/OfficeBillingSetup are office only)
  - AC only reachable indirectly: hospital route with default Type 1 gives the same price and invoice to hospital, but via route not a payer choice on the default RVG Contract
  - 'Per Procedure not per Booking' dropped as a defect: catalogue allows different payers per Procedure (OQ-55)
- **Evidence:** `aa-prototype/src/shared/flows/EditBillingSetupSheet.tsx:90-111 (payer saved only inside route branch), :143-176 (payer UI inside route==='billableParty')`, `aa-prototype/src/shared/flows/ManualCardForm.tsx:232-250`, `aa-prototype/src/shared/card/OfficeBillingSetup.tsx:36-44`, `aa-prototype/src/domain/billing/invoiceBuild.ts:125-212`, `aa-prototype/src/store/billablePartyActions.ts:21-57`, `aa-prototype/src/domain/types.ts:123-132 (BillableParty)`, `docs domain-model.md:14,40 (route replaced by Contract; payer independent of pricing)`
- **Verifier:** corrected from Partial. Re-read the story and domain-model: independence from pricing is an explicit rule and the code couples payer to billingRoute, so behaviour is wrong rather than merely incomplete. Kept the guardian-record point as a medium-confidence conflict (story itself still lets a guardian be set; OQ-67 open). Raised size to L: touches counterparty resolution, validator, three forms and seed; shares work with FT-11.2.

## FT-11.2 · Billable party and invoice contact · Contradicts

- **Requirement:** Each Booking records who pays and where the invoice is sent, defaulting to the patient. Contract may define the billable party (OQ-55); per-Booking override fate is OQ-67 (recommendation: keep override).
- **Prototype today:** Procedure.billingRoute (hospital/billableParty/insurer) decides the counterparty; Procedure.billablePartyId is an optional guardian override honoured only on the billableParty route (counterpartyForProcedure).   - Missing: no Contract-defined billable party (OQ-55 answer); Contract holderType 'billableParty' exists but payer is not derived from the Contract
  - Per-Procedure rather than per-Booking is NOT itself wrong: OQ-55 lets one Booking carry Procedures with different payers, so reviewer's 'payer is per Procedure' point dropped

- **Verifier:** corrected from Partial. Re-read catalogue + domain-model: the route step is explicitly replaced by the Contract and payer is independent of pricing; code still keys payer off billingRoute and defaults the form to hospital, so implemented behaviour is wrong, not just incomplete. Dropped 'per Procedure' as a defect. Shared work with US-11.2.2 (L there); invoice-email field itself is US-11.2.3 (outside this batch) but the FT body names it.
