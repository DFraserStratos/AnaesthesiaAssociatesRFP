# EP-10 · Payments, disbursement and AA fees · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-10) · catalogue `60e2d1e` · [EP-10](../../../../requirements-board/requirements/stories/EP-10.md)

> EP-10 payables work (US-10.2.1 correction, 10.2.6, 10.2.7) shares one design: remove the fee netting so the ACCPAY equals the receivable value (also DM-26 / US-10.3.1, OQ-60 open), then add a PaymentCycle/run entity (ISO week, status open/closed/scheduled/paid, held items) with an approval flag on payables. Key correction to the reviewer: the 5% AA service fee netted into the ACCPAY (agencyFee.ts, xeroHandoff.ts:234,270, seeds, Web Payments table, Xero sim, demo guide S4) contradicts EP-10/US-10.2.1 'exactly the amount received' and the 'BCTI same value as receivable' ruling; do the un-netting together with the US-10.3.x fee-invoice phase to avoid touching the same seed/UI twice. US-10.2.6 (Verify) and US-10.2.7 (Proposed) hinge on unresolved OQ-47, so build the cycle minimally and keep it replaceable. Cycle needs a stored shape change (PERSIST_VERSION bump, seed week stamps), and the demo clock is fixed at Tuesday 21 July 2026 so Friday/Monday/Tuesday beats need cycle-advance buttons placed on the Billing monitor only; demoTriggers.test.ts:54 forbids a 'payables' trigger label. Demo guide S4 (03-demo-script.md ~282-361) beats on payment received then Run payables need rewording for fee removal and the extra schedule step.
