# EP-10 · Payments, disbursement and AA fees · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-10) · catalogue `501b0b8` · [EP-10](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-10.md)

> Central defect: AA fee modelled as an illustrative 5% deduction per payable (agencyFee.ts, XeroAccPay.serviceFeeRate/serviceFeeAmount/grossAmount/amountPayable, case.authorisedAmount = net). Catalogue: payable value == receivable value, part payment releases exactly the amount received, and AA's fee is a separate monthly invoice. Removing the deduction touches domain/types.ts, agencyFee.ts, xeroHandoff.ts, paymentActions.ts (pro-rata), payablesActions.ts (full-payout check), selectors.ts paymentHistoryFor (fee/net columns), seed billing.ts + history.ts, DemoXero ACCPAY card, Web AccountsScreen Payments tab, tests (AccountsScreen, DemoXero, payablesActions, paymentActions, seedBilling); needs PERSIST_VERSION bump (currently 13). Do once; it closes the contradiction in EP-10, US-10.2.1, and removes the wrong model behind FT-10.3 and US-10.3.1. Then build one cluster: fee settings (US-10.3.3), monthly fee invoice entity + run + anaesthetist-visible/payable invoice (US-10.3.1, FT-10.3). Second cluster: payables run reworked per anaesthetist and period with an approve-for-payment step (US-10.2.6), net negatives and remittance advice (US-10.2.5, depends on US-08.6.2 credit flow). Payment day/weekly cycle (OQ-47) is open; do not build a cycle until confirmed. Demo-guide lines about the illustrative 5% fee and 'Net to you' (docs/demo-guide/03-demo-script.md ~252-272) must be rewritten; payment webhook and Run payables controls already exist (DemoControlPanel PaymentReceivedCard, AutomatedJobsCard); new controls needed for monthly fee run, refund/negative invoice, approve-for-payment. Verifier check: no implementation of monthly/fee-invoice/remittance/netting/approve-for-payment found in any non-test source; reviewer evidence line numbers largely right (paymentActions authorise block is at ~131-141 not 154-165).

## EP-10 · Payments, disbursement and AA fees · Contradicts

[EP-10](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-10.md) · [board](http://localhost:5180/#/board?item=EP-10) · status Confirmed · surfaces: domain, store, seed, simulator, web, demo-guide · confidence high

- **Requirement:** All payments land in AA first; two tracked states per ledger pair (paid in, disbursed); full payment releases full payable, part payment exactly the amount received; AA's fee is a separate invoice from AA to the anaesthetist, distinct from any receivable/payable.
- **Prototype today:** BillingCase tracks receivedAmount / authorisedAmount / disbursedAmount; receivePayment authorises the ACCPAY pro-rata; payables run disburses the increment. But ACCPAY = gross less an illustrative 5% 'AA service fee' (handoff computes aaServiceFeeFor(invoice.total)), so payable != receivable and part payment releases 95% of the amount received. No separate fee invoice.
- **Missing or wrong:**
  - AA fee modelled as 5% deducted from every payable (AA_SERVICE_FEE_RATE) instead of a separate fee invoice (wrong, superseded)
  - Payable value is 95% of receivable; catalogue says part payment releases exactly the amount received
  - Fee shown as a deduction in Xero simulator ACCPAY card ('Illustrative AA service fee' block) and in Web Payments history (Customer paid / AA fee / Net to you columns)
  - No AA fee invoice entity in the ledger
- **Evidence:** `aa-prototype/src/domain/billing/agencyFee.ts:7 (AA_SERVICE_FEE_RATE=0.05), :16 aaServiceFeeFor`, `aa-prototype/src/store/xeroHandoff.ts:234 (payable = aaServiceFeeFor(invoice.total)), :245 (spread into XeroAccPay)`, `aa-prototype/src/store/paymentActions.ts:53-58, :88-101 (authorised = ratio x amountPayable)`, `aa-prototype/src/store/payablesActions.ts:96-100 (fully paid out vs amountPayable)`, `aa-prototype/src/domain/types.ts:697-719, :780-797`, `aa-prototype/src/apps/demo/DemoXero.tsx:481-507`, `aa-prototype/src/apps/web/screens/AccountsScreen.tsx:192`, `aa-prototype/src/store/selectors.ts:763-830`

## US-10.2.1 · Payable released to match the amount received · Contradicts

[US-10.2.1](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-10.2.1.md) · [board](http://localhost:5180/#/board?item=US-10.2.1) · status Confirmed · surfaces: domain, store, seed, simulator, web, demo-guide · confidence high

- **Requirement:** Paid receivable authorises the matching payable into the next run; full payment releases the whole payable; part payment releases a payable for exactly the amount received, remainder stays outstanding on the receivable. Payment day/cycle (OQ-47) unsettled.
- **Prototype today:** receivePayment authorises cumulative pro-rata of ACCPAY.amountPayable (net of 5% fee), idempotent via payment key (webhook and poll); ACCREC received/balance update; payables run disburses only the increment. Simulator shows unpaid, paid and half-payment states; Admin shows payables waiting.
- **Missing or wrong:**
  - Authorised amount = received x 0.95 (fee deducted), not exactly the amount received; full payment releases 95% of the receivable, not the whole payable value
  - Web Payments history shows Customer paid / AA fee / Net to you, presenting the deduction as the norm
  - Payment day/cycle (OQ-47: Tue/Wed run or weekly) not represented; run is on-demand only (open question, low weight)
- **Demo trigger:** Existing: control panel 'Payment received (webhook)' (Full / Half) and 'Run payables'.
- **Evidence:** `aa-prototype/src/store/paymentActions.ts:53-58 proRataAuthorised, :88-101, :131-141`, `aa-prototype/src/store/payablesActions.ts:36-47, :96-100, :135-143`, `aa-prototype/src/apps/admin/screens/BillingMonitorScreen.tsx:121-143`, `aa-prototype/src/apps/demo/DemoControlPanel.tsx:538-620 (Full / Half payment)`, `aa-prototype/src/apps/demo/DemoXero.tsx:449-450, :481-507`, `aa-prototype/src/store/xeroHandoff.ts:234`
- **Verifier:** corrected from Contradicts. Verdict upheld (Confirmed-status; fee deduction contradicts 'exactly the amount received'). Corrected size S -> M: the fix is removing the fee deduction across types, handoff, pro-rata, seed, selectors, simulator and Web Payments tab, which is the same shared work as EP-10 (do once). Added the Web Payments columns point.
