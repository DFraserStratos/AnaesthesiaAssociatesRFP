# EP-10 · Payments, disbursement and AA fees · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-10) · catalogue `3d3a18c` · [EP-10](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-10.md)

> All five reviewer verdicts upheld after re-reading the catalogue files and code. The 5% service-fee model is baked across domain (agencyFee.ts, XeroAccPay.serviceFeeRate/Amount/amountPayable), store (xeroHandoff.ts:234, paymentActions pro-rata over net payable, selectors.paymentHistoryFor), seed (billing.ts:204, history.ts:265), Web Payments table ('AA fee', 'Net to you'), Xero sim pair view and Admin invoice. Removing it makes ACCPAY = ACCREC value (BCTI same value as receivable, US-09.1.4/OQ-42), which fixes US-10.2.1 as a side effect; do FT-10.3 fee removal, US-10.2.1 and US-10.3.1/10.3.3 together, and bump PERSIST_VERSION (seed shape change). appSettings (added 15a for warning rules) is a ready home for fee settings (fixed items + per-invoice rate); no fee settings exist yet. US-10.2.5 depends on a credit-after-invoicing/negative-invoice item in EP-08 (US-08.6.2, OQ-71/72) and on BCTI wording; US-10.2.6 and OQ-47 weekly cycle would reshape the single Run payables button into a weekly run with remittance advice (shared with 10.2.5). Fee invoice needs BCTI count per anaesthetist per month, paid-only (OQ-60 Greg view), and a separate fee receivable concept in the Xero sim (separate bank account). OQ-60 and OQ-47 are open, so placeholder amounts and cycle must be labelled assumptions. Demo-guide impact (03-demo-script.md): S3 Beats 2 and 3 (5% fee numbers $152.38/$7.62/$144.76), partial-payment beat and S4 half payment step must be rewritten; add beats for the monthly fee-invoice run and a refund netted in a payment run with remittance advice. Existing demo controls (payment full/half/replay, Run payables, Simulate payment and payout) are retained.

  - No AA fee invoice entity in the ledger
