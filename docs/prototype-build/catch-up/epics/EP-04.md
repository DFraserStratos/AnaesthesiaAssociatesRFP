# EP-04 · Contracts · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-04) · catalogue `60e2d1e` · [EP-04](../../../../requirements-board/requirements/stories/EP-04.md)

> EP-04 is a structural rewrite of the billing model, not an extension. Catalogue: one Contract per Procedure, holder decides who is billed (pays AA, else Booking payer), a single holderless 'No contract (RVG)', no hospital/insurer/procedure defaults. Prototype: Procedure.billingRoute (hospital/billableParty/insurer) + optional governingContractId, Type 1/2/3 contracts, protected default Type 1 per hospital/insurer, fallback in invoiceBuild.resolveContractForProcedure / contracts.selectContract, counterparty by route. Verification changes: FT-04.2 upgraded Partial to Contradicts ('Any code' Type 3 row prices a whole contract; contract-wide Type 2 rate); added price>0 refusal as wrong for US-04.2.4 and dropped a weak BTM-fallback point from US-04.2.2; US-04.1.1, 04.2.1, 04.2.2, 04.2.4, 04.2.10, 04.3.3 and EP-04 Contradicts all upheld; the Missing items (US-04.1.4 AA code, US-04.2.11 combinations) re-grepped with no hits. No Matches in this epic. Missing entities: Contract Holder (pays-AA flag, billable party, first-party anaesthetist), per-procedure contract lines (rate/discount/units/holder code), dated linked versions + review date, aaCode and composite search, invoice layout/delivery/GST fields on Contract, contract-named booking references, snapshot at AUTHORISED, insurance indication (OQ-93), procedure master and two-tab picker (EP-05 dependency, so XL sizes are lower bounds; bundle with EP-05). Cross-epic dependencies: EP-05 (procedure master, RVG groups, general procedure, anaesthetist adjustment only on first-party/No contract), EP-03 (picker on booking, mark-complete gate), EP-11 (Booking payer, direct insurer), EP-06 (prepaid from first-party contract), EP-07/08 (review warnings, invoice reproduction, additional invoices). Demo impacts: S5 Beat 4 (edit Health NZ end date) becomes new-version + snapshot view; the 'billing-failure' trigger (registry.ts:197, end-dates COS ACC contract then Resolve & retry clears the end date) relies on contractIneffective/no-default semantics and needs a new failure scenario (e.g. Booking with no Contract); demo-guide cheat sheet 'Contracts' (Type 1/2/3, protected default) and route chips ('Hospital / contract holder') must be rewritten; all 12 seeded contracts and procedures' billingRoute/governingContractId remodelled; PERSIST_VERSION bump. Existing demo controls usable: clock advance (new version taking effect), fire-hospital-message (feed Booking arriving without a Contract), S5 scenario jump. Open questions OQ-89, 93, 98, 99, 103 should be decided or built provisionally.

## EP-04 · Contracts · Contradicts

[EP-04](../../../../requirements-board/requirements/stories/EP-04.md) · [board](http://localhost:5180/#/board?item=EP-04) · status Confirmed · surfaces: admin, mobile, web, domain, store, seed, demo-guide · confidence high

- **Requirement:** Every Procedure selects exactly one Contract (No contract (RVG) offered first); the Contract's holder decides who is billed (holder if it pays AA, else the payer on the Booking); replaces route resolution plus governing-contract lookup. As many Contracts as needed.
- **Prototype today:** Procedure has billingRoute (hospital/billableParty/insurer) set separately and an OPTIONAL governingContractId. Billing run resolves route then contract; missing/expired contract falls back to a per-hospital/insurer protected default Type 1. Contracts typed 1/2/3. Counterparty derived from route, not from the contract's holder.
- **Missing or wrong:**
  - WRONG: separate billing route is the primary decision; Contract is secondary and optional
  - WRONG: per-hospital/insurer protected default Type 1 contracts and expired-contract fallback to them (catalogue: no hospital/insurer/procedure defaults)
  - WRONG: who is billed derived from route, not from the Contract's holder (pays AA vs payer on Booking)
  - MISSING: single stored 'No contract (RVG)' offered first for every procedure
  - MISSING: contract picker filtered by procedure, holder fit, date
  - MISSING: contract lines per procedure, AA code, holder records, dated versions, snapshot at AUTHORISED
- **Evidence:** `aa-prototype/src/domain/types.ts:216-248 (Contract type 1\|2\|3, isDefault)`, `aa-prototype/src/domain/types.ts:462-463 (billingRoute, optional governingContractId)`, `aa-prototype/src/domain/billing/invoiceBuild.ts:114-180 (resolveContractForProcedure: fallback by route/default)`, `aa-prototype/src/domain/billing/invoiceBuild.ts:187-215 (counterpartyForProcedure by route)`, `aa-prototype/src/shared/flows/EditBillingSetupSheet.tsx:175-186 (unfiltered select, 'None (default pricing)')`, `aa-prototype/src/domain/seed/contracts.ts:31-70 (default Type 1 per hospital)`

## FT-04.2 · Contract definition · Contradicts

[FT-04.2](../../../../requirements-board/requirements/stories/FT-04.2.md) · [board](http://localhost:5180/#/board?item=FT-04.2) · status Verify · surfaces: domain, store, admin, seed · confidence medium

- **Requirement:** A Contract is a dated set of terms for one holder; each line sets terms for one procedure (fixed price, contract unit rate, discount, base/modifier units); everything else shows through; no Contract sets one price for a whole RVG group. Status Verify.
- **Prototype today:** Contract has holderType/holderId, effective from/to, type 1/2/3. Type 2 carries one contract-wide agreed unit rate or percent discount; Type 3 has ContractPrice rows keyed by optional RVG base code (blank = any code), surgeon, ordinal, price only.
- **Missing or wrong:**
  - WRONG: 'Any code' price row (rvgBaseCode optional) sets one price for every procedure under the contract
  - Rate and discount are contract-wide, not per line
  - No base/modifier unit overrides on a line
  - Lines keyed by RVG base code, no procedure master
  - No blank-inherits / 0-is-a-value semantics (price must be > 0)
  - No holder/contract/line/booking-procedure structure per the ERD
- **Evidence:** `aa-prototype/src/domain/types.ts:216-262 (Contract, ContractPrice; rvgBaseCode optional)`, `aa-prototype/src/domain/billing/fee.ts:178-235 (type-based pricing; fixed-price match)`, `aa-prototype/src/apps/admin/flows/ContractEditSheet.tsx:155-187,276 ('Any code')`, `aa-prototype/src/store/contractActions.ts:205 (price must be > 0)`
- **Verifier:** corrected from Partial. Feature body states a rule ('no Contract sets one price for a whole RVG group'); the prototype's optional rvgBaseCode lets a Type 3 row price all codes, and contract-wide Type 2 rate is the pre-lines model. Implemented behaviour differs, so Contradicts rather than Partial. Medium confidence (status Verify).
