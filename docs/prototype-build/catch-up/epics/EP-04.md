# EP-04 · Contracts · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-04) · catalogue `d436947` · [EP-04](../../../../requirements-board/requirements/stories/EP-04.md)

> All eight verdicts upheld; one item (US-04.2.14) corrected in content. EP-04 rests on a different Contract model from the prototype's. Prototype: Contract.type 1/2/3 with header-level pricing; one holderType/holderId pointing at five separate masters (hospital, insurer, surgeon, organisation, billableParty); protected per-hospital/insurer default Type 1 contracts derived from the List hospital; an Insurer master with acceptsDirectClaims; Type 3 price rows auto-matched by RVG base code, surgeon and procedure ordinal; a Procedure-level billing route (hospital/billableParty/insurer) that decides who is billed; Contract edits applied immediately. Catalogue: contract holder records (is-billed, billable party, practitioner IDs, delivery output); the Contract decides who is billed (holder, or the Booking payer for price-only holders and No contract (RVG)); one AA-held No contract (RVG), no hospital/insurer defaults, nothing derived from the List location; stand-alone Contract lines (description, reference code, default RVG code, terms, line key); a filtered, ordered picker for office and anaesthetist; stage-and-submit dated versions. These interlock and should be built together, with invoiceBuild resolveContractForProcedure/counterpartyForProcedure and validateBookingForBilling as the load-bearing rewrite; seed bookings (36 governingContractId refs, mostly *Default) must be re-pointed and PERSIST_VERSION bumped. Additional gap found: the anaesthetist's OverrideCard (BtmCaptureBlock) can override any Procedure's price, including those priced from a Type 3 fixed-price contract, which contradicts OQ-117 and US-04.2.14; fix belongs with the fixed-price/line work and touches mobile and web. Dependencies: US-11.2.2 (payer on the Booking), US-11.4.3 (insurer/approval number on the Booking), US-03.4.1 (anaesthetist changes Contract; no anaesthetist picker exists), US-04.1.4 (AA code), US-04.2.10/04.2.13 (versions, upload) for US-04.1.6, FT-06.2 prepayment (prepaid flag), US-05.2.x pricing, US-08.4.6 (invoice description from a line). Demo script impact (docs/demo-guide/03-demo-script.md): S3 invoices the hospital default and Health NZ contract; S4 relies on the COS organisation-held contract having no default fallback, dated out by 'Trigger billing failure' and 'Resolve & retry', which changes entirely once there is no holder-derived fallback; S5 Beat 4 (contract effective-dating on Health NZ agreed rate) changes if edits become staged versions, and the Whitaker Health NZ snapshot depends on contract-holder billing. No new demo-trigger buttons are needed (all items are UI-driven), but seed content is needed: an anaesthetist price list (Dr Smith, Face lift $3,200, prepay flag), a multi-surgeon arrangement, and a holder record per party. contract-picker-mock/ (port 5181) is a design input for the picker, not part of the prototype.

- **Requirement:** An anaesthetist's own price list is an office-maintained Contract with a fixed price per procedure line, offered only on that anaesthetist's Bookings, holder not billed (Booking payer invoiced), fixed prices never allow the anaesthetist's price override, optionally flagged prepaid (starts the prepayment; lines need a price above zero). Anaesthetists cannot create or edit Contracts.
- **Prototype today:** ContractScope individualAnaesthetist can be set in the office-only ContractEditSheet; createContract/editContract refuse non-office; Type 3 price rows need price > 0 (all rows). No individual-scope contract is seeded (all ORGANISATION_SCOPE). Mobile/web have no Contract editing (matches). The anaesthetist's OverrideCard (fixed-fee charge or $ adjustment) is available on every Procedure regardless of contract, and fee.ts applies it to Type 3 totals. Prepayment is a Procedure payment category with no link to a Contract.
- **Missing or wrong:**
  - WRONG: billing goes to the contract holder, not the Booking payer
  - WRONG: the anaesthetist can override the price on a Procedure priced from a fixed-price contract (BtmCaptureBlock OverrideCard, fee.ts:254-266); catalogue forbids it (OQ-117)
  - Picker does not limit a Contract to its own anaesthetist's Bookings (EditBillingSetupSheet lists all contracts)
  - No prepaid flag on a Contract; choosing a prepay list does not start the prepayment; no 'prepay line must have price above zero' rule distinct from the blanket >0 rule
  - No seeded 'Dr B. Smith, Face lift $3,200' example
  - Price lists keyed by RVG base code, not free procedure lines with description
  - Holder of an own list is not a distinct 'not billed' holder
- **Evidence:** `aa-prototype/src/domain/types.ts:376-385`, `aa-prototype/src/apps/admin/flows/ContractEditSheet.tsx:165-181`, `aa-prototype/src/store/contractActions.ts:54,107,204,240`, `aa-prototype/src/shared/capture/BtmCaptureBlock.tsx:249-255`, `aa-prototype/src/domain/billing/fee.ts:254-266`, `aa-prototype/src/shared/flows/EditBillingSetupSheet.tsx:173-182`, `aa-prototype/src/domain/seed/contracts.ts (all ORGANISATION_SCOPE)`, `searched: prepaid\|prepayList\|isPrepay on Contract in src -> none`
- **Verifier:** corrected from Contradicts. Verdict upheld, but the reviewer listed 'fixed-price lines do not carry the no-override rule' as missing. Code shows it is actively wrong: OverrideCard is rendered for the anaesthetist on every Procedure and fee.ts applies it to Type 3 totals. Reworded and raised confidence to high. Size M assumes the holder/billing model of FT-04.3 / US-04.2.1 is built first.
