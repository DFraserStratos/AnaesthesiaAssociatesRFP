## EP-04 · Contracts · Contradicts

[EP-04](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-04.md) · [board](http://localhost:5180/#/board?item=EP-04) · status Confirmed · surfaces: domain, store, seed, admin, web, mobile, demo-guide · confidence high

- **Requirement:** Each Procedure selects exactly one Contract, which answers pricing, rules and by default the invoice recipient; replaces the separate billing-route step. Admin can set a different billable party without changing pricing.
- **Prototype today:** Procedure carries a required billingRoute (hospital/insurer/billableParty) set separately from an optional governingContractId. Completion validation demands a route, not a contract. Missing contract resolved to hospital/insurer default only inside the billing run; billableParty route resolves with no contract at all.
- **Missing or wrong:**
  - Billing route still a mandatory separate concept (validator 'Set a billing route for this procedure'; ROUTE_LABELS; ManualCardForm; EditBillingSetupSheet route selector; counterpartyForProcedure keyed on route)
  - Contract optional ('None (default pricing)'), not exactly one
  - Billable party is an alternative route, not an independent override of the Contract holder
  - Contract structure is old Type 1/2/3 + holder + org/individual scope: no category, scope filters, versions, fee-schedule detail, required inputs, invoice presentation (see children)
- **Evidence:** `aa-prototype/src/domain/billing/validateCardForBilling.ts:120-125`, `aa-prototype/src/domain/billing/invoiceBuild.ts:114-190,206-235`, `aa-prototype/src/shared/flows/EditBillingSetupSheet.tsx:100-186`, `aa-prototype/src/domain/types.ts:216-247,409,444-456`

Size raised L to XL: removing/reframing route touches every card-creation path, validator, invoice counterparty, review columns, seed, demo control panel and demo guide.
