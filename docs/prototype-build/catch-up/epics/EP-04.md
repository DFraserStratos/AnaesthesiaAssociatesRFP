# EP-04 · Contracts · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-04) · catalogue `a68f09b` · [EP-04](../../../../requirements-board/requirements/stories/EP-04.md)

> EP-04 in scope is graded against the original-RFP Contract model the prototype still implements: Type 1/2/3 Contracts, a protected default Type 1 per hospital and direct insurer (seeded Procedures point at them), billingRoute plus an optional governingContractId on the Procedure, one editable From/To date pair, and an unfiltered Contract select with a blank 'None (default pricing)' option in EditBillingSetupSheet. Almost every item therefore Contradicts rather than Missing; only US-04.3.4 is Partial. Verification confirmed all eight reviewer verdicts; the only correction is that the Contract edit sheet can already create an individual-anaesthetist-scoped Contract (US-04.2.14), though none is seeded or filtered by owner. Most of the work is shared: one XL rework of the Contract model (header plus lines, practitioner-ID holders, AA-held No contract (RVG), dated versions) across domain/types.ts, seed/contracts.ts, store/contractActions.ts, mastersActions.ts, billing/contracts.ts and invoiceBuild.ts, then a new filtered, ordered, searchable picker with step rail; per-item sizes overlap and must not be summed. PERSIST_VERSION must be bumped. Dependencies: US-04.1.x (holders, AA code, staged Contract changes US-04.1.6), US-04.3.5 (lock at authorisation), US-04.3.6, EP-05 pricing (line rate, discount, units), EP-06 prepayment (a prepaid Contract flag replacing the Procedure patientPaymentCategory trigger), US-11.2.2 (payer on the Booking replacing billingRoute), US-03.4.1 (anaesthetist may change the Contract) and OQ-117 (fixed prices block anaesthetist override). FT-04.2, US-04.2.10 and US-04.2.14 rest on OQ-131 and FT-04.3's step rail is a guess, so only the whole-Contract-versions reading should be built if the team accepts it. Demo-guide impact: S1 to S5 and the 'Beat 4: contract effective-dating' beat, plus the registry.ts COS ACC date-out trigger (~374-384), rely on hospital default Type 1 Contracts and fallback; reworking defaults, versions or the picker changes those beats, seeded invoices and demoScenarios tests.

## EP-04 · Contracts · Contradicts

[EP-04](../../../../requirements-board/requirements/stories/EP-04.md) · [board](http://localhost:5180/#/board?item=EP-04) · status Agreed (4) · surfaces: domain, store, seed, admin, web, mobile, demo-guide · confidence high

- **Requirement:** Contract is set up from four settings (holder billed, anaesthetist may change pricing, prepaid, belongs to one anaesthetist or surgeon); every Procedure selects exactly one, replacing route resolution; dated versions, never backdated or deleted; No contract (RVG) offered first and held by AA; the holder is billed if it pays AA, else the Booking's payer.
- **Prototype today:** Contract has type 1\|2\|3, holderType, scope, permitsIndividualArrangement, isDefault. Procedure carries billingRoute (hospital, billableParty, insurer) and an optional governingContractId; resolveContractForProcedure resolves the route first and falls back to a per-hospital or per-insurer default Type 1. Contracts are edited in place and deleted.
- **Missing or wrong:**
  - governingContractId is optional and billingRoute is a separate required concept, so there is no 'exactly one Contract per Procedure'
  - Who is billed comes from billingRoute, insurer or billable party, not from the Contract holder's 'is billed' setting or the Booking payer
  - Type 1/2/3 are categories; the catalogue says there are no kinds of Contract
  - Per-hospital and per-insurer protected default Type 1s exist; the catalogue has one No contract (RVG) held by AA and no hospital, insurer or procedure defaults
  - No 'anaesthetist may change pricing' or 'prepaid' Contract settings
  - Contracts are edited in place, can be backdated and can be deleted, with no dated versions
  - Insurer master and acceptsDirectClaims still drive routing
  - No stage-and-submit of Contract changes (US-04.1.6, outside this batch)
- **Evidence:** `aa-prototype/src/domain/types.ts:365-432 (Insurer, ContractHolderType, Contract, ContractPrice)`, `aa-prototype/src/domain/billing/invoiceBuild.ts:80-195 (defaultContractFor, resolveContractForProcedure)`, `aa-prototype/src/domain/billing/invoiceBuild.ts:196-225 (counterpartyForProcedure by billingRoute)`, `aa-prototype/src/shared/flows/EditBillingSetupSheet.tsx:174-186`, `aa-prototype/src/store/contractActions.ts:36-215`, `aa-prototype/src/domain/seed/contracts.ts:43-62`
