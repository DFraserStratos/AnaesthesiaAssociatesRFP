# EP-04 · Contracts · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-04) · catalogue `501b0b8` · [EP-04](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-04.md)

> Structural: the prototype is built on the old RFP model (required billingRoute + optional governingContractId; Contract Type 1/2/3 with 'permitsIndividualArrangement'; protected default Type 1 per hospital and direct-claim insurer; insurer stored on the Procedure). The catalogue model needs (a) a master procedure list plus Contract-to-procedure/hospital association driving the picker (US-04.2.1, US-04.3.2, US-04.2.11, FT-04.3; base-unit home disputed OQ-62), (b) Contract replacing billing route as the pricing and payer decision (EP-04, FT-04.3, US-11.2.2), including exactly-one-Contract defaulting to the List hospital's RVG Default Contract, (c) Contract payment setting, split basis and multi-procedure rule (US-04.2.5, US-04.2.12; OQ-68; US-08.2.3), (d) dated price lines, versioning and review date (US-04.2.10, US-04.1.2, US-04.3.5; US-08.4.4 reproduction), (e) fee-schedule line fields and holder codes (US-04.2.4, US-04.1.4, US-04.3.2 search; OQ-66). Build 04.2.1, 04.3.2, 04.2.11 and FT-04.3 together, with EP-04 route retirement. Verifier corrections: FT-04.3 re-graded to Contradicts (insurer route defaults to the insurer's own Contract; billableParty route resolves with no Contract); EP-04 size raised to XL; noted that the 'hospital' route (labelled 'Contract holder') already invoices the Contract holder, so the old-reading conflict is route-as-mandatory-step and route-tied override. Cross-epic: US-05.3.1 (modifier split above four; prototype's isAdditional time-only rule is the old reading, drives US-04.2.5 Contradicts), US-05.4.1 (Contract-gated anaesthetist price adjustment), US-05.1.6 (procedure master), US-07.2.2 (office review flag for US-04.3.7), US-08.6.2/US-08.6.4 (credit note re-issue, additional invoices), US-11.2.2 (billable party override). Open questions (OQ-48, 62, 66, 67, 68) mean several items should be built provisionally per their recommendations. Any Contract/Procedure shape change needs a PERSIST_VERSION bump (currently 13) and rework of ~30 seeded Procedures in domain/seed/cards.ts. Demo-guide beats affected (docs/demo-guide/03-demo-script.md): S5 beat 4 contract effective-dating (~lines 397-406) and compliance staging (DemoControlPanel.tsx:429-447) if Contracts become versioned or price-dated; the S3 exception beat relying on a group-held COS Contract with no default fallback (will not survive Contracts always defaulting to the RVG Default Hospital Contract); any beat that picks a billing route or governing Contract in Card billing setup. No new time-driven demo trigger is needed for this epic beyond a locked-Contract panel for US-04.3.5.

## EP-04 · Contracts · Contradicts

[EP-04](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-04.md) · [board](http://localhost:5180/#/board?item=EP-04) · status Confirmed · surfaces: mobile, web, admin, domain, store, seed, demo-guide · confidence high

- **Requirement:** Each Procedure selects exactly one Contract, which sets pricing, rules and by default who is invoiced (the holder); an admin can override the billable party without changing pricing. Replaces the RFP's separate billing-route resolution.
- **Prototype today:** Procedure has a required billingRoute (hospital=labelled 'Contract holder' / billableParty / insurer) plus optional governingContractId. On the 'hospital' route the resolved Contract's holder IS invoiced (matches the catalogue default); on billableParty and insurer routes the route, not the Contract, picks the payer. A missing Contract is resolved at billing time to the hospital/insurer protected default Type 1 (or none on billableParty route). Billable-party override only exists on the billableParty route.
- **Missing or wrong:**
  - Route is a separate required first step (validator fails 'Set a billing route'), the step the epic retires
  - governingContractId optional ('None (default pricing)'), not exactly one per Procedure; billableParty route resolves with no Contract at all
  - Insurer and billableParty routes pick the counterparty irrespective of the Contract holder
  - Billable-party override (guardian) is tied to the billableParty route, not independent of the Contract's holder default
  - Insurer stored on Procedure (informational/route) models funding via route, not via Contract (cf OQ-55)
  - Credit-note-and-reissue fallback (OQ-19) belongs to US-08.6.2, outside this epic
- **Evidence:** `aa-prototype/src/domain/types.ts:405-410,447-454 (BillingRoute, billingRoute?, governingContractId?)`, `aa-prototype/src/domain/billing/invoiceBuild.ts:114-183 (resolveContractForProcedure falls back by route), :192-212 (counterpartyForProcedure branches on route first)`, `aa-prototype/src/domain/billing/validateCardForBilling.ts:109-112 (billingRoute required)`, `aa-prototype/src/shared/flows/EditBillingSetupSheet.tsx:96-113,175-183 (route segmented control, guardian only when route==='billableParty', 'None (default pricing)')`, `aa-prototype/src/shared/format.ts:37-41 ROUTE_LABELS`

  - Picker not narrowed by procedure or List hospital (see US-04.3.2)

- **Evidence:** `aa-prototype/src/shared/flows/EditBillingSetupSheet.tsx:60,112,175-183`, `aa-prototype/src/domain/billing/invoiceBuild.ts:154-181 (route-based default resolution; billableParty returns resolved with no contract)`, `aa-prototype/src/shared/capture/BtmCaptureBlock.tsx:111-115,186-189 (read-only chip)`, `aa-prototype/src/domain/billing/validateCardForBilling.ts:109-112 (only billingRoute required)`, `searched: governingContractId writes outside seed/EditBillingSetupSheet -> none (grep of src)`

Implemented behaviour is wrong, not merely missing: insurer route defaults to the insurer's default Contract and billableParty route resolves with no Contract, against 'default is the hospital RVG Contract, never a Procedure without one'.
