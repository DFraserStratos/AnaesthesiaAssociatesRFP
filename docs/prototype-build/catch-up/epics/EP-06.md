# EP-06 · Prepayment · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-06) · catalogue `c9b65ad` · [EP-06](../../../../requirements-board/requirements/stories/EP-06.md)

> EP-06 as scoped here (FT-06.2 plus three stories) is a substantial gap, and the independent re-check confirms the reviewer's picture. The prototype has only the Phase 09 and catch-up Phase 20 prepayment, and code comments mark most of it 'INTERIM until Phase 27'. That means: a prepayment requirement derived from a prepaid Contract (correctly per Procedure, with the Booking flagged if any Procedure is), an office-only 'Raise pre-procedure invoice' button that sends at once, the balance run netting the prepayment, and an ACCPAY that goes to the anaesthetist and is released on receipt. Structural changes needed: 1. Payer on each Procedure (US-11.2.2, OQ-140), moved off Booking.payer. This drives one invoice per payer, a per-payer lock, and the Booking-level warning text. 2. An approval step on the outgoing-invoices screen with an AA on/off setting (US-13.7.4), plus the prepayment letter (US-06.3.6). 3. An AA Holding creditor in the internal ledger and the Xero simulator, a second transfer pair after List authorisation (US-06.4.1, OQ-125), and refund and move handling (US-06.5.2, US-06.5.4). 4. Removing the split-deposit prepayment shape (prepaymentDetail split/depositAmount) and its seed, UI text and test coverage, so the prepaid amount is always the Procedure's price. BillingCard, OfficeBillingSetup, InvoiceDocument and the seed audit all reference it. 5. OQ-120 on naming the anaesthetist on the invoice is still open. Demo guide beats that would change: S4 beat 1 (Fri 24 Souter AM, Annette Riley, whose seeded $800 deposit goes away) and the Xero and payables walk-through. The seeded paid prepayment INV0001 (Fri 24 PM, already disbursed) needs re-seeding. PERSIST_VERSION must be bumped. Most of this work overlaps EP-08, EP-09, EP-10, EP-11 and EP-13, so it should be planned together to avoid double counting.
