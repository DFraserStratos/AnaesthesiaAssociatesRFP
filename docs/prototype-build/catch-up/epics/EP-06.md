# EP-06 · Prepayment · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-06) · catalogue `1f067a8` · [EP-06](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-06.md)

> Structural: the prototype models prepayment as a per-Procedure category (billableParty route + selfFundedPrepayment + prepaymentDetail full/split). The catalogue makes it a Booking property driven by the anaesthetist's prepaid RVG set, so the trigger moves and the hand-picked 'Pre-payment' option in the payment category pickers (EditProcedureSheet, EditBillingSetupSheet, ManualCardForm) goes. Collides with EP-04/EP-05 model changes (billing route/category removal, Contract required, RVG groups US-05.1.3). Parent sizes (EP-06, FT-*) are rollups, not additive. Verified in code: no writer of prepaymentDetail outside the seed, so a UI-chosen 'Pre-payment' category never gets full/split and completion validation fails with no control to answer it. Raise treats missing detail as 'full' and prices via feeFor on captured/selected units with the contract stripped, so a pre-procedure full estimate has no time units (under-estimates or refuses with a misleading 'no self funded pre-payment procedure' message). Only the seeded Riley (split $800) and Nair (full, paid) cards demo the flow. Completion hard-gate with audited override (lifecycle.ts:93-125, PrepaymentOverrideSheet) is a settled ruling. Catalogue text is silent but its screenshot captions ('gate cleared', 'mobile-card-gate') show it is tolerated; keep as a demo device unless AA rules otherwise. Stale copy to fix: banner and invoice note say 'RFP open question' / 'discovery point for AA'. Dependencies: US-05.1.3 (RVG groups), US-05.2.2/OQ-50 (time rule), US-12.1.1 (unit value, exists), US-02.2.1/US-13.6.1 (estimated duration), US-08.6.2/US-08.2.2 (credit and rebill; a credit-note model is shared by US-06.4.2 and US-06.5.2), US-10.2.3/US-10.2.1 (receipts, payment run, trust timing), US-02.5.3 (cancel). OQ-38/40/42/50/03 all open, so Proposed items may shift. Demo script impact (docs/demo-guide/03-demo-script.md): S4 Beat 1 (Souter Fri 24 Jul AM, Annette Riley: complete blocked -> Override gate -> complete) changes if the trigger moves to the profile; seeded Riley (split) and Nair (full, paid INV0001/BC0001) need reshaping and a PERSIST_VERSION bump. S1 to S3 unaffected unless the category picker is removed from booking setup. Proposed demo triggers: clock jump / reminder on Admin Day for date-approach alert, overpaid-prepayment scenario on Admin Review, trust-account refund payout in Demo Xero, rebook-with-replacement after refund.
