# EP-06 · Prepayment · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-06) · catalogue `3d3a18c` · [EP-06](../../../../requirements-board/requirements/stories/EP-06.md)

> Verified against code (PERSIST_VERSION is 16). Core mismatch: prototype prepayment is a per-Procedure payment category (selfFundedPrepayment on billableParty route) with full or split-deposit detail, raised manually by office; catalogue is an anaesthetist-level prepaid RVG set, all-or-nothing auto-calculated estimate (contingency units, estimated duration), generated at booking setup, trust-held until procedure done, refunded on cancel, payable repointed on move. Corrections made by verifier: US-06.2.3 Partial to Contradicts (lower-than-estimate final fails the Booking, wrong behaviour), US-06.4.1 Matches to Partial (balance not traceable to the prepayment invoice, line still says deposit). All other grades upheld. No UI or store action sets prepaymentDetail (seed only), so a UI-created Pre-payment Procedure cannot pass completion validation. Prerequisites: US-06.1.1/US-05.1.3 (prepaid set on Anaesthetist profile), US-06.2.5 (estimated duration), US-06.3.6 (letters), US-06.5.1/06.5.2 (trust, refund, via US-08.6.2 credit) gate FT-06.5 and US-06.5.3; US-09.1.3/US-08.3.1 pair semantics for US-06.5.4; US-13.7.x date escalation (Phase 27) for US-06.3.2. Single fix covers FT-06.4, US-06.2.3 and US-06.4.2 (remove negativeTotal for prepaid overpay; update prePaymentInvoice.test.ts:182 and billingRun.test.ts:484 which encode the old rule). Money model gap: no trust-hold state between ACCPAY authorised and disbursed; payables run pays anything authorised and the seed disburses BC0001 on 16 Jul for a 24 Jul procedure. Cancel (lifecycle.ts:348) and move (lifecycle.ts:635) have zero money handling. Demo-guide impact: S4 Beat 1 (Riley Fri 24 AM split $800 on flat $1,200 fee) and Souter Fri 24 PM seeded disbursed prepayment change; InvoiceDocument deposit/balance copy and billing monitor 'fully pre-paid' copy need updating. EP-06 verdict is a roll-up; size overlaps children. Open questions OQ-38, OQ-61, OQ-76, OQ-80 do not block grading.
