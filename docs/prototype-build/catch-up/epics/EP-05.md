# EP-05 · RVG master data and fee calculation rules · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-05) · catalogue `501b0b8` · [EP-05](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-05.md)

> Structural: the multi-procedure rule (FT-05.3, US-05.3.1) is the one wrong behaviour in EP-05, one piece of work. feeFor/splitBillingUnits work per procedure, so the fix needs a Booking-level pass (sum modifier units, then allocate equal share plus remainder to primary) feeding procedureFee/cardFee, invoiceBuild line units, Review screen B.T.M, prepayment estimate, UnitsCard captions and the additional-procedure note; modifier capture stays on the primary (the pool) while additional procedures show an allocated share. Add a 7-over-3 = 3/2/2 domain test, a seeded 3-procedure Card with 7 modifier units, and PERSIST_VERSION bump if seed changes. OQ-15 is open (Ben to validate): build to the stated rule and flag it. The Contract-level multiProcedureRule (SECOND_CODE_PERCENT, ADD_ON_FEE) is domain-model only, not in FT-05.3; it belongs with Contract stories. Base-unit home (OQ-62) affects US-05.1.1 and US-05.1.6: the prototype has only the old RVG-master reading; a Procedure master with per-procedure base units, Contract base-unit override (US-04.2.2) and a procedure-by-operation-name picker (US-03.3.1) is a cross-epic change (Master data, ManualCardForm/CodePickerSheet, resolveBtm, seed). US-05.1.1 AA-sourced codes needs an RvgCode source flag and an Add flow in Master data. US-05.5.2 depends on the pre-op/post-op event feature (FT-03.7, US-03.7.1, OQ-63) and OQ-12 codes; reuse a fixed-fee Contract (US-05.2.5) rather than a typed amount. US-05.2.5 needs ContractPrice extension (time band, add-on) overlapping US-04.2.4. US-05.2.2 and US-05.2.3 need no code change; only 'part intervals round up (assumption)' captions and the control-panel 'Billing assumption' callout can be reworded once OQ-75 settles. Verification changed one grade: US-05.1.6 Missing to Partial (low confidence), since the operation-named RVG master with base units is the old-model equivalent. Demo-guide: no S1 to S5 beat exercises multi-procedure splitting, fixed schedules or ACC pre-op lines; the S1 partial-interval-rounding discovery note would change wording. No demo-trigger button needed for any EP-05 item (all behaviour is user-driven and visible)."

## FT-05.3 · Multi-procedure rule (supersedes RFP split-billing rule) · Contradicts

[FT-05.3](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/FT-05.3.md) · [board](http://localhost:5180/#/board?item=FT-05.3) · status Verify · surfaces: domain, mobile, web, admin, seed, demo-guide · confidence high

- **Requirement:** Within one Booking: base units on primary only; time units on every Procedure from its own times; modifier units all on primary if total <= 4, else split equally across every Procedure with remainder to primary.
- **Prototype today:** Base on primary only and time per procedure from own start/handover (both correct). But additional procedure is billed time-only: modifiers never charged on it, M row says 'Not charged on an additional procedure', primary keeps ALL modifier units whatever the total. No equal-split logic anywhere.
- **Missing or wrong:**
  - WRONG: splitBillingUnits returns btm.time.units only for isAdditional; modifier units never reach additional procedures; no total > 4 threshold
  - MISSING: equal integer split of modifier units across all procedures with remainder to primary (7 over 3 = 3/2/2)
  - MISSING: Booking-level modifier total; feeFor is per-procedure and FeeContext has no sibling procedures
  - WRONG copy: BtmCaptureBlock note 'bills for time units only; base and modifier units stay on the first procedure'; fee line 'Anaesthesia, additional procedure (time units only)'; UnitsCard B/M captions; CardDetailBody total line note 'Time units only'
  - Downstream consumers take per-procedure units: cardFee (feeContext.ts:84), invoiceBuild.ts:494 line units, ReviewScreen B.T.M column (primary only), prepayment estimate path; all need the allocated share
  - Fixed-price (Type 3) additional-procedure rule also keyed on the old time-only reading (fee.ts:212)
- **Evidence:** `aa-prototype/src/domain/billing/fee.ts:107-109 (splitBillingUnits)`, `aa-prototype/src/domain/billing/fee.ts:227-232 ('time units only' line)`, `aa-prototype/src/shared/capture/UnitsCard.tsx:59-60,77-80,86`, `aa-prototype/src/shared/capture/BtmCaptureBlock.tsx:209-213`, `aa-prototype/src/shared/card/CardDetailBody.tsx:230`, `aa-prototype/src/shared/capture/feeContext.ts:84`, `aa-prototype/src/domain/billing/invoiceBuild.ts:494`, `aa-prototype/src/apps/admin/screens/ReviewScreen.tsx:252-264`, `searched: multiProcedure\|remainder\|equal split in src -> none relevant`

  - MISSING: Contract base-unit override per procedure/code (US-04.2.2 dependency) and the 'consistently overridden, change your data' guidance
  - MISSING: picking a Procedure by operation name seeding RVG code and base units (picker is by RVG code grouped by site; model is OQ-62)

  - Vanessa's standard procedure list is not available as seed input
- **Evidence:** `aa-prototype/src/domain/types.ts:216-260 (Contract/ContractPrice: no base-unit override)`, `aa-prototype/src/domain/billing/fee.ts:58-70 (resolveBtm: base from RvgCode, baseUnitsSelected, or overridden capture)`, `aa-prototype/src/domain/seed/rvgCodes.ts:14-60 (operation-named codes with base units)`, `aa-prototype/src/shared/capture/CodePickerSheet.tsx (RVG-code picker, search code/name)`, `aa-prototype/src/shared/flows/ManualCardForm.tsx:104 (operation text from RVG description)`, `searched: procedureMaster\|masterProcedure\|baseUnitOverride\|operationName in src -> none`
