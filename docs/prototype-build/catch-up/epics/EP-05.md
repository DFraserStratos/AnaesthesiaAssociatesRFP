Admin CRUD plus PERSIST_VERSION bump (currently 13) needed. (3) Split anaesthetist adjustment from office override into two fields applied in order (BTM, contract price, anaesthetist adjustment, office override), with a Contract flag allowsAnaesthetistAdjustment and percent / fixed-final-price types for the anaesthetist (US-05.4.1, FT-05.4); today one Procedure.priceOverride is shared and the anaesthetist gets $ and fixed. DEPENDENCIES: EP-04 (US-04.2.2 pricing basis and base overrides, US-04.2.4 schedule lines, US-04.2.5 multi-procedure rule, US-04.3.5 contract snapshot at AUTHORISED; prototype resolves governingContractId live); EP-03 (US-03.3.1 pick by operation name vs RVG code per OQ-06, itemised modifiers); EP-06 (prepaid by RVG group needs US-05.1.3 groups; prepayment estimate and OQ-50 duration rule); US-08.6.4 additional invoices for OQ-53 combined procedures (not modelled; no bundle concept in src). ## US-05.3.1 · Multi-procedure BTM rule · Contradicts

[US-05.3.1](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-05.3.1.md) · [board](http://localhost:5180/#/board?item=US-05.3.1) · status Confirmed · surfaces: domain, store, mobile, web, admin, seed, shell, demo-guide · confidence high

- **Requirement:** Base units on primary only (structurally not editable on additional); each Procedure earns own time units; modifiers wholly on primary when total <= 4, else divided equally across all Procedures with remainder to the primary (7 over 3 = 3/2/2).
- **Prototype today:** feeFor is per-Procedure: isAdditional gives billableUnits = time units only; UnitsCard disables B and M and modifier chips on additional Procedures; Card totals sum independent Procedure fees.
- **Missing or wrong:**
  - No Booking-level modifier total or split; no 3/2/2 allocation
  - Additional Procedures never receive a modifier share, so the fee is wrong whenever modifiers exceed 4 units
  - feeFor/procedureFee/cardFee/invoiceBuild all price one Procedure at a time; needs a cross-Procedure allocation step
  - Modifier capture disabled on additional Procedures; where Booking-level modifiers are captured and how each share is displayed is undefined
  - Seed additional procedure carries its own asaClass (AS2) that is silently ignored and could double count once modifiers are pooled
  - Base-units block is UI plus calculation only; editProcedure does not refuse baseUnitsCaptured on an additional Procedure (structural claim only partly met)
- **Demo trigger:** Seed a 3-procedure Booking with 7 modifier units so it is visible in Lists without any action; optional Control Panel button 'Load 3-procedure card (7 modifier units)' shown only on the card detail screen, adding it to Dr Souter's next DRAFT List, so 3 / 2 / 2 shows in the Card total, Review screen and invoice lines.
- **Evidence:** `aa-prototype/src/domain/billing/fee.ts:102-109`, `aa-prototype/src/domain/billing/fee.ts:180-183`, `aa-prototype/src/shared/capture/UnitsCard.tsx:59-86`, `aa-prototype/src/shared/capture/ModifierChips.tsx:15`, `aa-prototype/src/shared/capture/feeContext.ts:36-88`, `aa-prototype/src/domain/billing/invoiceBuild.ts:264-330`, `aa-prototype/src/domain/seed/cards.ts:513-545 (Holt split card)`, `aa-prototype/src/store/lifecycle.ts:445-470 (editProcedure has no additional guard)`, `aa-prototype/src/domain/billing/fee.test.ts:71,151`

## FT-05.3 · Multi-procedure rule (supersedes RFP split-billing rule) · Contradicts

[FT-05.3](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/FT-05.3.md) · [board](http://localhost:5180/#/board?item=FT-05.3) · status Confirmed · surfaces: domain, mobile, web, admin, seed, demo-guide, shell · confidence high

- **Requirement:** Base units on primary only; every Procedure earns its own time units; modifier units all on primary when total <= 4, else split equally across all Procedures in the Booking with remainder to the primary.
- **Prototype today:** splitBillingUnits returns only time units for isAdditional; modifiers disabled and uncharged on additional procedures; UI copy, fee line text and card-total note say 'time units only'; Type 3 fixed-price fallback also time-only for additional.
- **Missing or wrong:**
  - No modifier split above 4 units (equal share, remainder to primary)
  - Additional procedures charged time units only, contradicting 'equal share of modifiers when total > 4'
  - Superseded 'time units only' wording in fee line description (lands on invoice lines), BtmCaptureBlock note, CardDetailBody CardTotal note, UnitsCard captions and fee.test.ts
  - Type 3 fallback for an additional procedure (fee.ts:206-214) is justified by the old split-billing hard rule and would need to follow the new rule
- **Demo trigger:** Best done as seed data: add a 3-procedure Souter card with 7 modifier units so the 3/2/2 split is visible on the Card total, Review screen and invoice lines. Optional Control Panel button 'Load 3-procedure card (7 modifier units)', shown only on the Lists / Admin card screens, adds that Booking to Dr Souter's next DRAFT List.
- **Evidence:** `aa-prototype/src/domain/billing/fee.ts:102-109 (splitBillingUnits)`, `aa-prototype/src/domain/billing/fee.ts:206-214`, `aa-prototype/src/domain/billing/fee.ts:227-229`, `aa-prototype/src/shared/capture/BtmCaptureBlock.tsx:209-211`, `aa-prototype/src/shared/card/CardDetailBody.tsx:230`, `searched: bundle\|combined in src -> none (only image bundles)`
- **Verifier:** corrected from Contradicts. Verdict upheld (feeFor:107-109 confirmed). Dropped the OQ-53 bundle/combined-procedure point: FT-05.3 text says nothing about bundles, it is an open question owned by FT-03.2/US-04.2.5/US-08.6.4. Added the Type 3 additional-procedure fallback and demo-guide wording. Size S because the calculation work is counted once under US-05.3.1 (L).
