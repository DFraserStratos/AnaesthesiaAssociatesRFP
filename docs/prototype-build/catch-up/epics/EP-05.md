# EP-05 · RVG master data and fee calculation rules · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-05) · catalogue `d436947` · [EP-05](../../../../requirements-board/requirements/stories/EP-05.md)

> All four verdicts were re-checked against code and upheld. Master data for RVG codes and modifier codes is read-only in Admin (only RvgCodesView and ModifierCodesView are mounted in MasterData; no add/edit action exists in the store) and seeded with invented demo codes, so US-05.1.1 and US-05.1.5 need an add/edit master editor, a hidden id replacing the code-keyed Records (masters.rvgCodes, masters.modifierCodes; CodePickerSheet and ContractEditSheet store the code), modifier values richer than one number, a reseed from AR-34/AR-16, and a PERSIST_VERSION bump. Two older readings are implemented and now contradicted: resolveBtm adds the captured ASA class (AS1-AS4 units) automatically, and EXCLUSIVE_MODIFIER_GROUPS makes PA/A/AS/OB one-per-band while the catalogue says no stacking limit is set and nothing but age pre-applies. Removing either changes the Ellison design-day fee pin ($344.50, btmCapture.test.ts, fee.test.ts, modifierUnits.test.ts), AsaCard/UnitsCard and the S1 capture beat in docs/demo-guide/03-demo-script.md. Age pre-application from the patient's age (US-03.3.8) has no implementation (no dob logic in domain/billing) and its bands are open in OQ-95. US-05.2.5 and US-05.4.2 share one gap: there is no distinction between the anaesthetist's override and the office's price change, and no Contract flag for 'anaesthetist may change pricing' (OQ-107, a US-04.2.4 dependency); OverrideCard takes no contract prop, so a fixed-price gate (OQ-117: never on a fixed price) means passing the Contract through BtmCaptureBlock and showing the price read-only. The mandatory-reason rule (PriceOverrideSheet, OverrideCard, validator) contradicts US-05.4.2's 'no reason needed' for the office path. The completion validator's start/handover requirement on every RVG procedure contradicts US-05.2.5 on fixed prices and could change S2/S3 validator beats. The AUTHORISED-List edit refusal narrows 'at any time' but belongs to the List-lock rules (EP-07); confirm intent rather than treat as an EP-05 defect. Greg's 28 October doubts about modifier-master value, and the open question of merging modifiers with RVG groups, suggest keeping the modifier editor lightweight.

## FT-05.2 · Unit and fee calculation · Contradicts

- **Requirement:** Procedure holds its own price/rate/discount values filled from Contract line and RVG code; a held price is the price (BTM kept for reference), else (B+T+M) x rate x (1-discount) with discount as its own invoice line; Contract version in force on the procedure date (prepaid keeps its issued prepayment price); price 0 gives a no-charge invoice; submission rejected if no price can be worked out.
- **Prototype today:** feeFor computes units x (anaesthetist unitValue \| Type 2 agreed rate \| rounded discounted rate) or looks up a Type 3 ContractPrice at pricing time, then a typed priceOverride. - **Missing or wrong:**

  - Prepaid Procedure does not keep its issued prepayment price: fee is recalculated and the deposit netted off

  - Mandatory override reason is still enforced (the reshaped model has none)

[US-05.1.1](../../../../requirements-board/requirements/stories/US-05.1.1.md) · [board](http://localhost:5180/#/board?item=US-05.1.1) · status Agreed (4) · surfaces: admin, domain, store, seed, demo-guide · confidence high

- **Requirement:** Admins hold each RVG group (hidden unique key, code, anatomy heading, base units above 0, optional published range, modifier units default 0), can add AA's own groups, and a type-ahead lists every row for a code with description and base units; the range is shown to the anaesthetist.
- **Prototype today:** Seeds 34 demo RVG codes keyed by code in a Record. The admin RVG codes view is read-only (Code, Description, Site, Base units, Absorbs). The CodePickerSheet searches code or name, groups by site, shows 'B n' or 'B min to max', and range codes require an in-range selected value at billing validation.
- **Missing or wrong:**
  - No add or edit of RVG groups in Admin (RvgCodesView is view only, 'Demo-plausible values'), so AA-added groups and 'base units above 0 on save' cannot be demonstrated
  - masters.rvgCodes is a Record keyed by code: no hidden system key, so one code cannot appear on several rows with different base units (the catalogue's reason for the key)
  - No modifier units field on the group (default 0)
  - Type-ahead is c.code.includes(lowercased query), so an alphanumeric code such as 'H1' would not match (codes uppercased); it also cannot show duplicate rows for one code
  - Seed is 34 invented numeric demo codes, not the NZSA guide's groups with printed anatomy headings and ranges
- **Evidence:** `aa-prototype/src/domain/types.ts:915-926 (RvgCode: code, description, anatomicalSite, baseUnits single\|range, absorbsModifierCodes; no key or modifierUnits)`, `aa-prototype/src/apps/admin/screens/masters/ReferenceViews.tsx:234-253 (RvgCodesView read-only)`, `aa-prototype/src/shared/capture/CodePickerSheet:14-47 (type-ahead, baseUnitsLabel, range display)`, `aa-prototype/src/domain/billing/validateBookingForBilling.ts:~158-165 (range selection must be within min..max)`, `aa-prototype/src/domain/seed/index.ts:478 (keyed by code)`, `searched: addRvg\|saveRvg\|upsertRvg\|rvgCodes: in src/store and src/apps/admin -> none`
