Part of the [gap analysis](../GAP-ANALYSIS.md#ep-13) · catalogue `60e2d1e` · [EP-13](../../../../requirements-board/requirements/stories/EP-13.md)

> EP-13 slice is largely unbuilt; all 10 reviewer verdicts upheld after re-checking code. Foundations absent: no Room entity, no surgeon profile or identifiers, no pairing data, no notification entity, no admin dashboard (admin lands on Day view). Surgeon is {id,name,specialty} and view-only in MasterData.tsx; it is a proper id master (pickers in EditListSheet/permanent lists use it), so FT-13.6 and US-13.6.2 are Partial. The warning routine (15a, one prepayment rule) exists but no UI calls openWarnings/warningsForList/clearWarning; the Booking banner reads prepaymentStatusFor directly, so FT-13.7 needs an admin to-do dashboard (likely US-13.7.2) and routing the banner through the routine. Dependencies: US-13.8.2 needs US-01.4.3 (anaesthetist moves own List) and FT-01.6 Draft List; US-13.8.1/13.8.2 share one notification slice and one demo button; US-13.6.3/13.6.4 share a pairing entity and feed US-01.3.5/01.3.6, and need an admin anaesthetist profile (US-12.1.4) and audit history (US-13.5.2); US-13.6.1 room email feeds US-02.3.3 and US-11.1.5; US-13.4.3 overlaps US-04.2.13 (OQ-100) and RVG/modifier masters (US-05.1.x view-only today), and its notes say no import screen is needed, so the loader demo is optional. Seed shape changes (rooms, surgeon fields, pairings, notifications) need a PERSIST_VERSION bump. Demo-script impact: S3 Beat 3 (illness cover, reassign whole List, 03-demo-script.md ~L202) changes if reassign gains the not-preferred soft warning grouping or an anaesthetist-side move posts a notification; S4 Beat 1 (prepayment warning) changes if banners route through the routine or an admin to-do list is added; the control panel needs a new 'Anaesthetist moves a List' trigger. Privacy of pairings makes a persona-switch demo beat natural (admin sees, anaesthetist sees nothing).
