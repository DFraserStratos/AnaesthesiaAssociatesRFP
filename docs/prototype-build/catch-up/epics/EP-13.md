# EP-13 · Admin oversight and master data · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-13) · catalogue `d4db277` · [EP-13](../../../../requirements-board/requirements/stories/EP-13.md)

> Notification pool is the largest gap: FT-13.8, US-13.8.1, 13.8.2 and 13.8.3 all hinge on one change (resolve tick, active/resolved states, active count, show-resolved filter). It reverses the old OQ-79 'no read/clear state' recommendation baked into NOTIFICATION_POOL_RULE (actionable:false), the NotificationsCard/Screen comments and the provisional caption. Needs Notification.resolvedAt/By, an audited office-only resolve action, a seed with active and resolved notices, PERSIST_VERSION bump (currently 25), and ideally one shared tick affordance with the to-do's Clear. Extra notice sources (alert from List/Booking, US-03.6.3; optional notify on single Booking move, US-01.4.7/OQ-85) belong to EP-01/EP-03 work and should post through postNotification; the cover-change update email (US-02.3.3, Phase 35 note) hangs off a notice row. Warnings: engine and to-do are sound (FT-13.7, US-13.7.2 match); only 1 of 5 listed rules exists in US-13.7.1, the others depend on EP-03 (base-unit range), EP-11 (payer, balance threshold) and EP-07 (insurer Contract); each owning build should add its rule plus a warningSamples entry. Pairings: US-13.6.3 complete; US-13.6.4 needs a small domain change so preferred orders within tier (rankAnaesthetistCandidates sorts on tier only) plus test and demo-guide edits. Audit: payments, receipts, disbursements (xero.paymentReceived, xero.disbursed, aaFee.paymentRecorded) are audited and shown, which contradicts the carve-out in both FT-13.5 and US-13.5.2 (one fix, drop or filter them); credit-note audit arrives with EP-08. Sign-in (US-13.5.3, FT-13.5 proposal) deferred by OQ-83; a skippable simulated login is the cheapest demo. Master data (US-13.4.1): RVG and modifier editing, insurer add/edit, contract-holder record (US-04.1.5) and a master public holiday calendar are missing; US-13.4.3 cutover load has only Reset. Demo-script impact (docs/demo-guide/03-demo-script.md): lines ~277, 296, 374 say preferred is marked and shuffled within tier (change if preferred lifts order); the notification beat (~341 to 364) says notices are not to-dos and describes busy-morning paging, which changes when notices can be ticked and hidden; any sign-in screen must be skippable so S1 to S5 still start straight in. Verifier changes: FT-13.5 Partial to Contradicts (consistency with US-13.5.2 carve-out); US-13.4.1 size M to L and one weak point dropped; US-13.8.2 surfaces trimmed. All Agreed-status Matches (US-13.1.1, US-13.6.3, US-13.7.2) re-checked against code and upheld.
