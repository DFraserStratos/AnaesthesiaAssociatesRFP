## US-12.1.1 · Dollar value per unit · Partial

[US-12.1.1](../../../../requirements-board/requirements/stories/US-12.1.1.md) · [board](http://localhost:5180/#/board?item=US-12.1.1) · status Proposed (1) · surfaces: domain, store, admin, web, seed · confidence medium

- **Requirement:** Each anaesthetist has their own dollar value per unit (no shared price list, Commerce Act). Proposed design: at AUTHORISED the rate and unit value (plus contract terms and party details) are copied into the billing record so a later change cannot rewrite an issued invoice.
- **Prototype today:** unitValue on each Anaesthetist ($26 to $42), shown in Masters and record, edited with unit value > 0 and audit. fee.ts multiplies by live unitValue. The billing run persists Invoice subtotal/gst/total and InvoiceLine units/amount, so issued invoices keep their amounts. No rate or unit value field on Invoice, InvoiceLine or BillingCase. Admin ReviewScreen (authorised List) and web ListDetailView recompute fee via bookingFee/procedureFee from current masters.
- **Missing or wrong:**
  - No snapshot of the unit rate (or contract terms, party details) on the billing record at AUTHORISED: InvoiceLine has only units and amount (types.ts:1128-1135)
  - After a unit value edit, an AUTHORISED (locked) List still shows fees recalculated at the new rate (ReviewScreen.tsx:68-69,109; ListDetailView.tsx:77; shared/capture) while its invoices keep the old amounts, so the two disagree and the lock is not honoured on screen
  - Invoice document does not show the rate used (lines show units and amount only)
- **Demo trigger:** Existing: Masters > Anaesthetists > Edit unit value, then reopen an authorised List in Review or web List detail. Today the fee changes; after the fix the locked List and its invoices keep the rate in force when it was authorised.
- **Evidence:** `aa-prototype/src/domain/types.ts:214`, `aa-prototype/src/domain/types.ts:1112-1135`, `aa-prototype/src/domain/billing/fee.ts:187-195`, `aa-prototype/src/store/mastersActions.ts:292`, `aa-prototype/src/store/billingRun.ts:65-114`, `aa-prototype/src/apps/admin/screens/ReviewScreen.tsx:68-69,109`, `aa-prototype/src/apps/web/screens/ListDetailView.tsx:77`
- **Verifier:** corrected from Matches. Re-opened the code. Reviewer noted the invoice amounts are stored but treated that as enough. Checked the consumers: ReviewScreen and web ListDetailView call bookingFee/procedureFee against live masters, with no snapshot for AUTHORISED Lists, so a later unit value change visibly rewrites locked-List fees. The snapshot clause sits in 'Technical discussion' (a proposal) not an acceptance criterion, so confidence medium and size S; core 'own value per anaesthetist, no shared list' fully matches.
