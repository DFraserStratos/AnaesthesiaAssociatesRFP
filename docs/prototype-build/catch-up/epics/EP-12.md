# EP-12 · Anaesthetist profile and reporting · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-12) · catalogue `c9b65ad` · [EP-12](../../../../requirements-board/requirements/stories/EP-12.md)

> EP-12 slice here is FT-12.2 plus US-12.2.1. FT-12.2's own body states rules (flat list; monthly GST report of payments AA passed on; ledger not Xero), so it is graded normally, not Grouping. The ageing concept lives in three places that must change together: web Accounts 'Overdue' sub-tab and route (/web/accounts/overdue), the web Dashboard 'Receivables aging' panel with its onViewOverdue link (the dashboard is US-12.2.3 and links to US-08.3.5 'financial position'; check whether that story wants ageing at all before removing the panel), and the mobile AgeChip. Add bookingId and listId to AccpayInvoiceRow so both apps can link to the Booking. The GST report (sibling US-12.2.2, status Verify, graded elsewhere) should switch from billing.receipts to disbursements (billing.disbursements has atISO) and drop the period selector and the masters gstPeriod read (retired in US-12.1.2), and add a download/print action on web (US-03.1.4). The ledger-not-Xero rule already holds: all these views read state.billing. OQ-123 (billing-practice reporting hooks) and OQ-134 (overdue alerts vs prepayment alert, which affects US-06.3.2 and US-11.3.2, not this list) are unresolved and do not change either grade; OQ-123 can be a presenter talking point. Demo guide: S3 Beat 3 narrates 'does not remain under Overdue', Beat 4 mentions 'Payables, GST activity and Overdue', docs/demo-guide/01-personas mentions receivables ageing, and 04-presenter-cheat-sheet.md around line 372 says 'aging is derived'; these need rewording. S1, S2, S4 and S5 are unaffected.

## FT-12.2 · Reporting for anaesthetists · Contradicts

[FT-12.2](../../../../requirements-board/requirements/stories/FT-12.2.md) · [board](http://localhost:5180/#/board?item=FT-12.2) · status Proposed (1) · surfaces: web, mobile, domain, store, demo-guide · confidence high

- **Requirement:** Anaesthetists get two reports: a flat list of what is owed to them, and a monthly GST report of the payments AA passed to them. Both read from the Billing/Invoice Engine's own ledger, not Xero. OQ-123 asks whether reporting on billing practice (e.g. modifier use) is wanted, with at least hooks kept; it is unresolved.
- **Prototype today:** Web Accounts has Overdue (ageing table Current/31-60/61-90/90+), Payments, GST activity and AA fees sub-tabs. Mobile Balances has an Outstanding list (age chips) and a 'GST this month' peek. All read state.billing, never state.xero, so the ledger-not-Xero rule holds. The GST report (gstActivityFor) is built from billing.receipts (amounts received from payers, gross + GST), with a Monthly/Bi-monthly/Six-monthly rolling-window selector defaulting from masters.anaesthetists[].gstPeriod. No download, email or print. No billing-practice reporting or hooks.
- **Missing or wrong:**
  - WRONG: GST report lists receipts (money received from payers, 'Date received', 'Amount received') rather than the payments AA passed to the anaesthetist in the month (disbursements exist in state.billing with atISO, but the GST report does not read them).
  - WRONG: GST report has a Monthly / Bi-monthly / Six-monthly selector over a rolling N-month window and reads the retired masters gstPeriod; the catalogue says monthly only (US-12.1.2 retired note, US-12.2.2).
  - WRONG: outstanding report carries ageing buckets (web columns and totals, mobile age chips) and is named 'Overdue'; the catalogue says flat list, no ageing, no Overdue view (US-12.2.1). The dashboard 'Receivables aging' panel is a related ageing surface (the dashboard itself is US-12.2.3).
  - MISSING: GST report cannot be downloaded, emailed or printed (US-12.2.2 'suits the web app').
  - MISSING: no reporting on anaesthetists' billing practice (modifier counts etc.) and no hooks for it (OQ-123, unresolved; a presenter can say it is deferred, so low priority).
- **Demo trigger:** No new control needed: the existing Xero simulator 'Simulate payment and payout' (S3 Beat 3) and the payables-run disbursement already produce the payments AA passes on, which the monthly GST report should list.
- **Evidence:** `aa-prototype/src/apps/web/screens/AccountsScreen.tsx:32-36,88-186 (AGING_COLS, OverdueTable, bucket totals)`, `aa-prototype/src/apps/web/screens/AccountsScreen.tsx:384-470 (periodWindow, GstReport, Segmented period, receipts rows, 'Amount received')`, `aa-prototype/src/store/selectors.ts:975-1010 (gstActivityFor over state.billing.receipts)`, `aa-prototype/src/store/selectors.ts:929-958 (outstandingAccpayInvoicesFor, receivablesAgingFor)`, `aa-prototype/src/apps/mobile/screens/BalancesScreen.tsx:36-48,121-136 (GST peek from receipts, AgeChip)`, `aa-prototype/src/apps/web/screens/DashboardScreen.tsx:75-77,195-198 (Receivables aging panel)`, `searched: print\|download\|mailto in AccountsScreen.tsx -> none; modifier usage / billing practice report in src/apps -> none`

- **Requirement:** Admins hold each anaesthetist's contact, registration number, HPI CPN and bank account details on the profile (not Xero only); a record saved without an HPI CPN or without bank details is refused.

  - HPI CPN is optional (type comment 'where available', label '(optional)', addAnaesthetist/editAnaesthetist accept blank, 'HPI CPN not set' branch); must become mandatory and refuse the save
  - No refusal when bank details are missing
  - Seed anaesthetists need bank details (all 13 already have an HPI CPN); PERSIST_VERSION bump (currently 25)

## US-12.2.1 · Outstanding balances list · Contradicts

[US-12.2.1](../../../../requirements-board/requirements/stories/US-12.2.1.md) · [board](http://localhost:5180/#/board?item=US-12.2.1) · status Agreed (4) · surfaces: web, mobile, store, demo-guide · confidence high

- **Requirement:** Each anaesthetist sees a flat list of their own unpaid payables (about 100 rows), oldest first, with no rollup or grouping: no ageing buckets and no age chips. Each line links back to its Booking (AC: opening a line opens its Booking). Office staff, not the app, answer queries about a line.
- **Prototype today:** Mobile Balances > Outstanding: one card per unpaid ACCPAY invoice, oldest first, showing patient, outstanding amount, invoice number and payer, an ACC chip and an AgeChip ('Nd', warning tint over 60 days), plus a total card. Web Accounts > Overdue: same rows with the amount placed in Current / 31-60 / 61-90 / 90+ columns, bucket totals row and an Outstanding total. Rows are plain divs/tr with no click handler; AccpayInvoiceRow has no bookingId or listId, so no navigation to the Booking exists. Rows raised today are hidden until the next day.
- **Missing or wrong:**
  - WRONG: age chips on mobile rows (AgeChip, warning tint above 60 days).
  - WRONG: ageing buckets on the web table (four bucket columns, per-row bucket placement, per-bucket totals) and the sub-tab/route named 'Overdue'; the catalogue has no Overdue view or ageing.
  - WRONG (related surfaces): dashboard 'Receivables aging' panel with bucket bars and an 'n accounts over 60 days' link to Overdue, built from the same receivablesAgingFor.
  - MISSING: AC 'Back to the Booking': neither mobile nor web rows open the Booking; AccpayInvoiceRow lacks bookingId/listId (the case has bookingId, and the web Booking detail route /web/lists/:listId/bookings/:bookingId and the mobile equivalent exist as targets).
  - MINOR/uncertain: rows raised today are hidden (next-day visibility, from the old RFP). The story text only says 'unpaid payables'; no catalogue text found for next-day visibility on this list, so treat as a presenter-explainable difference, not a firm gap. Whether an authorised List's invoices appear as lines is outside this story's text.
- **Evidence:** `aa-prototype/src/apps/mobile/screens/BalancesScreen.tsx:72-96 (rows, no navigation),121-136 (AgeChip, >60 tint)`, `aa-prototype/src/apps/web/screens/AccountsScreen.tsx:32-36,88-186 (AGING_COLS, bucket table, totals, no row onClick)`, `aa-prototype/src/apps/web/screens/DashboardScreen.tsx:27,75-77,195-198 (Receivables aging, onViewOverdue)`, `aa-prototype/src/store/selectors.ts:859-876 (AccpayInvoiceRow, no bookingId/listId),911-923 (next-day filter, oldest-first sort),929-957`, `searched: bookingId\|navigate\|onClick on rows in BalancesScreen.tsx and OverdueTable -> none`

## US-12.2.2 · GST report · Contradicts

[US-12.2.2](../../../../requirements-board/requirements/stories/US-12.2.2.md) · [board](http://localhost:5180/#/board?item=US-12.2.2) · status Verify (3) · surfaces: web, mobile, domain, store, seed, demo-guide · confidence high

- **Requirement:** Each month the anaesthetist gets a list of the payments AA made to them in the month with the GST component of each (not invoices sent), something to download, email or print so it suits the web app. BCTI treatment still open (OQ-29, OQ-47).
- **Prototype today:** Web Accounts > GST activity: period selector (default from the anaesthetist gstPeriod), rolling window, rows of date received, invoice, payer, amount received, GST component, period totals. Mobile Balances > 'GST this month': receipts this month with GST. Both come from gstActivityFor over billing.receipts.
- **Missing or wrong:**
  - Rows are receipts (r.atISO, grossAmount), not disbursements; billing.disbursements (id, accPayId, amount, atISO, payablesRunId) and case.disbursedAtISO exist and should drive the list (US-10.1.2)
  - Bi-monthly / six-monthly options and the gstPeriod master field contradict a monthly report
  - No download, email or print (searched web apps for print\|download\|mailto\|csv: none)
  - Labels 'Amount received' / 'Payer' / 'No payments received' should read as payments passed to the anaesthetist
  - BCTI link not shown (open in OQ-29, OQ-47; status Verify, so low priority)
- **Demo trigger:** Existing 'Simulate payment and payout' on the Xero pair view (Demo > Xero) records the disbursement that should populate the month's report; add 'Download CSV', 'Print' and 'Email me this report' buttons on the web GST activity tab (CSV/print produce a file or print view of the rows; email shows a sent confirmation toast).
