# EP-12 · Anaesthetist profile and reporting · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-12) · catalogue `1f067a8` · [EP-12](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-12.md)

> Structure: no anaesthetist-facing Profile screen exists on mobile (More tab is a static persona card + demo note) or web (nav avatar is a label). The catalogue images for EP-12 are almost all admin-side (Master data) for the profile and anaesthetist-side for reports. One new Profile surface (unit value, GST period, contact, bank, prepaid tick list, editable by the anaesthetist and by the office on their behalf) would close US-12.1.1/.2/.3/.4 together; plan as one phase sharing the Admin anaesthetist editor (MasterData/EditAnaesthetistSheet). Dependencies: US-12.1.3 needs EP-06 (US-06.1.1 prepaid set, US-06.2.1 derived trigger, prepaid estimate rules) and RVG groups (US-05.1.3); the per-procedure 'Pre-payment' payment category chooser (ManualCardForm, EditProcedureSheet, EditBillingSetupSheet) becomes redundant/contradictory, and seeded prepay cards (SEED_PREPAID_CARD_ID, prepaymentUnpaidList) would need re-seeding via the anaesthetist's prepaid set. US-12.1.4 bank details feed the EP-10 payables run (disbursePayable, Xero sim 'Pay now'). PERSIST_VERSION (13) must bump on any seed/shape change. US-12.1.1 snapshot ties to US-04.3.5 / US-08.4.4 (lock terms at authorisation). US-12.2.1/.2/.3 depend on EP-08 ledger semantics (US-08.3.1 to 08.3.5): decide whether 'unpaid payable' means uncollected from payer (current) or not yet disbursed; the Payments tab's 'AA fee = gross minus authorised' deduction conflicts with EP-10/FT-10.3 (AA fee on its own invoice), a cross-epic issue on the same Accounts screen. Verification corrections: FT-12.2 regraded from Grouping to Matches (states its own ledger-not-Xero rule, which is honoured). Reviewer's 'Productivity/Leave unrequired' dropped (catalogue image includes productivity). Export/print and HPI-editability gaps dropped as not required. GST period gaps are small: alignment/period navigation on web plus label drift ('biMonthly' raw in Master data table vs 'Bi-monthly' vs 'Two-monthly'). Demo beats (docs/demo-guide/03-demo-script.md, not re-read): beats using Balances/Overdue/aging or the GST tab, and any prepayment beat relying on the per-procedure 'Pre-payment' category, change if prepayment becomes profile-derived; a unit-value edit beat re-prices authorised lists today and should be revisited if a snapshot is added. No new demo-trigger buttons needed for EP-12: everything is user-visible without a control.

## US-12.1.3 · Prepaid procedures · Contradicts

[US-12.1.3](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-12.1.3.md) · [board](http://localhost:5180/#/board?item=US-12.1.3) · status Confirmed · surfaces: domain, store, seed, mobile, web, admin, demo-guide · confidence high

- **Requirement:** Each anaesthetist's profile holds their own list of prepaid RVG codes and groups; a Procedure using one of those codes must be prepaid before the anaesthetist carries it out, checked across the whole Booking.
- **Prototype today:** cardRequiresPrepayment is true when any procedure has billingRoute billableParty and patientPaymentCategory selfFundedPrepayment, chosen manually per procedure in ManualCardForm / EditProcedureSheet / EditBillingSetupSheet. The gate itself (Pre-payment required banner, raise pre-payment invoice, office override, cleared when paid) works. No Anaesthetist prepaid field, no RVG group master, no profile screen on mobile/web/admin.
- **Missing or wrong:**
  - No Anaesthetist prepaid set (rvgCodes[], rvgGroups[]) and no RVG group master
  - Trigger is a manually chosen 'Pre-payment' payment category, not derived from RVG code/group membership in the anaesthetist's set (contradicts US-06.2.1 note: prepaid is a property of the procedure choice)
  - No tick-list UI for codes/groups on any surface (mobile/web profile or admin on behalf)
  - Seed has no prepaid sets; seeded prepay cards (SEED_PREPAID_CARD_ID, prepaymentUnpaidList) use the category flag
  - Depends on EP-06 (US-06.1.1, US-06.2.1) and RVG groups (US-05.1.3)
- **Evidence:** `aa-prototype/src/store/selectors.ts:307-313`, `aa-prototype/src/domain/types.ts:141-152,416-430,469`, `aa-prototype/src/shared/flows/EditProcedureSheet.tsx:23`, `aa-prototype/src/shared/flows/ManualCardForm.tsx:48`, `aa-prototype/src/shared/flows/EditBillingSetupSheet.tsx:29`, `aa-prototype/src/shared/card/CardDetailBody.tsx:131,512-545`, `searched: prepaidCodes\|prepaidRvg\|rvgGroup\|prepaidSettings\|bank in src -> none`

## US-12.1.1 · Dollar value per unit · Partial

[US-12.1.1](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-12.1.1.md) · [board](http://localhost:5180/#/board?item=US-12.1.1) · status Proposed · surfaces: domain, store, admin, web, mobile · confidence medium

- **Requirement:** Each anaesthetist has their own $ per RVG unit (no shared price list). Technical note: on AUTHORISED the rate/contract/party details are copied to the billing record so later unit-value changes cannot rewrite an issued invoice.
- **Prototype today:** Anaesthetist.unitValue per person; admin Edit/Add sheets set it (>0, audited). fee.ts reads live unitValue. Invoices are created at authorise so issued invoices do not change, but nothing is snapshotted on the List/Card: Admin Review of an AUTHORISED list uses live anaesthetist.unitValue, and editAnaesthetist's doc comment says a change 're-prices every Type 1 fee that reads it'.
- **Missing or wrong:**
  - No rate/unit-value (or terms/party) snapshot stored on the List/Booking at AUTHORISED; Review screen and other fee views of an authorised list re-price when unitValue changes (technical-discussion behaviour, story is Proposed)
  - No anaesthetist-facing place to see or set own unit value (More tab has no profile; requirement component is Anaesthetist App, though the catalogue images only show the admin edit)

- **Requirement:** Admins hold each anaesthetist's contact details, registration number, HPI where available, and bank account details (in the system, on the profile, not Xero only), used for the payables run.

  - Not shown in Master data table: HPI (minor); HPI not editable after creation (minor, not required by AC)

## US-12.1.2 · GST period · Partial

[US-12.1.2](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-12.1.2.md) · [board](http://localhost:5180/#/board?item=US-12.1.2) · status Proposed · surfaces: web, admin, mobile · confidence high

- **Requirement:** Each anaesthetist sets their own GST period (monthly, two-monthly, six-monthly) so the periodic activity summary aligns to it. Images: office sets it on the anaesthetist record; web GST view defaults to it.
- **Prototype today:** gstPeriod on Anaesthetist; Edit/Add sheets use GST_OPTIONS ('Monthly', 'Two-monthly', 'Six-monthly'); web GstReport defaults its Segmented to the profile value (useState initial only) and computes start-of-month(N-1 months ago) to today; the segmented change is local state. Mobile 'GST this month' is fixed to the current calendar month (matches the catalogue's mobile image caption 'received this month').
- **Missing or wrong:**
  - Web window is rolling to today, not the aligned GST period (no current/previous period navigation)
  - Web period control is a local override that does not persist and the default is captured once at mount (later office edits are not picked up until remount)
  - Label drift: admin Master data table prints raw enum ('biMonthly'), web says 'Bi-monthly', edit sheet says 'Two-monthly'
  - No anaesthetist-facing place to set or view own GST period
  - Mobile peek ignores the profile period (minor: catalogue mobile image itself shows 'this month')
- **Evidence:** `aa-prototype/src/apps/web/screens/AccountsScreen.tsx:266-285,292-300`, `aa-prototype/src/apps/mobile/screens/BalancesScreen.tsx:43-47,63`, `aa-prototype/src/apps/admin/flows/fieldChrome.ts:25-29`, `aa-prototype/src/apps/admin/screens/MasterData.tsx:183`, `aa-prototype/src/apps/admin/flows/EditAnaesthetistSheet.tsx:60`

## US-12.2.2 · Activity summary for GST · Partial

- **Requirement:** Date-ranged summary of amounts received and the GST component of each, aligned to the anaesthetist's own GST period, to help prepare the GST return. Images: web 'for the GST period', mobile 'this month'.

  - Mobile fixed to the current month regardless of profile period (consistent with the catalogue's mobile image)

  - Mobile has no dashboard (requirement text says web app only; component lists mobile + web)
