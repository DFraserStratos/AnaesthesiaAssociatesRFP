# EP-02 · Booking intake and change handling · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-02) · catalogue `efe123c` · [EP-02](../../../../requirements-board/requirements/stories/EP-02.md)

> Structural: the prototype has one append-only audit trail (mutate.ts) and a shared HistorySheet reachable from every Booking, so US-02.5.5 and most of US-02.5.8 are in place. Every gap sits downstream of the intake rebuild. There is no hospital-list application path (the matching screen, FT-02.1 / Phase 33, is not built; HL7/FHIR S12 to S15 are interim stand-ins now Future scope), no unmatched queue (US-02.1.4, US-11.1.5), no stubs, and no multi-user office (US-13.5.1; one hard-coded actor, Kirsty W.). The procedure text is the one real contradiction on the history side: EditProcedureSheet still lets people hand-edit it, which US-02.5.7 now forbids, and feed updates never replace it. The prototype also actively contradicts the stub rule: createBooking/upsertPatient turns a no-NHI incoming row into a Booking with a provisional Patient (and the seed carries one, shown as 'NHI pending'), against US-11.1.4 and US-02.6.1. Dependencies: US-02.5.7/02.5.8 depend on the matching screen (hospital text replacing rooms' text, hospital-sourced history entry) and US-03.1.9 (text shown with the Contract and RVG choice); US-02.6.1/02.6.3 depend on US-11.1.4 and US-11.1.5; US-02.6.3 depends on US-02.6.1. The old contract model (governingContractId) will be reworked by EP-04, so US-02.5.5's Contract-selection history needs rechecking then. Status caveats: 02.5.5 is Proposed; 02.5.7, 02.5.8, 02.6.1 and 02.6.3 are Verify (agreed in the room or answered by Donald only, not yet seen by Greg/Vanessa/Ben as applicable), so wording may still move. Demo-script impact: S1 (feed messages MSG-STG-1001 to 1004, 1010) and S4 (Exceptions) change when hospital updates replace procedure text and no-NHI rows become stubs; any beat that hand-edits an operation via 'Edit operation' changes because hand edits are removed.
