## EP-02 · Booking intake and change handling · Contradicts

- **Requirement:** Four booking sources; every change recorded with its source; a day move is cancellation plus new Booking; first release applies nothing automatically (hospital data lands on a review and merge screen); inbound changes accepted until the office authorises the List.
- **Prototype today:** BookingSource has all four values (display only) and audit/history shows who, role, source. Admin phone-advice and anaesthetist manual add work. HL7/FHIR canned messages create, edit, reassign and cancel Bookings immediately via integration actors; a surgeon-PDF inbox reviews then ingests rows onto an ACTIVE List. - **Missing or wrong:**
  - No hospital review-and-merge screen; applyEffect writes Bookings straight away (contradicts 'nothing is applied automatically')

  - Hospital intake is badged Future scope (Messages/Feed config tabs, FutureScopeNote, S1 script line 113 'arrives in a later build') although the catalogue treats the hospital download as the priority pathway
  - No-NHI inbound rows create provisional patients/Bookings instead of waiting
  - Surgeon-PDF update overwrites procedure text, with no approve/reject of differences on a matched Booking
- **Demo trigger:** Control-panel button on the new matching screen: 'Receive tomorrow's theatre list' loading a canned set of hospital rows (new, changed, cancelled, no-NHI, moved-day) into the review queue; nothing applies until the office actions each row.

[US-02.3.3](../../../../requirements-board/requirements/stories/US-02.3.3.md) · [board](http://localhost:5180/#/board?item=US-02.3.3) · status Verify (3) · surfaces: admin, domain, seed, store, demo-guide · confidence high

- **Requirement:** On-demand 'draft update email' on a Booking: admin picks changes from history, a mailto: window opens prefilled with subject, boilerplate, chosen changes and To (hospital contact for cover change, surgeon's room for Booking change); body shortened to ~2,000 chars with a note; nothing sent or recorded.
- **Prototype today:** Nothing. HistorySheet lists audit entries read-only. Hospital and Surgeon entities carry only id/name (and specialty). Invoice email is a separate simulated send.
- **Missing or wrong:**
  - No 'Draft update email' button on admin Booking
  - No picker over history changes
  - No mailto: generation with subject/boilerplate/change list
  - No hospital or surgeon's-room contact email in masters or seed
  - No length-limit handling with 'shortened' note
  - No offer of the cover-change email from the List-move notification (US-13.8.2 / US-01.4.3)
- **Evidence:** `searched: mailto\|update email\|draft.*email\|cover.change in aa-prototype/src -> none`, `aa-prototype/src/domain/types.ts:155-164 (Hospital/Surgeon id, name only)`, `aa-prototype/src/shared/booking/HistorySheet.tsx (read-only list)`
