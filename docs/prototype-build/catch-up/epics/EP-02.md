# EP-02 · Booking intake and change handling · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-02) · catalogue `60e2d1e` · [EP-02](../../../../requirements-board/requirements/stories/EP-02.md)

> Structural: hospital intake needs a new staged-row model (pending import rows + matching screen) in store/domain; today HL7/FHIR messages and PDF rows apply directly (code comment at integrationActions.ts:161 names this catch-up Phase 33). The matching screen is shared by FT-02.1 / US-02.1.1 / 1.2 / 1.3 / 1.5 and the unmatched queue (US-02.1.4, outside this list): build once (L) and treat the rest as increments, so do not sum the sizes. Nearest analogue to reuse: Integration Monitor (message log, feed field mapping, Surgeon PDFs tab); its HL7/FHIR/dead-letter machinery is Future scope in the catalogue's view, and FEED-CPH (Christchurch Public) is out of scope for first release. US-02.5.7 (Procedure source texts) is a cross-cutting data-model change (Procedure.sourceTexts[{text,system,arrivedAt}], PERSIST_VERSION bump, seed, createBooking no-trim, ingest adds rather than overwrites, 'as given' field on admin phone-advice and anaesthetist manual forms) and feeds US-02.3.1, US-02.4.1 and US-02.1.2; display above procedure/Contract is US-03.1.9. US-02.3.3 needs hospital and surgeon's-room contact emails (US-13.4.1, US-13.6.1), links to change history US-02.5.5, and the move-own-List office notification (US-01.4.3 / US-13.8.2, not present). Dependencies: US-01.6.1 Draft List, US-02.1.4 unmatched queue, OQ-13 (format unknown, keep simulated fields generic). Demo guide impact (docs/demo-guide/03-demo-script.md): S1 Beat 1 (MSG-STG-1001 creates a Booking directly) and Beat 4 (MSG-CPH-2001 dead-letter, mapping fix, MSG-STG-1002) change when hospital rows go to a matching screen; S2 phone-advice beat is touched by the 'as given' field. Demo triggers: 'Receive hospital download' / 'Sync from hospitals' on the matching screen. Verification: all 9 gradings upheld; only tweaks were confidence (US-02.1.1, 02.1.5, 02.5.7 medium) and the Copy-booking nuance on US-02.3.1.
