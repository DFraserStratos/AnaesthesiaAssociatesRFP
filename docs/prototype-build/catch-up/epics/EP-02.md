# EP-02 · Booking intake and change handling · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-02) · catalogue `1f067a8` · [EP-02](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-02.md)

> Structural: (1) Core gap is a new Admin matching screen plus a staged inbound-row store slice (e.g. integrations.inboundRows). FT-02.1, US-02.1.1 to 02.1.5, 02.5.1 and 02.5.6 depend on it. Re-route processMessage so HL7/FHIR messages and download rows are staged (with change type new/modify/reschedule/cancel) and applied only on admin decision, reusing the existing guarded write paths and MSH-10 dedupe. The unmatched queue is the same screen. Because the shared cancel/reschedule/modify story images are captured from the current simulator (message received then applied), the staging change also alters S12 to S15 demo beats. (2) Draft List (unassigned, no Slot; US-01.6.1, DM-05/06) is a prerequisite for the 'create Draft List' action in US-02.1.2; Lists currently always have an anaesthetist. (3) Card to Booking rename (DM-01) touches all copy here; do it first. (4) Intake channel is not recorded: AuditSource has no pdf/download/admin-entry values, PDF ingest and phone advice are both 'office'. Add an intake-channel field (or audit sub-source) to Booking to satisfy EP-02 'source recorded' and FT-02.5. (5) US-02.3.2 explicit save is the enabler for US-02.3.3 (change set to email) and US-02.5.6 (conflicts caught at save); CardDetailBody is shared with anaesthetists, so buffering must be admin-only or a separate admin edit mode. BrowserRouter (not a data router) means the unsaved-changes guard needs beforeunload plus an in-app guard, not useBlocker. (6) Domain: contact emails on Hospital and Surgeons' room (US-13.4.1, US-13.6.1) for US-02.3.3; rowVersion fields on Card/Procedure for US-02.5.6; persisted contract snapshot for US-02.5.5. Bump PERSIST_VERSION (13) when seed shape changes. (7) Shell: no screen-contextual demo control exists (AppShell harness bar is static, DemoClockMenu and DemoResetButton only); proposed triggers (Sync now / Simulate scheduled pull / Fail next sync on the matching screen; 'Hospital changes this booking now' on admin booking detail; sample download loader; 'Upload PDF' simulated on Surgeon PDFs) need a small screen-scoped DemoContextMenu slot using route matchPath, with logic kept in src/shared or src/store for pwaPurity. (8) Verifier changes vs reviewer: US-02.2.1 Matches to Partial (no upload action, S), US-02.5.2 Matches to Partial (silent time-only fallthrough when no target List, S), US-02.5.1 size L to M, EP-02 gains the intake-channel point. Still Matches: US-02.4.1, US-02.4.3 (low confidence, billingReference not copied), US-02.5.3, US-02.5.4. Demo script beats affected (docs/demo-guide/03-demo-script.md): S1 around lines 94-110 (S12 New booking replay currently lands Sarah Mitchell automatically; would need a matching-screen accept step); S2 Beat 2 phone advice (~line 171, 179); S4 Beat 4 integration dead-letter (~324-331); S5 MSG-STG-1002 (~381); line 410 'last-write-wins' must change if US-02.5.6 is built; Control Panel scenario messages and 'Ingest PDF row' card; PWA panel unaffected (mobile only).
