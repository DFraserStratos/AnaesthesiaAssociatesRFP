# EP-03 · Booking and Procedure capture (anaesthetist) · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-03) · catalogue `d436947` · [EP-03](../../../../requirements-board/requirements/stories/EP-03.md)

> EP-03 (this slice: US-03.1.9, US-03.3.1, US-03.6.1) is still built on the older model: a Procedure is a free-text description plus a required RVG base code, with the governing Contract chosen only by the office. The catalogue now treats the procedure as received text (rooms and hospital), the Contract as the pivot, and the RVG code as optional. All three verdicts were re-checked against the code and upheld. Structural changes this implies: - Procedure data needs rooms, hospital and invoice description fields, plus a Contract line entity (default RVG code, own base units, invoice description, price/rate/discount). Today Contract is only Type 1/2/3 plus ContractPrice rows, and Type 3 keys on rvgBaseCode as a stand-in for procedure type. - validateBookingForBilling (aa-prototype/src/domain/billing/validateBookingForBilling.ts) is the single place to realign completion. Require a Contract, require times only on time-priced Contracts, make the RVG code optional, add a modifier explanation field, and stop blocking out-of-range base units. Reconsider whether the insurer/category/prepayment/route gates belong to the anaesthetist at completion. - The warnings framework has one rule (prepaymentUnpaid). The out-of-range base-unit warning needs a new rule, which belongs to US-13.7.1. - The anaesthetist cannot change the Contract (US-03.4.1), and the Contract-change reset (US-03.3.1) would be new. Both depend on the Contract-line model (US-04.2.4 / US-04.3.4). The RVG picker should also regroup by RVG body headings and show only on RVG-priced Contracts. - The invoice description chain depends on US-08.4.6 and US-02.5.7 (as-received text). OQ-130 is unresolved, so build to its recommendation (admin edit kept, with a 'newer received description' cue) and flag it. OQ-93 does not alter US-03.6.1 as written. Demo-script impact (docs/demo-guide/03-demo-script.md): beats that capture and Mark complete (around S1 lines 156-169 and the List-submit beat near line 529) assume seeded Bookings that complete with an RVG code and times and no Contract or modifier explanation. Changes here need re-seeding (bump PERSIST_VERSION) and adjusting those beats. The S1 'Mark complete finds missing data' beat needs a different missing-data example, for example a missing Contract or modifier explanation instead of a missing finish time. The story screenshots (web-mark-complete-blocked etc.) would be re-shot.
