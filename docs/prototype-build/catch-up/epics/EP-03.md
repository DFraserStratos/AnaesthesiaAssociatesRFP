## US-03.2.1 · One primary Procedure · Contradicts

[US-03.2.1](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/US-03.2.1.md) · [board](http://localhost:5180/#/board?item=US-03.2.1) · status Confirmed · surfaces: domain, mobile, web, admin, seed, store, demo-guide · confidence medium

- **Requirement:** Exactly one primary per Booking; base units, and modifiers under the US-05.3.1 rule (all on primary if total <= 4, else equal share with remainder to primary), anchor to it.
- **Prototype today:** splitBillingUnits gives an additional procedure time units only; B and M steppers and ASA/modifier chips are disabled with 'Not charged on an additional procedure'; note says base and modifier units stay on the first procedure. feeFor prices each procedure in isolation. isAdditional flag, not isPrimary.

  - No modifier split above 4 units (needs Booking-level computation; 7 over 3 = 3/2/2)
  - UI caption/note encode the old RFP rule
  - No isPrimary flag or exactly-one invariant; copyCard yields a Booking with no primary (see FT-03.2)
  - Type 3 second-procedure pricing keyed by ordinal, not Contract multi-procedure rule
- **Evidence:** `aa-prototype/src/domain/billing/fee.ts:107-109,212`, `aa-prototype/src/shared/capture/UnitsCard.tsx:59-80`, `aa-prototype/src/shared/capture/BtmCaptureBlock.tsx:209-217`, `aa-prototype/src/domain/types.ts:484`, `docs/discovery-reference/Updated Requirements/catalogue/requirements/US-05.3.1.md`

## FT-03.2 · Booking structure: primary and additional procedures · Contradicts

[FT-03.2](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/FT-03.2.md) · [board](http://localhost:5180/#/board?item=FT-03.2) · status Confirmed · surfaces: domain, store, mobile, web, seed, demo-guide · confidence medium

- **Requirement:** A Booking has exactly one primary Procedure and zero or more additional Procedures in the same anaesthetic episode.
- **Prototype today:** createCard makes first Procedure isAdditional:false; addProcedure adds isAdditional:true; removeProcedure protects the first by position. copyCard creates a SEPARATE Card (a new Booking per US-02.4.3 'Copy a Booking') with one skeleton Procedure created isAdditional:true, so it shows 'Additional procedure ... base and modifier units stay on the first procedure' although no first procedure exists on that Card, and it bills time units only. No isPrimary flag or exactly-one guard; ProcedurePatch can set isAdditional freely (no UI does).
- **Missing or wrong:**
  - copyCard produces a Booking with zero primary Procedures (cardActions.ts:218 isAdditional:true on the only Procedure); under the catalogue a copied Booking is a new Booking with its own primary, so it wrongly loses base and modifier units and shows the additional-procedure note
  - No explicit primary designation or exactly-one invariant (positional ordinal by procedure id; removeProcedure guards by position not flag)
  - UI never labels the primary; only 'PROCEDURE n' headers and the additional note
  - OQ-53 (combined/bundle procedures) not modelled; open, no gap counted
- **Evidence:** `aa-prototype/src/store/cardActions.ts:133,218,491-500`, `aa-prototype/src/store/lifecycle.ts:443`, `aa-prototype/src/shared/capture/BtmCaptureBlock.tsx:209-214`, `aa-prototype/src/domain/billing/fee.ts:107-109`, `docs/discovery-reference/Updated Requirements/catalogue/requirements/US-02.4.3.md (copy = skeleton without procedure details)`
- **Verifier:** corrected from Matches. Reviewer accepted positional primary. Re-opened copyCard: it flags the sole Procedure of a new Card as additional, contradicting 'exactly one primary' and US-02.4.3. Shares the isPrimary refactor with US-03.2.1/03.2.2 (assign to same phase).
