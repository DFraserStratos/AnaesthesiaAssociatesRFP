# EP-03 · Booking and Procedure capture (anaesthetist) · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-03) · catalogue `501b0b8` · [EP-03](../../../discovery-reference/Updated%20Requirements/catalogue/requirements/EP-03.md)

> Structural: (1) No Event entity. FT-03.7/US-03.7.x need a new domain element (or Procedure variant) attached to a Procedure with own date/time, time or fixed fee, billable flag, no modifiers, an office approval step and an invoice-build path with link to the original; it replaces the B8 post-op addendum Card (store/cardActions.ts addPostOpAddendum, Card.cardType/addendumOfCardId, CardDetailBody button, DemoControlPanel stagePostOpScenario). Needs PERSIST_VERSION bump. OQ-63 and OQ-12 are Open: build against the recommendation (own element on the Procedure, own invoice line, office approval) and mark provisional. (2) 'Billed = gone' (isListBilled, M10; authoriseList bills immediately) hides every worked past List from mobile/web/WeekStrip. FT-07.4 and US-07.4.1 still say the List drops off the to-do view, but US-03.1.6, US-03.1.7 and US-03.7.1 need reachable past Procedures, so a read-only history/look-back path plus seed History as browsable Lists (older than the 14-day horizon) is the shared prerequisite. (3) Contract ownership: FT-03.4, US-03.3.1 and US-03.6.1 hinge on an anaesthetist-facing Contract picker (filtered by procedure, US-04.3.2), admin approval of the Contract selection in Review (US-07.2.2), and a Contract-required-inputs concept (US-04.2.7). OfficeBillingSetup is office-only today. (4) Primary Procedure: only implicit (first by id); FT-03.2 (corrected to Partial), US-03.2.2 and the modifier split rule (equal share when total > 4) push toward explicit isPrimary, a set-primary action, and fixing Card Copy, which currently yields a Booking with no primary. (5) Range handling: clamp plus validator block must become accept-and-warn, which depends on a warning routine (US-13.7.1; no warning entity exists). (6) NHI wording: 'NHI pending' across mobile/web/admin vs catalogue 'NHI missing'; mobile list rows blank; keep in step with the OQ-49 provisional-booking decision. (7) Persona note: anaesthetist apps run only as Dr Souter, but the post-op scenario is staged for Dr Sharma, so the anaesthetist-side event flow cannot be shown today.\n\nDemo-script impact (docs/demo-guide/03-demo-script.md): S4 Beat 2 post-op addendum (~L303-312) is replaced by the event flow; S1 Beat 3 capture on mobile (~L125-145; Mark complete refusal and list-complete gate) changes if Contract pick and contract-required inputs become completion requirements, and the RVG range step changes when out-of-range is accepted with a warning. No automatic or time-driven triggers are needed in this epic; office approval of events is a manual Admin action. Verification changes: FT-03.2 Matches to Partial; US-03.1.6 Contradicts to Partial; the other ten gradings upheld, with corrected evidence and demo_trigger persona on the post-op items.
