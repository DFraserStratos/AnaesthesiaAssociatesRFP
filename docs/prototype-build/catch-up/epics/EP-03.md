# EP-03 · Booking and Procedure capture (anaesthetist) · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-03) · catalogue `a68f09b` · [EP-03](../../../../requirements-board/requirements/stories/EP-03.md)

> EP-03 events (FT-03.7, US-03.7.1, US-03.7.2) are structurally absent: the interim post-op addendum (addPostOpAddendum, marked INTERIM until Phase 38b/39) models the opposite of the catalogue, a Booking on a List instead of an element on the Procedure. Closing them needs one new domain entity (event: time\|fixedFee\|additionalInvoice\|credit, own date/time, invoice tick, own billable party, reviewed flag), store actions, event UI in the Booking detail on mobile, web and admin, an event review step, a standalone 'next billing run' that bundles by billable party (Invoice.kind needs additional and credit), and a PERSIST_VERSION bump. The three items should be planned as one build; sizing them separately overstates the total. Dependencies: US-03.1.6 (past Procedures; billed Lists leave the anaesthetist's views at authorise, so a past-Procedure entry point needs a different view), US-08.6.1/08.6.3/08.6.5, FT-11.2, US-05.5.2 and OQ-12 (parked), FT-04.3 (step rail, working direction only), US-08.4.6/OQ-130 (invoice description). US-03.6.1's new minimum (Contract required, times only for time-priced Contracts, modifier explanation, RVG optional) rewrites validateBookingForBilling and needs a modifier-explanation field; it interacts with the add-booking form (no Contract chosen there; Contract is office-only in EditBillingSetupSheet). It also shows hospital/approval references only as a free-text billingReference, with no insurer approval number. US-03.1.9 needs separate as-received rooms and hospital descriptions plus an invoice description on the Procedure and a Contract summary; correction to the first review: the S14 hospital message does not touch the description at all (only time and note), and the overwrite is in the PDF-row ingest. US-03.1.4 is a principle and matches. Demo script impact: S4 Beat 2 (post-op addendum, docs/demo-guide/03-demo-script.md ~543-553) would be rewritten; the S1 mark-complete beat changes with the new completion rules; S3 billing beats are unaffected unless events join the invoice list.
