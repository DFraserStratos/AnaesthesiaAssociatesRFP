## US-02.1.4 · Unmatched queue · Partial

[US-02.1.4](../../../requirements-board/requirements/stories/US-02.1.4.md) · [board](http://localhost:5180/#/board?item=US-02.1.4) · status Verify (3) · surfaces: admin, demo-guide · confidence high

- **Requirement:** Unmatched rows stay in a queue for manual intervention. An incoming booking with no NHI waits at intake (no Booking created), shown on Intake beside the unmatched rows as a row waiting for an NHI, with a stub standing in its place on its List (seen by anaesthetist and office) until the office adds the NHI. Nothing is silently dropped.
- **Prototype today:** Intake > Matching has Open / Unmatched / Decided filters; the Unmatched filter includes no-NHI rows (store/matchingSelectors.ts importRowViews, ~135-150, 'rows waiting for an NHI included'). A no-NHI row is assessed waitingForNhi with queue 'unmatched' and creates no Booking (domain/intake/matching.ts:~525-535); placeStubsForRows (store/stubSettle.ts:~31-65) puts a stub on its List, drawn in the admin List table, web List detail and mobile List detail (ListDetailScreen.tsx:125); adding the NHI resolves it into a Booking. The dedicated Waiting for NHI view (chase address, urgency, Add NHI) is only at /admin/patients/waiting under the Patients nav item. Matching rows link across to it (MatchingTable.tsx:120). INTAKE_TABS (IntakeScreen.tsx:21-26) has only Matching, PDF lists, Data quality, Validators. Intake's badge (matchingAttentionCount, all open rows) already includes waiting rows; the Patients badge also counts them (patientAttentionCount adds waitingNhiRows).
- **Missing or wrong:**
  - Waiting for an NHI is not a tab on Intake (INTAKE_TABS has no such tab); the view exists only at /admin/patients/waiting, so waiting rows are not 'on Intake beside the unmatched rows' as now written. The tab itself is specified mainly by US-11.1.5 and is the same build.
  - MatchingTable's 'Waiting for NHI' TextAction (to /admin/patients/waiting, line 120) and the receive-no-nhi-list demo trigger (screen 'Admin · Patients · Waiting for NHI', routes and indexPath /admin/patients/waiting, registry.ts:~2364-2380) point at the Patients path and must repoint to the Intake tab.
  - patientAttentionCount still adds waitingNhiRows, so the Patients badge double counts rows that become an Intake tab; it should drop them (Intake's count already includes them).
- **Demo trigger:** Existing: 'Receive list with a missing NHI' (receive-no-nhi-list) and 'Office adds the NHI' (pwa-office-adds-nhi). Repoint receive-no-nhi-list's screen, routes and indexPath to the Intake waiting tab.
