## EP-14 · Health systems integration · Contradicts

[EP-14](../../../requirements-board/requirements/stories/EP-14.md) · [board](http://localhost:5180/#/board?item=EP-14) · status Proposed (1) · surfaces: admin, simulator, shell, demo-guide, store · confidence high

- **Requirement:** HL7 v2/FHIR and national identity (NHI) integration is inbound only, never writes back. In the first release St George's and Southern Cross rows arrive on the matching screen on their own with no import button, and the office decides every row. More feeds, automatic matching and HL7/FHIR are Future Work; NHI lookup is in scope.
- **Prototype today:** Admin Intake > Matching has a primary 'Import hospital file' page action opening ImportDialog, which calls importHospitalDownload with a canned sample file (the D52 'no sync' reading). A bar demo trigger 'Import hospital file' (matching-receive-theatre-list) stages the same rows, described as standing in for the hospital's file arriving. HL7/FHIR simulator at /demo/integrations (badged Future scope) parses canned messages into Matching rows via processMessage, with a message log, retry, dead-letter and mapping fix. Nothing writes back to any hospital (no outbound code found). NHI lookup is simulated through shared/nhiHub. Staged rows never apply until the office decides.
- **Missing or wrong:**
  - WRONG: MatchingScreen shows an 'Import hospital file' button and ImportDialog (office pulls a file by hand), contradicting 'no import button and no sync button' (US-02.1.5 and EP-14 Notes, 26 Nov).
  - WRONG vocabulary: the demo trigger is labelled 'Import hospital file' and described as a file being imported; it should read as a hospital sending its list (for example 'Hospital sends its theatre list').
  - Nothing on the matching screen shows rows as arriving by themselves from the two hospitals (no arrival indicator or source label). The only paths are the manual import or a demo-bar press.
  - No explicit 'inbound only' statement or visible proof that nothing is sent back (for example in the audit or integration monitor).
  - Adapter and transport configuration matrix (v2 or FHIR, polled or pushed per hospital) is not shown. FEED_META and the mapping screen cover mapping only. This is Proposed technical discussion and arguably Future scope.
  - Open decision on how many formats ship at go-live is not represented. This is only a question.
- **Demo trigger:** Rename the existing bar trigger on Admin, Intake, Matching from 'Import hospital file' to 'Hospital sends theatre list' (choices St George's and Southern Cross). It stages the rows on Matching as an arrival. Optionally seed the first arrivals at reset so the demo opens with rows already waiting. Keep 'Fire hospital message' on /demo/integrations for the Future Work HL7/FHIR discussion.
