## US-01.3.6 · Anaesthetist priority tiers for assignment · Contradicts

[US-01.3.6](../../../requirements-board/requirements/stories/US-01.3.6.md) · [board](http://localhost:5180/#/board?item=US-01.3.6) · status Verify (3) · surfaces: admin · confidence high

- **Requirement:** The tier sits with the rate per unit on one card on the anaesthetist's page, changed by Edit, choose, Save (Cancel leaves it; each save is a separate audited change; a single click never saves). Available anaesthetists are ordered by tier then shuffled within a tier. Admin can filter both the available anaesthetists and the Anaesthetists list by tier. The default is Tier 4, and anaesthetists never see tiers or get tier-ordered colleagues.
- **Prototype today:** AnaesthetistRecord.tsx has a separate 'Priority tier' card whose SlidingSegmentedControl onSelect calls changeTier, which calls setPriorityTier at once (audited, default 4 stored by absence). The rate per unit sits in the separate Profile card, edited via the EditAnaesthetistSheet. The candidate pickers (AnaesthetistCandidates, DraftListCandidates) order by tier, then pairing, then a seeded shuffle, with a Filter by tier control. Web and mobile anaesthetist views are name-ordered with no tiers. AnaesthetistsView has a Tier pill column but no filter.
- **Missing or wrong:**
  - WRONG: the tier is saved by a single click (SlidingSegmentedControl onSelect -> setPriorityTier); the requirement is Edit, choose, Save, Cancel
  - WRONG: the tier is its own card, not on one card with the rate per unit
  - MISSING: a tier filter on the Anaesthetists list in People (only a Tier pill column exists)
  - MINOR: the shared Edit/Save/Cancel card pattern used by the rest of the page does not exist yet; it arrives with the People section record pattern lifted out of the Contract page
- **Evidence:** `aa-prototype/src/apps/admin/screens/AnaesthetistRecord.tsx:31-37 (changeTier saves immediately), :54-59 (separate 'Priority tier' card), :61-70 (rate per unit in the Profile card)`, `aa-prototype/src/store/officePrivate.ts:132-156 (setPriorityTier, audit)`, `aa-prototype/src/domain/pairingPreferences.ts:69-90, :284-300 (tier order, shuffle keyed on requestKey, tierFilter)`, `aa-prototype/src/apps/admin/components/pairing/AnaesthetistCandidates.tsx and DraftListCandidates.tsx (Filter by tier)`, `aa-prototype/src/apps/admin/screens/masters/AnaesthetistsView.tsx:30, :77 (Tier column pill only, no filter control)`, `searched: tierFilter\|Filter by tier -> only the pairing pickers, not AnaesthetistsView`
- **Verifier:** corrected from Contradicts. Re-opened AnaesthetistRecord.tsx, AnaesthetistsView.tsx and EditAnaesthetistSheet.tsx and upheld the Contradicts verdict and all four gaps. Only the size changed, from S to M. The requirement puts the tier and the rate per unit on one card changed by Edit, choose, Save, so the Profile card's rate editing (now in a sheet) also has to move into that card, with the tier and rate saved as separate audited changes. This is more than a one-hour tweak, and it overlaps the People record pattern. It stays in admin screen files that Contracts phases 45 to 49 do not touch, so it is still a Lane C candidate.

## US-01.1.1 · Two Slots per anaesthetist per day · Partial

[US-01.1.1](../../../requirements-board/requirements/stories/US-01.1.1.md) · [board](http://localhost:5180/#/board?item=US-01.1.1) · status Agreed (4) · surfaces: domain, store, admin, seed · confidence high

- **Requirement:** The Scheduling Engine writes an AM and a PM Slot, free, for every active anaesthetist for every day across the rolling horizon even with nothing booked, then paints the anaesthetist's calendar and recurring bookings on top; the third OOH Slot is office-opened only; an anaesthetist made inactive has no Slots after their last day and Slots again from the day made active (US-12.1.6).
- **Prototype today:** domain/seed/canvas.ts generates AM+PM for active anaesthetists only, all Free, paints leave and series, then recurring bookings, with clashes becoming Draft Lists. The same path serves seed, clock roll-forward, new anaesthetist, reactivation and horizon extension. OOH is never generated. The Active/Inactive toggle in EditAnaesthetistSheet calls editAnaesthetist, which uses anaesthetistCanvasDelta from state.clock.todayISO. Inactive removes Slots from today and is refused if Lists exist from today; reactivation regenerates from today. There is no last-day date, reason, clearable or scheduled inactivity, and no date-driven trimming.
- **Missing or wrong:**
  - No 'last day': Slots are removed from today the moment Inactive is saved, rather than kept until a chosen last day
  - The refusal ('N Lists from today. Reassign them first.') is keyed to today, not to Lists after the last day, and the office is not shown which Lists to reassign
  - No way to clear a future last day, and no reason captured (US-12.1.6)
  - Reactivation always regenerates from today, not from a chosen 'active again' date
  - Inactive status is not date-driven, so rolling the demo clock past a last day would not trim Slots
- **Evidence:** `aa-prototype/src/domain/seed/canvas.ts:116 (active filter), :122-137 (AM/PM, default Free), :140-175 (leave, series, recurring painted, clash handling)`, `aa-prototype/src/store/slotActions.ts:970-1001 (anaesthetistCanvasDelta: active flag, removes Slots from fromISO)`, `aa-prototype/src/store/mastersActions.ts:369-410 (canvas follows active from todayISO; 'listsAhead' refusal; canvas.trim and canvas.generate audit)`, `aa-prototype/src/apps/admin/flows/EditAnaesthetistSheet.tsx:128-130 (Active/Inactive Segmented, 'Their sessions from today are removed.')`, `searched: lastDay\|inactiveFrom in aa-prototype/src -> only unrelated AdminApp date ref and a mobile calendar state`
