# Prototype map: domain layer (aa-prototype/src/domain, excluding seed/)

Paths below are relative to `aa-prototype/src/domain/` unless they start `aa-prototype/`. This layer is pure TypeScript: no React, no store, no routes, no `fetch`, no `Date.now()`. `domainPurity.test.ts` enforces the purity. It holds the entity types (`types.ts`, 3105 lines), the status/lifecycle vocabularies, every pricing/billing rule (`billing/`), the simulated-integration parsers (`integrations/`), NHI validation, the demo clock and about 76 colocated tests. The store (`aa-prototype/src/store/`) calls these functions and writes the results through `mutate()`. Because there are no screens here, the "route/screen" parts of the brief are replaced by "who calls it". Screens that read these rules are found by grepping the function name under `aa-prototype/src/apps/`. Barrel: `index.ts` re-exports types, clock, slots, listPairing, draftLists, rng, nhi, nzhis, billing, seed, warnings, listProgress, outOfHours, bookingSearch, xero (never `xeroSim`: US-10.2.4 fence).

## 2. Contracts section (all in `billing/` unless stated)

**Contract model: `contracts.ts`.**
- `Contract` (67): id, `aaCode` (unique, normalised), `holderReference`, `invoiceDescription`, `defaultRvgGroupId`, `name`, `holderId` (a Party), `billsTo: holder | payer`, `linkedSurgeonIds[]`, `linkedAnaesthetistId`, `prepaid`, `anaesthetistMayOverridePrice`, `pricing`, `status: active | disabled`, `systemRole?: noContractRvg | openPriceFallback | rvgFallback`, `specialtyIds[]`, `fundingTagId?`. There is NO date, `replacedBy`, `effectiveFrom`, `replaces`, `group`, or `parent` field. Contracts are edited in place; there are no versions.
- `ContractPricing` (48): `rvgAnaesthetistRate | rvgContractRate{unitRate} | rvgDiscount{discountPct} | fixed{ranges[]} | open`. `CHOOSABLE_PRICING_KINDS` (143) excludes `open`.
- `contractRefusal(next, ctx)` (264) is the one save guard (the store applies it). Codes (186): nameRequired, aaCodeRequired, aaCodeTaken, holderMissing, holderFixed, rateAboveZero, discountRange, openNotChosen, systemRoleNotChosen, prepaidBillsPayer, prepaidNotRvg, overrideOnlyRvg, holderBillsPayer, holderBillingDetails, noLinksOnHospital, linkRequired, linkUnknown, prepaidFixed, pricingKindFixed, systemFixed, systemNeverDisabled, specialtyUnknown, fundingTagUnknown. Immutable after create: holder, prepaid, pricing kind. System Contracts: only name, aaCode, invoiceDescription editable (`SYSTEM_CONTRACT_EDITABLE_FIELDS` 64), never disabled.
- `billsPayerOnly(holderKind, prepaid)` (146): prepaid, AA-held or anaesthetist-held always bill the payer. `takesLinks` (151): hospital holders take no links. `nextAaCode(prefix, existing)` (171) gives `PFX-001`. `noContractRvg` (156) throws unless exactly one. `contractMatchesQuery`/`contractSearch` (384/404): query matches name, holder reference, AA code, invoice description, default RVG code, ignoring case and spaces. `ContractFilters` (368): status (`active` default), holderId, fundingTagId. `linkFits` (450): where a Contract is offered (hospital-held only on that hospital's Lists; linked on its surgeons'/anaesthetist's; unlinked AA/insurer/funder everywhere).

**Party master: `parties.ts`.** `PartyKind` = `aa | hospital | insurer | funder | surgeon | surgeonGroup | anaesthetist` (32); `Party` (44): name, `codePrefix`, billingName, email, postalAddress, `deliveryMethod: email | post`, hospitalId, billingIdentity. `partyRefusal` (141) codes (82): nameRequired, hospitalRequired, hospitalOnlyOnHospital, notAaRooms, oneAaParty, aaReadOnly, codePrefixFormat, codePrefixTaken, kindFixedWhileHolding, hospitalFixedWhileHolding, oneHospitalParty, billingNameRequired, deliveryRequired, emailRequired, postalAddressRequired. `billingDetailsRefusal` (180), `CREATABLE_PARTY_KINDS` (190), `suggestCodePrefix` (205). `partyOptions.ts`: picker options for Split/events (`partyOptionsFor` 42, `splitPartiesOn` 107).

**Funding tags: `fundingTags.ts`.** `FundingTag {id, code (unique, upper-cased), order, funderPartyId?}` (24). `fundingTagsInOrder` (37), `moveFundingTag(up|down)` (114), `fundingTagUsage` (56), `fundingTagRefusal` codes `codeRequired|codeTaken|funderUnknown|funderKind` (84; funder must be insurer or funder Party), `fundingTagForFunder` (46, the rail's "Suggested"), `isAccTag`/`procedureAccFunded` (51/67: ACC is a tag, never a pricing path).

**Specialties: `specialties.ts`.** `Specialty` (24); `specialtyNameRefusal` (99, `nameRequired|nameTaken`); `contractFitsSpecialties` (62: a Contract with none fits every surgeon; otherwise any overlap, A10); `specialtyUsage` (72).

**Price ranges: `priceRanges.ts`.** `PriceRange {startISO, price}` (28). Starts unique, may be in the past; a range ends the day before the next start; last is open-ended. `rangeInForce(contract, dateISO)` (50) = latest start on or before date, else null ("Needs a price", `NEEDS_PRICE_LABEL` 240). `addRange/editRange/deleteRange` (69-78); `validatePriceRanges` (134, prepaid needs price above 0); `deleteRangeRefusal` (175, never the last); `rangeSummary(contract, today)` (225) for list rows; `describePriceRange` text helpers. Changing a price from a date = add a range. Prices are derived so a new or backdated range re-prices every un-held Procedure; issued invoices never change.

**Consequences of a Contract change: `contractChanges.ts`.** `proceduresStillOnContract(input, contractId, fromISO)` (43): Procedures on `governingContractId`, not cancelled, List not `AUTHORISED`, List date on or after `fromISO` (Draft Lists included), sorted by date/time; returns `StillOnRow` (procedureId, bookingId, listId, dateISO, scheduledTime, patientName, procedureText). `authorisedKeptPrice` (84) and `keptPriceOnContract` (126): authorised Procedures inside a range span that kept their locked price. Titles: `stillOnTitle` (138), `NOTHING_MOVES` = "Nothing moves by itself: open each to move it." (143). Nothing moves or re-prices a Procedure automatically.

**History: `contractHistory.ts`.** Read from the append-only audit. `CONTRACT_HISTORY_ACTIONS` (16): `contract.create|update|disable|enable|fallbackCreate|priceRange.add|update|delete`. `contractHistoryFor(audit, id)` (54), `contractFieldChanges` (38), `disabledDaysByContract` (68) and `contractDisabledOn(audit, id)` (81): the disable DAY comes only from the latest disable/enable audit entry (a Contract carries no date field).

**Where an invoice goes: `fallbacks.ts`.** `InvoiceDestination` (29) = `patient{prepaid} | hospital{holderPartyId, fundingTagId} | special{holderPartyId}`; `destinationOf(contract, parties)` (39) is derived, never stored; `destinationKey`, `destinationHint` (63: "Offered under St George's > ACC"). `ensureFallbacks` (242): exactly one system `open` Contract per destination, plus the `noContractRvg` and `rvgFallback` ones (`findFallback` 220, `seedFallbackId` 281).

**Step rail: `contractRail.ts`** (the Procedure's Contract picker; UI is the `ContractRail` component). Step 1 destination (Patient / hospital / Special, with counts), step 2 narrow (Patient: Standard then Prepaid; hospital: funding tags in order; Special: holders), step 3 Contract search over candidates only. `isContractCandidate` (111): active, not linked only to retired surgeons, no system Contract, `linkFits`, `contractFitsSpecialties`, fixed price needs a range in force on the List date. `contractCandidatesFor` (141, order: AA holder first, then name, AA code), `contractRailFor` (351), `RAIL_ROW_LIMIT` = 50, `suggestedPathFor` (334), `hospitalTagsFor` (300), `railAnswersFor` (445), `applyContractChange` (488), `contractChangeRefusal` (516; "Only the office changes a prepaid Contract"), `contractAllowedOn` (538, `anyStatus` option), `startForAddedProcedure` (563), `mayTypeEnteredPrice` (182). Insurance never narrows candidates.

**Other Contract-adjacent:** `contractEventFees.ts` (per-Contract fixed fees per pre/post-op event type; refusals `contractNotFound|priceInvalid|typeTaken|typeInvalid|codeTooLong|descriptionTooLong`), `startingValues.ts` (choosing a Contract fills the RVG code if empty), `rvgDetail.ts` (`asksRvgDetail`: RVG kinds ask for RVG code, start, finish, modifiers step; fixed/open collapse the form), `priceStatus.ts` (`priceStatusFor`), `masterLoad/` (section 8).

## 3. Pricing and fee engine

- **Price ladder, `procedurePrice.ts`** `priceFor` (127): first that applies: (1) AUTHORISED lock price (`held.authorised`), (2) prepaid amount once the prepayment invoice is raised, (3) typed `enteredPrice`, (4) computed (`computedPriceOf` 95: units x rate, less discount as its own amount; or the fixed range in force), (5) `needsPrice` (reason `openPrice | noRangeInForce`). Who may type a price: `anaesthetistMayTypePrice` (170), `officeMayChangePrice` (196), messages `INTEGRATION_PRICE_MESSAGE`, `PREPAID_PRICE_RAISED_MESSAGE`, `typedPriceProblem` (232). `timedRate.ts`: rate per kind (`rvgAnaesthetistRate` = anaesthetist unit value; `rvgContractRate` = Contract rate; `rvgDiscount` = unit value less pct) shared with timed events.
- **Fee, `fee.ts`**: `resolveBtm` (108) = Base + Time + Modifier units from captured inputs (overridden captures win; B from `baseUnitsFor` typed override > chosen range value > group figure > 0). `feeFor` (279) composes `FeeResult`. `unitsUnderRule` (168). `bookingFee.ts` is the one entry point: allocates a whole Booking (`multiProcedure.ts`) then `feeFor` per Procedure. `bookingTotal.ts`: office total incl. events (reading logged).
- **Time units, `timeUnits.ts`**: `DEFAULT_RVG_TIME_RULE` = 15-minute units to minute 120, then 10-minute units, part intervals round up (`timeUnitsFromMinutes` 95 min = 7, 120 = 8, 121 = 9). Rule is data in `masters.rvgTimeRule`; `validateRvgTimeRule`.
- **Modifiers, `modifiers.ts`**: RVG 2021 modifier master plus AA's own (hidden ids; codes not unique); age modifier from DOB on procedure date (under 1 = A2, 1 = A1, 2-69 none, 70-79 A1, 80+ A2; none on groups flagged `noAgeModifier`); claims need an explanation and entered units where the value is not a plain number.
- **RVG groups, `rvgGroups.ts`**: hidden id, non-unique printed code, base units, published range (guide), modifier units, included modifiers, retired flag; `rvgGroupPickRefusal` (not found, retired). `rvgDetail.ts`, `warnings/rules/baseUnitsOutsideGuide.ts` use the range.
- **Multi-procedure, `multiProcedure.ts`**: exactly one primary (`primaryOf` 34). Base units only on the primary even when it is fixed/open priced (PROVISIONAL, OQ-132/D78: then none is billed). Modifier units up to `MODIFIER_SPLIT_THRESHOLD` = 4 all on the primary; above it split `floor(total/n)` across RVG-priced participants, primary takes the remainder (`allocateModifierUnits` 100). Fixed/open Procedures take no share.
- **Lock (the pricing snapshot at AUTHORISED), `lock.ts`**: `buildBookingLock` (294) copies each Procedure's Contract settings with only the range in force, RVG group, B/T/M, rate, discount, price, who is billed, split shares, payee (the List's anaesthetist at authorise), GST rate, totals. `invoiceDraftsFromLock` (486) and `priceBookingFromLock` (567) read the lock only (no masters). Rejected Bookings are held back whole. `lockViewFor` (831), `compareInvoice` (619), `migratedLockFromInvoices` (672) for seeded history, `authorisedPricesFromLock` (889), `lockedContractIds` (884). `invoiceBuild.ts` previews the same via the lock builder.
- **Split, `splitShare.ts`**: shares `amount | percent | rest`; `resolveSplit`, refusal when the party is gone or no fee yet; credit with `CreditCause 'split'` when changed after invoicing.
- Money: `money.ts` (`roundToCents`, `toCents`, `formatMoney`). GST is `GST_RATE` = 0.15 (`invoicePresentation.ts:50`), added once at invoice foot; all prices held ex GST.

## 4. Billing outputs

- **Who is billed, `whoIsBilled.ts` and `procedurePayer.ts`**: a Contract with `billsTo: holder` bills the holder Party; every other Contract bills the Procedure's payer (patient or other person). `billablePartyForProcedure` (82), `invoiceDeliveryFor` (303; email, post or noAddress), `payerContactMissing` (217), `childPayerOn`/`isMinorOn` (`ADULT_AGE` 257 to 274). `payer.ts`: email and address validation sentences.
- **Invoice presentation, `invoicePresentation.ts`**: layout (holder's vs patient's), supplier block, cross-match, line views (`invoiceLineViews`); `invoiceRecord.ts` the stored invoice from a draft; `insurance.ts` insurer/funder choice lists, approval number.
- **Prepayment, `prepayment.ts`, `prepayHolding.ts`, `prepaymentLetter.ts`**: a Procedure needs prepayment when its Contract is `prepaid` (fixed price; never RVG kinds). Per-payer groups (`prepaymentGroupsFor` 195), status (`none|awaitingApproval|unpaid|partPaid|paid|notNeeded|changedAfterSending`, `prepaymentStatusOf` 274), draft invoice (`prepaymentInvoiceDraftFor` 323). Payable of a prepayment goes to `AA_HOLDING_ACCOUNT` (not paid itself); a transfer (`newPrepayTransfer`, ledger 202) moves it to whoever did the List. Letters: merge fields (`LetterMergeField` types.ts 1742), kinds `request|reminder|anaesthetistChanged`.
- **Ledger, `ledger.ts`** (805 lines; Phase 36): every invoice is a pair (receivable, payable/BCTI) made in the same mutate (`newBookingPair` 128, `newAaFeePair` 166). Payable released exactly as money is received (`applyReceipt` 258, `payableRelease.ts`). `applyDisbursement` 299, `applyOffset` 317, `applyCredit` 346. `ledgerChecks` (449) imbalance formula: receiptsHeld - payablesDue - holdingBalance - creditsHeldForPayers + recoveryDue. `ledgerPosition` 515, `anaesthetistPosition` 617, `patientPosition` 733, `bctiRecordsOf` 783. Amounts exact to the cent; `gstComponentOf` = 3/23 of gross.
- **BCTI and AA fee**: `bcti.ts` (one BCTI per receivable, counted once per anaesthetist per month; `BCTI_COUNT_RULE`, OQ-29 open), `aaFee.ts` (`aaFeeFor` = fixed items + per-BCTI charge x count, ex GST; `buildAaFeeInvoice` 92; `validateAaFeeSettings`).
- **Credit notes, `creditNote.ts`**: credit is always for the whole invoice (no part credit, OQ-97/D31); reverses the payable; replacement invoices point back (`ReplacementLink`); `splitTotalCheck`. `additionalInvoice.ts`: free-form lines (qty x unit, no Contract/RVG imports, pinned by test). `billingEvent.ts`: free-text charge or credit with typed amount ex GST. `procedureEvent.ts`: `EVENT_KINDS` (54), `eventInvoicing` (173), party resolution. `prePostOpEvent.ts`: `EVENT_TYPES` (64) accPreOpAssessment, otherPreOp, postOpWardReview, hduReview, painConsult, otherPostOp; each records a time or fixed fee, no modifiers/base units; `ACC_PREOP_PRESETS`; `validatePrePostOpEvent` 167; `pricePrePostOpEvent` 227 (`NO_EVENT_RATE_MESSAGE`); types constants "until Phase 42 says otherwise".
- **Payables run and cycle, `payablesRun.ts`, `paymentCycle.ts`**: weekly cycle named by ISO week (days from `appSettings.paymentCycle`: Friday close, Monday checks, Tuesday schedule; Proposed, OQ-47). `buildWeekRun` 84, `applyHolds` 125 (`heldInHoldingAccount`), `netNegatives` 146 (oldest negatives net against oldest positives; run never pays below zero), `paymentSchedule` 212, `remittanceAdvice` 254, `reconcileWeek` 156, `weekAnomalies` 193.
- **GST report, `gstReport.ts`**: per anaesthetist per calendar month from ledger disbursements only (cash basis; each part-payment falls in its month).
- **Xero rules (pure), `xero/`**: `queue.ts` exponential backoff (2,4,8,16,32,60,60 minutes; alert from N failures), `divergence.ts` compares ledger receivables with Xero mirror. ## 5. Scheduling

- `slots.ts`: Slot id `S-<registration>-<date>-<AM|PM>`; AM/PM generated per active anaesthetist across the horizon. `clock.ts` horizon: `HORIZON_PAST_DAYS` 14, `DEFAULT_HORIZON_MONTHS` 4 (`horizonFor` 105).
- `slotStatus.ts`: statuses are master rows read by id (`SEED_STATUS`: free, holiday, unavailable, publicHospital). Helpers `isOpenForBooking`/`isClosed` (via `bookable`), `validateSlotStatusDraft` (214; label max 16, long 32, description 160; refuses a name equal to a List state), `validateRetireSlotStatus`, `validateAvailabilityRange`, `slotsInRange`.
- `availabilitySeries.ts`: repeating days off (weekday set, sessions, every 1-4 weeks, from/until, per-instance exceptions); writes status onto Slots.
- `holidays.ts`: hospital closed on a date if it has its own holiday or a public holiday not listing it open. `conflicts.ts`: a List conflicts only when its hospital is closed (soft warning, never a block); anaesthetist unavailability never conflicts (the List is moved first).
- `listPairing.ts` `pairingIssues`: one hospital and surgeon on every List; anaesthetist and Slot on ACTIVE/SUBMITTED/AUTHORISED. `draftLists.ts`: Draft = no anaesthetist/Slot; `compareDraftLists`, `waitingMinutes`, `draftListAvailability`, `assignDraftToSlot`, `draftFromActive`, recurring-clash helpers, `DRAFT_ASSIGN_WARNINGS`. `listProgress.ts`: when a List leaves the anaesthetist's main view and its label. `lists/listOrigin.ts`: origin stamped at creation, `originAfterRoomsRow`.
- `listMoves.ts`: anaesthetist moves own List (availability only, no pairing prefs or tiers; `receiveRefusal`, `pushTargets`). `bookingMoves.ts`: move a single Booking to a free colleague, always into a new List (D61). `recurringBookingProjection.ts`: recurring booking projects Lists across horizon; closed sessions skipped and named. `outOfHours.ts`: `OOH` session opened by the office, at most one per anaesthetist per day, never generated.
- `pairingPreferences.ts` (office-private; surgeon/anaesthetist `NOT_PREFERRED|PREFERRED`, tiers 1-4, within-tier shuffle with seeded RNG): no import from the anaesthetist apps (privacy test).
- History: `bookingAsAt.ts` (undo the audit newest-first to a cut; `REVERSE` map per action code), `changeSets.ts` (`snapshotBooking`, `diffSnapshots`), `updateEmail.ts` (`pickableChanges`, `netPicked`, `EMAIL_FIELDS` allowlist), `notifications.ts` (one shared admin pool, no user).
- Search and text: `bookingSearch.ts` (NHI-shaped query matches exactly; else every name word), `dateText.ts` (all date formats), `dateDays.ts`, `names.ts`, `surgeons.ts`, `surgeonContacts.ts`, `bankAccount.ts` (dashed NZ account; shape only, no check-digit modulus).

## 10. Gaps seen against the 25 Nov Contracts-section decisions (for the planner)

- No Contract-level "replace from a date" concept exists: no field, no pure function, no audit action beyond the eight in `CONTRACT_HISTORY_ACTIONS`. The `contractChanges.ts` header mentions "a new Contract that replaces this one from a date" but only supplies the listing (`proceduresStillOnContract`), which is keyed on the old `contractId` and a `fromISO`; nothing moves Procedures.
