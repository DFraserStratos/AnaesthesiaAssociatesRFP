# Prototype map: domain layer (aa-prototype/src/domain, excluding seed/)

Paths are relative to `aa-prototype/src/domain/` unless they start `aa-prototype/`. The layer is pure TypeScript: no React, store, routes, `fetch`, `Date.now()` or `Math.random()` (`domainPurity.test.ts` forbids imports of react/zustand and of `../store|theme|apps|shell|shared`). It holds the types (`types.ts`, 3109 lines, the one entity file), the demo clock, the NHI/NZHIS rules, the whole billing engine (`billing/`, about 70 files, "one place per rule"), the integration translators, the intake matcher, the warning rules and the schedule/availability rules. There are NO routes or screens here: screens, store actions and the audited `mutate()` live in `src/store` and `src/apps`; each section says which store file consumes the rule where known. Guards that return refusals as data (`Outcome`) live in `store/lifecycle.ts`, not here. Barrel: `index.ts` exports most modules but deliberately NOT `xeroSim` (US-10.2.4 fence). Almost every file comments "catch-up Phase NN; US-xx" and "our reading" notes: those mark choices the owner still has to confirm.

## 2. Lifecycle and schedule rules

- **List lifecycle**: the transition guards are in `aa-prototype/src/store/lifecycle.ts` (`submitList :241`, `authoriseList :301`, `completeBooking :131`, `editRefusal :68`, `authoriseBlockersFor :407`). ACTIVE to SUBMITTED to AUTHORISED strictly ordered, no Returned state; anaesthetist edits own ACTIVE and SUBMITTED Lists until authorised; office edits ACTIVE/SUBMITTED; nobody edits AUTHORISED; integration writes only while ACTIVE. Domain parts: `listProgress.ts` (`ListProgress` toFinish|readyToSubmit|submitted|invoiced|authorised|upcoming; `hasLeftMainView` = AUTHORISED), `listPairing.ts:40 pairingIssues` (hospital + surgeon required, known, newly chosen retired record refused, unchanged retired allowed), `draftLists.ts:46 assignDraftToSlot` (DRAFT to ACTIVE, keeps id/Bookings/trail).
- **Draft Lists** (`draftLists.ts`): `compareDraftLists` order, `waitingMinutes`, `draftListAvailability`, `recurringClashDraft`, `draftFromActive`, `removeBlockedReason` (active Bookings must be moved/cancelled first), `DRAFT_ASSIGN_WARNINGS` closed-hospital wording (warn, keep conflict). Closed or inactive session is refused, not warned (`listMoves.ts:80 sessionNotOpenRefusal`).
- **Moves**: `listMoves.ts` (`receiveRefusal :108`: same day and session, different empty slot, active colleague, open status; `ownMoveRefusal :139`: only owner, only ACTIVE, today or later, never Draft/SUBMITTED/AUTHORISED; `pushTargets`, `movableListsFor`, `VACATED_SESSION_CHOICES` free|unavailable). `bookingMoves.ts` single-Booking move: receiver must be free in that session; always creates a NEW List (never joins one); `RECEIVER_LINES` reasons noSlot|notAvailable|hasList. Both are availability-only: deliberately never read pairing preferences or tiers (D44).
- **Slots/status**: `slots.ts` (`slotIdFor`, `projectedListId`, `effectiveSlotTimes`, `defaultScheduleSettings` = 4 months, AM 07:30-12:30, PM 13:00-17:30), `slotStatus.ts` (lookups; `validateSlotStatusDraft` limits label 16, longLabel 32, description 160; List-state words refused as status names `:195`; `validateRetireSlotStatus`; `isOpenSlot`, `anaesthetistChoices`, `validateAvailabilityRange`, `slotsInRange`). Status colour provenance and parity: `statusTokenParity.test.ts`.
- **Availability series** (`availabilitySeries.ts`): repeating days off; `validateSeriesDraft` (>=1 weekday, every 1-4 weeks, AM/PM/both, start today or later, within horizon), `seriesOccurrences/Instances`, `planSeriesWrite` (writes status onto Slots), exception keys `date-session`, `activeSeriesUsing` (blocks retiring a status).
- **Recurring bookings** (`recurringBookingProjection.ts`): `projectRecurringBookingChange` returns a plan {create, update, remove, kept, skipped}; kept reasons hasBookings|hasRecords|submitted|authorised|officeEdited|movedByOffice|otherRecurringBooking|draft; a closed session becomes a Draft List (recurringClash) not a silent skip; `activeOn/coversDate`.
- **Conflicts/holidays**: `holidays.ts` (Closure from hospital holidays + public holidays with `openHospitalIds`; `shutdownAt`), `conflicts.ts` (`expectedConflicts`, `reconcileListConflicts`, clears kept as cause string `holiday:<id>`/`publicHoliday:<id>`; `isBackdropList` = ids starting `L-HIST`/`L-RB-`, excluded from office surfaces; `CONFLICT_REASONS` = "Hospital closed"). Applied by `store/conflictReconcile.ts`.
- **Out of hours** (`outOfHours.ts`): session `OOH`, default 18:00 to 21:00, max 1 per anaesthetist per day, `openOutOfHoursRefusal`, `outOfHoursTimesRefusal`, `sessionRank` order AM, PM, OOH. Who may open one when the office is closed is open with AA.
- **Anaesthetist activity** (`anaesthetistStatus.ts`): `statusOn` active|leaving|inactive from start/lastDay/activeAgain; `isActiveOn/During/InMonth`, `listsAfterLastDay`, `ownContracts`, `contractsToOfferBack` (contracts to offer back when inactive; actor label `INACTIVE_CONTRACTS_RULE_WHO`). `anaesthetistPanel.ts` (side-panel rows: linked contracts, next Lists).
- **Master retire** (`masterLifecycle.ts`): `isRetired`, `retireBlockers(kind hospital|surgeon|aaModifier, facts)`. `masterValidation.ts` hospital/holiday/public-holiday field rules; `surgeons.ts` HPI CPN shape (2 digits then 4 letters... shape only), `surgeonContacts.ts`, `specialties.ts` (specialty usage and `contractFitsSpecialties`, empty means all), `pairingPreferences.ts` (labels, tiers, `pairingAcknowledgement` for NOT_PREFERRED, `OFFICE_PRIVATE_AUDIT_ACTIONS`), `bankAccount.ts` (BB-bbbb-AAAAAAA-SS shape only, no modulus check, `maskBankAccount`).
- **Booking history**: `changeSets.ts` (`snapshotBooking`, `diffSnapshots`, `changeSetsFor`; ignores lastModified*), `bookingAsAt.ts` (undoes the audit newest-first via a `REVERSE` table per action code), `bookingSearch.ts` (anaesthetist search: query min 2 chars; NHI-shaped query matches exactly, either format, check char not required; name search folded).

## 3. Clock, NHI, NZHIS, privacy, patients

- `clock.ts`: `DEMO_TODAY = '2026-11-24'`, `INITIAL_CLOCK` 08:00, pure `today/now/advanceMinutes/advanceDays`, `HORIZON_PAST_DAYS = 14`, `DEFAULT_HORIZON_MONTHS = 4`, `horizonFor`. Store owns the state (`store/clockActions.ts`). `rng.ts` seeded streams only.
- `nhi.ts`: `validateNhi` (:72). 7 chars, no I/O. Current `AAANNNC`: weights 7,6,5,4,3,2, mod 11, remainder 0 invalid, check digit = 11 - r (10 becomes 0). New `AAANNAX`: mod 23, check letter = alphabet[23-r-1]. Header notes the catalogue still labels the current format "modulus 24" (a flagged mismatch). `nhiEntryFeedback` live feedback, `generateNhi`, `NHI_REASONS` single source for copy.
- `nzhis.ts`: `ETHNICITY_DEMO_SUBSET` (12 Level 4 codes, curated), `validateEthnicityCode` verdict valid|outsideDemoSubset|malformed (5 digits).
- `nhiRegister/`: synthetic national register (built from seed, never stored): `lookupOnRegister` (validates first; invalid NHI never "reaches" it), `registerDifferences` / `applyRegisterRefresh` (fill blanks automatically; differing values only if office chooses `useRegister`, default `keep`). Hub availability simulated via `DemoSettings.nhiHubMode`.
- `patients/`: `buildNhiIndex` (reports duplicates), `detailDifferences` (name/address trimmed case-insensitive, phone digits, DOB exact; differences held in `pendingDetails`), `waitingNhi` (`WAITING_NHI_URGENT_WITHIN_DAYS = 3`), `patientBalance.ts` (only receivables billed to the patient themself count; `patientBalanceSummary`, strength none|mild|strong by age vs threshold, `patientCentricBalance`).
- `privacy/`: `findNhiTokens/redactNhis` (check-digit-valid tokens only), `maskRawRow` with `RAW_ROW_MASKING` policy (nhi, yearOnly, lastThree, domainOnly, suburbOnly, initials; `MASKING_POLICY_NOTE` says AA must agree it). `xeroContact.ts`: patient/billable-party Xero contacts carry only the hidden internal id label, never PII.
- `dateText.ts` date/time text helpers ("Tue 21 Jul to Fri 24 Jul"; always "to", never dashes); `names.ts` surname forms; `dateDays.ts`.

## 4. Billing: contracts, parties, step rail, pricing, units

- **Party** (`billing/parties.ts`): kinds `aa|hospital|insurer|funder|surgeon|surgeonGroup|anaesthetist`; fields name, codePrefix, billingName, email, postalAddress, deliveryMethod email|post, hospitalId. `partyRefusal` codes include oneAaParty, aaReadOnly, codePrefixFormat/Taken, kindFixedWhileHolding, oneHospitalParty, billingNameRequired, deliveryRequired, emailRequired, postalAddressRequired (`PARTY_REFUSAL_MESSAGES`). Counts per party/tag in `partyContracts.ts`. `fundingTags.ts` (FundingTag SXAP/HNZ/ACC style; ACC is a tag not a contract kind; `isAccTag`, `procedureAccFunded`, `moveFundingTag`).
- **Contract** (`contracts.ts:67`), flat, edited in place, Active|Disabled, never deleted: aaCode, holderReference, invoiceDescription, defaultRvgGroupId, name, holderId, `billsTo holder|payer`, linkedSurgeonIds, linkedAnaesthetistId, `prepaid`, `anaesthetistMayOverridePrice`, `pricing` (`rvgAnaesthetistRate | rvgContractRate{unitRate} | rvgDiscount{discountPct} | fixed{ranges[]} | open`), systemRole (`noContractRvg|openPriceFallback|rvgFallback`), specialtyIds, fundingTagId. 24 refusal codes (`ContractRefusalCode`, `CONTRACT_REFUSAL_MESSAGES`): e.g. prepaidBillsPayer, prepaidNotRvg, prepaidFixed, overrideOnlyRvg, holderBillsPayer, noLinksOnHospital, linkRequired, systemNeverDisabled, pricingKindFixed (kind cannot change after creation). Helpers: `nextAaCode`, `contractSearch`, `linkFits` (where offered), `noContractRvg`, `billsPayerOnly`, `takesLinks`. System fallbacks per destination in `fallbacks.ts` (`InvoiceDestination`, `destinationOf` derived never stored, `openPriceFallback`, `rvgFallback`).
- **Price ranges** (`priceRanges.ts`): fixed contracts hold dated ranges; range in force = latest start on/before date; starts unique, past allowed; `validatePriceRanges` (prepaid needs a price), `rangeInForce`, add/edit/delete refusals.
- **Contract grouping/history**: `contractGroups.ts` (six groupings kind|holder|tag|surgeon|destination|pricing), `contractHistory.ts` (audit-derived history, replacements, disabled days), `contractChanges.ts` (`proceduresStillOnContract`, kept prices; "nothing moves by itself"), `contractSimilarity.ts` (similar-name hint, never blocks), `contractEventFees.ts` (fixed fee per pre/post-op event type replaces recorded time).
- **Step rail** (`contractRail.ts`): decision that prices a Procedure. Step 1 destination Patient|hospital|Special; step 2 narrow (Patient: Standard|Prepaid, never Prepaid for anaesthetist; hospital: funding tags in order; Special: holders); step 3 Contract search among candidates. `isContractCandidate :111` (Active; held by List's hospital, or linked to its surgeon/anaesthetist, or unlinked AA/insurer/funder; specialty overlap; fixed price needs range in force; insurance never narrows), `contractRailFor :351`, `suggestedPathFor`, `contractChangeRefusal :516` (prepaid contract office only, open price typed by office unless contract lets anaesthetist, not-a-candidate), `applyContractChange`, `startForAddedProcedure`. `RAIL_ROW_LIMIT = 50`. `startingValues.ts` fills RVG code from contract default only if none set.
- **Price function** (`procedurePrice.ts`): `priceFor` ladder: held `authorised` (snapshot) > `prepaid` line > `typed` (enteredPrice) > computed; result `priced{price, heldBy, computed}` or `needsPrice{noRangeInForce|openPrice}`. Computed: `rvgAnaesthetistRate` units x anaesthetist `unitValue`; `rvgContractRate` units x unitRate; `rvgDiscount` units x unitValue less discount (rounded once); `fixed` range price; `open` none (`timedRate.ts` is the one rate source, shared with timed events). `anaesthetistMayTypePrice`, `officeMayChangePrice` (prepaid raised: use credit/additional invoice), `INTEGRATION_PRICE_MESSAGE` (integration cannot change a price), `typedPriceProblem` (not below 0), `isNoChargeBooking`. `priceStatus.ts` = "Needs a price" selector.
- **B/T/M** (`fee.ts`): `resolveBtm :108` base from RVG group (`rvgGroups.ts baseUnitsFor`: typed override > chosen value on ranged group > starting figure > 0 without code; any value accepted, outside-guide only warns), time from `timeUnits.ts` (tiers as data in `masters.rvgTimeRule`; default 15 min units to 120 min then 10 min, part interval rounds up: 95 min=7, 120=8, 121=9, 125=9), modifiers from `modifiers.ts`. `feeFor :285` yields lines (RVG line with units, discount line), subtotal, total, `needsPrice`. Overridden captures win over computation.
- **Modifiers** (`modifiers.ts`): modifier master = NZSA RVG 2021 table + AA's own (hidden id, code not unique); `AGE_BANDS` completed years on procedure date: under 1 = A2, 1 = A1, 2-69 none, 70-79 A1, 80+ A2; origins chosen|age|included; `claimRefusal` (explanation required, max 200 chars, duplicates and pre-applied refused, entered units validated for ranged rows), `resolveModifiers`, `claimCompletionProblems`.
- **Multi-procedure rule** (`multiProcedure.ts`, `bookingFee.ts`): base units only on primary; time on every procedure from its own start/finish; Booking modifiers recorded once on primary, all on primary while total <= 4 (`MODIFIER_SPLIT_THRESHOLD`), above 4 split equally across RVG-priced procedures with remainder to primary (7 over 3 = 3/2/2); fixed/open-priced procedures take no share and lose none; exactly one primary else refusal `NO_PRIMARY_MESSAGE`. `allocateBooking`, `bookingFeeFor`.

## 5. Billing: completion, review, lock, invoices, who pays

- **Completion** (`completion.ts:75 completionFailuresFor`): a Booking can be completed when each Procedure has a Contract, on RVG kinds the RVG code + start + finish (finish after start) + modifiers step answered (primary only) + valid claim explanations, and a price (not "Needs a price"). Approval number, payer contact are NOT conditions. Failure codes noContract|contractGone|rvgCode|startTime|finishTime|modifiersStep|modifierExplanation|needsPrice, with `fixableBy` anaesthetist|office. `rvgDetail.ts` decides what a pricing kind asks for (fixed/open collapse the form). Moving a completed Procedure to an RVG kind reopens it (`contractChangeAsksRvgDetail`).
- **Review flags** (`reviewFlags.ts`; never block): contractChanged, contractNoLongerFits, contractDisabled, needsInvoiceDestination, needsPrice, typedPrice, notCompleted, payerContactMissing, btmOverride, prepayment (Prepaid left off / sent no longer needed / sent before a change).
- **Pricing snapshot at AUTHORISED** (`lock.ts`: `buildBookingLock :294`, `BookingLock`, `ProcedureSnapshot`, `invoiceDraftsFromLock :486`, `contractAsLocked`): copies contract settings with only the range in force, RVG group, fee as recorded, who is billed, split shares, payee (List's anaesthetist at authorise), patient and billed parties as printed, GST rate, totals checksum. Unpriceable Booking locks `rejected` and is held back whole while the rest of the List bills. Run never reads live masters. Messages `LOCK_MISSING_MESSAGE`, `PREPAID_SPLIT_MESSAGE`. `invoiceBuild.ts` = preview via the same lock path; `invoiceRecord.ts` draft to stored `Invoice`; `validateBookingForBilling.ts` pre-flight (holder exists, price computable, split fits; cancelled excluded).
- **Invoice presentation** (`invoicePresentation.ts`): `GST_RATE = 0.15` constant (prices ex GST, GST at foot), layout holder vs patient, BTM breakdown and cross-match only on holder layout, supplier+agent, buyer-created tax invoice wording (PROVISIONAL, OQ-29), delivery stamp. `invoiceState.ts` (Finances Invoices tab rows: invoice|prepayment|creditNote; unpaid|partPaid|paid|awaitingApproval; default filter unpaid).
- **Who is billed** (`whoIsBilled.ts`, `payer.ts`, `procedurePayer.ts`, `partyOptions.ts`): contract `billsTo` decides holder vs the Procedure's own payer (patient or `BP####` other payer, identity not name matching); `payerContactMissing`, `invoiceDeliveryFor` (email vs post vs noAddress); address validation NZ-style (4-digit postcode, street/PO Box, city) and email shape (`payer.ts`). `insurance.ts`: only an insurer (not funder like ACC/HNZ) needs an approval number. `procedureStack.ts`: procedure text kept as received (hospital's replaces rooms'), invoice description default order (D37), `whoIsInvoicedFor`, `pricingBasisFor`.
- **Split** (`splitShare.ts`): user-typed shares `$48` or `48%` or "rest"; >=2 distinct parties, at most one "rest" and typed shares must be below fee; `resolveSplit` exact to cents; refused for prepaid; `splitDoesNotFitMessage`.
- **Prepayment** (`prepayment.ts`, `prepayHolding.ts`, `prepaymentLetter.ts`): prepaid contracts (Patient > Prepaid, never RVG kinds; or Prepaid fixed backstop with typed amount); derived per Procedure and per payer group (D85), amount = Procedure price when raised, then read-only; statuses awaitingApproval|unpaid|partPaid|paid|notNeeded|changedAfterSending; `AA_HOLDING_ACCOUNT` payee (never paid out by the run; moves to anaesthetist at List authorise via `transferFor`); `PREPAYMENT_NAMES_ANAESTHETIST = true` (OQ-120 open); letters from admin templates with merge fields, estimate wording refused (`validateLetterTemplate`, name max 60, body max 2000), kinds request|reminder|anaesthetistChanged. Approval setting `appSettings.prepayment.approvalRequired` (default on).

## 6. Billing: events, credits, ledger, payment cycle, fees

- **Events** (`procedureEvent.ts` `EVENT_KINDS`, `EVENT_RULES`): additionalInvoice and credit (office any Procedure, anaesthetist own only; needs an invoiced Procedure; always own invoice); preOp/postOp/billing (anaesthetist own or office; invoice tick shown; may bundle on the same party's run invoice). All reviewed by office (`review.state`). "Next billing run" is an explicit `runEventInvoicing` (demo action), not scheduled.
