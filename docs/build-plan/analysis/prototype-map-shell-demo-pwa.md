# Prototype map: shell, demo surfaces, demo triggers, PWA

Orientation. This area is the prototype's harness, not product UI. `aa-prototype/src/main.tsx` mounts `App.tsx` -> `AppRouter` (`src/router.tsx`), a data router (`createBrowserRouter`, built once, `useBlocker` for the Admin Booking unsaved-changes guard). One layout route (`AppShell`) holds a 48px ink harness bar (product name, persona chip, **app switcher**, **Demo actions** menu, **demo clock** menu, **Reset**) above the routed app. Under it sit the three apps (`/web`, `/admin`, `/mobile`, the last inside the simulated `PhoneFrame`) and four demo-only surfaces (`/demo/*`). Screen-contextual **demo triggers** (87 entries, `src/shared/demoTriggers/registry.ts`) show in the bar's Demo actions menu (surface `bar`) and, for the handset, in the PWA's Demo sheet (surface `pwa`). `/demo/control` is the presenter index: clock, Reset, the S1 to S5 scenario jumps and a by-screen index of every trigger (it fires none). The installable PWA (`pwa/main.tsx`, `vite.pwa.config.ts`) is the Mobile App alone: no `AppShell`, no web/admin/demo code (`src/pwa/pwaPurity.test.ts` enforces it). All state is the one Zustand store; triggers call store actions as named actors. Nothing here is product behaviour except where noted.

## 3. Demo-trigger machinery (src/shared/demoTriggers/)

Not re-exported from `shared/index.ts` (import by path or `shared/demoTriggers`).
- `types.ts` `DemoTrigger`: `id` (kebab, `data-shot="demo-action-<id>"`), `label` (no en/em dash), `description`, `screen` (Control Panel heading), `alsoScreens?`, `routes` (react-router `matchPath` patterns, `end: true`, against full pathname, first match wins), `surfaces: ('bar'|'pwa')[]`, `badge?` ('future-scope' | 'office-stand-in' | 'colleague-stand-in'), `overSheet?` (PWA chip lifts above an open sheet), `when?(state, ctx)`, `choices?(state, ctx)`, `defaultChoice?`, `disabledReason(state, ctx, choiceId)` (null = runnable), `run(api, ctx, choiceId) -> {ok, message, link?}`, `confirm?` (bar only: two-click), `indexPath(state)` (Control Panel "Open screen"; null = nowhere yet), `indexEmptyReason?`, `indexHint?`. `ctx` = `{pathname, params, published}`.
- `match.ts`: `demoTriggersFor(state, pathname, surface, published)` (registry order; filters by surface, route, `when`), `groupTriggersByScreen` (by `screen`, then `alsoScreens`), `initialChoice`.
- `useDemoTriggers.ts`: `useDemoTriggerRows(surface)` is the one behaviour shared by bar and PWA sheet: per-row choice/result state keyed by pathname (reset on route change), `armed` confirm state, calls `trigger.run(useAppStore, ctx, chosen)`. Re-renders on store, published-context, trigger-memory and sign-in-session changes. The PWA sheet ignores `confirm` and `result.link` (only the bar renders them).
- `context.ts`: UI-only store `useDemoContextStore`; screens publish state the URL cannot carry via `useDemoTriggerContext(key, value)` / `useDemoTriggerContextWhile(key, value, active)`. Keys (publisher): `integrationsSim.selectedMessageId` (DemoIntegrations.tsx:57); `matching.selectedRowId` (admin/screens/MatchingScreen.tsx:62); `aaFees.month` (AaFeesScreen.tsx:74); `adminDay.selectedSlotId` (components/SlotDrawer.tsx:79; nothing consumes it); `adminDraftLists.openListId` (DraftListDrawer.tsx:66); `adminMasters.view` (screens/masters/MasterData.tsx:48); `adminPicker.listId` (SessionStatusSheet, AssignDraftListSheet, ReassignListFlow); `adminContracts.openContractId` (admin/screens/contracts/ContractPage.tsx:62, on the Contract page); `adminContracts.tab` ('contracts'|'parties'|'fundingTags', ContractsSection.tsx:37, published as 'contracts'; Phase 48 adds the other two tabs); `mobileCalendar.day` (mobile/routes.tsx:248); `adminBooking.dirtyBookingId` (AdminBookingDetail.tsx:81); `nhiHub.inUse` (ManualBookingForm, AddNhiSheet, RegisterRefresh); `support.tab`, `support.requester` (shared/support/SupportPanel.tsx:42). New key = add to `DemoContextValues`, publish from the screen.
- `memory.ts`: `useDemoTriggerMemory` (UI-only, unpersisted): `lastMessageId`, `lastWebhook`/`webhookCounter` (payment replay), `photoCaptureRequest` (read by mobile/routes.tsx:75), `regenerated[invoiceId]` (read by InvoiceDocument.tsx:662), `nhiScan` (read by PrivacyChecks). `nhiScan` cleared on `onDomainReset`.
- `InlineDemoTrigger.tsx`: runs a registry entry by `id` from inside a product sheet (dashed "demo" button + badge); only user: `ask-colleague-make-available` in admin/components/pairing/AnaesthetistCandidates.tsx:206 (picker scrims cover the bar).
- `procedureTextTriggers.ts`: pure helpers for `hospital-description-arrives` (AR-35 wordings from `domain/seed/sourceWording`). `demoGuidePresses.ts`: test support for `demoGuideSync.test.ts`. `DemoTriggerBadge.tsx`: badge component.
- **How a trigger calls the store:** `run: (api) => helper(api, ...)`, where `api` is the bound `useAppStore`; helpers live in `src/store/*` (named actors from `store/demoActors.ts`: `OFFICE_ACTOR`/`officeActorOf(shell)`, `SOUTER_ACTOR`, `HOSPITAL_FEED_ACTOR`, `SEED_LOAD_ACTOR`, `STRATOS_SUPPORT_ACTOR`) and go through `mutate()`/lifecycle guards, so audit shows the stand-in. Exceptions: `switch-office-user` calls `api.getState().setOfficeUser` (no audit); `pwa-sign-out` writes the browser session (`shared/session/anaesthetistSession`, not AppState); `photo-capture-future` writes trigger memory only; `scan-nhi-leaks` writes memory.
