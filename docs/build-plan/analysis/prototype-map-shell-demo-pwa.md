# Prototype map: shell, demo surfaces, PWA, router, demo-trigger registry

Paths are relative to `aa-prototype/` unless absolute. Line numbers are as read on master (f885f67c). Read-only analysis.

**Orientation.** `src/main.tsx` mounts `App.tsx` -> `AppRouter` (`src/router.tsx`, a data router from `createBrowserRouter`, built once). Every route sits under the layout route `AppShell` (`src/shell/AppShell.tsx`), the 48px dark harness bar (title, "Prototype" pill, synthetic-data badge, persona chip, app switcher, Demo actions menu, demo clock menu, Reset) above an `<Outlet/>` in `<main data-aa-modal-scope>`. The three product apps (`/web`, `/admin`, `/mobile`) are nested layout routes whose screens are mapped in other files; this file records only their route table. Demo-only surfaces live in `src/apps/demo` (`/demo/control|xero|integrations|data|catalogue`). Demo actions are NOT buttons on the Control Panel: they are `DemoTrigger` entries in `src/shared/demoTriggers/registry.ts` (88 entries), matched by pathname and shown in the harness bar (`bar` surface) or the installed PWA's "Demo" bottom sheet (`pwa` surface). The Control Panel holds the clock, Reset, the S1 to S5 scenario jumps and a read-only index of the registry. The PWA (`pwa/main.tsx`, `vite.pwa.config.ts`) mounts only the Mobile App with `MobileViewport` as host, with no `AppShell`; presenter controls move behind the More tab (`PwaDemoPanel`) and the Demo chip (`PwaDemoActions`).

## 1. Route table (`src/router.tsx`)

`RootRedirect` (router.tsx:~95) sends `/` and any unknown path to `APP_CONFIG[shell.currentApp].path` (last-selected app, persisted). Legacy `.../cards/:cardId` routes go to `LegacyBookingRedirect` (`shared/legacy`).

## 4. Demo-trigger registry (`src/shared/demoTriggers/`)

**Files.** `types.ts` (contract), `registry.ts` (`DEMO_TRIGGERS`, 2955 lines, entries start line 847), `match.ts` (`demoTriggersFor(state, pathname, surface, published)`: filter by `surfaces`, `matchPath({path, end:true})` over `routes`, then `when`; `groupTriggersByScreen`; `initialChoice`), `useDemoTriggers.ts` (`useDemoTriggers`, `useDemoTriggerRows(surface)`: per-row choice/result/armed state reset on pathname change; results keyed `pathname|id`; `run` = arm confirm if `confirm` set, else `trigger.run(useAppStore, ctx, chosen)`), `context.ts` (published-screen-state store), `memory.ts` (replay memory: `lastMessageId`, `lastWebhook`, `webhookCounter`, `photoCaptureRequest` (consumed by `MobileListsRoute`), `regenerated` per invoice, `nhiScan`; cleared on `onDomainReset` for nhiScan), `InlineDemoTrigger.tsx` (runs a registry entry by id from inside a dialog; used only by `apps/admin/components/pairing/AnaesthetistCandidates.tsx:206` for `ask-colleague-make-available`), `DemoTriggerBadge.tsx`, `procedureTextTriggers.ts` (pure helpers for hospital-description), `demoGuidePresses.ts` (test support, parses the guide's "Demo actions → Label" / "Demo sheet → Label" presses; `demoGuideSync.test.ts` checks them against the registry), `index.ts` barrel.

**`DemoTrigger` shape** (`types.ts`): `id` (kebab-case, also `data-shot="demo-action-<id>"`), `label`, `description`, `screen` (Control Panel heading), `alsoScreens?`, `routes[]` (matchPath patterns), `surfaces` (`'bar'|'pwa'`), `badge?` (`future-scope|office-stand-in|colleague-stand-in`), `overSheet?` (PWA chip lifts above an open sheet), `when?(state,ctx)` (visibility), `choices?`, `defaultChoice?`, `disabledReason(state,ctx,choiceId)` (null = runnable), `run(api, ctx, choiceId) -> {ok,message,link?}`, `confirm?` (two-click), `indexPath(state)`, `indexEmptyReason?`, `indexHint?`. `ctx` = `{pathname, params (route params), published}`.

**How a trigger calls the store.** `run` receives the real `useAppStore` api and calls named store/domain functions (almost all take `(api, actor, ...)` and return `Outcome`), never sets state directly. ### Placing a new trigger by name
1. Pick `screen` heading and `routes` (matchPath patterns over `router.tsx` paths; add `*` or a constant above), `surfaces` (`bar` for framed, `pwa` for the handset; both if the route exists in both).
2. If it needs state the URL lacks, add a key to `DemoContextValues` and publish it from the screen with `useDemoTriggerContext[While]`, then gate with `when` / read `ctx.published`.
3. Write the staging/action in a `store/*Demo.ts` file taking `(api: AppStoreApi, ...)`, going through guarded actions as the right actor; `run` only maps its `Outcome` to `{ok,message,link?}`. Add `disabledReason` (idempotency/refusal text), `indexPath`, `choices` as needed, `confirm` if it replaces data.
4. Append to `DEMO_TRIGGERS` (order = display order in menus and the index). Keep the demo guide in step (`demoGuideSync.test.ts`: guide presses must name a real label). Label rules: no en/em dashes, no "slot"/"swap"/"card" vocabulary.
