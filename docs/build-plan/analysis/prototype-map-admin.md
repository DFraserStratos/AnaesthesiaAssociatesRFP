# Prototype map: Admin Web App (aa-prototype/src/apps/admin)

Orientation. The Admin Web App is the office's desktop app at `/admin` (route table `aa-prototype/src/router.tsx:133-242`; thin route wrappers that turn URL params into props and callbacks into `navigate()` are `apps/admin/routes.tsx`). `AdminApp.tsx` is the layout: a dark side nav with amber attention badges, the day-scoped derivations (roster, slot views, warnings, summary line) and three transient overlays kept as component state, not routes (the session drawer `SlotDrawer`, the Draft List drawer `DraftListDrawer`, `OpenOutOfHoursSheet`), plus the Help panel. Every screen sits on one frame, `components/AdminPage.tsx` (modes `fit` / `fluid` / `document`; min width in `layout.ts`). There is no sign-in and no role switching inside Admin: the app always acts as the office actor `officeActorOf(shell.officeUser)` = Kirsty W. or Sam T. (`store/demoActors.ts:34-43`, swapped by demo trigger `switch-office-user`); office-only rules are enforced in the store (`actor.role !== 'office'` refusals), not by hiding UI. All data is the in-browser store (`useAppStore`); no `fetch`. **State on master at 26 Nov 2026: the Finances shell (phase 58: six routed tabs, record pages, legacy redirects, counts) and its read models (59) are built; the tab bodies are still the old Billing monitor / Invoices / Payments / Ledger / Xero / AA fees screens moved in unchanged (Wave 5, phases 60 to 67, rebuilds them, not yet done). Contracts (45 to 49), People (50 to 57) and Intake (33, 34, 40) are built.** Admin has no catalogue "Intake front door" yet beyond the five Intake tabs below: PDF lists are read from a fixed sample library, with no confidence values and no scans (see section 11).

## 3. Day view, drawers, session and List flows

**Day view** (`AdminDayRoute`; `components/DayNav.tsx`, `DayGrid.tsx`, `DraftListBand.tsx`, `RightRail.tsx`). DayNav: day stepping, +/-1 week, date picker capped at the horizon end, Roster order / A to Z sort (`?sort=az`), "Find available" (`AvailabilityFinderSheet`). DayGrid: one row per rostered anaesthetist, ruler 07:00-18:00 (longer when an out-of-hours session or evening Draft List exists, `util.ts` `rulerFor`), blocks coloured by display status (`displayStatusKey`), per-block warning/conflict/note signals, interactive status legend (hide a status), four focus filters (attention, conflicts, note, warnings), paging (`?page=`) or one scrolling list (`?rows=all`), hover control per row "Open out-of-hours session" (shown for today and later days only). Draft Lists band above the rows (unassigned, never filtered). Beyond the horizon: message plus "Go to the last day" (reads Schedule settings).
**Right rail** (`RightRail.tsx`): `MiniCalendar`; `RailReadings` (upcoming prepayments via `useUpcomingPrepayments`, `PrepaymentsRailCard`); `RailWorkCard` with two tabs To-do and Notifications (`components/WarningsToDo.tsx`, `NotificationsCard.tsx`); Day notes card (`addDayNote`, store/dayNoteActions.ts:22; optional "flagged"). To-do rows = every open warning (clearable with `clearWarning`, store/warnings.ts:251) plus Bookings with no Contract (`needsInvoiceDestinationBookings`; no Clear) plus replaced Contracts still active (`replacedContractsToDisable`; no Clear); first 6 shown, "Show all".

**SlotDrawer** (`components/SlotDrawer.tsx`). Two bodies. *Empty session*: Assign List (`flows/AssignListSheet.tsx` -> `assignListToSlot`, store/slotActions.ts:389; hospital + surgeon required, not-preferred pairing warns and records `list.pairingAcknowledged`, closure shows `ConflictCallout`, refused if the session is closed or occupied), Book (phone advice) (`flows/PhoneAdviceBooking.tsx`: assigns then opens `AddBookingFlow`), Edit times (`EditSlotTimesSheet` -> `setSlotTimes`, slotActions.ts:753), Change status (`SessionStatusSheet`), Close out-of-hours (`closeOutOfHoursSession`, outOfHoursActions.ts:75, refused while it holds a List), History. *List body*: Edit list (`EditListSheet` -> `editList`, lifecycle.ts:738; also `setSlotTimes`), Reassign list (`ReassignListFlow` -> `reassignList`, slotActions.ts:1013; not on AUTHORISED), Change status (not on AUTHORISED), History (`shared/booking/HistorySheet`, ids = list + slot), the Bookings table (`ListBookingsTable`, with intake stubs via `useListStubs`), per-Booking Move (`MoveBookingFlow` -> `reassignBooking`, lifecycle.ts:876, refuses AUTHORISED source/target; prepaid move shows `PrepaymentMovedCard`), Add booking (`shared/flows/AddBookingFlow`), `ConflictPanel` (Clear conflict / Flag again), `OfficeAlertLine`, `ChangedSinceSubmitted` cue, update-email actions (`flows/UpdateEmailActions.tsx`).
- `SessionStatusSheet` (flows/): set a session's availability status from the status master. A closing status on a session holding a List forces "Where does this List go?": Return to office (becomes a Draft List) or Hand on to a colleague's open session (tier order, preferred pairing, not-preferred apart, not-available colleagues shown disabled); commits `markUnavailableAndMoveList` (store/listMoveActions.ts:478); a SUBMITTED List can only be handed on; AUTHORISED refuses. `setAvailability` (slotActions.ts:730) refuses `holdsList` for closed statuses. Rule: unavailability is never a conflict (D59).
- `ReassignListFlow`: moves to a colleague's free session same day/session; vacated session becomes Free or Unavailable (`defaultVacated`); candidates ranked by `components/pairing/AnaesthetistCandidates.tsx` (`rankAnaesthetistCandidates`, tier then preferred pairing, shuffled by request key); not-preferred target warns, "Confirm reassignment anyway"; a prepaid List warns (`listHasSentPrepayment`).
- `OpenOutOfHoursSheet` -> `openOutOfHoursSession` (outOfHoursActions.ts:20): one per anaesthetist per day, default 18:00-21:00 (`domain/outOfHours.ts` `OUT_OF_HOURS_DESIGN`), must start after PM end; then drawer opens for Assign List.
- `AvailabilityFinderSheet`: open (free, no List) sessions for a day and session, tier-ordered; picking opens the drawer on Assign List with the surgeon preselected.
- Pairing preferences UI (private to office): `components/pairing/*` (`PairingSection` on anaesthetist and surgeon pages, `PairingAddSheet` -> `addPairingPreference`, `PairingEndSheet` -> `endPairingPreference`); logic `domain/pairingPreferences.ts`, `domain/listPairing.ts`.
- Recurring bookings (Master data): `flows/RecurringBookingSheet.tsx`, `recurringBookingCopy.ts`; actions `addRecurringBooking`/`editRecurringBooking`/`retireRecurringBooking`/`applyRecurringBookingsToCanvas` (store/mastersActions.ts:871-1058); preview of kept/skipped rows (`previewRecurringBookingChange`); a recurring clash makes a Draft List (`recurringClashDraft`, domain/draftLists.ts).

## 4. Draft Lists, Conflicts, Notifications

- **Draft Lists** (`screens/DraftListsScreen.tsx`; `components/DraftListDrawer.tsx`, `DraftListBand.tsx`; flows `DraftListSheet`, `AssignDraftListSheet`, `RedateDraftListSheet`, `RemoveDraftListSheet`, `AssignListFields`). Lists in state DRAFT: no anaesthetist, no slot. Tabs Waiting / History (assigned or removed). Sorted soonest first (`compareDraftLists`), "waiting" time from the demo clock (`waitingMinutes`). Actions: New Draft List (`createDraftList`, store/draftListActions.ts:97; hospital, surgeon, day within horizon, session, kind, source required), Assign (`assignDraftList` :395: candidates via `DraftListCandidates` using `draftListAvailabilityFor`; closure warning `draftClosureWarning`), Change date (`redateDraftList` :278), Remove (`removeDraftList` :328; blocked while active Bookings exist, `removeBlockedReason` domain/draftLists.ts:291). Assign becomes ACTIVE in the same List (Booking ids kept). Draft Lists carry intake stubs; a Draft List with `holiday` conflict is possible.
- **Conflicts** (`screens/ConflictsScreen.tsx`): rows from `conflictRows`, grouped by day, filters in URL. One conflict kind only: a List at a hospital closed that day (hospital holiday or public holiday; `domain/conflicts.ts`, `domain/holidays.ts`). Soft warning: never blocks. Row actions Open the List / Day / Clear (`ClearConflictSheet` -> `clearListConflict`, store/conflictActions.ts:28, optional note) / Flag again (`restoreListConflict` :65). Conflicts are stamped by `mutate()` re-running `reconcileListConflicts` (store/conflictReconcile.ts); AUTHORISED Lists never conflict.
- **Notifications** (`screens/NotificationsScreen.tsx`, `components/NotificationsCard.tsx`): one shared pool for all admins (`domain/notifications.ts`, `NOTIFICATION_POOL_RULE`: kinds `listMoved`, `bookingMoved`, `officeAlert`; pageSize 6; no expiry). Active until an admin ticks (`resolveNotification`), hidden for everyone; "Show resolved" shows who and when. Row opens the List drawer, Draft List drawer or the moved Booking. A move offers an update email (`NotificationEmailAction`, `flows/UpdateEmailActions.tsx`).
- **Update email** (`flows/UpdateEmailComposer.tsx`; domain/updateEmail.ts; store/emailTemplateActions.ts `recordUpdateEmailDrafted`:129): pick saved changes from a Booking's or List's history, template, recipient, preview, "Open in mail client" is a real `mailto:` (length-capped, `MAILTO_MAX_LENGTH`); writes one `updateEmail.drafted` audit entry. Nothing is sent.

## 6. Review queue, Review, authorise, review flags

Approval raises nothing; the next billing run does (see `EventsAwaitingRunPanel` on Payments). A credit is reviewed as one unit (`approveCreditUnit`, store/creditActions.ts:465).
- **ReviewScreen** (`screens/ReviewScreen.tsx` 875 lines, `/admin/review/:listId`): header with hospital, session, anaesthetist, surgeon, specialty, day; previous/next queue buttons; per-Booking table (Time, Patient, Procedure stack, Times, B-T-M units, Units, Fee, Flags) with fee from `bookingFee` using locks/held prices; List totals (needs-price makes the total "Needs a price"); who is billed (`procedureStackViewFor`: invoiced party, "Split", "Mixed", "Needs an invoice destination"); change history per Booking/Procedure; open warnings per Booking with Clear; contract-change Approve / Correct (`approveContractSelection`, `approveContractChangesOnList`); anaesthetist's alert with Resolve; "Changed since submitted" cue (`useChangedSinceSubmitted`, `changedSinceSubmitted`); stubs; phone note (`logListNote`, lifecycle.ts:~420, any list state, office only); once AUTHORISED, locked pricing record (`lockViewFor`) and delivery summary (`runDeliverySummary`, emailed / to post / no address counts).
- **Authorise** (`authoriseList`, store/lifecycle.ts:301): office only; List must be SUBMITTED (strict ordering, no "Returned" state; no return-to-anaesthetist action exists anywhere); refused while a Procedure "Needs a price" (`authoriseBlockersFor` :407, the single blockers seam) or any non-cancelled Booking is incomplete (`incompleteBookingsOn`); approves any unapproved contract changes in the same commit; writes the pricing snapshot `billing.locks[bookingId]` for every non-cancelled Booking (`takeLockFor`; Contract settings, range, price, who is billed/paid); then emits `listAuthorised`, which the billing run consumes (`wireBillingRun`, store/billingRun.ts:353; skipped for a Booking draft store). UI button disabled while incomplete or blockers; `ConfirmSheet` first.
- **Review flags** (domain/billing/reviewFlags.ts, `REVIEW_FLAG_RULES`; never block): contractChanged (pending change by anaesthetist, warn), contractNoLongerFits (warn; `contractAllowedOn`), contractDisabled (warn; Procedure dated on/after the Contract's disable day read from audit, `disabledDaysByContract`; D81), needsInvoiceDestination (warn), needsPrice (warn), typedPrice (neutral; typed price on a non-open Contract beside the computed one), notCompleted (neutral), payerContactMissing (neutral; billed payer has no email or address), btmOverride (neutral; "T adjusted +1 manually" etc.), prepayment (neutral "Prepaid, left off"; warn "Pre-payment sent, no longer needed" / "...before a change").
