# Prototype map: Admin Web App (aa-prototype/src/apps/admin)

Orientation. The Admin Web App is the office's desktop app at `/admin` (route table `aa-prototype/src/router.tsx:122-186`; thin route wrappers `apps/admin/routes.tsx`). `AdminApp.tsx` is the layout: dark side nav with attention badges, the day-scoped derivations, and three transient overlays (session drawer `SlotDrawer`, Draft List drawer `DraftListDrawer`, `OpenOutOfHoursSheet`) held as state, not routes. Every screen sits on one page frame, `components/AdminPage.tsx` (modes `fit` / `fluid` / `document`; `PageToolbar`, `PageBody` with `rail` or `nav`; 1280px min width). There is no sign-in and no role switching inside Admin: the app always acts as the office actor `useAppStore(s => s.shell.officeUser)` (Kirsty W. or Sam T., `store/demoActors.ts`; swapped by demo trigger `switch-office-user`); office-only rules are enforced in the store (`actor.role !== 'office'` refusals), not the UI. All data is a fake in-browser store; no `fetch`. **State on master (Phase 45 built, 46 to 49 in lanes, not on master):** Contracts is its own side-nav section with a list at `/admin/contracts`, a page per Contract at `/admin/contracts/:contractId` (tabs Overview / Bookings / Event fees / History, per-card editing, confirmed Disable), and New contract still a side panel on `/admin/contracts/new` (46 replaces it). Parties and Funding tags are still Master data views (tab links on the Contracts section point across to them; 48 moves them). There is no Replace-from-a-date, no grouped catalogue by kind (47), and Patients, Anaesthetists, Surgeons and Specialties are still where they were (Patients in the nav, the others under Master data and `/admin/masters/...` profile routes). Anaesthetist `active` (inactive) already exists as a flag (section 5).
