# Prototype map: Admin Web App (aa-prototype/src/apps/admin)

Orientation. The Admin Web App is the office's desktop app at `/admin`. The route table is `aa-prototype/src/router.tsx:103-186`; thin route wrappers (URL params to props, callbacks to `navigate()`) are `apps/admin/routes.tsx`. `AdminApp.tsx` is the layout: dark side nav with attention badges, the day-scoped derivations (roster, slot views, warnings, summary line) and three transient overlays held as component state, not routes (session drawer `SlotDrawer`, Draft List drawer `DraftListDrawer`, `OpenOutOfHoursSheet`), plus the Help panel (`SupportSidePanel`). Every screen sits on one page frame, `components/AdminPage.tsx` (modes `fit` / `fluid` / `document`; 1280px min width, `layout.ts`). There is no sign-in and no role switching inside Admin: the app always acts as the office actor `officeActorOf(shell.officeUser)` = Kirsty W. or Sam T. (`store/demoActors.ts`, swapped by demo trigger `switch-office-user`); office-only rules are enforced in the store (`actor.role !== 'office'` refusals), not hidden in the UI. All data is the fake in-browser store (`useAppStore`); no `fetch`. **State on master (26 Nov 2026): the Contracts section (phases 45 to 49), the People section (50 to 57: Anaesthetists, Surgeons, Specialties, Patients as routed tabs with record pages) and Intake's Waiting for NHI tab are all built.** Master data now holds only places, schedule, billing codes, settings and go-live views. Finances (six tabs, in the latest commits) is requirements and an exploration only: no `/admin/finances` route, no side-nav item exists.
