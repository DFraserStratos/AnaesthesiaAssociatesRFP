## Goal

The office decides an update to a List AA holds, from any source, a whole List at a time, and sees why it matched before anything is applied. Layout: [intake-ideas.html](../../explorations/intake-ideas.html) `#idea1` mock A (the update workbench), `#reco` (the version track from Idea 3, the Slot card from Idea 2), `#journey` (the re-send and the day-before List).

- **The update bench** (`workbench/UpdateBench.tsx`, 68's stub), for a hospital update or a re-sent rooms' PDF alike: the header's **version track** (the List's first version and each later arrival, each with its source mark and time, the proposed one marked), the **match-basis strip** (surgeon, hospital, and day and session each ticked or not; how many of the List's patients were found, and how many by NHI; no score), the **Slot card** (the anaesthetist, day and session the List sits in, with its state); then the **List-level difference table**, one row per Booking with a tick (ticked by default), the current and the new values side by side, added Bookings marked, each removal struck through to confirm, and a stub whose NHI arrives shown as "NHI arrives, stub becomes a Booking".
- **Apply** applies the whole List's ticked changes as one change set (new `store/intakeApply.ts`, on 68's `intakeDecide.ts`, D118): an unticked change is decided as **left out** and changes nothing; a ticked removal is recorded as a cancellation (the Booking stays visible, marked cancelled); an applied NHI turns the stub into the Booking on the patient's one record (DM-17); an added Booking lands with no Contract (D125); a List authorised and locked refuses, as today (US-02.5.4). **Reject** rejects the whole List with a reason and changes nothing on the schedule.
- **The hospital's List for a List the rooms sent** is proposed as an update to that List (its first version the rooms' PDF), never a new List.
- **The cancellation bench** (`workbench/CancellationBench.tsx`): a hospital's cancellation of one Booking, shown with the Booking and its List; Apply marks the Booking cancelled, Reject (with a reason) changes nothing.
- After any decision the bench calls `onDone` and the feed moves to the next arrival (68's dispatcher).
- **One Add NHI path:** RowPanel's `addNhiToStub` and its `stub-add-nhi` button go (with the panel, or wherever any part of it is reused), so the Hub lookup sheet (72's `AddNhiSheet`) is the one manual path (US-02.6.3).
- `docs/DECISIONS.md` line 14 becomes one change set per applied List.
