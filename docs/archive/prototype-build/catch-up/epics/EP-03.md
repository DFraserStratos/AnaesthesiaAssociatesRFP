# EP-03 · Booking and Procedure capture (anaesthetist) · gap details

Part of the [gap analysis](../GAP-ANALYSIS.md#ep-03) · catalogue `63a4490` · [EP-03](../../../../requirements-board/requirements/stories/EP-03.md)

> EP-03 slice (6 items): US-03.2.1, US-03.3.1, US-03.3.4 and US-03.3.8 Match (all upheld on re-check, including the Agreed US-03.2.1); FT-03.7 and US-03.7.1 Contradict (upheld). The capture side (primary Procedure, RVG type-ahead, ranged base units, itemised modifiers, age modifier) was rebuilt in catch-up phases 19 to 24 and is current. The only structural gap is events (phases 38b and 39b): there is no event entity, only the interim addendum Booking. Closing it removes addPostOpAddendum, Booking.bookingType 'postOpAddendum' and addendumOfBookingId, the addendum banner in BookingDetailBody, the interim BillingLinesCard, and the related audit labels, and needs a PERSIST_VERSION bump. Note the billing run is event-driven on List authorise (wireBillingRun), with no user-triggered 'run' control, so next-run billing of events needs a new demo button on the Admin Billing monitor. Dependencies: US-03.7.2 and US-03.7.3 (bill an event, see a Procedure's events), EP-08 (bundling by billable party, additional invoices US-08.6.3, credits as events US-08.6.5), FT-11.2 billable party, US-05.5.2 (ACC pre-op events, OQ-12 parked), US-03.1.6 (past Procedures are read-only seeded history on backdrop Lists, so events on them need new reach), US-07.3.2 (events off Lists). OQ-12 and OQ-138 do not block the generic event; OQ-132 is open for US-03.2.1 and the prototype's provisional reading (base units stay on the marked primary, none billed when it is fixed priced) matches the story as written. Residual small points, not gaps: the US-03.3.4 prose says an included modifier 'cannot be unselected' while its criteria say none is locked (prototype follows the criteria); a fixed-price primary on a mixed multi-procedure Booking still shows a Modifiers section (consistent with US-05.3.1); the Admin Modifiers 'Provisional' badge is defensible since OQ-95 is still to confirm with Vanessa. Demo guide: S4 Beat 2 'post-op addendum' (docs/demo-guide/03-demo-script.md, 02-workflows-and-handoffs.md, 04-presenter-cheat-sheet.md, README.md), the DemoControlPanel S4 blurb and recipe, and the 'stage-post-op' trigger text would be rewritten around 'add an event on a Procedure, then run the next billing run'; no other scripted beat is affected.
