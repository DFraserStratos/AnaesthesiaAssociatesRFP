## Goal

Every command, link and switch-between control sits on one component each, with today's look kept unless a README question changed it.

1. **One button** (U08, U36). The shared `Button` gains the teal-outlined secondary the mockups draw, a desktop and a compact size, a disabled reason printed beside the button, `shot` and pass-through attributes. The two `ActionBtn` copies, the six hand-rolled teal outlines and the hand-rolled desktop buttons move onto it. Red is kept for one button, "Cancel booking" (question 8).
2. **One text action and one back link** (U13, U21). The shared `TextAction` takes sizes, `flush`, `inline` and a disabled reason; the private `LinkButton`, `linkStyle` and about 40 inline teal copies go. A shared `BackLink` replaces five identical desktop copies, the mobile header backs and both `BackLink`s; Review and Invoices keep only their breadcrumb (question 9).
3. **One icon button** (U20). `IconButton` and a `CloseButton` preset replace 13 private stepper definitions and 9 close or clear buttons. The label is required by the type, so Admin Day's `‹ ›` get names (bug 5), and every clear or remove button returns focus (bug 9, clear half).
4. **One segmented control, one tab strip, one filter row** (U16, U17, U32). `SortToggle` becomes a call site of the segmented control; Balances takes the standard look (question 17). `LineTabs` replaces four tab strips; the two page switches become underline tab links (question 18). `FilterPills` and `ProgressBar` replace two copies each, and the three main navs mark their active item for assistive tech (question 3).
