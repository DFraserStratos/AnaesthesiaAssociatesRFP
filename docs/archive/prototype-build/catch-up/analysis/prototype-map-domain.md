# Prototype map: aa-prototype/src/domain (except seed)

Orientation. `aa-prototype/src/domain/` is the prototype's pure layer: TypeScript types for every entity (`types.ts`, 1800 lines), the demo clock and seeded RNG, NHI/NZHIS helpers, scheduling rules (slots, availability, conflicts, Draft Lists, moves, pairing, recurring projection, out-of-hours), the billing maths (`billing/`, the largest part: Contracts, step rail, price ladder, fee engine, multi-procedure rule, completion, review flags, who is billed, invoice presentation, pricing lock, AA fee/BCTI), warning rules (`warnings/`) and the HL7/FHIR integration translators plus canned messages (`integrations/`). It has NO routes, screens, store actions or React: `domainPurity.test.ts` forbids React/zustand/store/apps/shell/shared imports. Everything here is called by the store (`src/store/*`, which owns state, `mutate()`, lifecycle transitions and audit) and by the three apps. Lifecycle TRANSITIONS (DRAFT to ACTIVE to SUBMITTED to AUTHORISED, billing run, Xero hand-off) are NOT in this folder: only the state names, guards and pure rules are. Most files carry a header comment naming the catch-up Phase, US-/DM-/OQ- ids and AR-58 sections they implement: grep the file header to find a story. All paths below are relative to `aa-prototype/src/domain/`. Each `x.ts` has an `x.test.ts` unless noted.

## 11. Warnings (`warnings/`)
Derived, never stored, never block. `evaluateWarnings` (`routine.ts`): runs active rules, strong before mild then rule order; cancelled Booking yields none; stored `WarningClearance` hides a warning only at same or higher strength. Registry `rules/index.ts` `WARNING_RULES`: `prepaymentUnpaid` (strong, before; states required/outstanding), `baseUnitsOutsideGuide` (RVG guide), `childPayer` (mild, per Procedure), `approvalNumberMissing` (mild, insurer only), `splitDoesNotFit` (mild, after, per Procedure). Facts built by store `warningFactsFor`. `settings.ts` `defaultAppSettings`; `AppSettings` {warningRules, aaFee, schedule}. No UI to edit rules (US-13.7.4 future). Kinds `beforeProcedure|afterProcedure`.
