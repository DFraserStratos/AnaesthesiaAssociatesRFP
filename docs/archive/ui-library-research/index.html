Replacing the custom UI with standard component libraries

This report checks every tool from Griffin Wooldridge's video "UI Libraries for Claude Code" against a full inventory of the three apps (Admin, Anaesthetist Web, Anaesthetist Mobile) and the shared kit. It maps each hand-built component to a library replacement and lists what is missing. The goal is a future app that real developers can recognise and rebuild. Six research agents gathered the material: three read the codebase and three researched the libraries online. Versions are as reported by npm and GitHub on 11 November 2026.

Guiding principle: unify, don't decorate. The aim is recognisable, standard building blocks that real developers can rebuild on whatever framework the real system uses. It is not about adding polish. No new animation, effects or "standout moments": existing motion is kept and re-expressed, nothing more. Start from README.md in this folder; it holds the goal, the principles, the provisional decisions, the open questions and the detailed inventories.
See every component live: the prototype has a demo-only catalogue page per app, at /demo/catalogue/admin, /demo/catalogue/web and /demo/catalogue/mobile (with the dev server running). Each row is one real, interactive component with its name, what it does and its replacement, grouped by the same libraries as the map below. The code is in aa-prototype/src/apps/demo/catalogue/.

Summary

Today
No component library. About 211 component files and about 2,870 inline style={{}} objects reading TypeScript tokens in src/theme/. Tailwind v4 is installed, but its utility classes are never used.
Recommended foundation
shadcn/ui on the Base UI base with Tailwind v4, on React 19. Our tokens go into shadcn's CSS variables, and the brand is published as a private @aa registry.
Specialists
Sonner (toasts), Base UI Drawer (mobile sheets; not Vaul, which is unmaintained), Base UI Combobox (type-aheads), cmdk (⌘K palette), TanStack Table and Virtual, React Hook Form and Zod, react-day-picker, NumberFlow (live totals only), Motion, Recharts.
The video's "designed" tier
Not used, because the goal is unification, not flourish. Magic UI, Aceternity and RareUI are motion and effects libraries. 21st.dev is for browsing only. Beautiful UI is kept as reference in case an AI assistant is ever added.
Stays custom
The Admin DayGrid scheduling canvas, the mobile SlideStack with edge-swipe-back, status-cell rendering, the invoice document, and the billing review and pipeline choreography. These get rebuilt on library primitives: tooltips, popovers, focus handling.
Biggest wins
Focus trapping and restore on every overlay, real menu, tab, combobox and grid keyboard models, a toast system, accessible tooltips instead of about 75 title= attributes, sortable and paginated tables, drag-to-dismiss sheets, and one form and validation pattern.

The video's libraries, rated for this project

The video sorts libraries into three tiers: foundations handle behaviour and accessibility, specialists do one component well, and designed components add flash and polish. The video's own advice, which stands, is to restyle shadcn's radius, colours and type so it does not look like a default template, and to keep to "one standout moment per page".

How the UI is built today

  • Shared kit in src/shared/ui (Button, Field/TextField/TextArea/FormError, Segmented, SlidingSegmentedControl, NameSearchBox, Pill, TickBadge, TickButton, SuccessOverlay, DockSpacer) and src/shared/surface (Dialog, BottomSheet, SurfaceProvider).
  • The surface seam: useSurface().Overlay renders a BottomSheet on mobile and a Dialog on web and admin. About 20 shared sheets and about 37 Admin sheets go through it. That makes it the single best place to swap in a library: Drawer on mobile and Dialog on web, behind the same seam.
  • Styling: inline style objects from tokens.ts, statusColours.ts and motion.ts, plus about 45 aa-* classes in global.css (inset contract, clickable rows, hover-reveal, print, a reduced-motion collapse). Hover is often done with JS mouse handlers, and there is no consistent focus ring.
  • Motion: named patterns (controlPress, selectionSlide, sheetIn, cardAdvance, completeTick, valueTick, reducedMotionFade) with CSS keyframes referenced from inline animation strings.
  • Scale of the job: Admin alone has 117 files (about 17.9k lines), 17 tables, 28 native selects, 15 native date inputs and 6 native time inputs. Every popover and menu is hand-written, and the outside-click and Escape logic alone is written three times.

What stays custom (no library covers it)

Admin DayGrid canvas
A time-proportional 07:00 to 18:00 ruler that extends for out-of-hours sessions, absolutely positioned blocks, AM and PM merging, hatched and dashed status fills, conflict and attention overlays, the Draft List band, hover-reveal gutters and filter-and-regroup. Resource-timeline products (FullCalendar, Bryntum) would fight the design. Rebuild it on primitives: roving focus with grid/gridcell roles, Tooltip or HoverCard on blocks, ContextMenu for block actions, and TanStack Virtual if the number of rows grows.
Mobile SlideStack
URL-driven depth with every layer kept mounted, parallax and dim, inert on parked layers, and an iOS edge-swipe-back gesture (touch only, axis lock, velocity commit). No library ships an iOS-style stack navigator. Rebuild on Motion's drag and AnimatePresence, and add focus moves to the new heading on push and pop.
Collapsing mobile masthead
A scroll-driven large-title fold. Small and bespoke. Emil's gestures and mobile-native skills cover the feel.
Billing review and pipeline
Authorise choreography, review flags, the changed-since-submitted cue, the lock-on-authorise state and the per-List pipeline stepper with Resolve and retry. Build them from Card, Badge, Table and AlertDialog, but the flow is ours.
Invoice document
Two recipient layouts, a serif document voice and print isolation (deliberately not inside a fixed Dialog). Keep it as a print-styled page.
Device hosts and inset contract
PhoneFrame (CSS scale()), MobileViewport, the --aa-inset-*, --aa-keyboard-inset and --aa-dock-height variables, and DockSpacer. Prototype harness only, but library portals must target the frame.

Accessibility gains from the swap

  • Overlays: no focus trap, initial focus or restore anywhere. BottomSheet has no Escape. Dialog has no scroll lock. aria-modal is set without making the background inert.
  • Menus claim role="menu" with no arrow keys. AppSwitcher has no Escape.
  • Segmented controls use aria-pressed buttons rather than radios, with no roving focus (only StatusRadioGroup is correct).
  • Tabs lack role="tab" and aria-selected (Web Accounts, Integrations, AaFees). Navs lack aria-current (SideNav, WebNav, BottomTabBar).
  • Clickable <tr> rows are mouse-only. Web List detail's Bookings table has no keyboard handle at all.
  • Comboboxes have no combobox or listbox semantics. The DayGrid is a page of individual Tab stops with no grid model.
  • There is no consistent focus ring. accent.focusRing is used in one place, and inputs have no focus style.
  • Mobile screens have no headings (titles are divs), and focus is not moved after a stack push or pop.
  • Several inputs are labelled only by placeholder (notes textarea, Integration Monitor inputs, the DayNav date, DemoData selects).
  • z-index values are ad hoc and set per file (60, 70, 90, 100, 120, 200). Library portals plus one layering scale replace them.

Constraints and risks for the migration

React 19 first
Recent shadcn code passes ref as a normal prop. On React 18 refs are silently dropped, which breaks focus handling and measuring. Upgrade before running shadcn init.
Brand rules in tokens
--primary and --ring are teal. Crimson lives only in identity tokens (--sidebar-primary, masthead, avatar), never in --primary or --accent (in shadcn, --accent means hover background). Delete any non-teal filled variant. Add six --status-* tokens with tint and on-tint values. Set fonts to Schibsted Grotesk and Spline Sans Mono, with tabular-nums in data cells.
Avoid the "shadcn look"
Use our radius scale (ctl 10, card 14, panel 20, sheet 24), our type and our motion patterns rather than stock tw-animate fades, and denser data rows. Publish all of it as a private @aa registry so every developer and agent pulls the branded version.
Phone frame and portals
The prototype renders mobile inside a CSS scale()d PhoneFrame. Library portals default to body and position with Floating UI, so they can misplace content. Point Drawer, Popover and Toaster at the frame container. Base UI also wants isolation: isolate on the app root.
Determinism
Calendars and date pickers default to the real "today". Always pass the demo clock's date (DEMO_TODAY) and the horizon as min/max. No library may call new Date() on our behalf in seeded views.
Test and capture hooks
Keep the data-shot, data-validation-* and demo-trigger attributes on the DOM nodes that the Playwright and capture suites target. shadcn parts carry data-slot, which helps.
Motion and reduced motion
Re-express the seven named motion patterns on Motion or CSS. Keep the global reduced-motion collapse. Magic UI parts do not check reduced motion; NumberFlow does.
Copy-in has no upgrades
shadcn code becomes ours. Churn is real (eight styles, a cn package migration, Vaul replaced by Base UI Drawer, TanStack Table v8 to v9). Pin a snapshot and record it.
Library health
Vaul is unmaintained. @use-gesture is dormant. Tremor is stale. cmdk is slow but stable. NumberFlow, Floating UI and dnd-kit/react are still 0.x. Only RareUI is weak among the video's picks.

Suggested migration order

  1. Groundwork: React 19, path alias, shadcn init --base base. Map tokens.ts and statusColours.ts into CSS variables with @theme inline. Build the @aa registry and preset. Write the CLAUDE.md rules (no raw palette classes, teal only, shadcn first).
  2. Primitives behind existing seams: Button, Field/Input/Textarea/Select, Badge (status variants), Avatar, Card. Swap the inside of Overlay: Dialog on web, Drawer on mobile. Every one of the roughly 57 sheets improves at once.
  3. Feedback: mount Sonner and convert the inline success banners and UpdatePrompt. Replace title= with Tooltip.
  4. Navigation: Admin Sidebar, web NavigationMenu, Tabs for sub-tabs, Breadcrumbs, mobile tab bar as a <nav>.
  5. Pickers: Combobox for RVG, surgeon, specialties and contract. Calendar and Date Picker in place of the 21 native inputs and the custom month grids (keeping custom day content).
  6. Tables: TanStack Table v9 with shared column helpers across the 17 Admin tables, then the web tables. Add TanStack Virtual for audit and RVG.
  7. Forms: React Hook Form + Zod for the Admin sheets, then capture, with store refusals mapped to field errors.
  8. Custom pieces on primitives: DayGrid accessibility (grid roles, Tooltip, ContextMenu), SlideStack and SuccessOverlay re-expressed on Motion with unchanged behaviour, Recharts for aging, DropdownMenu row actions.
  9. Only if decided at pick-up (new features, not unification): the ⌘K palette, Resizable rail, dnd-kit reorder, dark mode.

Claude Code tooling

shadcn MCP server
npx shadcn@latest mcp init --client claude lets Claude browse, search and install from shadcn, third-party and private registries (namespaces such as @aa, @magicui, @reui in components.json).
shadcn skill
npx skills add shadcn/ui runs shadcn info --json for project context and enforces conventions (FieldGroup for forms, ToggleGroup for option sets, semantic colours). A separate Radix-to-Base UI migration skill commits per component, which conflicts with this repo's no-commit rule.
Emil Kowalski's skills
npx skills add emilkowalski/skills --skill pick-ui-library -a claude-code. It is invoked by name only. Also relevant: gestures, mobile-native, ask-sonner, break-ui, remove-animations, review-animations, apple-design.
pick-ui-library's choices
Base UI (primitives), cmdk (⌘K), Sonner (toasts), input-otp, Leva (control panels), Motion, NumberFlow, torph (text), Cobe (globes), Satori, shiki, Liveline (live charts), Recharts, dnd kit, react-virtuoso (virtualisation), Zustand, clsx, cva, next-themes. It names no drawer, table, form or date-picker library, so this report fills those gaps.
Before adopting any third-party skill or MCP server, read its files. Skills run with Claude's permissions in this repo.
