The prototype stops an anaesthetist completing a Booking whose prepayment is unpaid, unless the office lifts it with an audited override (a July 2026 prototype ruling). The catalogue has no such gate: its control is the [escalating unpaid-prepayment alert](US-06.3.2) as the procedure date approaches, and the anaesthetist decides whether to go ahead. Should the system also hard-block completion while a prepayment is outstanding?

Recommendation: no gate; the alert is the control. This is the catch-up plan's build default (reverse finding RV-09, Phase 27) if no answer comes in. If the gate is kept, it would fire from the [detected prepayment requirement](US-06.2.1), not from a patient category.
