The RFP describes two things that both sound like "an anaesthetist is unavailable for a half-day",
and it's not clear if they're the same mechanism:

1. **List.status** (p.14, p.19 principle #3): a field painted directly on the List, whose own example
   value is "on leave", e.g. "this anaesthetist is on leave Tuesday PM."

   RFP quotes:
   - p.14: "Status reflects the current state of the List ... e.g. available, available for
     emergency, unavailable, on leave (etc)". "Availability is set at the List (half-day) level."
   - p.19 #3: "A List's status is meaningful on its own (e.g. 'this anaesthetist is on leave
     Tuesday PM') even with no Cards attached."
   - p.19 #4: "The List is the unit of availability, not the Anaesthetist or the Day."
   - p.17 (List Status master, no "on leave" in its vocabulary): "e.g. private, public, pre-op,
     holiday, unavailable, free".

2. **Anaesthetist Availability** (p.17, p.19 principle #7): a separate master calendar the anaesthetist
   maintains via the mobile app, kept independent of any List assignment, which the RFP says is
   *"reconciled against the canvas (e.g. flagged conflicts, surfaced as constraints) rather than
   merged into the List record itself."*

   RFP quotes:
   - p.17: "Maintained by each Anaesthetist via the mobile app ... independent of any List
     assignment. Any change in these settings is immediately reflected in the Schedule."
   - p.19 #7: "expected to be reconciled against the canvas (e.g. flagged conflicts, surfaced as
     constraints) rather than merged into the List record itself."
   - p.19 Open Questions: "How should Anaesthetist Availability and Hospital Holiday data be
     reconciled against the schedule canvas, as hard constraints, soft warnings, or something else?"

These can't both be true of the same field. There are two possible models:

- **Model A: Availability is set on the List.**
  - The anaesthetist sets "on leave" straight onto the List.
  - List.status and Availability are the same thing.
  - Principle #7's "not merged into the List record" is then wrong, or only applies to something else.

- **Model B: Availability is a separate calendar.**
  - It is compared against Lists and surfaced as a conflict badge.
  - List.status's vocabulary shouldn't include availability states like "on leave" at all. Those belong to Availability.
  - List.status keeps the admin/booking-facing values from p.17: private, public, pre-op, free.

**Needed from AA:** which model is correct. It changes what belongs in the List.status vocabulary in OQ-17.

## Answer

As you would have heard in the transcript.

The System will create AM & PM slots for every active anaesthetist. These slots can have a status, or a list.
