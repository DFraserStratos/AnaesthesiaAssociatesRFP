A [Draft List](US-01.6.1) is a List with no anaesthetist yet (requests arrive daily from surgeons' rooms and secretaries). We have assumed it records the hospital, surgeon, day and session. To confirm with AA:

- What is known when a request arrives (is the surgeon always known? patients or Bookings yet?)
- Who creates them (only admin staff, or also the matching screen from a hospital row)
- What happens if the request is cancelled or never filled
- Whether a Draft List can be put in front of anaesthetists as an offer, or only assigned by the office
- Can you add extra bookings to a list which isn't "defined"

Recommendation: hospital, surgeon, day and session are required; Bookings may be added before assignment; a Draft List that is never assigned is closed by an admin with a reason.

## Answer

Answered in Oct 1st Transcript

From the transcripts:

- A Draft List is a List created with no anaesthetist. The surgeon, hospital, day and session are always known when it is created (the hospital booking always comes first), and all four are needed to turn it into a List. Only the anaesthetist can be missing.
- AA staff create one when a surgeon's room needs an anaesthetist, and an admin can make an ad hoc List from a slot. How else they are created (for example from the matching screen) was left for later.
- Bookings can be added to a Draft List before an anaesthetist is assigned. A List is mainly managed by the surgeon's office; AA adds to it only for an instant addition in theatre.
- A request the surgeon's office cancels, or that is never filled, is simply removed, or its date is edited. Closing it with a reason was not discussed.
- It is never put to anaesthetists as an offer; the office assigns it.
- Draft Lists must show prominently in the core planning view. The name is kept for now but may change.
