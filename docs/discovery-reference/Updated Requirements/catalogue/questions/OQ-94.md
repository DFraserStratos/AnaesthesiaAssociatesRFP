The RVG's Neurosurgery and Spine group notes say "These Base Units include Loading for Prone Positioning if needed", so P1 (non-supine positioning, 2 units) is shown at 0 and locked on those codes ([default modifiers](US-05.1.4)). But the Neurosurgery codes come in pairs: H7A, H8a and H9a are supine/lateral, and H7b, H8b and H9b (prone, park bench or sitting) are exactly 2 units higher, which is where the +2 shows.

Does the lock apply to the 'a' (supine) variants too, or only the 'b' variants? The same applies to Spine sub-codes such as S3a/S3b.

Recommendation: Lock P1 on all 20 codes the group notes cover (the note applies to the whole group, and Donald's example named H7A), and confirm with Vanessa.

## Answer

Yes: P1 is included in the base units of every Neurosurgery code, 'a' and 'b' alike, and of every Spine code. Donald, 8 October: H7, H8 and H9 are headings with no base units of their own; H7A/H7b, H8a/H8b and H9a/H9b are the actual codes, and all of their base units include prone positioning.

The RVG says so in the P1 row of its modifier table ([page 12](AR-16#p12)): "Any position that is non-supine, non- lithotomy, or non-lateral IF not already accounted for (It is included in Spine and Neuro Base units)". The Spine group note ([page 9](AR-16#p9)) reads "These Base Units include loading for prone positioning if needed". The (+2) printed in the Neurosurgery group header is P1's own value, the loading the base units include, not the gap between the 'a' and 'b' codes.

So on every Neurosurgery code H7A to H9b and every Spine code S1 to S10 (with their sub-codes), the P1 positioning modifier shows as a pill already selected at 0 units that cannot be unselected. (See Typed decision 2026-10-08 · Donald (product owner))
