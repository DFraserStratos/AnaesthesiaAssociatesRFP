The OQ-06 board answer puts base units on the RVG code master (a Contract may override). The meeting agreed the opposite: base units live on a master procedure list, each procedure with its own base units ideally derived from an RVG code, with default and hospital Contracts taking them from it, and Donald proposed dropping "RVG" from its name. Which is it? Also: the user picks from "the procedure list grouped by RVG body headings" (OQ-53); is that list of operation names (the master procedure list) or of RVG codes?

Recommendation: the master procedure list, as agreed in the room, with the RVG code master keeping the guide's own values; Vanessa's standard procedure list is the input.

## Answer

As I see it. 

The Master RVG procedure list hold RVG codes, and each procedure has one or two default RVG contracts which holds the base units and all other settings.

The meeting adds: in the room Donald described "a master list of procedures, which has the groupings of body parts", which "may reference RVG codes", and "really the base units live in the contracts": for every procedure a base contract, "understood to be the standard RVG recommendation for base units", maintained by hand after an initial spreadsheet import. The transcript says one base contract per procedure; the answer says one or two. Greg asked how a (rare) RVG change flows through, and floated making contracts children of a master code so a change routes to every contract with that parent (Donald: "it could have multiple parents"; Greg: "That's all right if we do that. All those thousands, it's becoming really too many relationships"); not settled. (See Notes 2026-10-02 · AA meeting with Greg #3 #22 #40)

The meeting adds, and moves the answer above:

- Where base units live was in doubt again, and is now settled (see the update below). The guide (taken as true for now): "Each procedure belongs to one RVG group and uses that group's base units unless AA sets a different figure for that procedure." The draft technical design holds them on the RVG group, with a procedure override that is "Typically null" and contract lines as sparse overrides. Greg, 7 October: "There isn't an RVG default contract except for a header in the system... It's a default RVG relationship." Donald: whatever the path, there is "always going to be at least one option... using the RVG guide to determine the base units and modifiers", "just a pre-system-defined one"; Greg: "It will always generate one contract that can be selected." Same outcome, the wording waits for Greg's document. Greg accepted named custom RVG-style Contracts. The procedure spreadsheet asks for an RVG code and base units on each procedure row.
- How a Procedure is picked: two routes, by procedure (body section and subgroup) or straight by RVG code, then the Contract (agreed with Greg and at the client meeting). Every procedure always has an RVG code, and Greg wants every booked procedure assigned to a procedure, even on a fixed price. In tension: at the client meeting the RVG code may be left blank at setup for the anaesthetist when admin cannot match it confidently, as long as the billable party and billing strategy are set; what then blocks submission was not discussed.

(See "Notes 2026-10-07 · AA meeting with Greg #16 #18 #31 #60 #61", "Notes 2026-10-07 · AA client meeting #27 #28 #31 #38", "Notes 2026-10-07 · Pricing model documents #8 #21 #28")

Update 2026-10-07 (settled): base units live on the [RVG group](US-05.1.1); a [procedure](US-05.1.6) may carry its own figure, which wins where set; and a Contract line may override both. This replaces the answer's per-procedure default RVG Contracts holding base units, which are retired ([US-04.4.2](US-04.4.2)): No contract (RVG) is the one default Contract, offered for every procedure, and holds no base units of its own. Greg's wording, "a default RVG relationship", not a default RVG Contract (Notes 2026-10-07 · AA meeting with Greg #60), is consistent with this.
