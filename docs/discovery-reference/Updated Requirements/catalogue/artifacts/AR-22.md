The lifecycle of a List and its Bookings, DRAFT → ACTIVE → SUBMITTED → AUTHORISED. A Draft List has a surgeon, hospital, day and session but no anaesthetist: it arises from an office request, an anaesthetist moving a List to the office, a recurring booking on an unavailable Slot or a reschedule clash, waits in the Admin App (Bookings can still be added), and is either assigned to an anaesthetist by an admin or removed or re-dated. An Active List has all five (anaesthetist, surgeon, hospital, day, session), whether assigned from a Draft List or set up assigned. While it is active a Booking stays editable, and may be amended or moved, until the List is submitted; after the procedure the anaesthetist finalises each Procedure's billing details, marks the Booking complete once the minimum billing data is present, and submits the List once every Booking is complete. Submitting removes the anaesthetist's edit access while the List stays visible to them as completed, unbilled; the office reviews the Bookings, approving each Procedure's Contract, corrects anything directly (there is no returned state) and authorises the List. Authorising locks the Bookings, Procedures and Contract versions and hands the whole List to the Billing/Invoice Engine, which processes each Booking and raises one invoice per billable party in each Booking.
