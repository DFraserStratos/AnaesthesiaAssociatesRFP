The Billing/Invoice Engine flags a Booking as requiring prepayment whenever any of its Procedures carries an RVG code in the [anaesthetist's prepaid set](US-06.1.1), and only where the [billable party](US-11.2.2) is a person paying for the patient (the patient, or for example a guardian), never an organisation such as an insurer or hospital.

This is checked across the whole Booking, not just its primary Procedure, since the typical case is a hospital Booking with an additional, elective cosmetic Procedure added on.

## Acceptance criteria

- Given a Booking with a Procedure in the prepaid set whose billable party is an insurer or hospital, when it is checked, then no prepayment is flagged.

## Notes

Q&A #5: prepaid is a property of the procedure choice, not the contract. There is no [Pre-paid Contract category](US-04.1.1), so the Contract never triggers it (OQ-25).

The patient-only limit comes from the OQ-58 answer. OQ-73 answered: "patient" means any person paying for the patient, never an organisation. Greg: "prepayments are always patient-direct... there's no hospital involved in this process."
