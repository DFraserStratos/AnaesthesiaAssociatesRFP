As the system, I can regenerate any past invoice exactly from the locked data and Contract version.

## Technical discussion

Proposed in our RFP response: full change history and invoice reproducibility are required across roughly 28,000 invoices a year. Azure SQL temporal tables at the data layer act as the audit log, so no write path can bypass it and point-in-time reconstruction is a direct query rather than a log replay. Trigger-based audit tables were considered workable but more bespoke and weaker at point-in-time reconstruction; a domain-event log may still be used where the reason for a change matters, but not as the primary history mechanism. The invoice itself stays reproducible because the reference data it depended on is copied into the billing record at AUTHORISED (see US-04.3.5).
