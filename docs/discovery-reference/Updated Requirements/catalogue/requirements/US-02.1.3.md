When an imported row matches an existing Booking, the admin sees the field-level differences, such as time, patient or procedure, before applying them.

A later update for an already matched Booking arrives in the same screen, matched by:

- the date
- the surgeon
- the location
- the slot

The admin then approves the update.

This is so admins can check exactly what a hospital update changes before it reaches the schedule.

## Notes

An update to an already matched Booking still goes through this manual approval, showing the differences; for a row with no match, the admin effectively accepts it as a new record (Greg). Donald: automating updates after the first match "wouldn't take too much", but this manual step stays in for now. Confirmed again on 2026-10-07: a later update is matched by "the date, the surgeon, the location, the slot", and staff "just say approve update"; automated approvals come once the matching is trusted.
