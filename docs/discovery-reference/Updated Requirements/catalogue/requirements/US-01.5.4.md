Admins see every availability conflict across the schedule in one coloured view, instead of running a report and printing, annotating and reprinting it. A conflict is a booked List where the [hospital is closed](US-01.5.1) or the anaesthetist is unavailable ([conflict flagging](US-01.5.2)), including a short-notice sickness. Each conflict is coloured and shows the reason, the anaesthetist and the hospital.

From a conflict, an admin can reassign the List to cover it ([reassign a List](US-01.4.1)). The conflict clears once the List is covered or the clash is removed.

This is because the office has to run a report today to find which surgeon needs covering and which anaesthetist is away, and wants to see it at a glance ("a dashboard with colour").

## Acceptance criteria

- Given an anaesthetist who marks a booked List unavailable, when an admin opens the dashboard, then the List appears as a conflict and its Bookings are still in place.
- Given a conflict, when the List is reassigned to an available anaesthetist, then the conflict clears.
