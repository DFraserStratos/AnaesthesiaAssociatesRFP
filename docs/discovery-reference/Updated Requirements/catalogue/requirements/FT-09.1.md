For each [ledger pair](US-08.3.1), the engine creates an ACCREC to the payer and a draft ACCPAY to the anaesthetist together, in the same transaction, and links the two itself using the Xero IDs each one returns.

## Technical discussion

Proposed in our RFP response: one [authorised List](US-08.1.1) can produce several invoice pairs across different counterparties. If a later pair fails, the pairs already in Xero cannot be unwound, and a pair created only on the ACCPAY side is money owed to an anaesthetist with no receivable behind it. The expected handling is to track billing state per invoice rather than per List, so partial runs are resumable and visible. The specific policy, and who resolves it, is to be confirmed during Scoping and Design.
