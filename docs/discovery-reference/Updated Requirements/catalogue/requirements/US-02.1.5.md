The system pulls booking data from St George's and Southern Cross, the two hospitals integrated today, into the [matching screen](US-02.1.2), so an admin no longer downloads it by hand. It pulls:

- on an automatic schedule
- each time an admin opens the matching screen
- when an admin presses a sync button

The screen shows when each hospital was last synced, and shows a failed sync rather than hiding it.

Matching stays a manual admin review, as it is today. The sync only brings rows in; nothing is applied to a Booking until an admin decides.

This is so the office stops pulling from these two hospitals by hand, and keeps the checking step it relies on (who is on the List, double bookings, changed times, patients appearing and disappearing).

## Acceptance criteria

- **Scheduled pull.** Given a configured hospital, when the schedule fires, then new and changed rows from that hospital arrive on the matching screen.
- **Pull on open.** Given an admin opens the matching screen, then a sync runs for each integrated hospital.
- **Manual sync.** Given the sync button is pressed, then a sync runs immediately.
- **Last sync.** The screen shows the time of the last successful sync per hospital, and any failed attempt.
- **No silent apply.** Given rows have arrived, then every row still goes through the admin's match, create or reject decision, and rows that cannot be matched stay in the [unmatched queue](US-02.1.4).
