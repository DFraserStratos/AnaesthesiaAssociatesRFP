When an admin assigns a List, or a [Draft List](US-01.6.3), to an anaesthetist and the surgeon and anaesthetist are on the [blacklist](US-13.6.3), the system shows a warning. It is a soft warning: the admin can still go ahead.

The pickers also separate the blacklisted options from the others:

- choosing a surgeon for an anaesthetist's Slot, the surgeons blacklisted for that anaesthetist sit in their own clearly labelled group
- choosing an anaesthetist for a Draft List, the anaesthetists blacklisted for its surgeon sit in their own clearly labelled group

This is so the office sees a bad pairing before committing to it, without a hard block that would be worked around, the same way [availability conflicts](US-01.5.2) only warn (OQ-09).

## Acceptance criteria

- **Separated.** Blacklisted options appear apart from the others and are labelled.
- **Still selectable.** An admin can select a blacklisted option.
- **Warned.** Given a blacklisted pairing is selected, then a warning names the pairing before the assignment is saved.
- **Both paths.** The warning shows when assigning a List in a Slot and when assigning a Draft List.
