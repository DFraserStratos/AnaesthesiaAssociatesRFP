The Scheduling Engine updates an existing Booking whenever a modification arrives, from any source. This story is the automated path: a modification that arrives from an integration, such as a hospital feed or a surgeon's list, is applied without an admin deciding it.

Every update records who or what changed it, when, and what changed. For an automated update, the "who or what" is the integration it came from.

## Acceptance criteria

- **Automated update.** Given a modification arrives from an integration for a Booking the system holds, when it is applied, then the Booking is updated without an admin deciding it, and its [change history](US-02.5.5) records the integration as the source, when it was applied and what changed.

## Notes

Automated changes from an integration come after MVP (Donald: "automated changes need to happen after MVP"), with [automatic matching and updates](US-14.6.2). Until then, a change that arrives from a hospital still goes through the admin's review before it is applied (see [automatic sync](US-02.1.5)), and changes that arrive any other way are made by an admin through [manual booking entry](FT-02.3). Greg noted there could still be automatic changes wanted, for example a change to a patient's insurance details.
