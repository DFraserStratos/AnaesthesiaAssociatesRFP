When a List conflicts with a [hospital closure](US-01.5.1) or with the anaesthetist's [own unavailability](US-01.5.3), the Scheduling Engine flags it, rather than silently merging the data.

The flag is a soft warning, not a block: the Booking stays where it is, an availability conflict appears, and the List changes colour so the office can see it and resolve it (see the [availability conflict dashboard](US-01.5.4)). Blocking creates more problems than it solves. The same mechanism covers a short-notice sickness.

## Acceptance criteria

- Given a List whose hospital is closed or whose anaesthetist is unavailable, when a Booking is made on it, then the Booking is accepted and the List is flagged as a conflict.
- Given a booked List, when the anaesthetist marks it unavailable or the hospital closure is added, then the Bookings stay and the List is flagged.
- Nothing in the flow blocks the admin from continuing.

## Technical discussion

Proposed in our RFP response: this is treated as a business policy question for AA (OQ-09). Because bookings must be accepted up to the start of a session and theatres open for emergency work, a rule that cannot be overridden would be worked around outside the system. AA's answer (OQ-09) is a plain soft warning, so the response's confirm-with-a-captured-reason step is not required.

## Notes

Settled: soft warning (OQ-09). Private hospitals close on statutory holidays and over Christmas shutdowns; emergency work then goes to public hospitals, which are out of scope.
