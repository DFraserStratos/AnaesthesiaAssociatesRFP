A standard routine checks Bookings, and the billable parties on them, for known conditions and raises a warning for each one it finds. Each warning carries text saying what is wrong, and a Booking can carry more than one.

Warnings come in two kinds and two strengths:

- **before-procedure** or **after-procedure**, by when the condition matters
- **mild** or **strong**

Staff can always go ahead: a warning never blocks.

The current warnings are:

- an [unpaid prepayment](US-06.3.2): kind and strength not yet set
- a [billable patient with a balance](US-11.3.2): for an amount owing, mild while under the alert threshold, strong once over it, with days counted from the invoice date; a credit balance raises a mild warning; kind not yet set
- a [child as the billable party](US-11.2.4): mild, kind not yet set
- [base units outside the RVG code's range](US-03.3.1): an after-procedure warning for the office, strength not yet set

This is so every check works the same way, through one routine.

## Acceptance criteria

- **More than one.** Given two conditions on one Booking, when the routine runs, then both warnings show, each with its own text.
- **Never blocks.** Given a Booking with a warning, when it is saved, submitted or authorised, then the action goes through.
