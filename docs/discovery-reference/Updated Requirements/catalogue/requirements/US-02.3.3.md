After an admin [saves a change to a Booking](US-02.3.2), a button opens a compose window in their default mail client, prefilled with:

- a subject
- a boilerplate message
- the list of changes made since the last save
- the To address, where known (the hospital's or the surgeon's room's contact email)

The admin reviews, edits and sends it themselves. The system sends nothing.

This is so hospitals and admin teams are told about a change without a true integration and without writing each email by hand. The main trigger is a cover change (a new anaesthetist on a List), which Vanessa spends a lot of time emailing today.

## Acceptance criteria

- **Compose window.** Given a saved change, when the admin presses the button, then the default mail client opens with the subject, boilerplate and change list filled in.
- **To address.** Given a contact email is held for the hospital or the surgeon's room, then it is in the To field; otherwise To is left empty.
- **Length.** Given the change list is too long for the limit, then the body is shortened to fit and says so.
- **Nothing sent.** The system does not send the email or record it as sent.

## Technical discussion

This uses a `mailto:` link. Limits to design around: plain text only (no formatting, no attachments), and a practical length of roughly 2,000 characters for the whole link, which varies by mail client. The To address needs contact emails held on the hospital record ([reference tables](US-13.4.1)) and on the [surgeons' room](US-13.6.1).
