As the system, I act on each message as received to support late bookings up to session start.

## Technical discussion

Proposed in our RFP response: latency is likely caused by batching rather than SFTP itself. The system would poll the existing drop at short intervals and process each message the moment it lands, bringing latency from hours to under a minute without any hospital changing anything. The response prefers going live on near-real-time processing immediately, with hospitals moving to push transports progressively, rather than go-live waiting on other organisations.

The response assumes an existing SFTP drop of hospital messages; Q&A 2026-09-24 #4 says no live hospital integration exists today.
