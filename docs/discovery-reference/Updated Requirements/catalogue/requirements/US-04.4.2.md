Each procedure on the [master procedure list](US-05.1.6) has one or two default RVG Contracts, understood to be the standard RVG recommendation. They hold the procedure's base units and all its other settings.

The default RVG Contracts are imported from spreadsheets at the start, then maintained by hand, so a rare change to an RVG unit value is applied by hand.

This is so that, with base units living in Contracts, every procedure always has a standard price to start from.

## Acceptance criteria

- Given a procedure on the master list, then it has at least one default RVG Contract holding its base units.
- Given a Procedure priced on its default RVG Contract, then its base units come from that Contract.

## Notes

The OQ-62 board answer says one or two default Contracts per procedure; in the meeting Donald described one base Contract per procedure. Greg floated linking Contracts to a master code so an RVG change flows through to every Contract under it; not adopted.

How these per-procedure default RVG Contracts relate to each hospital's [RVG Default Hospital Contract](US-04.3.3) is not settled: for example where the hospital default takes its base units from, and which of them the [Contract picker](US-04.3.2) always offers. Greg's possible no-default-Contract model bears on this too (OQ-78).
