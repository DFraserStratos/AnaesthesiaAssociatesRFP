Ease of use is the headline requirement. Data entered once. Mobile-first anaesthetist experience. Deterministic, testable billing maths. Volumes: about 85 anaesthetists, 28,000 invoices a year.

## Technical discussion

Proposed in our RFP response:

- Hosting: Microsoft Azure, with encryption at rest and in transit and geographically redundant storage. Azure SQL holds schedule, billing and audit history. The intention is to host all data in Azure New Zealand North for NZ health data residency; as that region lacks the full Azure feature set, its use is to be confirmed in discovery.
- Edge protection: all internet traffic is fronted by Cloudflare, with geo-fencing to NZ traffic (if appropriate) and automated blocking of unusual request patterns.
- Compliance: the Health Information Privacy Code 2020 is the governing instrument, with HISO 10029 as the security framework and baseline. All data, including patient and practitioner information, is encrypted at rest and in transit.
- Application security: a Secure Development Lifecycle with code reviews and dependency scanning; strict input validation and sanitisation against injection, XSS and other common web vulnerabilities; comprehensive logging for integrity checks and forensic analysis.
- Penetration testing: independent third-party testing before go-live and for any major release or architectural change, with an annual test suggested (ideally aligned to avoid duplication). Issues are assessed and actioned by severity. Cadence and vendor to be agreed with AA.
- Vulnerability management: continuous automated scanning of code and cloud infrastructure (Azure Security Centre), dependency scanning with GitHub tooling, a monthly patch cycle with fast-track remediation for critical vulnerabilities, and Azure SQL monitoring of the production database for suspicious activity.
- Support access: Stratos personnel hold no standing access to production data; where investigation needs it, access is granted for a defined period and logged. Staff are bound by confidentiality obligations.
- Breach response: AA, as the agency holding the information, makes the notification decision; Stratos handles detection, containment and forensic analysis and gives AA the factual basis in time to meet the statutory timeframe. Escalation path and contact points to be agreed in Scoping and Design.
- Backups: automated daily full backups with frequent incremental log backups, encrypted in transit and at rest, geo-redundant copies in a secondary Azure region, and quarterly recovery tests.
- Disaster recovery: aim to restore the database from backups within 2 to 4 hours; point-in-time restore within the previous 35 days; long-term backup retention for up to 10 years. A cost-effective data retention policy is to be defined with AA.
- Environments and release: Development, Test, UAT and Production. Build and deployment pipelines are fully automated (GitHub, GitHub Actions), and each change is accepted by AA in UAT before release to Production.
- Infrastructure as Code (Terraform or Bicep): consistent environments, fast rebuild for recovery, every infrastructure change tracked and reviewable. The environment and software belong to AA, so another provider could take the system over.
- Monitoring: Azure Monitor and Application Insights for real-time health visibility.
- Support: BAU support Monday to Friday, 8:30am to 5:30pm NZT. Weekend or on-call cover is not provided by default; given late bookings up to the start of a session, coverage is to be discussed during scoping. Response targets where an SLA is in place: P1 1 hour, P2 same business day, P3 3 business days, P4 at an agreed time.
