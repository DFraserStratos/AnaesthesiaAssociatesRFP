Some surgeons do not want to work with some anaesthetists. Admin staff record each such pairing on a blacklist, maintained on the [surgeon's profile](US-13.6.2). The blacklist could also be shown on the anaesthetist's profile.

Each entry is one anaesthetist and one surgeon. Recommendation: allow an optional reason. Admin staff can see and maintain the blacklist; they already keep it today.

This is so the system knows the pairings the office keeps in its head today and can warn when one is about to be matched (see [the assignment warning](US-01.3.5)).

## Acceptance criteria

- **Record a pairing.** An admin can add a blacklist entry from a surgeon's profile. If the blacklist is also shown on the anaesthetist's profile, the entry appears there too.
- **Remove a pairing.** An admin can end an entry; the history of who changed it is kept (see US-13.5.2).
- **Warns, never blocks.** Blacklisted surgeons are shown clearly separated from others when choosing, and can still be selected. A soft warning shows when a (Draft) List is [assigned](US-01.3.5) and when an anaesthetist [hands their own List to a colleague](US-01.4.5).

## Notes

This needs the surgeon master list rather than free-text surgeon names. Greg's name for it was the 'naughty list'; the catalogue calls it the blacklist. What an anaesthetist sees of it, when [reassigning their own List](US-01.4.5), is OQ-43.
