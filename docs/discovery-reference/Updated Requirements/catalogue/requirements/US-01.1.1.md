The Scheduling Engine will create exactly two Slots for every active anaesthetist in the system on a daily basis, across the rolling horizon (four months in current practice): an AM and a PM Slot. It does this even when no List is attached and nothing is booked.

Each new Slot starts as free. Slots are created even when the anaesthetist is free or unavailable, so the views can show every anaesthetist.

This is so the Admin team always have somewhere to make bookings, and the calendar shows a complete picture with no gaps.

## Technical discussion

Every Slot is created and stored across the rolling horizon (four months in current practice), empty ones included (OQ-64; Greg: "the foundation on which everything else is painted"). Lists with no anaesthetist ([Draft Lists](FT-01.6)) show too.

The generation run, as Greg described it:

1. writes an AM and a PM Slot, as free, for every active anaesthetist
2. then paints the [anaesthetist's own calendar](US-01.5.3) (holidays and other unavailability) first, then the surgeons' [recurring bookings](US-01.3.2) on top (Donald; Greg: "Yes")

A surgeon's recurring booking that lands on a Slot the anaesthetist has already marked unavailable becomes a Draft List for the office to resolve (OQ-81).

## Notes

About 85 x 120 x 2 = 20,000 Slot records at current roster size.
