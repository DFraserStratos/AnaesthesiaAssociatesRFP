Every Contract carries AA's own unique identifier, alongside any holder codes kept for reference on its [Contract lines](US-04.2.4).

Holder codes are kept only for reference, so AA needs its own code to identify each Contract among thousands. The identifier is a short, structured AA code, and admins can [search the Contract list by it](US-04.3.2) (OQ-66).

## Acceptance criteria

- Given a new Contract, when it is saved, then it has a unique short AA code.
- Holder codes are kept for reference and do not replace the AA identifier.

## Notes

Ben says Contracts will all need codes. A short structured AA code is accepted for now (OQ-66), but its format is not set: it is part of designing the Contract, which Greg is to think through ("We need to design a contract"). Donald has doubts about the model, so it is built for now and validated later.

Greg read this story on 7 October without change ("OK. So far so good") and asked for a composite search, "like a modern search where you can type it in and figure out where it is", across the AA code, the holder's own codes and names. The draft technical design gives a Contract no AA code beyond its name, so the code stays a requirement (OQ-66) that the developers must add.
