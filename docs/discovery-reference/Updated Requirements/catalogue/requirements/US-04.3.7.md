Where a hospital's sheet says a Procedure is under contract but the Procedure is not on that Contract's schedule, an admin can still set the Contract on the Procedure and mark it to confirm with the hospital. This is the 'thirteenth operation': a new arrangement the hospital has introduced that AA does not have on file yet.

The office confirms with the hospital before the patient is invoiced, so the patient does not pay and then have to be refunded. If the hospital confirms there is no fixed price, the Procedure stays on the [default RVG Contract](US-04.3.3) and only the [billable party](US-11.2.2) changes, for example to the hospital. If it confirms a fixed price, the admin adds the price to the Contract's [schedule](US-04.2.4).

This is because hospitals bring out new contracts during the year and the schedule AA holds lags behind.

## Acceptance criteria

- Given a Procedure not on the Contract's schedule, when an admin sets that Contract, then the Procedure is flagged 'to confirm with the hospital' and shows on the [office review](US-07.2.2).
- Given the flag is open, when the List is invoiced, then the office confirms with the hospital before the patient is invoiced.
- Given the hospital confirms default pricing, when the admin clears the flag, then the Procedure is priced by RVG units and the billable party can be the hospital.

## Notes

The flag and the schedule update are our proposal; the meeting only described Vanessa checking with the hospital, and the default RVG outcome was only raised as a possibility. Example given: Christchurch Eye, where Vanessa checks with the hospital before billing the patient. When hospital data can define the Contract itself, that is future state (OQ-22) and sits in the Future Work lane; today the office reads the hospital sheet and sets it.
