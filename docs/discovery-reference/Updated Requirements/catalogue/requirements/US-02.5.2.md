The Scheduling Engine moves a Booking, or a whole List, to a new date, List and/or time whenever a reschedule arrives automatically from an integration, for example when a surgeon's rooms move a List.

Its [change history](US-02.5.5) stays intact through the move.

In the case of a clash / conflict, where the booking can't be moved to the new location automatically, the list becomes a [draft list](FT-01.6).

This is so the schedule follows the surgeon's rooms, who decide that a move happens, even when AA's own information (who is already booked, who is unavailable) means it cannot be applied exactly as sent. A move made by a person is a separate path, with a human looking at it: an anaesthetist [moving their own List](US-01.4.3) or [a single Booking](US-01.4.7).

## Acceptance criteria

- **Single Booking to the same surgeon's List.** Given an automated reschedule moves a Booking to a session where the same surgeon has a List, when it is applied, then the Booking moves onto that List, whoever that List's anaesthetist is.
- **Whole List, Slot free.** Given an automated reschedule moves a whole List and its anaesthetist's Slot in the new session is free, when it is applied, then the List moves there and stays assigned to that anaesthetist.
- **Clash becomes a [Draft List](FT-01.6).** Given an automated reschedule whose new location clashes with what AA holds, for example the List's anaesthetist already has a List in that session or is unavailable, when it is applied, then the change is accepted, not paused, and the List at its new date becomes a Draft List for the admin team to deal with.
- **History kept.** Given any automated reschedule, then the moved Booking or List keeps its change history, and the reschedule is recorded with the integration as its source.

## Technical discussion

- Surgeons' rooms send a copy of their List, a snapshot, not individual changes (Greg: "we're trying to work out the deltas"), so a reschedule has to be recognised by comparing snapshots.
- Two Lists apparently cannot merge (Donald), so a whole List moved into a session where the same surgeon already has a List is not simply combined with it.
- For a clash, the option of pausing the automated change in the admins' [matching screen](US-02.1.2) was considered and not taken: the surgeon's rooms decide the move happens, so the change is accepted and only the anaesthetist may end up different.
- Still open (OQ-87): a single Booking moved to a session where the surgeon has no List; what happens to a whole List moved into a session where the same surgeon already has one (Greg: "I think it goes to draft because there are some ugly combinations there"); and how a move is recognised from the snapshots.
