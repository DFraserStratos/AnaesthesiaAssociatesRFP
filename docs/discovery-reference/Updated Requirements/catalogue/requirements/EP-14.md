RFP scope for HL7 v2 and FHIR R4 hospital integration. No live hospital integration exists today (the real pathway is a manual download and matching screen, EP-02), so this is retained as future scope.

## Technical discussion

Proposed in our RFP response:

- A dedicated integration tier connects to hospital systems (HL7 v2 / FHIR R4 booking and clinical detail) and national health services (identity).
- Transport is an adapter: whichever way a message arrives, it enters the same queue and path. Moving a hospital from polling to push changes one adapter only, leaving the queue, retry policy, failure handling and translation untouched. The per-hospital picture (v2 or FHIR, polled or pushed) is a maintained configuration matrix.
- Future transports (an HTTPS endpoint for HL7 v2 sites, FHIR Subscriptions or scheduled resource polling for FHIR sites) depend on each hospital building an outbound interface on its own timetable, so hospitals are planned to move progressively.
- How many hospital integration formats are supported from go-live versus introduced progressively once in production is an open decision.

The response describes today's messages as landing on an SFTP drop for batch processing; this differs from Q&A 2026-09-24 #4, which says no live hospital integration exists today.
