The system's reference data is loaded at cutover from controlled spreadsheets that AA owns and has checked, not from Solutions Plus records. The spreadsheets cover:

- hospitals
- surgeons and surgeons' rooms
- [RVG groups](US-05.1.1) and [procedures](US-05.1.6), with base units
- [modifiers](US-05.1.5) with their units
- any Contracts (Could be RVG, fixed or other style)

The starting data is seeded once, run by a developer (directly against the database or similar), and then changed by hand on screen. This one-off seeding is separate from the [Contract schedule upload](US-04.2.13). Loading is repeatable, so a test system can be wiped and reloaded.

Solutions Plus is used only for operation names: its operation list is a starting list of names. Its unit values are not used, and junk entries, such as '10% discount' saved as a permanent operation, are removed before loading.

This is because there are few enough hospitals and surgeons to rebuild clean reference data from a spreadsheet, and the Solutions Plus values are not canonical.

## Acceptance criteria

- Recommendation: given a controlled spreadsheet, when it is loaded, then rows failing validation are reported and not loaded.
- Given a test system, when it is wiped and the same spreadsheets are loaded again, then it holds the same reference data.
- Recommendation: given the Solutions Plus operation list, when it is used as a starting list, then only names are taken and entries such as '10% discount' are excluded.

## Technical discussion

The draft technical design ([AR-29 p10](AR-29#p10)) suggests the same MVP baseline: a developer-run import, then office screens to create, edit and retire records, with loading repeatable so test environments can be wiped and reloaded. It is a draft and may change before the catch-up build (Notes 2026-10-07 · Pricing model documents #36).
