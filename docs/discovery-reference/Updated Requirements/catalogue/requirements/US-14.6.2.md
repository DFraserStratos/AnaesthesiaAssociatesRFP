Once the incoming data shapes are understood, the system matches incoming hospital rows to Lists and Bookings itself, and applies routine updates such as changed times, without an admin deciding each row. Anything it cannot match, or that looks wrong (a double booking, a patient who has disappeared or appeared), still goes to an admin for review.

This is so the office's daily check of the hospital sheets shrinks to the exceptions.

## Notes

Today's process, which the first release keeps, is a [manual matching review](US-02.1.2). In the future state the hospital's data can define the Contract, as AA answered in OQ-22 (Notes 2026-09-29 #7).
