When an admin edits a Booking in the Admin App, they save it explicitly. The system knows what changed since the last save: for each field, the value before and after, who saved it and when.

This is so an admin can review before committing, and so the saved changes can be reported, for example in a [drafted booking update email](US-02.3.3).

## Acceptance criteria

- **Explicit save.** Edits to a Booking are applied only when the admin saves.
- **Unsaved warning.** Leaving the page with unsaved edits warns the admin.
- **Changes known.** After a save, the system holds the list of fields changed since the previous save.
- **History.** Each save is recorded in the [append-only change history](US-02.5.5).

## Technical discussion

Saves are where [concurrent edits](US-02.5.6) are caught. Whether List-level changes (such as reassigning the anaesthetist) use the same save is covered by OQ-46.
