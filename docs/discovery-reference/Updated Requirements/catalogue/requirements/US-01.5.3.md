From a calendar in their app, an anaesthetist keeps their own Slots' availability up, independent of any List assignment:

- they mark days off ahead
- they can create a series (recurring days off are a rule on the calendar)
- they can edit or delete one instance of a series

For the anaesthetist this is a status, not a List. Marking a Slot unavailable when it already holds a List is surfaced to the office; how the clash is handled, a [conflict flag](US-01.5.2) or the Lists becoming [Draft Lists](FT-01.6), is OQ-64.

## Notes

Working reading of the OQ-27 answer: this is the same mechanism as the [Slot status](FT-01.2), not a separate record reconciled against Lists. Greg's contrary view (an unavailable half-day as "an unavailable list") is noted. The logical model is OQ-64.
