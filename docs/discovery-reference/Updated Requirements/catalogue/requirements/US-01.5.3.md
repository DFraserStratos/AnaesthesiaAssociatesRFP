From a calendar in their app, an anaesthetist keeps their own Slots' availability up, independent of any List assignment:

- they mark days off ahead
- they can create a series (recurring days off are a rule on the calendar)
- they can edit or delete one instance of a series

For the anaesthetist this is a status, not a List. Marking unavailable a Slot that already holds a List asks the anaesthetist to return the List to the office or assign it to a colleague ([mark unavailable while holding a List](US-01.5.5)).

## Notes

This is the same mechanism as the [Slot status](FT-01.2), not a separate record reconciled against Lists: OQ-64 settled the Slot as a box with a status that a List goes into. The debate over a Slot or a List with a status was resolved as logical versus implementation model.
