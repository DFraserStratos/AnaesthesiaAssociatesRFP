Admins maintain a master list of procedures by operation name, for example appendicectomy. Each one is mapped to the RVG code or category it belongs under, even where the RVG guide does not name that operation, and holds its own authoritative base units.

There are far fewer RVG entries than operation names, so the mapping is done by hand; gaps are filled with Vanessa's help.

Base units are held per procedure, not derived from the RVG code alone, because the same RVG code can appear with different values (for example minor versus simple). A [Contract can override](US-04.2.2) a procedure's base units for a hospital or funder arrangement. Positioning loadings such as sitting (beach-chair) or prone are [modifiers](US-05.1.5), not base units.

This is so the Billing/Invoice Engine always starts from a reliable base unit figure.

## Acceptance criteria

- Given a procedure in the master, when it is saved, then it has an RVG code or category and its own base units.
- Given an RVG code that appears with more than one base value, when procedures are mapped, then each keeps its own base units.
- Given a Contract with a base unit override for a procedure, when the Procedure is priced, then the override is used.
