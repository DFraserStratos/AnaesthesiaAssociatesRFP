Admins maintain a master list of procedures by operation name, for example appendicectomy, grouped by body part. Each procedure has a group, a subgroup and the RVG code or category it belongs under, even where the RVG guide does not name that operation. It also holds the procedure's [default modifiers](US-05.1.4).

There are far fewer RVG entries than operation names, so the mapping is done by hand; gaps are filled with Vanessa's help.

This list does not hold base units. Base units live in each procedure's one or two [default RVG Contracts](US-04.4.2), understood to be the standard RVG recommendation, because the same RVG code can appear with different values (for example minor versus simple). Where it does, AA can choose either way, and the system supports both:

- one default Contract for the procedure, with a range of base units
- one default Contract per kind, for example simple and complex, each with its own value

- A [Contract can override](US-04.2.2) a procedure's base units for a hospital or funder arrangement.
- If a procedure's base units are consistently overridden, AA should consider changing its own underlying data (the default RVG Contract) rather than keep overriding.

Positioning loadings such as sitting (beach-chair) or prone are [modifiers](US-05.1.5), not base units.

This is so every procedure maps to its RVG code and has a default RVG Contract to price from, giving the Billing/Invoice Engine a reliable base unit and modifier figure.

## Acceptance criteria

- Given a procedure in the master, when it is saved, then it has an RVG code or category and at least one default RVG Contract.
- Given a Contract with a base unit override for a procedure, when the Procedure is priced, then the override is used.
